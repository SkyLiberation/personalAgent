# 评测模块规范（EVM）

> 适用于 `evals/**`，补充根 [AGENTS.md](../AGENTS.md)的评测约束。修改评测前阅读 [EVD](../docs/devSpec/change-evidence.md)、[QLT](../docs/devSpec/quality-security.md)、[评测体系](../docs/evals/README.md)及目标目录；仅整理本文时按 DOC 检查。本文拥有用例登记、比较身份、归档和执行效率。

## 1. 证据分类不能混用

验证类别和替身边界由 [QLT](../docs/devSpec/quality-security.md#1-测试职责与覆盖)拥有；完整 Product E2E 资格由根规范拥有。直调 Application 的旅程是 Integration，文件名、marker 或 `baseline` 标签不提升证据等级。

产品失败 baseline、指标 baseline 和回归 E2E 的区别由 [EVD](../docs/devSpec/change-evidence.md#1-用户结果与工程约束的可执行基线)拥有；命名不能提升证据资格。

涉及模型前置决策时执行 [EVD 连续验证](../docs/devSpec/change-evidence.md#11-模型依赖链必须连续验证)；归档保留依赖、同轨迹消费、前置失败与后置未到达。评测 Prompt 执行 [COD 通用契约](../docs/devSpec/code-structure.md#6-生产-prompt-是版本化代码契约)，题目、资料和标签由场景数据提供。

## 2. Canonical owner 与写入口

| 文件 | 唯一职责 |
| --- | --- |
| `evals/e2e_quality/evidence_catalog.py` | 证据类别、`UserOutcomeContract` 与机器 eligibility |
| `evals/e2e_quality/validation_catalog.py` | 横切套件与预声明检查点；引用用例，不复制输入、评测器或改写类别 |
| `evals/e2e_quality/evidence_audit.py` | 只读语义、重叠和配置样本组审计 |
| `evals/e2e_quality/release_gate.py` | 发布归档信任判断 |
| `evals/e2e_quality/measurements.py` | 测量 schema |
| `evals/e2e_quality/metrics_report.py` | 聚合报表 |

新增或修改用例同步受影响 catalog、typed contract、选择器和[权威文档](../docs/evals/README.md)，不维护第二份发布清单。内部输入、评测器输出、测量和配置身份 typed；边界校验失败显式记录，不填默认成功。

## 3. 每条用例必须有唯一验收目的

用例的目标、证据类别、关键反事实、范围外事项和断言责任主体须可从 catalog、contract 或权威文档反查。

- 断言只覆盖声明结果、必要反事实及权限、隔离、幂等与副作用不变量；删除不影响目的的断言应清理。内部路径只有属于公开契约时才能作为产品通过条件。
- 优化用例的来源、预声明与验收执行 [EVD 闭环规则](../docs/devSpec/change-evidence.md#14-真实用例驱动优化与验收闭环)。不同横切套件复用同一密封 Trace，分别报告整例结果与已确定局部检查点。
- E2E 失败按 [QLT 阻塞流程](../docs/devSpec/quality-security.md#2-e2e-阻塞按目标阶段和单变量处理)审查并归档，不另建状态或发布清单。

局部通过、后续独立失败与合法终态按 [EVD 归因](../docs/devSpec/change-evidence.md#1-用户结果与工程约束的可执行基线)判断；局部通过不进入产品成功分子。

## 4. 产品 E2E 与 grader 边界

运行前固定评测器版本、输入和结果契约，判断用户可观察结果与关键反事实。字符串包含、工具调用、对象存在或模型自述不能替代语义结果；确定性字段仍按公开契约精确断言。

改变评分语义须用封存真实答案或代表性正反例验证评分资格；评分依赖模型时，再执行对应真实模型评测。纯确定性判据用适用只读回放和工程检查验证，不为形式调用模型，也不新增单元测试替代套件；产品行为改变仍按 EVD 验收。历史评分不覆盖，新评分形成独立身份与结果。

## 5. 比较身份与归档

每次执行形成独立、带 checksum 的归档；历史证据不覆盖。baseline、适用消融或责任边界反事实、target 分别可还原。失效方案的专属记录清理由[优化规则](../docs/optimization/README.md#待验证方案与失效方案的保留规则)拥有，不能删除共享支持、有效结论或产品发布证据。

临时诊断脚本、隔离实验源码、来源快照、日志和新运行归档放在 `.tmp/<专题>-<日期>/`，不向 `C:/pae` 新写文件。正式 E2E 与 Offline Eval 源码在 `evals/`。运行前显式设置适用的 `PERSONAL_AGENT_E2E_TRACE_DIR`、`PERSONAL_AGENT_PRODUCT_EVIDENCE_DIR` 及脚本输出目录，子进程同样适用。旧默认路径与历史归档未迁移时保留真实坐标，不能只改文档冒充迁移。`.tmp/` 被 Git 忽略，可复用结论须写入权威文档；需共享或发布的证据须另封存到可访问位置。

- 归档保存输入、身份、正式入口、交互模式、初始事实、代码身份与 dirty digest、配置、Prompt、模型、服务方、transport、schema、预算、fixture、评测器版本、样本计划、实际结果、Trace 和 checksum；不适用字段注明原因。代码身份有 commit、tree 或 patch，不能只有标签。
- 比较固定用户目标、输入、入口、初始事实、结果契约及声明变量外的条件；可用时固定 seed，不支持 seed 时记录缺口。两个独立随机轨迹不等于单变量确定性反事实。
- 比较器拒绝校验和失效、角色错误、身份不一致或代码与配置完全相同的伪配对。不同评分器、模型、服务方、Prompt、预算或配置组不混算；声明变量改变这些条件时采用新比较设计。
- 性能比较固定工作负载和重复计划，分别报告质量、时延、tokens、成本及恢复；不同任务与配置不能直接比较。不可用指标标未知，不能填零。
- pytest 失败、调用异常和缺失报告保留原始失败身份；晋级或局部检查不得覆盖原始 `pytest_outcome`。
- 历史证据复用须记录归档坐标、校验和、原始代码与配置身份、结果及适用边界。身份一致时复用有效归档；跨代码身份仅可按 [EVD](../docs/devSpec/change-evidence.md#12-按实际影响选择证据)作为准入参考或行为保持依据，须以变更差异及相关检查证明所验证消费者的行为、契约、实际模型输入与外部依赖语义保持。无法证明时执行新验证；不能改写旧身份、重标为新版本执行通过或并入目标版本发布分子。
- 横切检查只消费校验和有效且代码、配置、评测身份一致的 Trace；缺例、重复节点或跨身份拼接须失败。

## 6. 运行与声明

运行前预声明门槛、样本量、重复次数、成本与停止条件；按任务需要选择评测，不默认启动全量 live 矩阵。

验收与重新打开按 [EVD 第 1.4 节](../docs/devSpec/change-evidence.md#14-真实用例驱动优化与验收闭环)执行。真实阶段回放按 Offline Eval 保存 E2E 来源；未执行、未到达和失败按原计划保留，旧通过记录保持原身份。

定向 target 只证明该变更边界。发布声明须绑定目标 clean revision 的完整 release matrix，不能引用 dirty 版本或旧归档替代。报告分子、分母、未执行与未到达数量，以及适用的方差或置信边界；一次轨迹内多次调用不能冒充独立任务样本。不挑成功重跑，不改评分器迎合失败。

## 7. E2E 执行效率是评测设计门禁

高成本评测先完成 collect-only、影响路由和成本估算，按第 5 节核对可复用历史证据；检查与升级范围按 [EVD](../docs/devSpec/change-evidence.md#12-按实际影响选择证据)选择。无耗时依据时先做最小独立 pilot，再决定完整样本组。

停止线由本次方案预声明，不能将固定秒数当作所有模型的产品超时契约。没有任务依据时，单样本 60 秒、样本组 10 分钟或 200,000 tokens、同配置耗时超过有效基线两倍，作为成本重审信号；到达信号后在原子样本安全结束时暂停新增样本。已预声明并有依据的不同预算须记录理由；历史样本的原停止线不事后修改。

重审先区分服务方延迟与评测开销，再考虑独立样本归档、数学早停、实测顺序、最小影响选择及已证明隔离的复用。不得通过并发、缓存、mock、低预算或删样本掩盖成本。没有安全取消与 typed failure 归档时不强杀运行。

- 开发迭代可 fail-fast、排序与定向选择，保持正式输入、生产预算和评分契约，并报告实际执行与未执行量；不冒充完整发布证据。
- 完整发布不使用 `-x`、样本裁剪或测试旁路；promotion 不以 `--maxfail` 覆盖 typed 门禁。早停只依据预声明约束与已封存样本，局部良好结果不能提前晋级。
- 评测器、文档或无产品影响的脚手架使用适用 Offline Eval、历史只读回放和静态检查；完整 release matrix 只用于发布判断或必要的漂移复核。
- 新能力优先复用已有用例与 Trace；只有新目标、入口、初始事实、故障边界或反事实无法承载时才新增 case。
- 提速变更记录前后工程依据、覆盖、反馈时间、样本数与成本，不声称未经测量的收益。

运行、配对、promotion 和 release gate 命令由[运行与发布](../docs/evals/04-running-and-release.md)维护。
