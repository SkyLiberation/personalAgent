# 生产 Prompt 模块规范

> 适用于 `src/personal_agent/kernel/prompt_templates/**`，补充根 [AGENTS.md](../../../../AGENTS.md)的模板约束。修改模板前阅读 [COD 通用契约](../../../../docs/devSpec/code-structure.md#6-生产-prompt-是版本化代码契约)和 [CTX 输入审计](../../../../docs/devSpec/context-memory-retrieval.md#12-system-prompt-与-context-的设计及问题分析)；仅整理本文时按 DOC 检查。本文拥有注册、序列化和版本规则。

## 1. 唯一注册与生产消费

生产 Prompt 定义为 `PromptSpec`，使用稳定的职责名称，由 `personal_agent.kernel.prompts` 唯一注册。Root 根据 `Settings.prompt_language` 创建不可变 `PromptCatalog`，显式传给业务与 Adapter；调用方从实例 Catalog 取得正文与版本并写入请求及 Trace。默认中文，不使用进程可变语言或旧全局 getter。

语言资源按领域组织，复用名字、owner 和输出契约；译文独立版本化并绑定中文源版本，缺项、重复名称、源版本及占位变量失配时拒绝。Schema 仅对说明／标题做只读本地化，不改变机器字段与校验结构；已有消息、来源及执行事实保持原文。英文缺中文元数据翻译时显式失败，不回退中文。

工程生成的动态包装、工具结果说明、可修复错误和默认说明也须进入具名语言资源，由产生或物化它的 owner 选择实例 Catalog；不能只检查 System 与 Schema 后宣称全部输入已本地化。类级 Pydantic 校验通过显式 `ValidationInfo.context` 接收 Catalog，默认中文；不得用全局语言、异常文字反向匹配或递归 payload 翻译改写业务数据。模板变量应避免与 Catalog 方法参数（如 `name`）冲突，检查实际调用实参绑定。

本模块只拥有指令与输入序列化，不拥有业务事实、权限、执行、状态迁移、预算或完成判断。评测 Prompt 遵守 COD 的通用性要求，但不因此注册为生产能力。

## 2. 结构与输入边界

动态区块使用稳定结构并明确数据与指令边界；来源、角色、可信范围及成功标准按 COD 和 CTX 表达。不是所有自然语言正文都必须转换为 JSON，结构化边界也不能替代语义说明。

工程自有提示正文统一采用 Markdown：有职责分区的长指令使用标题、段落和清单，按职责选择分区；简短反馈及字段说明保留普通段落，不机械补齐固定标题。动态包装同样通过具名 Catalog 资源生成。工具参数、JSON 数据、原文、代码及第三方独立提示保持各自协议与保真边界；不得对最终请求递归替换标题或改写历史。中英文镜像同步结构与版本，标题插入不能合并原段、删除限定或改变变量。

已有文字的引用与恢复职责由 [COD 文本引用规则](../../../../docs/devSpec/code-structure.md#21-已有文字通过引用传递)拥有；序列化保留当前合法引用、可读原文和来源对应关系。

只有明确的行为保持迁移才要求实际发送字节不变。修复已知语义缺陷按产品变更取得证据、更新版本，不能同时声称保持字节。

## 3. 版本与验证

改变模板正文、字段语义、示例或输入构造契约时更新 `PromptSpec.version`；动态任务数据变化不等于模板版本变化。

静态检查与适用 Offline Eval 核对注册、版本、实际输入往返、输出 schema 和消费链。字节保持声明以实际请求对照为依据；语义变更按 COD 运行真实模型评测及适用 target E2E。未获准候选删除生产正文、旁路和专用版本，必要诊断与有效证据按归档规则保留。
