# ADR 0052 工具策略必须在派发前生效

状态为已接受的派发边界决定。验收进度归 [MCP 接入 Spec](../mcpDesign/README.md#521-工具策略决定与派发门禁)。

## 背景

真实 Filesystem MCP 探针发现，工具策略要求确认后，通用网关仍将移动发给 Server。旧实现依赖工具自行预览，并从业务参数读取确认。通用工具缺少可信的确认原件和预览契约。

## 决定

Policy 拥有判定。执行消费者只将允许决定解释为可派发，并在执行前写策略审计。未获准时沿现有权限错误返回，执行器不会调用具体工具。通用派发入口没有审批事实写入口。同步删除以自报确认驱动的通用幂等写入，保留历史查询和记录。适用的待确认 Command、审批绑定和恢复仍由具体 Application 持有。

## 取舍与防护

同一策略也服务入口准入和已注册能力投影。入口凭借宿主认证主体及可信渠道执行允许名单，投影消费部署拒绝规则，实际执行按调用上下文再次判定。工具参数与授权上下文分开传递。具体适用边界和验收归 [MCP 接入 Spec](../mcpDesign/README.md#522-身份入口与能力可见性)。

Gemini CLI 固定提交 `3c311be` 的 Scheduler 先检查 Policy，拒绝时结束，需确认时消费用户决定，随后才进入 Scheduled，执行器只消费已调度调用。采用这个派发顺序，保留本工程现有 Policy 契约和业务确认所有权。给 MCP 单独打补丁会留下相同问题的其他工具入口。增加通用审批持久层当前没有已准入的业务消费者。[策略与调度源码](https://github.com/google-gemini/gemini-cli/blob/3c311beac2e78336816dd4a123db39743f9fbf85/packages/core/src/scheduler/scheduler.ts#L603)

验收比较同一 HTTP 请求在修复前后的 MCP 实收日志和文件状态，并检查直接提交确认字段、部署拒绝和合法读取。已有知识删除、恢复和保存走各自确认契约。仅在具备对应 Application 的正式确认入口及授权、拒绝和恢复证据后，开放需确认的外部写入。
