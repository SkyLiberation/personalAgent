# ADR 0020：将来源支持标准固定接入 Conversation 验证

## 背景

生产 Verifier 曾把“应用端执行代码”接受为“开发者负责权限验证”的依据。中文验证契约加独立来源支持标准先后在两份固定输入中拦住该推断，但其他论断、反馈范围和自主修订仍有缺口。用户明确要求先接入已成立的优化，在正式路径继续定位；不再等全部离线问题解决才保存工程收益。原始证据和本轮过程由[推进记录第 56 节](../optimization/verification-source-support.md#56-将独立来源支持检查接入正式-verifier)拥有。

## 决定与责任主体

`verify_interaction_draft` 固定从 Registry 读取中文验证契约和独立来源支持标准。系统标准与冻结用户标准合并去重后，使用现有 typed 参数模型序列化为 JSON；模型恰好返回每项判断，工具校验完整性并执行全项通过聚合。任何来源支持失败或证据不足都禁止该稿作为通过结果发送。

用户标准继续由 `InteractionIntent` 唯一派生。回执的 `success_criteria` 和 `criteria_digest` 继续绑定原用户标准；模型报告的 `criterion_results` 还包含验证器固定提供的来源支持项。系统检查不伪装成用户原文要求，不回写用户标准。语义状态属于模型，标准完整性、聚合与文本绑定属于工具；工具版本和来源标准版本进入真实模型请求。

失败回执由现有 Conversation 循环消费，模型决定补证或改稿，修订稿再次验证。Verifier 只定位原句与证据缺口，不代写答案、不改变事实或权限、不代替 Completion。普通无验收要求的请求仍走原路径，本次不扩大 Verifier 的触发范围。

## Complexity Justification

新增一个有生产消费者的版本化标准模板，不新增类、字段、数据库、Port、服务或循环。复用已有 `criterion_results`、参数模型、执行网关和运行时调用点。删除独立标准注入、完整性校验或全项聚合后，必检与拒稿回归测试会失败；删除失败反馈消费后，修订重验测试会失败。

旧英文 v2 和标题拼接输入被直接替换，无双轨、开关或降级路径。中文判据复用已验证候选，JSON 数据边界和系统标准权威说明是明确的工程变化；不声称与离线请求字节完全一致。原报告和回执 Schema 的字段与枚举保持，说明补充系统检查的归属，不需要存量数据迁移。

## 外部参考与证据

采用已核对的两个独立 A 级依据：[RAGAS Faithfulness 官方契约](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)规定检查回答论断能否由检索资料推出；[OpenEvals groundedness](https://github.com/langchain-ai/openevals/blob/cf22d62f030cdf607f8c02bd604cb6374511642f/python/openevals/prompts/rag/groundedness.py)区分有效推断与额外前提。核对日期为 2026-09-10，详细比较见推进记录第 47 节；本工程失败事实决定是否接入，不复制外部评分、分阶段模型或平均分门槛。

Contract 已覆盖来源支持遗漏、重复、两种失败状态、反馈消费和修订后重验。真实原研究请求的 target 单独封存，实际结果统一见推进记录；接入不等于所有声明均能判准，也不等于产品完成或可发布。

## 风险、未采用方案与后续处理

已知风险包括其他文档级否定仍被认可、来源不足与任务覆盖混淆、反馈范围含混，以及真实模型可能不继续修订。按用户本轮决定，保留最小接入并逐项记录后续反例，不因独立缺口恢复旧英文验证器。安全、权限或文本绑定的因果回归须单独处置。

不让回答模型选择是否添加来源标准，不改写用户原要求，不增加投票、第二验证服务、固定修订次数或参考答案。广泛正例控制与发布矩阵仍是剩余验证；后续修改基于正式链路失败事实进行，不能把模型状态、契约测试或一次拒稿外推为普遍正确。
