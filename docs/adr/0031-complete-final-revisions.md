# ADR 0031：完整基稿上的局部修订

**状态：完整交接检查点成立，局部合并 Offline 成立；正式 E2E 失败，未取得产品完成资格。** 日期：2026-09-20 至 21 日。失败与上一轮提示尝试见[修订第 121 节](../optimization/revision-feedback-loop.md#121-修订引用保留约束与完整稿合成边界)，本轮原始证据保存于[归档](../../.tmp/final-revisions-20260920)。

## 背景与决定

真实研究拒稿之后，旧正文仍在，但逐段引用关系没有进入下一轮请求；模型重新成文时会漏选上一稿依据。明确保留提示在固定状态中没有补齐全部引用，故不继续叠加同义限制。采用完整基稿交接和局部修改协议，恢复未修改内容由确定性代码负责。

`SubmittedFinal` 是原 Interaction Journal 中的完整提交事实，保存原生 `FinalMessage`。同一交互的资源引用以运行身份和模型回合标识基稿，包含主体；只允许修改最新基稿。它不证明来源支持或交付成功，不新建草稿库、缓存或第二写入口。后继请求只展示最新提交，旧版本仍在日志中供审计；新交互不继承旧基稿，旧档案缺少基稿时只能重新提交完整回答。

生成端唯一外壳改为 `FinalSubmission.submission`。完整稿仍是 `FinalMessage`；修订稿是 `FinalRevision`，包括 `base_ref`、`edits` 和本次取证充分性。每项修改针对一个从 1 开始的段落，支持追加引用、替换全部引用或替换完整论述单元。拆分、重排与整体重写直接提交完整稿。没有旧结构的输入兼容或猜测式转换。

## 责任主体与正式路径

Conversation 决定正文及引用，`_verify_before_send` 前的提交记录进入原 `_commit` 日志写入口；`_decide` 投影最新基稿及验证意见。`final_revisions.py` 唯一负责当前基稿绑定和原子合并，精确引用仍由原 `citations.py` 恢复。过期版本、错主体、不存在的段落、重复修改或无效引用均拒绝；不部分写入、不自动补证、不模糊匹配。

合并输出仍是完整 `FinalMessage`，进入原 `_verify_before_send`，将全部正文和全部单元提交到原覆盖、来源支持与用户结果核验。Completion 与通过稿绑定不变。旧充分性不自动继承；未修改段落也没有自动通过资格。模型提交修订就表示提交合成后的完整回答，不增加额外工作循环或隐式交付触发。

## 外部依据与取舍

沿用同日核对的两项独立 A 级依据：[Anthropic Text editor tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/text-editor-tool) 的 `text_editor_20250728` 与 Gemini CLI 固定提交 `3c311beac2e78336816dd4a123db39743f9fbf85` 的 [`edit.ts`](https://github.com/google-gemini/gemini-cli/blob/3c311beac2e78336816dd4a123db39743f9fbf85/packages/core/src/tools/edit.ts)。前者由应用执行精确替换，后者读取当前文件并写入完整计算结果。来源身份和局限见[已核对记录](../../.tmp/revision-preservation-20260920/external-sources.json)。

只采纳局部修改与完整产物的责任分离，不采纳字符串复制定位、模糊恢复、额外修复模型、文件授权或备份系统。它们不能证明本工程语义修订稳定。使用系统已有 `ResourceRef` 表示基稿身份，不增加第二种身份模型或通用 JSON Patch。

## 复杂度说明（Complexity Justification）与退出

新增四个 typed 数据契约：段落修改、整稿修订、生成外壳和完整提交事实；一个合并模块及其错误类别。各自分别由模型输出、输入解析、日志恢复和正式核验消费，没有独立存储、配置开关或额外模型调用。删除成文阶段旧外壳、引用错误反馈中重复复制完整稿的字符串；完整提交成为引用关系的正式来源。

验证先检查真实失败数据的完整交接、未改部分保真、错误引用可替换、版本和范围拒绝及完整核验输入，再进行有界真实模型 Offline。局部检查成立后执行原中文研究 E2E 一例，原用户契约与失败结果保持；不运行单元测试。未修改段落被跳过、补丁导致可见范围扩大或错版本应用均否定候选；一次有界修正后仍失败则停止叠加，撤回未获资格部分并保留证据。独立无据论断不靠放宽核验解决。实际执行四次真实模型 Offline，总计 175,278 tokens；局部候选与两个语义边界符合预期。原中文 E2E 已执行一例并失败，9 份完整稿进入原核验，最后服务方 429 导致入口 503。完整重写仍漏引，原始修订种类未保存，不能声称正式稳定采用局部修改。交接收益单独[固化](../optimization/completed/complete-rejected-draft-handoff.md)，原结果由[评测登记](../evals/02-current-case-inventory.md#完整基稿与局部修订的验证)拥有。五个生产文件净增加 110 行；保留有证据的交接及合并，不再叠加操作或重复长跑。
