# ADR 0047：独立Python分析分别核验目标定义与回答交付

日期：2026-11-03更新。当前设计由[Spec §9.14](../optimization/to_verify/analysis-goal-maintenance.md#914-分离目标核验与回答核验的职责及历史)拥有，已接入并完成新连续前三轮，实际语义边界见[记录§34](../optimization/to_verify/verify_results/analysis-correctness.md#34-分离目标与回答核验的空会话连续前三轮)。旧统一核验第一轮因目标阶段要求已有数值而误拒、正常答案0及其费用由[记录§33](../optimization/to_verify/verify_results/analysis-correctness.md#33-逐项用户要求核验的空会话连续前三轮)保留；§31的原分[1,0,1]及§32的原分[1,0,0]保持历史身份。

## 问题与决定

目标定义与回答交付需要不同判据。统一任务曾因没有最终答案拒绝尚待执行的目标，使目标前置门禁与计算相互等待。用户现要求拆分核验职责及历史。目标核验只判断任务定义是否忠实表达用户要求；回答核验只判断本次实际交付是否符合要求。目标被接受只允许目标操作生效，不能证明实际任务已经完成。

范围仍为独立Python direct分析。默认目标创建、修订及沿用在写入前核验，读取除外；回答按原核验契约处理。2026-11-05 两类核验的部署选择统一改为 [ADR 0050](0050-verification-feature-flags.md)的 feature flags，默认开启，关闭时明确未核验；旧 `required`、`none` 配置已退出。主模型在原循环生成目标、执行、回答及修复，不增加目标提取阶段，不接claims、来源前置审读或程序复核。

## 责任、Context及调用

Conversation沿原Tool Port调用内部`verify_interaction_draft`，Runtime绑定`task_context.kind`选择目标或回答专用Prompt及固定总契约，分别记录`interaction_goal_verification`和`interaction_answer_verification`。两类模型均返回最小`UserRequirementAssessment`；每项含用户要求、三态和对应说明，Runtime聚合为原`SemanticVerificationReceipt`，不独立改写模型语义。

原Journal为唯一历史事实来源。`task_context.turns`保留每轮完整原始用户问题；目标请求只含目标提交、对应目标判决及目标修订，回答请求保留回答、对应回答判决、修复后回答及每次回答当时实际通过的目标。各自在筛选后保持原交互顺序，跨轮继续累计。2026-11-04按[Spec §9.22](../optimization/to_verify/analysis-goal-maintenance.md#922-核验交互逐条物化与通过判决精简)扩展回答事件的typed verified_goal：从原已接受目标操作的verification_ref恢复不可变通过回执，不新增目标写入口或持久镜像；每轮首次采用或更换goal时展示正文，每次回答绑定其目标判决编号，禁止用全局当前目标回填历史。当前有效目标只作为目标核验的参考另行交接，目标仍是可纠正工作解释，不代替用户原话。目标核验不再收到回答属性或尚未交付状态；两者都不重放普通工具和执行轨迹。主循环仍保留完整原生调用、工具结果、Runtime拦截及修复。

目标核验检查要求是否被正确规定，未来结果可以待取得；反馈仅指出任务定义的差异。回答核验比较实际结论与原要求，按正常回答、澄清、限制或失败的原属性判断。当前目标或历史通过不能豁免冲突，合法补充和不同实现方法不自动成为失败。

## 门禁、恢复与压缩

复用原网关、报告归一、回执及反馈消费者。Context要求全部事件与当前职责一致、最后提交无判决；回执绑定职责和确切正文。目标成功事实仍引用确切通过观察，由Journal校验后写入，拒绝不改变目标版本；回答仍经过原Completion才能交付。失败反馈按原调用进入主循环，由模型自主修订。

缓存绑定包含实际职责、历史、标准及正文；同稿恢复消费原回执，不把目标通过用于回答，也不跨用户问题复用。命中失败缓存仍追加原Runtime拒绝反馈，旧缓存交接修复及边界由[记录§28](../optimization/to_verify/verify_results/analysis-correctness.md#28-取消强制读取后的前三轮与缓存交接修正)拥有。

容量按本职责实际提示和Schema估算。核验摘要检查点按职责分别保存，只取同职责来源；摘要原件、digest及模型响应均绑定职责。仅压缩已结束且通过的历史轮次，完整用户原话、当前轮与未解决反馈保留。旧混合检查点和`goal_context`参数从当前内部契约删除；封存旧运行由其原源码解释，不新增兼容旁路。未触发压缩不声明语义效果。

## 复杂度、验证及退出

复用一个内部工具适配器和唯一日志，新增回答专用任务以及现有二值职责的Context和检查点绑定，避免重复服务和可写历史。原普通来源核验、Intent、claims及其他业务契约保持。固定提示中不加入本题对象、数字、条件或答案线索，中英文镜像同步版本。

从原第一问、CSV及空会话经正式HTTP连续前三轮一次，真实目标、核验、执行、回答及修复逐次接续；不做隔离模型验证，不注入旧结果。实际请求审计与用户结果分别报告，独立评分不回流Runtime。预算、判据及停止条件由子Spec唯一维护；静态检查不替代语义验收，不运行单元测试。正式失败封存后按最早责任复审，不以扩大预算或同义补采替代修复。
