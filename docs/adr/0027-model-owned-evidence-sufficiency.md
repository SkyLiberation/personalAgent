# ADR 0027：由模型判断本稿取证是否充分

**生产状态：2026-09-29 起退出。** 独立缺项分类暂停后，专用于越过其覆盖拒绝的 `evidence_sufficiency` 已从研究与 Final 契约移除；本 ADR 的局部结果与原始失败仍按历史版本保留。现行决定见 [ADR 0033](0033-claim-deletion-and-document-absence-pause.md)。

**历史状态（2026-09-18）：候选已接入，局部语义已验证；正式 target 已执行并按原契约失败，该次运行的封存记录不足以判断覆盖分支是否被触发，收益与撤回条件都还没有证据。** 当轮活动边界见[语义验证设计](../future/conversation-verification-false-positive.md#3-条件候选与因果准入顺序)，过程与证据见[取证第 116 节](../optimization/evidence-acquisition.md#116-由模型决定结束取证的契约验证)。

## 背景与决定

读取覆盖只描述实际返回内容，不能决定是否必须继续检索；来源可能没有所问条款，读完也不保证找到答案。原路径在缺项分类命中且来源未读完时立即拒绝，模型无法表达当前稿已具备充分的有限依据。当前正式 baseline 复现覆盖拒绝，后续又因 Final 引用结构非法而未交付；两个问题分别记录，不宣称充分性契约会修复引用格式。

候选在 `FinalMessage` 内增加可选 `evidence_sufficiency`，由 `EvidenceSufficiencyAssessment.reason` 表达模型认为现有证据足以支持本稿的理由。继续检索沿用原工具动作。覆盖反馈明确给出补证、修订或提交声明维持本稿的出口，不要求全文读完，也不预设一定存在答案。

验证入口仍校验引用、构造实际证据并执行缺项分类与绑定校验。声明存在时，覆盖分支继续进入局部支持和整体语义核验；声明缺失时保留覆盖反馈。未读范围不因声明改变，理由也不进入任何事实证据输入。通过后的正文仍由同一语义回执绑定，Completion 不变。

## 责任与生命周期

Conversation 拥有本次取证充分性的语义判断；执行系统拥有读取、搜索和版本事实；引用目录拥有证据绑定；Verifier 判断原稿实际断言与用户目标；Completion 判断所需结果证据是否齐全。

充分性声明与本次完整 Final 同时提交，只允许用于 `answer`。原服务直接把本次声明和本次引用传给验证工具，不缓存、不从历史稿复制，也不在后续 Final 缺少声明时自动沿用。新稿需由模型重新提交判断；源身份、可见性和版本继续由原引用链验证。理由不能代替正文中的未知范围说明。

## 复杂度与生产路径（Complexity Justification）

唯一新增类型为跨 Final 和验证参数共享的请求内语义契约；没有新增工具、Port、存储、状态机或循环。正式入口仍为 `/api/conversation/turn`，原 Composition Root 装配的 Conversation 服务调用原验证工具。修改原覆盖分支，不保留实验开关或备用实现；当前候选源码与初始工作树各自归档。

未采用仅追加“可以停止”的提示，因为原无条件覆盖分支不会消费它；未采用声明后直接交付，因为模型自评不能证明事实支持；未采用强制补读与固定搜索次数，因为这些策略不能证明所需条款存在。

## 外部机制比较

2026-09-17 核对两项独立 A 级官方协议：[Claude Code Stop hooks](https://code.claude.com/docs/en/hooks#stop)区分停止反馈与后续模型回合，并说明应避免不可解决条件持续阻塞；[Gemini CLI AfterAgent](https://geminicli.com/docs/hooks/reference/#afteragent)区分拒绝、修订反馈和停止控制。后者页面标注 2026-04-10 更新。

采纳反馈与结束决策分离的形式，拒绝移植其循环次数、清空 Context 或终止即成功等假设。它们没有与本工程相同的缺项充分性契约，本方案属于结合本工程失败的推导。详细范围见[外部核对](../../.tmp/evidence-sufficiency-20260917/external-comparison.md)，不能以外部机制代替本工程验证。

## 证据与退出条件

预声明、真实 baseline、代码身份、实际输入审计和语义样本保存在[本轮归档](../../.tmp/evidence-sufficiency-20260917)。固定责任边界验证只改变本稿声明是否存在，保留稿件、来源、分类及其他消费者；这类 Contract / Runtime Conformance 不能冒充 Product E2E。两条随机轨迹不用于证明局部因果。

已执行的相关检查为 183 项通过；真实模型已完成 6 个有效边界的单次检查；初始歧义正例的拒绝与修正后样本分开报告，共 18 次请求。Baseline 脚手架错误地设置 REVIEW 环境变量，原共享 recorder 因而保留 target 标签；原密封文件未改写，实际变更前身份另行记录，不能用于机器 baseline/target 晋级配对。

正式 target 已在原中文入口执行完毕并失败，原始结果与代码身份保存在[本轮归档](../../.tmp/evidence-sufficiency-20260917/target)。`target-code.zip` 与 `candidate-code.zip` 摘要相同，因此失败阶段可按对象核对。

| 实际结果 | 能支持的判断 |
| --- | --- |
| 断言 `delivered=False`，`disposition=limitation`，命中 64 个决策回合上限 | 本轮没有交付用户结果，终止原因是回合上限，不是入口错误 |
| 46 次工具调用中 21 次 `verify_interaction_draft` 失败：17 次 `cited_support_rejection`、4 次引句绑定参数错误（`invalid_param`） | 失败落在生成与局部支持语义，以及 ADR 0029 修复前的引句绑定行为 |
| 21 次验证失败中没有一次 `source_coverage_rejection` | 只能说明本轮没有产生覆盖拒绝，不能说明覆盖分支未被触发 |
| 三个比较主题覆盖均为 `false`，最早失败登记在 `input_index=8` 的 `tool_execution` | 阻塞发生在成稿与验证环节，不在取证入口 |
| `2,207,132` tokens、65 次模型调用、46 次工具调用、`provider_usage_complete=true`，未达到 6M tokens 与 96 次工具上限 | 本轮用量完整，但只支持“已执行并失败” |

该 target 既不能证明候选有效，也不能检验本条撤回条件：声明放过无据保证、跨稿自动沿用与覆盖循环转移都要求先分辨覆盖分支的实际行为。**归档格式决定了本轮无法作这个分辨：追踪记录只保存验证工具的结果，不保存入参，因此不含 `source_reading_state`、缺项分类结果和 Final 的 `evidence_sufficiency`。** 声明存在时覆盖分支即使命中也不产生拒绝，痕迹只会表现为后续的局部支持拒绝；分类未命中时同样只有局部支持拒绝，两者在该归档中不可区分。所以本轮的结论只能记为“该次运行不可判定”，不能写成覆盖分支未被触发或声明未被消费。

**另一份同代码的服务日志补上了本节缺失的入参观测。** 2026-09-18 的同代码复验归档中，服务日志的 `tool.audit` 与 `llm.parse` 事件显示 4 次验证都携带非空声明、来源 `fully_read` 全为假、每次验证前均执行缺项分类，结果为局部来源支持拒绝。这说明“模型提交声明、稿件进入来源支持核验”这条路径在正式链上真实发生过；仍未取得“声明使有据稿件通过核验并交付”的收益证据，该证据来自另一次运行，不改变本处“该次 target 不可判定”的结论。

4 次引句绑定失败属于 [ADR 0029](0029-bind-verifier-feedback-to-input-unit.md) 修复前的行为，当前代码只校验 `evidence_ids`，不因本轮结果回退该修复。归档的完成时间与报告耗时互相矛盾，另有约 9 小时无新 `llm.parse` 完成日志的缺口且原因未确认，本轮的时长与时间戳不作延迟证据。

若声明放过无据保证、污染引用、跨稿自动沿用或仅把相同覆盖循环转移到后续 Verifier，撤回相应候选。若正式用户结果未通过，保留原始失败并按实际责任边界判断；一次有界修正后仍复现同一问题时停止局部补丁。未通过完整门禁不得作为发布依据。
