# ADR 0030：以文档版本和原文位置标识引用

**状态：已接入目标代码，按用户要求仅做 Offline 验证；长期 E2E 观察尚未执行。** 日期：2026-09-18，2026-09-22 扩展至全部生成端引用。问题、实际结果和限制由[引用坐标记录](../optimization/citation-coordinate-confusion.md)拥有，后续观察条件见[活动设计](../future/citation-coordinate-identity.md)。本决定替换 ADR 0024 中逐观察累加的行引用编号，并删除完整结果号，不改变读取工具与原文存储。

## 背景与决定

正式研究第五稿提交不存在的 `e1698`，相关原文第 1698 行却对应三个合法编号。混淆原因尚不能由输出唯一确定，但重复读取导致同位置多身份、阅读行号到引用序号的二次映射可由代码确认。

全部生成端引用使用 `d1:1698`，其中 `d1` 在本次可见输入中按文档首次出现分配。Artifact 窗口绑定完整 `ResourceRef`，包含资源身份、主体和版本；完整内联网页以来源 URL 与原始正文 SHA-256 标识快照，按原文分行；其他内联结果按查询已分离的 payload 确定性 JSON 文档分行，以能力名与内容摘要标识。后续追加同文档读取不改变文档号；同版本同范围重复返回使用同一个引用。文档号是可重建的当前视图，不是持久资源身份，禁止跨交互或不同可见集合复用别名。

连续多行使用 `d1:1697-1700`，起止均包含，结束行必须大于起始行；单行仍写 `d1:1698`。范围中每一行都必须以完整行出现在当前可见目录中，同一版本的不同读取窗口可以共同覆盖范围；不能跳过未返回行、跨文档或用部分字符补全整行。非连续行分别引用。目录仍逐行提供原文，不预先枚举范围。

部分长行使用 `d1:1698:1-80`，字符范围按已返回字符串计算，起止均包含。这仍仅支持原样选择实际返回的字符片段，不支持任意裁切。整行与部分行不同，只有实际返回完整行时才提供不带字符范围的整行引用。同一坐标出现不同正文或来源时确定性失败。

完整结果也必须选择文档行，目录、输入投影与提交 Schema 均不再支持 `rN`。`document_kind=source_text` 表示来源正文，`tool_result` 表示工具结果文档；后者的行号属于返回结果，搜索摘要不冒充已读网页正文。卸载后的摘要、失败与核验输出不生成引用；只有实际返回的读取窗口可引用。Verifier 的 `e001` 等局部编号仍只在一次核验内标识已还原证据，不属于生成端可引用目录。

## 责任主体与生产路径

Journal 与 Artifact 拥有原始结果及版本，执行系统拥有来源和返回位置；Conversation 选择引用，`citations.py` 唯一构造坐标与恢复内容。`CitationSource` 保留 URL、行、起始列与文档种类，资源版本和内联内容摘要必须恰有一个；不会为内联结果创建虚假的 Artifact 引用。`SourceReadWindow` 与同位置一致性断言约束机械边界，语义支持继续由原 Verifier 判断。

正式消费者仍为 Conversation Action／Final 的 `materialize_citation_context` 和 `_verify_before_send` 内的 `materialize_cited_draft`，修订合成也使用同一绑定器。范围由 `_resolve_citation` 确定性展开为已有的逐行证据，每行继续携带原 `CitationSource`；交给核验器的正文和来源与显式逐行引用完全一致，不增加范围来源副本或另一套引用编号。范围长度不能超过可见目录大小，防止无界展开；缺少中间行时反馈明确指出缺失坐标。

原 Composition Root、工具、Plan、覆盖、取证充分性和核验意见绑定不变。`conversation.final` 为 `v19-document-line-ranges`，保留提交前自检，Schema 统一接受单行、连续整行和实际字符片段；不保留旧 `eN`、`rN` 输入解析或自动替换。行范围是同一文档坐标契约的扩展，旧协议历史失败不改写为通过。

## 外部依据与取舍

复核的两个独立 A 级源码是 OpenCode `v1.2.0` 的 `ReadTool` 与 Gemini CLI `3c311beac2e78336816dd4a123db39743f9fbf85` 的 `ReadFileToolInvocation`，分别见[路径及行号输出](../../.tmp/plain-source-tools-20260916/external/opencode-read.ts)和[文件与读取范围](../../.tmp/plain-source-tools-20260916/external/gemini-read.ts)。本轮复用[已核对的快照身份](../../.tmp/citation-coordinate-confusion-20260918/audit.json)。

只采纳同一资源与原文坐标的表达，以及连续读取范围的机制，不移植其文件系统授权、可变路径生命周期或截断策略。OpenCode 使用起始行与数量，Gemini 使用起止行；二者并不证明采用本工程的 `dN:L-R` 引用语法。它们不保证本工程模型的引用正确率；本工程继续依靠带版本的资源引用和精确可见范围校验。没有采用增加提示禁令、静默修正坏编号、额外选证模型或原生供应商引用服务。

## 复杂度说明（Complexity Justification）

在既有引用投影内统一文档映射与位置一致性检查，删除整条结果引用及重复正文投影。此前统一结果号的变更新增一个只读行投影类型与一个内联文档构造函数，三个生产文件净增 43 行，见[统一归档](../../.tmp/unified-citation-lines-20260922/promotion.json)。本次连续行扩展仍只修改这三个文件，新增一个私有解析函数，净增 17 行，见[范围变更归档](../../.tmp/citation-line-ranges-20260922/promotion.json)。范围在已有绑定责任主体中展开，不增加模型、来源字段、表、配置、持久状态、生产模型调用或运行循环。

原始执行记录保持，正文在每条模型输入的 `citations` 中只投影一次，查询及读取状态另行保留；重复观察仍保留，不声称输入成本下降。范围只减少生成端需要书写的引用项数，不减少核验器实际接收的证据内容。

## 验证范围与退出

用户明确要求引用改造只做 Offline 验证，因此不执行 E2E，不维护或运行 `tests/`。9 月 18 日的历史验证绑定当时仍保留结果号的版本；9 月 22 日使用近期失败修订的原始工具事实，核对全部文档行、实际模型投影与来源恢复，并检查重复来源、不同内联快照、部分行和不可见范围。两个真实模型短样本分别检查网页正文和搜索结果使用统一格式；不复用旧结果宣称新版本长 Context 已通过。具体预声明与结果由[问题记录](../optimization/citation-coordinate-confusion.md)拥有，局部通过不等于完整交付或发布。

错绑版本或主体、改写原文、放宽可见范围、同坐标内容冲突未拒绝均直接否定候选，应修正或撤回对应部分。无据结论、漏引和独立核验误判分别归因，不以放宽引用检查追求通过。长期概率性混用仍按原约定在后续正常 E2E 中观察，本轮不提前迁入 completed。
