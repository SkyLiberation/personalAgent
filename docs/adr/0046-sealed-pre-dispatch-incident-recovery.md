# ADR 0046：封存证据证明未派发的单次作业恢复

状态：2026-10-26 单次操作恢复核对已通过，真实 HTTP 接续已启动；执行及续跑结果由[用例盘点](../evals/02-current-case-inventory.md)拥有。

## 背景与依据

用户明确要求恢复 LongDS Netflix task2。原 `.tmp/ls25/t01/capture` 第 21 轮 Command `44f0494d6141d9b65848f4eaca8b77e7483bf18625c2225f9f46866463383ceb` 的本地 `job.json.tmp → job.json` 替换返回 WinError 5，后续 Docker 同名查询为 404，结果被保存为 unknown。原代码与当前代码逐字一致：先将 `create_requested` 置真，再持久化，再调用 Docker；结合已知 image、空 container ID、确切落盘异常和同名查询，异常唯一定位到调用 Docker 之前的状态落盘。仅凭 Docker 404 不能证明未执行。

现有普通 reconcile 保留 unknown，无法消费上述源码及封存事故证据。恢复目标是关闭这一笔被误分类的未派发失败，再继续第 21—34 轮；不修改生产代码，也不将技术失败记为程序成功。

原第 21 轮的工具反馈已写入 Journal，内容为 `unknown/backend_unknown`，工具错误分类为 `unrecoverable`。后继调用 `0dd1be86700842c1aab6f75f26a891f1` 的完整准备请求包含该反馈，但原件状态为 pending、response_refs 为空；实际 HTTP 请求均未包含该失败反馈。调用在 `before_send` 的未决执行门禁被拦截，再由 `application_budget` 处理写入终态 limitation。因此没有一次模型收到该错误后的修复尝试，不能归因为模型修复失败。既有终态返回路径先于已接受请求恢复，原样重发同一 run 也只返回原 limitation。分析模型的业务代码修订与 Runtime 的执行状态恢复属于不同责任，本次单次操作恢复没有修复这一通用闭环缺口。

## 决定、责任与边界

在 `.tmp/lr2/` 新副本中执行一次有审计的操作恢复，原归档及原 unknown 回执只读。临时 `PythonExecutionPort` 适配器仅接受上述完整 Command、原 scope、digest、许可、原字节摘要、封存错误及同版本源码证明，并再次读取真实 Docker 确认同名容器不存在。任一绑定不符或查询不可确认时停止。

适配器只提供这一笔请求的 `reconcile`：返回“派发前持久化失败”的 typed failed outcome，不提供进程退出码、stdout 或新计算结果。`execute` 永久拒绝，`cleanup` 不操作原临时目录或原后端记录。通过既有 `PythonExecutionService.execute()` 的恢复分支及 `FileInteractionJournal` 公共写入口追加当前执行 Fact 和 Receipt；不手改 JSON，不删除已接受动作，不改变 Command。事故报告保留原 unknown、完整证据绑定和新失败回执，区分历史观察与恢复结论。

这是原执行协议缺少事故证据输入时的一次运维例外，不增加生产状态、Port、开关、模型阶段或持久镜像，也不自动推广到其他 unknown。实际源码审计、原生落盘错误和真实 Docker 查询共同拥有“未派发”判断；模型不参与该判断。程序分析和业务答案仍由原正式 HTTP、模型与执行链产生。

## 验证与防护

先验证原 seal、源码身份、Command、程序及输入摘要、原 20 轮真实消息和许可。恢复只调用一次 reconcile、零 execute；重复提交同一已接受请求必须返回同一失败回执，跨主体请求必须拒绝。复核未决集合清空、其余执行事实和模型消费保持、原 seal 仍有效。完整操作报告单独封存；这些核对仅证明操作恢复边界，不计产品正确率。

随后在原主体、对话、完整 Journal、原文件及原许可下，以新 run 从同一官方第 21 轮请求继续；旧 run 已终态且截止，不能改写。保留 25,235,993 已知生成 tokens、1 次未知用量及此前实际执行耗时，任务 60M 及每轮 10M/40 决策限制保持。许可最晚至北京时间 2026-10-26 23:46；再次核对其有效期。新增回答独立评分，不重新评分前 20 轮；遇 429、身份变化或新未决执行则保留事实并停止。

## 替代方案与退出

普通 reconcile 已确定只能维持 unknown；全任务重跑会丢失接续边界并重复消费，直接改状态或删除 Journal 则失去 canonical 写入口和审计。选用绑定单一事故的操作适配器，无生产净复杂度增加。

本例外仅用于此次用户授权的 task2 恢复，最晚 2026-10-27 退出；脚本作为不可再执行的事故证据保留，依靠独占进度文件防止重复启动。长期状态分类与 Windows 落盘修复另按 EVD 准入，不由本次操作宣称修复。操作证明不成立则撤回操作副本，原封存保持，停止新模型请求。
