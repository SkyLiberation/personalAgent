# ADR 0057 · Conversation 技能作用域

日期 2026-11-23。作用域已接入，两个真实样本均验证目录、正文来源及 926 页交付。工程级样本的字母顺序与默认命名未达技能规则。[验收记录](../problems/Skill-Use-Bench/SF03_t1_merge_unordered.md#工程级与用户级技能验证)

## 问题与依据

公开 PDF 用例证明技能可以被模型按名称读取。基线的实际出站工具描述由进程级 `PERSONAL_AGENT_SKILL_ROOT` 决定，同一实例只能展示一份目录。DeepSeek Harness 根据工作目录查找工程根目录，再按工程、用户和打包来源处理同名技能。[公开用例证据](../problems/Skill-Use-Bench/SF03_t1_merge_unordered.md) · [DeepSeek 目录装配](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/packages/skill/skill-filesystem/src/index.ts#L252-L271)

## 决定

部署人员用 `PERSONAL_AGENT_SKILL_SCOPES` JSON 将用户主目录绑定到认证主体，将本机工程根绑定到认证主体和 `session_id`。Conversation Web 请求只有会话 ID，没有可信本机工作路径。组合根只接受具有 Web 认证密钥的主体，随后按已确认的身份和会话选择目录。沿用既有的打包技能根作为第三类来源。[目录和加载契约](../context/skill.md)

目录按启动快照读取。工程级和用户级权限只在已认证 Web 入口生效，其他入口沿用部署打包技能。Skill 组件负责按权限合并目录和处理同名优先级，Conversation 在决策上下文物化时仅展示当前可见摘要，工具网关执行时按同一入口、身份和会话重新选取正文。Journal 绑定工程级和用户级权限快照的目录摘要，权限改变时已有作用域绑定的会话须另开会话，避免恢复时继续使用被撤回目录的历史回执。旧会话在首次使用作用域目录时通过新会话接入。无作用域目录时，已有打包技能会话保留原配置方式。

静态工具描述由固定版本维护，当前目录放到主请求末尾的 Step Context。此切片复用注册、治理工具执行、原生回执与 Journal，新增两个目录授权字段和一个可空的快照摘要。无需新增工作区 API、表、监听进程或技能启动命令。

## 验收与撤回

沿正式 Conversation HTTP 复用 `SF03_t1_merge_unordered` 的原始任务及 PDF。一个样本为同一用户同时配置同名工程和用户技能，一个样本只配置用户技能。使用同一上游技能原件。校验实际出站目录只有一个同名条目，正文回执的来源分别为 `project` 和 `user`，并独立校验交付 PDF。用原运行的认证主体与会话检查未授权主体及其他会话的目录物化，并核对权限变化对恢复的拒绝。局部确定性检查与完整 PDF 结果分别记录。

模型在目录可见后仍自主选择加载。实验每种作用域各一条公开样本，用运行器的既有预算。发生工具准入越权、来源判定错误或跨会话泄露时撤回本切片，保留原公开题证据和打包技能运行方式。
