## 37. 思考控制参数与原生会话回传边界

**2026-09-10 本轮不重做先引文后结论的提示试验，转而核对服务方真实思考控制。** 旧 `selection.py` 已按 `action_id → quote → supported_statement` 输出，原候选取舍在第 2 节；`cited-units` 的 `citations` 也先于 `text`。它们不证明生成内部一定先依据后结论，却足以排除仅换字段顺序作为未经探索的新方案。没有因此重跑生成或增加引用字段。

当前证据把两种额度分开。MiMo 的[Chat API](https://mimo.mi.com/docs/en-US/api/chat/openai-api)和[深度思考说明](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/deep-thinking)将 `max_completion_tokens` 定义为思考加正文的总上限，公开列出的 `thinking` 控制为开关；本次文档核对没有取得可用于该直连服务的独立强度参数，不猜测 `reasoning_effort` 或第三方网关字段可用。其[超参数说明](https://mimo.mi.com/docs/en-US/api/guidance/model-hyperparameters)还明确，thinking 开启时 `temperature`、`top_p` 会采用服务方值，不能以传入 0 实现确定性思考。历史温度传输缺口发生在 thinking 关闭条件，不能拿它解释当前已开启 thinking 的全部错误。

另一个不同控制来自 [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)：其当前 OpenAI 格式支持 `reasoning_effort=low/high/max`，未指定时默认 `high`，`xhigh` 仍映射 `high`，`max` 对应独立档位。第 35 节 D1 没有指定该字段。因此本轮 E1 是同一 Pro 模型的推理强度敏感性诊断，不是继续轮换模型、要求更长思考文本或修改证据提示。旧响应没有回报实际强度，默认值的依据是本次官方文档，不冒充历史服务端遥测。

预声明 E1：逐字复用第 35 节 D1 的五条消息、正式 FinalMessage Schema、所有来源、用户任务、计划、验收、末尾读取摘要、显式禁令与其余请求参数，只新增 `reasoning_effort=max`。使用相同 `deepseek-v4-pro`、服务地址及现有凭据，不改变默认 MiMo 或 `.env`。不附 D1 回答、可见 think、人工标签、特定反例或新来源。只运行一次，输出上限 32,768，超时 480 秒，无自动重试或结构修复，单次至多 110,000 tokens、8 分钟。

预声明仍按完整六维中文正文和来源支持判定：保留正向事实与条件，不将已读未知写成指南没有规定，不把执行扩成权限，不添加无据排他；官方 URL 可追溯但不能替代支持关系。局部谨慎或未知单独记录，不能覆盖原完整交付 E2E。正常 `stop` 后仍有语义失败即停止该强度分支，不继续更换模型、增加字段或用提示强迫延长思考。只有实际 `length` 才允许先封存，再将总输出上限扩大到 65,536 做一次额度恢复；该条件调用单列身份、成本和结果，不能覆盖首答失败。两次总上限 275,000 tokens、16 分钟，未发生截断时不得执行第二次。

同时做只读原生会话边界审计。恢复链中 Action 返回真实 `tool_calls` 和 `reasoning_content`，后续请求却只包含 system/user 与重建的执行资料，没有前次 assistant/tool 历史。MiMo 中文指南对带工具调用的 assistant 回传规定必带 reasoning，英文 API 页使用建议措辞，两者强度差异保留；DeepSeek 文档另区分当前请求有无 `tools`，没有 tools 时历史 reasoning 会被忽略。不能把这些条件不加区分地套到当前 Final。整条消息未回传也不同于回传时漏字段，本轮不称其为已证实的 400 缺陷或幻觉根因。先核对实际 wire、调用次序和早期可见推理，不注入历史、伪造工具结果或恢复协议。

本轮属于 Offline Eval、只读协议分析与文档更新。模型拥有语义结果，服务方拥有参数含义，封存请求与响应拥有调用事实，人工审计检查来源范围。没有新增生产 Prompt、阶段、Schema、持久化、消费者或删除项，净生产复杂度为 0，canonical 评测器继续后置。原始脚本、参数依据、输入、响应及检查只写 `.tmp/source-support-20260910/thinking-control/`，不写 C:/pae。以下结果在预声明和实际调用后补充。

**E1 正常交付完整正文，但更高思考强度没有在本样本中纠正支持关系。** 实际返回 `deepseek-v4-pro`，停止状态为 `stop`，正式类型与正文一致，六个比较维度及三个官方 URL 均存在。用量为 60,851 输入、8,852 输出，其中 6,693 为推理，共 69,703 tokens、128.883 秒。没有达到 32,768 上限，没有重试或结构修复，因此未执行 65,536 条件恢复。D1 与 E1 的五条消息完全相同，服务方统计的输入用量相差 13 tokens；不据此猜测隐藏处理原因。两组各一个样本，只能报告本次结果，不能推出 `max` 稳定优于或劣于默认强度。

来源支持失败保留四项原话：权限段写“Function calling 指南正文没有给出统一的权限检查模型，也没有指定权限检查由哪一方负责”，又从应用执行代码推导“据此可推断权限控制必然落在应用侧自己执行的代码中”。前者超出当前 60/120 片段的观察范围，后者缺少连接执行与权限责任的前提。标为推断且声明不是官方保证，不能使“必然”获得依据。结果段还写“结果本身的格式没有强制 schema，也没有输出结果的 schema 校验机制”，总结重复“无输出 schema 校验机制”；内容格式自由不足以支持不存在校验机制的断言。选择段新增“并未保证模型一定会调用或只调用给出的工具”，允许不调用不能同时支持后半句关于工具集合限制的否定。本轮不据此反向宣称实际 API 必然执行哪种限制。

正确内容与错误分别保留。OpenAI 的 `parameters`、零个或多个调用、延迟加载、通常字符串与图片文件例外、`call_id` 均有对应前提。MCP 的服务端 MUST、客户端 SHOULD、可选 `outputSchema` 及声明后的条件，以及授权教程的可选性和 STDIO 范围仍保持。没有把 MCP 目录变化总结中省略接收者条件直接判成面向所有接收者的保证，也没有把局部正确覆盖整答失败。逐项依据及限定见 [E1 人工审计](../../.tmp/source-support-20260910/thinking-control/E1-review.json)。

完整可见推理先列引文，随后将应用执行到权限责任称为可辩护的推导，并认为标注推断即可避免冒充官方保证。它将指南没有权限模型称为谨慎、诚实的说法，末尾逐项引文自检仍接受这些判断。这与第 11、35 节已观察到的标准放宽一致：能定位引文、能复述禁令、增加思考量，都没有自动维持论断的主体、谓词与范围。当前证据来自模型实际返回的可见文本，不当作隐藏内部算法的因果证明。按预声明停止该强度分支，不继续加预算、轮换模型或增加同义提示。

**原生历史审计确认了上下文重建差异，但没有证明它导致本问题。** 限定恢复归档中 `sequence <= 44`，共 10 次 Action 请求及首次 Final。10 次 Action 均携带 17 个原生工具定义，返回真实工具调用和合计 21,848 字符的推理；后续请求没有前次 assistant、tool 消息或 `reasoning_content`。当前 `ConversationService._decide` 将会话文本、计划和 typed 执行资料重新组装，没有消费适配器返回的完整原生消息。原始调用及边界见 [native-boundary.json](../../.tmp/source-support-20260910/thinking-control/native-boundary.json)，不包含随后 Verifier。

早期 `33600-0032.json` 的推理已经认定权限由应用开发者负责，最终准备前也已有指南未规定权限的概括。因此回传旧推理可能保留错误，不能当作补入正确证据。MiMo 的回传约定、当前消息重建方式和已观测语义错误须分别判断；没有回传整条消息，不等同于回传带工具调用的消息时漏掉必填字段。下一边界只允许先寻找被重建丢失、且能区别错误形成与错误延续的信息，再设计保持真实工具调用及结果配对的反事实。尚不准入历史注入、额外事实持久化或生产回传修复。
