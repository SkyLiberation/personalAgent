## 已证明问题与责任

原中文自然任务要求说明 OpenAI 模型、宿主应用（含 MCP 客户端）和 MCP 服务器的协作，分别解释工具选择、调用、权限与结果校验，区分模型能力、应用实现和协议要求，附官方 URL 并如实限定未知。2026-10-08 正式轨迹已消费最终 v6 的拒稿、真实修订和当前稿接受，独立评分仍 0/1；原用户结果与局部机制分别计分。正式身份与原失败由[登记](../../evals/02-current-case-inventory.md#2026-10-08-选证状态修复后的正式入口结果)拥有。

错误稿把授权段落冠以“MCP 规范要求”。同一 Artifact 第 453 行明确章节是非规范性设计指导，第 471 行给出授权建议。实际输入审计证明 453 未进入生产模型，来源请求 0046 与 canonical 快照 0033 逐字一致，错误标签仍被原来源 v1 放行。外部原文拥有行为及性质，执行系统与 Runtime 拥有实际读取、身份和引用，Verifier 拥有语义支持判断。完整 Artifact 已保存，不能代替模型实际看到必要限定。

## 本轮复审范围与防护

先沿实际抓取、Artifact、关键词检索、读取、选证引用和来源请求核对同一资料的变化，明确已有上位限定怎样成为实际可见及可引用输入。当前代码的 `ReadableHtmlParser` 将标题作为普通文本块，`search_artifact_text` 只返回命中行；两项结构事实须与封存来源身份共同审查，不能直接推成新增章节结构的必要性。继续区分资料结构已丢失、完整资料仍可取但未被选择，以及核验已见前提仍漏判这几种原因。

当前来源任务同时核对行为、主体、范围和义务强度，但没有独立表达“某行为属于协议规定还是非规范性指导”的判断契约。实际构造只提交 draft、execution_evidence 和 fragments，原任务的 r4 三类归属要求未进入来源请求；原文齐全不能证明判断标准也齐全。因此此前“最小充分”仅指事实裁剪，完整任务契约充分性仍待诊断。其 Schema 只表达无据 findings，不能证明模型实际完成性质检查；此次有性质反证仍放行已否定该任务的可靠承担能力。可见理由辅助提示它把“规范要求”解释为普通引述、把官方 URL 作为归属依据；这不是唯一根因的因果证明。

下一设计先重审核验目标与语义判据：资料载有某行为、该行为属于哪类规范性质、在该性质内具有哪种义务强度分别须有实际原文支持；拒绝须指向稿件实际断言和冲突依据，合法设计指导、建议与真正协议条款均有通过出口。核对当前局部输入怎样承接原任务的层级区分要求，明确是否需要调整现有来源职责和输入输出契约，而非直接新增核验阶段。随后证明最早修正责任、最小差异和实际消费者，以同一最小充分负例及对应正控制区分新机制与旧机制，再决定取证链的最小修正。性质由原文拥有，代码守住身份、权限与引用；原用户目标、成功标准及主方案职责保持。

## 输入判断契约的隔离诊断预声明

2026-10-08 用户授权继续改变最小输入直至核验器识别。本轮新因果依据是实际来源输入缺少原 r4 归属要求，以及“规范要求”存在普通引述与协议性质的语义分歧；三个变体只用于定位，不据成功筛选证明生产收益。错误127字授权声明、真实原文、来源身份、Runtime片段目录与输出Schema保持，模型、thinking、480秒deadline及原恢复策略保持。归档为 `.tmp/verifier-input-decision-contract-20261008/`，累计此前5,520,173已知tokens及8次未知消耗保留。

| 变体顺序 | 相对前一输入的唯一变化 | 区分的假设 |
| --- | --- | --- |
| A1 | 在原最小请求增加 canonical r4 的原文和身份，现行Source v1保持 | 已识别原性质错误1/1，引用授权e001与性质限定e003；合法指导及真实协议两个正控制均通过，条件局部3/3 |
| A2 | A1若仍漏放，仅将三项原证据按452、453、471原文次序排列，id、文字和来源保持 | A1已成立，未调用；证据次序假设未验证 |
| A3 | A2若仍漏放，仅将隔离系统任务改为简短的通用内容支持与性质归属两项检查，实际材料保持 | A1已成立，未调用；精简性质判据假设未验证 |

每个变体先运行同一真实负例；漏放时封存并审查这一变体，再进入预声明的下一因果比较，不重采样同一输入。找到首个实际识别目标性质错误的变体后，停止尝试其他变体，运行同输入契约的合法设计指导和真实协议条款两个正控制，避免拒绝一切。负例须定位Runtime c2.f1，并说明非规范性性质与稿件归属的冲突；字段合法或无关拒稿不算识别。首次正控制失败停止，该变体不取得资格。

预声明最多3个变体负例及首个识别变体的2个正控制，共5个逻辑调用、60,000已知tokens与1,800秒原子复审边界，恢复和未知用量独立计账。实际仅调用A1三项，各1次，6,673 tokens，无恢复或新增未知；模型调用用时合计58.5秒。实际输出先封存再审阅，A2和A3未调用。新增字段来自隔离typed输入与当前canonical要求投影；正稿为既有单处标签修正，协议条款由真实原文和引用恢复，手工投影均为条件Offline Eval。[评测登记](../../evals/02-current-case-inventory.md#2026-10-08-最小输入补充真实归属要求后识别)拥有实际成本、输入和结果。

最小有效变化是在原输入追加 r4 原文“发送内容必须区分模型能力、应用实现与协议要求这三类归属。”及其criterion_id，不改现行Prompt、错误稿或三项原证据。此观察支持任务语境影响局部归属判断的假设，但独立判决不证明唯一根因或稳定识别率。负例反馈同时用了“强制性”一词，本轮仅认可它明确指出的非规范性指导与协议性质冲突，不将该词作为稿件明确断言MUST或独立强度错误的证据。正控制2/2守住合法指导与真实协议条款通过出口。

当前事实支持下述输入契约候选，尚未形成生产修复资格。实际生产原来还缺453限定，手工给出真实限定不能证明自动取证已完成；须通过同一模型轨迹消费实际取证、写稿和核验输出，不把此三项判决计为产品E2E。

## 拟议最小方案与防护

本轮设计修正限定于两项已证边界：Source未获得原任务判断语境；原生产链未取得章节性质限定。局部来源核验负责当前claim的支持关系，Coverage负责用户目标的研究覆盖，Final负责当前整份交付，独立grader负责外部用户结果评测；这些职责保持。Final已经获得冻结验收项，其通过不能补出未返回原文，也无需因本问题再次增加原始会话。

1. **从唯一任务事实源物化Source约束。** `verification_steps`已有当前冻结`ReviewCriteria`，直接用现行`research_goal_requirements(criteria)`投影输入requirements，与当前draft、execution_evidence和fragments一起交给Source。初版沿用这份冻结要求，不新增语义筛选调用或claim与目标的事实镜像；r4只是实际诊断样本，不在代码按编号或“MCP”关键词硬编码。隔离typed输入先验证全量冻结项相对诊断单条r4的差异，相关性压缩须有后续证据。
2. **明确Source按当前声明使用这些要求。** requirements用于理解稿件中的归属、条件和断言语义；Source仍只核验当前claim，不因该claim没有独立满足全部目标而拒绝。内容支持与性质归属分别核对，建议和真实协议条款均有合法通过出口。输入语义改变后更新唯一Source契约版本和全部消费者，旧v1报告不作为新契约通过依据；沿用现有model-binding生命周期内冻结验收项及reuse起点，核对复用的稿件、证据和任务约束一致，不预建新的持久化镜像。
3. **通过现有反馈与取证链取得限定。** 先以原0046完整真实输入、不手工补453，检查带真实任务约束的Source能否识别性质支持缺口。没有取得限定时反馈说明缺少的前提，不把未知章节性质写成已知非规范性。选证v7和研究模型消费本次实际反馈，通过既有search_artifact、read_artifact取得真实章节上下文；writer v17使用实际返回坐标修订或有据收窄，Runtime保持来源、权限与引用绑定。核验再次消费当前稿及其实际引用，确认必要限定已进入SDK请求；真实读取但未被引用物化同样不算解决。
4. **保留原主方案和最小变更边界。** 修订者继续消费真实旧稿与反馈，Final v6继续独立检查当前稿。此候选复用既有来源请求、工具、typed引用和复验，没有新增核验阶段、资料表、模型调用类型或通用章节解析层；网页标题结构调整只有后续证据证明现有链无法取得必要信息时另行准入。生产迁移采用唯一新输入契约并清理相应旧构造，独立评分语义及已校准参考保持。

本方案是待验证设计，最早修改点是Source请求物化，不将一次诊断成功当作生产修复。全量要求可能改变局部判断的影响由下表正控制及实际请求审计约束。生产复杂度目标是在既有边界增加typed输入和任务投影、沿用现有反馈消费者，新增模型阶段和持久化事实均为零；实际行数与调用成本由实施结果计量。
