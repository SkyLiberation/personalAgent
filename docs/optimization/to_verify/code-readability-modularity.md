# 代码可读性与功能模块化整理

问题编号：`CODE-READABILITY-MODULARITY-001`。变更类型为规范文档修订及严格保持行为的内部重构。

## 问题与目标

现行 COD 已要求唯一职责和生产可达性，但尚未把控制流可读性、功能模块的公开入口与内部协作写成明确检查条件。本轮先补齐这些规则，再审计生产代码中职责混装、重复实现和隐式依赖，选择有工程依据的相关模块整理。

目标是让读者从正式入口、模块职责和 typed 输入输出理解执行路径，并在同一职责的唯一实现处修改规则。初始排查以当前工作树为事实基线；已存在的研究能力修改和原始评测结论继续保留。

## 责任与落地方式

- 根 `AGENTS.md` 与 `CLAUDE.md` 同步保存全局门禁；COD 拥有代码可读性与模块划分正文，DOC 和中文写作规范拥有文档的阅读结构。
- 先按调用关系、职责和重复实现定位工程约束，再确定代码整理边界。抽取沿现有 Application、工具或 Adapter 边界组织，以现行生产调用方消费，清理被替代的实现。
- 保持用户结果契约、模型请求、工具协议、权限、状态、错误及副作用语义。跨越这些边界的差异须按 EVD 升级证据并重新准入。
- 改动后同步权威说明与索引，按优化规则将已成立的结论固化；本文的范围、证据和状态随落地更新。

## 验收计划

1. 在 `.tmp/readability-modularity-20261009/` 保存当前文件身份与受影响源码快照，使用可重复 AST 审计定位重复职责、函数依赖和生产调用点；记录整理前后的结构差异。
2. 对保持行为的移动、命名和控制流整理，核对迁移后的 AST、调用契约及依赖方向。涉及模型请求构造时，对照实际构造结果的字节、Schema、消息角色和顺序。
3. 必要离线回放使用已有真实输入与现行责任边界，报告实际样本和差异；不以逐函数用例或理想中间状态替代产品验收。行为保持依据不足时执行受影响的定向真实 E2E。
4. 运行 lint、依赖和规范检查，核对根入口逐字一致、尺寸、路由样本、文档链接、锚点、代码块和表格。现有 `tests/` 保持只读。
