# LongDS 长程数据分析 Spec

问题编号：`KNOWLEDGE-DECISION-DELIVERY-001`。本文拥有原 Netflix task3 连续分析用例、LT 需求、跨 run 依赖、L0—L3 及官方评分协议。已执行计划与结果移至[LongDS 验证记录](verify_results/longds-analysis.md)；新增 task2 语义候选及其独立身份见[长程语义设计](longtask-semantic-consistency.md)。

当前未知用量单独记录，不单独停止；确定性额度耗尽、许可到期及无法确认的执行继续按原门禁处理。实际策略见[Runtime](../../topics/runtime.md)，回答装配见[Verification 专题](../../topics/verification-and-completion.md)及[ADR 0041](../../adr/0041-replaceable-answer-result-modules.md)。历史记录中的旧额度、未知用量停止线和模型配置只说明当时身份。

状态：独立 Python 许可、跨轮原件及任务消费聚合已经接入；task3 完整交付和第 17→18 轮进程恢复已有实际证据，语义正确性尚未全部达标。最初接入状态与每次运行配置见[验证记录](verify_results/longds-analysis.md)，正式分数见[评测盘点](../../evals/02-current-case-inventory.md)。本页拥有固定用例与验收合同，新增语义机制由[SEM 候选](longtask-semantic-consistency.md)拥有。

## 1. 问题、用户结果与用例身份

**用持续变化的分析条件检验成果接续，而不是继续等待 SciFact 自然填满窗口。** 用户需要从 Netflix 目录和各国搜索热度建立市场分析，逐步修改口径、回看历史与临时假设，最终推荐三个市场。错误的历史版本会改变后续数值与推荐，因此长期依赖属于问题本身。

选定 `LongDS v1.1 / Lite` 的 `business/netflix_movies_and_tv_shows/task3`，完整 36 轮，16 个 CSV 共 3,454,619 字节，最长标注依赖跨度 30 轮。每轮原有 `context` 和 `question` 共同构成用户请求；它们是公开基准构造的委托，不是本工程采集的真实用户记录。固定提交、原题、依赖及文件尺寸见[来源清单](../../../.tmp/longds-design-20261023/source-manifest.json)与[只读审计](../../../.tmp/longds-design-20261023/task-audit.json)。

首轮请求的中文表达示意：

> 请根据附件中的 Netflix 目录和每周搜索热度，清洗数据，建立片名主表、国家／类别／导演／演员明细表和国家搜索热度汇总，报告清洗后条数、明细条数及后续需要的缺失情况。

此示意只解释任务，不替代完整原题。正式中文版本须逐轮保留原 `context` 的清洗、分母、年份、百分数、四位小数和并列排序规则，并冻结与英文原件的对应关系。这里描述已封存的 task3 中文身份；新增正式任务按[运行入口](../../evals/04-running-and-release.md)保留官方原稿，不据此自行翻译题面。第 18 轮临时改变长电影阈值，第 24 轮回看导演惩罚之前的评分，第 34 轮组合不同历史口径，第 36 轮综合推荐；采集器按顺序发送，未来问题不提前进入模型 Context。

36 轮是用户交互轮数。它验证持续分析与跨轮状态，不单独证明自主选题或一次委托后台执行；是否发生容量压力按实测记录。题目分数、流程完成、恢复和压缩分别报告。

## 2. 需求与行为规格

| --- | --- | --- |

| LT-02 自主计算 | 模型按需选择原件和工具；使用 Python 时自行编写或修订程序，执行后消费真实输出并保留版本 | 工程不提供解题程序、预计算表或期待数字；错误由原工具反馈，L1／L2 |
| LT-03 分析状态 | 模型遵循仍生效的用户原约束，正确区分本轮变更、默认更新、临时假设及历史回滚；计算和回答使用相应口径及成果版本 | 正确结果不能仅靠旧回答自证；原件来自当前授权下的真实历史，缺失明确反馈，不注入正确历史替换；L1／L2，已确认缺口见 [长程语义的整体复审与下一准入](verify_results/analysis-correctness.md#4-长程语义的整体复审与下一准入) |

| LT-05 结果评分 | 每轮实际 Final 独立对照该轮官方答案；完整任务同时报告逐轮分数及第 36 轮推荐 | Judge 故障、未答和语义错误分别记录；生产不消费评分反馈，L2 |

依赖继续为正式 Interface → Conversation Application → 既有 Model／Tool／Artifact Port，外层实现 Port 并由 Runtime 装配。评测 runner 位于 `evals/`，只发送原题、保存真实回答及评分；不得在该适配器里选择代码、推断市场结论、扫描执行结果后给模型补分析，或另起 Agent 循环。若当前授权或完成路径不能表达此任务，保留其正式失败，从最早责任处做最小适配，而不是绕开 Composition Root。

上述接入复用既有模块，未新增 Service、Repository、CodeAgent 或分析 Aggregate。独立许可、跨轮原件与任务消费约束沿原 owner 实现，typed 绑定见 ADR 0040；已验证的阶段及恢复边界保持原身份，不把语义失败解释为原接口尚未接入。新语义候选的实施和验证按其独立 Spec 推进。

## 4. 模型输入、工作成果与反馈

1. **初始事实。** 准备器将 16 个输入文件作为当前主体的合法只读 Artifact，经正式附件入口提供确切引用及中立环境说明。固定数据源身份、文件字节和可用 Python 库，生产侧只获得数据及当前原题；`answer`、`code`、`metadata.json`、参考 notebook 和依赖标签保留在评测侧独立目录，不挂载给执行容器，也不作为搜索来源。
2. **对话语义。** 调用方按正式契约携带实际已发生的用户／助手消息，保留前轮错误答复；不以标准答案替换。新轮的问题使当前 Plan 按原规则修订或新建，Plan 完成不清除仍可用于后续问题的获准成果，也不让 Plan 变成长任务数据仓库。
3. **原件接续。** 通用分析由 Conversation 从原 Journal 投影历史程序和 stdout 等有效引用，真实跨轮消费及其语义边界见[验证记录](verify_results/longds-analysis.md)。每次读取重新检查主体、对话及当前授权，不因同 user 或文件名相同默认可见；撤权、版本缺失和未获本次授权的跨对话来源明确拒绝。该投影属于运行输入事实，不能由采集器拼接工具观察或手工替换 Journal。
4. **分析状态。** 模型自己编写清洗、连接、评分和比较程序，并决定如何记录默认口径、临时分支及历史程序版本。现有 Python 不保留解释器变量，模型可复用程序和真实 stdout Artifact，作为下一程序的显式输入；Runtime 不代写分析账本，也不按照第几轮挑选状态。该安排提供原件接续，没有证明模型能正确选取当前口径；两项完整任务已出现分支混用及候选池误继承，后续按 [长程语义的整体复审与下一准入](verify_results/analysis-correctness.md#4-长程语义的整体复审与下一准入) 复审原约束、解释、程序和成果的连续消费。是否需要扩展工作产物须另有因果依据，不因错误存在就预建 Notebook 或新状态服务。
5. **反馈与完成。** 原参数、绑定、执行失败及 stderr 沿原观察回到同一模型循环，模型决定修订、补读或返回限制；工具成功不等于本轮答对。计算输出作为真实执行证据进入适用 Final／核验链，实际答案经正式 HTTP 返回后才发送下一原题。无真实用户补充时，模型请求澄清或确认会结束本次标准运行并记录未完成，不由采集器代答。
6. **Context。** 当前请求、有效分析约束、必要历史与引用由原物化职责提供，数据正文按需读搜。history checkpoint 属于原 run，不能复制给新 run 并假定覆盖成立；跨轮历史若需要新的压缩契约，先按真实请求取得压力证据再更新主循环唯一设计。LongDS 不保证当前百万窗口自然触发压缩，未触发单列未覆盖。

## 5. 评分、比较与正确性边界

优先沿用固定版本的官方题面、答案和 Judge 契约，不先设计新评分 Prompt 或投票流程。每轮要求的内容全部正确计 1，错项或缺项计 0，数值及排序按官方规则。该任务报告正确轮数／36、完整逐轮判分和最后推荐；完整正确完成需 36／36，低于此值保留实际成绩，不把流程走完写成全部答对。整套 Lite 的官方宏平均不能与单个 task3 的分数排名比较。

中文产品运行采用逐轮完整中文镜像；英文原题是独立比较身份，分别保存源码、模型／Provider、题面版本、预算、工具、原件及 Judge 配置。只有同任务同协议的对照才比较 Harness，模型不同的公开榜单只作组合系统参考。本页原用例只选 task3，不要求先跑完整套 Lite 才认可局部机制；后续 Lite 原稿批次和 task2 目标分别按运行入口及 SEM 设计固定身份。

官方 Judge 属于外部有参考答案的模型评分，不保证机械精确。保留原始判分、理由和服务错误；Judge 未产生有效判分时，报告评分覆盖不足，不补采到通过。若出现错判，先核对题面最小充分输入与官方规则，按 QLT 定位；真实 Agent 输出保持，不在该组中修改 Judge 后覆盖成绩。额外观察状态继承、回滚或错误传播只作归因，不取代官方分数，也不向运行中的模型回灌答案。

本轮不恢复旧研究 claim／verifier，不启动旧语义修复；LongDS 离线评分用于测量新任务结果，不能因此把错误压缩摘要、旧报告或原 E1 重标通过。自然压缩与进程恢复只在实际到达对应链路时按各自契约计分。

## 6. 分阶段验收与停止条件

| 用例 | 入口、固定输入及实际动作 | 判据与证据类别 |
| --- | --- | --- |
| L0 零模型准备 | 固定版本完整 36 轮；核对 16 份真实附件、64 MiB／32 项绑定上限、确切镜像库、正式 Schema、主体及源／答案目录隔离；检查新 run 与同 run 恢复请求规则 | 中文镜像、文件字节／blob、隔离、正式上传及镜像 import 已检查；通用许可装配已实现，实际 target 与覆盖按验证记录解释。准备不调用模型、不执行业务分析，不计产品能力通过 |
| L1 最小正式 baseline | 从空对话以正式 Web 连续执行原第 1、2 轮；真实模型自行读数据、写程序、消费成果并回答，沿当前部署和完成契约 | 保存完整实发请求、能力投影、实际接受／执行及两轮答案。能定位当前接口的最早缺口即可准入对应候选；未执行不得写失败。两轮通过只证明该阶段，不算 36 轮结果 |
| L2 完整连续任务 | 以通过 L1 边界验证的单一代码版本从空对话执行完整 36 轮；当前模型、数据和预算冻结，每轮仅接入前轮真实结果 | 流程完整、36 轮逐项准确率和第 36 轮推荐分别报告。业务数值或语义错误保留并沿真实状态继续，不注入纠正；只有该完整链支持本用例长程分析结论 |
| L3 进程恢复 | 从 L2 实际第 17 轮 Final 和工具事实均提交、无在途执行的边界保存原状态，换新 Runtime 再以原主体／对话提交第 18 轮，继续后续问题 | 实际恢复程序及结果版本、预算不重置，并产生新分析及最终回答；单纯重取第 17 轮 Final 不计通过。独立身份保留来源，L2 未覆盖本分支时不否定其正常链证据 |

L1 是新增能力的正式入口基线，不为凑轮数强制选择 Python。若模型有合法的其他完成方式，按真实结果判断；Python 未执行只记该工具分支未覆盖，不能记为模型漏参。L2 的工具路径、程序数量、压缩次数和实验耗时均不是成功条件。

必要反事实取自 L1／L2 实际请求与程序：同主体其他对话的未授权引用拒绝且零执行；一份实际输入或 stdout 原件不可用时准确反馈、恢复原件后可消费；已用程序及参数同一请求恢复不重复执行；达到已声明额度或授权到期时不新增模型调用，未知用量按当前政策记录。原题第 18、24、34、35 轮本身提供临时假设、回滚和混合状态的结果检查，不用手写理想历史替换它们。权限、缺失及预算检查点与原用户结果分列，实际阶段回放注明 Offline 范围。

额度拒绝继续按原许可与当前 Runtime 契约验收；已被撤销的未知用量单独停止反事实仅保留在[历史验证计划](verify_results/longds-analysis.md)，不作为当前验收义务。

Python 权限、原件缺失与确切请求恢复可先消费本次正式 target 已提交的真实执行阶段：选定不可变 Journal revision，确认所用 Python 已终态并有原 Receipt，复制该前缀及引用原件、记录各 SHA-256 后单独封存。该阶段允许生成侧继续核验，故只用于零模型、零新增执行的 Offline 反事实，不作为完整用户结果、模型费用恢复或 L3 检查点。回放只改变请求作用域或暂时移开一份真实 stdout 字节；恢复原字节后核对原回执，不生成替代程序或补写执行事实。

L3 的采集职责限于 `run_longds.py` 的正式 HTTP 生命周期与真实文件快照。L2 第 17 轮完整响应已返回后，核对该 run Final 已提交且无未知或在途执行，再复制原 `server-data`、原授权文件、确切附件引用及已发生消息，封存为检查点。本次采用 [切回 MiMo 的长任务验证](verify_results/longds-analysis.md#3-切回-mimo-的长任务验证) 的单轨迹接续：原进程在检查点后退出，新 Runtime 以原主体／对话／授权摘要及绝对到期继续第 18—36 轮，仅换传输 API key；前后段分别封存，按唯一轮次合计完整任务成绩，不再重复采样一个独立后半段。缺少完整检查点时拒绝恢复；不能从参考答案或元数据补历史，不能延长授权来抹去停机成本。

封存和 checksum 校验由既有 `longds_materials.py` 统一拥有，准备、评分及恢复读取同一只读校验，不使生成采集器依赖评分逻辑。新增恢复入口及校验复用已在独立能力 target 结束后接入；评分的官方 Prompt、模型请求构造及解析保持，9 项 AST 对照一致、8 份实际封存校验通过，复用原资格，不重付资格费用。新评分同时保存本次评分和材料模块源码，原资格来源与成绩不覆盖；当前 target 的评分在这次整理之前已完成，沿其原源码身份保留。

本轮设计和来源审计的预算为零业务／模型调用。后续 L1 固定为一次最多两用户轮，L2 为一次完整 36 轮，L3 为一个实际检查点；不按结果追加样本。先参考官方每用户轮 3,600 秒及原论文每轮 40 个推理／动作步骤，在本工程按其真实轮次口径显式配置并记录差异，技术重试另计物理用量；不把官方每轮一小时改称整任务一小时。任务总 token／费用和总截止须在运行前定值封存，参考本工程已有 20M 累计额度时是全任务上限，不是每轮赠送；Judge 的资格、样本及独立额度由 [本轮执行计划与固定配置](verify_results/longds-analysis.md#1-本轮执行计划与固定配置) 固定，与生成用量分列；预算未定不得启动。按实际完整请求和可用执行时限估算是否容纳样本，依据不足先保留待准入。

模型／工具协议错误使用原有界恢复；达到重复无效动作、权限失败、无法确认的执行、确定性额度耗尽或许可到期等原停止条件时，结束并保留未执行轮数。未知用量继续如实记录，不单独触发停止。普通答案错误继续完整测量，离线评分不改变运行路径；不在同一组改 Prompt、镜像、窗口、翻译或预算后续跑并合并成绩。新方案按 EVD 取得对应边界证据后，以新身份验证，原失败保留。

## 7. 实施顺序、删除项与整体 critic

1. **保持 L0／L1 准备与基线合同（LT-01、LT-04）。** 准备原题／中文镜像、真实数据和固定环境，核实正式授权、普通 Final 及已回答后的新 run。评测适配仅调用正式入口，不使用外部 ReAct 实现替换生产模型循环。
2. **按最早失败完善通用边界（LT-02—LT-04、LT-06）。** 独立 Python 许可、跨轮原件和预算分别属于原执行、Conversation／Artifact 和 Journal；以真实阶段验证一个因果切片再继续。涉及权限、持久化或完成语义的决定先写 ADR、更新对应唯一子 Spec 和受影响架构正文，不临时在 evals 中补生产职责。
3. **按原合同解释或执行新的 L2 身份（LT-01—LT-06）。** 没有本地解题脚本、标准中间表或正确 Plan 注入，消费真实程序和输出；记录完整准确率、错误传播及成本。达到已声明边界即关闭相应问题，不额外追加十轮完整任务作为语义修复组。
4. **独立推进 L3 和实际容量分支。** L3 验新 Runtime 的实质接续；容量分支继续由主循环 §3.11／C6／E3 拥有。没有自然触发时不扩大上下文正文或缩小窗口，也不阻止已经取得的长程分析成绩。

删除或替换的是把 Python 曝光、接受和费用条件直接等同检索许可的相关耦合，以及仅为未交付 Plan 服务却被误当全部分析历史的传递假设；正式替换必须覆盖生产、恢复和有效评测消费者。检索领域仍保留自己的部署及完成规则。保持当前 [Python 工具契约](python-data-analysis-tool.md)的 `code`／`input_files`、受控沙箱和原件字节；不恢复硬编码统计注入，不新增 Netflix 工具、持久 Notebook、用户下载或打包。

整体 critic：任务的业务价值是正确维护持续变化的分析状态并形成市场建议；36 轮真实依赖解决了 E1 负载代表性不足。框架仍由同一模型循环、现有执行和原事实 owner 承担，变更只覆盖正式基线证明的边界；评分是成熟外部协议，不等于生产语义批准或完全确定性事实。独立许可、原件投影和任务消费聚合已经接入，已完成的局部反事实与当前正式 target 分别记录；跨用户轮的实质接续与完整交付已有证据，语义正确性按独立评分及后续候选另验。开放研究和压缩收益分别保持原目标，不从固定问题序列或榜单分数外推。
