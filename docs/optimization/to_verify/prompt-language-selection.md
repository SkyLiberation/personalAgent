# Prompt 语言选择与 MiMo 配置 Spec

2026-10-27。用户明确要求新增可替换的英文 Prompt，生成入口统一使用 MiMo-V2.6-Flash，评分使用 MiMo-V2.6-Pro，替换后完整重跑 task2。本文分别约束语言、生成配置和评分配置；联合运行不用于宣称某个变量的独立收益。

## 1. 目标与已确认基线

- 当前注册表有 45 条生产 Prompt、22,526 字符，没有语言选择；调用覆盖 Application、工具说明、结构化包装／恢复、历史摘要及 Graphiti。中文任务逻辑与 task2 官方英文输入并存。
- 已封存的 task2 完整轨迹使用 MiniMax 与中文 Prompt，34 轮交付，DeepSeek 评分 2/34。原件为 `.tmp/cf27/c`、`.tmp/cf27r/c`、`.tmp/cf27q/c`，逐轮结果由[原验证记录](verify_results/longds-analysis.md#12-task2-完整前后验证)拥有。
- 当前 Judge 的模型和端点写死为 DeepSeek；生成配置仍有多处 MiniMax 覆写。共同 Provider Policy 已支持 MiMo，无需新建品牌适配器。
- 准备清单在 `.tmp/english-mimo-task2-20261027/`：当前 45 条模板及真实 HTTP 中的 41 条中文 Schema／工具元数据已独立盘点。语言覆盖不能只修改主 system。

新增英文是语言能力，不预设中文导致旧错误或英文能修复目标扩大。保留中文主契约，英文与中文分别版本化及验证。

## 3. 架构与责任

依据[架构入口](../../architecture/README.md)、[Prompt 模块规范](../../../src/personal_agent/kernel/prompt_templates/AGENTS.md)及[Provider 装配](../../architecture/cross-cutting.md#2-模型调用的实际组合)确定以下边界。

`kernel.prompt_registry` 拥有不可变 `PromptSpec`、语言资源及查找契约；`kernel.prompts` 是唯一资源注册入口。资源不拥有 Goal、执行、事实、权限或预算。沿现有领域模板组织英文资源，复用中文模板的名字、owner和输出契约，英文保存独立版本与所对应的中文源版本，源版本失配时拒绝使用。

Composition Root 从 typed Settings 的 `prompt_language` 取得一个不可变 Catalog，显式传给实际消费者。Application 负责其业务指令，Model Adapter 负责其包装／恢复指令；各自从同一实例 Catalog 取正文及版本。Schema 的英文说明是原 typed Schema 的只读投影，不产生第二验证模型。只替换说明和标题，保留原 schema 校验及所有机器字段；未登记的中文元数据在英文模式下显式拒绝。原用户消息、来源及实际执行返回值保持原文。

不设置进程全局可变语言，也不根据模型或 Provider 猜语言。`zh` 为产品默认；本次 task2 显式设置 `en`。新增语言只需添加资源并注册，业务调用方不增加语言分支。旧全局 Prompt getter 迁到 Catalog，全部活动消费者及回放同轮迁移，历史源码快照只读。

生成入口沿现有模型工厂与 Provider Policy；本次只统一配置，不改 Admission、执行、恢复和完成协议。评分配置属于 evals，由 typed Judge settings 解析独立环境变量，再注入原 `MeteredJudge`。它继续使用共同 Provider Policy、原 SDK 计量、资格、预算和解析，不与生产 Prompt 语言绑定，也不加入备用评分模型。

## 4. 外部依据与采用范围

Schema本地化只沿[JSON Schema applicator](https://json-schema.org/draft/2020-12/meta/applicator)定义的子Schema及定义／属性映射遍历，`const`、`enum`、`default`、`examples`中的对象属于数据，即使含title／description键也必须逐字保持。独立审查已复现普通递归会改写const约束，必须修正后才能冻结；Adapter分别处理response_format包装和内部schema，不能把包装当Schema遍历。

元数据缺项在一次局部修正后再次出现，英文运行保持停止。按[GNU gettext的提取](https://www.gnu.org/software/gettext/manual/html_node/xgettext-Invocation.html)与[未翻译清单](https://www.gnu.org/software/gettext/manual/html_node/msgattrib-Invocation.html)机制重审：不再只以历史样本出现过的字符串作为完整清单，而是先从当前实际发送Schema／动作工厂完整提取，再一次列出未翻译项。本工程提取对象为14个实际输出／研究动作Schema及真实smoke的17个工具，不安装PO工具或新增Runtime流程。完整清单定位了3条嵌套说明；全部注册后须一次完成当前构造、整组历史输入和常量反事实，不能逐条异常驱动补译后直接启动。该清单只证明当前可达边界，后续新Schema仍以显式缺项失败。

- [Python gettext](https://docs.python.org/3/library/gettext.html)：按显式语言选择独立目录及消息资源。采用语言与调用方解耦的资源目录机制；本工程保留现有 `PromptSpec` 版本和 owner，不增加运行时机器翻译。未找到翻译时采用显式错误，避免目标运行混回中文。
- MiMo [模型说明](https://mimo.mi.com/models/en-US/mimo-v2.6-flash)、[Pro说明](https://mimo.mi.com/models/en-US/mimo-v2.6-pro)及[Token Plan 接入](https://mimo.mi.com/docs/tokenplan/integration)：模型名为 `mimo-v2.6-flash`／`mimo-v2.6-pro`；本次使用专用 Token Plan 端点。两模型均为1M上下文、128K最大输出；配置保守声明1,000,000／131,072，不扩大本次32,768请求输出。
- [MiMo 思考协议](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)：使用 `thinking.type=enabled`，无 `reasoning_effort`；思考下不发送自定义采样参数；原工具交换完整回传 `reasoning_content`。复用已有 MiMo Policy，不增加额外品牌分支。

外部协议证明可接入，不证明 task2 正确性。既有源码及真实捕获提供本次缺口依据。

## 5. 验证顺序与预算

1. 先记录缺语言入口、实际中英混合输入及 Judge 写死的基线；完成资源、调用方、配置及实际请求的影响清单。
2. 零模型验证全部模板、占位变量、源版本、Schema结构及调用方迁移；复用完整真实请求核对中文保持、英文指令和说明覆盖、原始消息保真、独立实例和错误拒绝。只证明物化及配置边界，不冒充模型语义通过或单元测试。
3. MiMo Pro 用原官方正反例重新取得资格。统一评分预算1M，计入资格、旧34轮复评及新34轮评分，不能新目录清零。旧对照采用刚完成的 MiniMax／中文Prompt三段34轮答案；原 DeepSeek 2/34 保持历史身份，不直接混比分数。
4. 中文主 Prompt 保留独立正式入口 smoke，使用原 CSV 的中文自然表达做行数及字段检查，避免翻译 task2 原题。预声明最多1M tokens／一小时，只验证中文可达及实际结果，不用于 LongDS 成绩。
5. 中文 smoke 和评分资格通过后，用新身份按原英文题面连续执行 task2 34轮。新生成上限60M／34小时原许可、每run10M／40次决策／3600秒；输出32,768，工具和镜像沿原值。源码、语言、配置、材料及资格冻结到独立短路径后启动。
6. 从全部真实请求核对语言及模型绑定，逐轮评分与比较、分别报告正确性、交付、成本、延迟、中断及恢复。只有34/34正确才可说该用例全部通过，direct/none不计完整核验后的发布证据。

英文、生成模型及评分模型共同改变，结果只报告组合配置的观察，不拆归英文或某个Provider。服务拒绝、未决执行、配置漂移、非answer及原预算门禁保持；如有独立兼容阻塞，先按真实边界有界修正并更新本Spec，不以反馈注入答案或重复整轮凑通过。语义0分保留，不为改善得分改原题或评分判据。
