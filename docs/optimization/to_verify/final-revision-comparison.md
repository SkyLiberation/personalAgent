## 失败事实与输入差异

来源归属连续续接中，汇总模型实际收到旧稿及出处纠正反馈，将来源改为 OpenAI，同时把“步骤包括”改成“流程所列步骤为”。正文仍列四项，前文说明共五步，自检又声称四步已逐项核对。最终核验放行，独立评分按完整清单与原文冲突拒绝。此次研究 claims 没有改变；实际拒稿、生成稿、当前引用及两个报告见[连续审查](../../../.tmp/source-attribution-repair-20261002/continuation-review.json)。

同一轨迹的[实发输入审计](../../../.tmp/final-revision-comparison-usage-20261002/verifier-grader-input-audit.json)确认：

| 消费者 | 实际输入 | 相关边界 |
| --- | --- | --- |
| 独立汇总 v2 | 26,180 字符 user 输入，含 basis、旧完整稿及失败反馈 | 有修订依据，实际修正出处时改变了列举范围 |
| 最终 Verifier v4 | 59,288 字符 user 输入，8 个逐段引用单元 | 有五步数量原文，缺应用侧执行那一行；没有旧稿和旧反馈，仍放行当前数量矛盾 |
| 独立评分 v8 | 118,204 字符 user 输入，含原目标、当前答复及官方参考资料 | 额外取得第五步原文，按答案主动生成的完整清单识别事实错误 |

存在原文范围差异，也存在最终判据漏判。五步数量依据已进入最终请求，识别完整四项清单与五步声明冲突无需先取得第五步内容。原最终模板主要描述来源关系、引用和验收项，缺少明确的修订比较和完整清单核对。这里定位可修改的输入与契约边界；单轨迹不推断模型隐藏思考的唯一原因。

## 解决机制与防护

当前研究版本及实际引用原文拥有事实依据；汇总模型拥有表达修订，最终 Verifier 拥有最终声明的忠实性，Runtime 拥有适用反馈选择、版本和字节绑定。

1. Conversation 从同次运行现有 Journal 读取最近核验 Receipt，以其身份恢复确切拒稿和反馈。仅当最近 Receipt 为拒绝、绑定相同 `research_ref` 和冻结原项、正文等于上一份实际 `SubmittedFinal` 时带入 `previous_verification`。首稿和不适用反馈不带入旧稿；复用已有 typed Receipt，模型无需重抄旧文字。
2. `VerifyInteractionDraftArgs` 校验研究版本、原项、失败状态及旧稿 digest/ID；当前 `cited_units` 继续与当前段落逐字、按序绑定。历史投影只含一份旧稿、失败项和修订反馈，限于最近适用结果，避免累积全历史或复制来源全文。
3. `synthesis:v3-revision-scope` 先确定反馈涉及的说明，提交完整稿前对照旧稿和 claims，保留其他有据事实的主体、条件、数量、列举范围及义务强度，核对正文、总结和自检的一致性。
4. `final_verification:v5-revision-comparison` 先逐项确定当前实际断言，对照当前 claims 和本段原文；分别检查原问题是否修复、前后稿有哪些语义变化、每处变化是否有据。反馈范围外的变化同样核对。部分例子与完整清单按整句和上下文区分，完整清单核对数量和要素。同段每项事实分别判断，研究通过或自称核对不替代当前支持。
5. 旧稿与反馈只定位修订，事实判断服从当前依据。有据修改和同义表达可通过，旧稿错误按依据纠正。用户目标继续决定必要回答范围；作者主动声称完整时核对其声明，不把来源全部细节升为必答项。新事实仍经实际研究取证、来源核验和版本交接；评分器参考库保持评测归属。

正式路径为中文 Conversation 入口 → 已核验研究 → 独立汇总 → Runtime 最终核验 → 原 Completion Gate。比较在现有核验请求内执行，无新增模型阶段、持久状态或替代判决。删除历史投影会使核验丢失修订基稿与反馈，该反事实随下一轮验证执行。

## 身份、验证与退出

[本轮预声明及改动前身份](../../../.tmp/final-revision-comparison-usage-20261002/plan.json)固定模型调用预算为 0，Offline Eval 和 Product E2E 均为 0，只执行静态检查。原条件局部反例保持原分母，没有新正式枚举范围 baseline。

本轮 4 个生产文件的 Ruff、compileall 及依赖 DAG 检查通过，未新增生产模块或类；本次差异为新增 92 行、删除 23 行。11 份关联文档的本地链接及锚点检查无错误，命令结果与改动身份见[静态归档](../../../.tmp/final-revision-comparison-usage-20261002/static-checks.json)。这些结果仅记录工程检查，语义和恢复验收按下述条件继续执行。

统一验证先消费封存真实拒稿及连续输出，按当前原文范围核对数量漏判，再由汇总实际修订并继续核验、评分。相邻控制包含：纠正出处但保留部分列举、合法同义改写、旧稿错误获有据修复、反馈范围外新增无据声明，以及研究版本或原项改变后的反馈失效。分别计比较接入、语义判决、范围保真和用户结果，实际输出不中途替换为理想稿。

局部边界成立后运行一个原中文正式 HTTP target，从空资料连续消费真实模型和取证，沿用原预算及独立 v8 评分。调用、输入量、tokens、耗时与用户结果分别报告。一次有界修正仍复现该边界时停止同向追加，重审归因并按 ADR 0032 的临时接入期限处理；语义控制出现回归则撤回对应候选部分，保留有效历史证据。
