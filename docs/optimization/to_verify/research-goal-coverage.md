#### CLM-01 完整审读的执行方法

范围由[冻结计划](../../ablation/claim-verifier-baseline.plan.json)中的 `pilot`、`main`、`new-shadow` 固定：11 份完整输入、22 份报告，完整组 15 条、移除组 8 条原始 finding，共 23 条。聚焦、翻译、追问和重复诊断不进入本次分母。“不增加模型调用”指不重新运行被测模型、writer 或模型评分器；脚本只整理、校验和计数，不生成语义标签。2026-10-20 用户授权执行，AI 初审结果已封存在[完整报告](../../ablation/claim-complete-review-20261020.md)及[逐行数据](../../ablation/claim-complete-review-20261020.json)，归档使用 `.tmp/claim-complete-review-20261020/`。本会话此前已接触部分报告和旧裁决，本轮明确为非盲 AI 初审，不能将当前先读正文的顺序写成独立盲审。文本、证据绑定及要求完全相同的关系经逐字段校验后复用裁决，仍逐输入保留覆盖记录和版本分母。81 个回答段、76 个 claim、104 个原验收项及全部反馈均有记录；十条关系和两条反馈保持未决，独立人工复核另记。

1. **整理证据包。** 按任务和版本关联原用户请求、冻结要求、完整回答、claims、每个单元绑定原文及两组真实报告，核对原始身份和校验和。原件只读保留，审读投影隐藏组名，仍保存能恢复原报告和 finding 序号的映射；target 等内容会暴露组别的限制单列，不能宣称完全盲审。
2. **先标实际正文，再看报告。** 对每份完整回答中的可独立判断关系，以及用户原项是否由完整回答实际交付，记录原句位置、原文坐标及支持、缺证、明确冲突或未决的依据。关系粒度按实际语义固定，同一问题在 claim 与答案出现只计一次；不把每句或每个编号自动当一个事实。随后单独审读 claims，区分答案共有问题与研究稿独有问题。来源支持只使用本单元自己的绑定原文；目标满足只看实际完整回答；执行说明按适用的真实执行记录判断，记录缺失时保留未知。
3. **逐条对照 23 条反馈。** 将每条 finding 映射到实际关系，检查问题是否成立，并分别核对类别、定位、说明和引用。相同关系的重复反馈合并计点，纯同步要求与 claim 独有纠错单列；不能把它们直接计入答案纠错或误报。报告提示了初审遗漏的新问题时，重新依据正文和原文裁决，保留初审与报告提示后补录的区别；新问题对两组使用相同判据，不能拿模型报告直接充当真值。歧义或证据不足以裁决的项目记录未决，不强行计为正确或误报。
4. **独立复核后汇总。** 交付两份相互关联的审读表：关系表记录样本／版本、被评位置、实际断言、证据、判断与依据；反馈表记录原报告／序号、对应关系、四项反馈质量及复核状态。复核者检查两表及分歧。若只由本会话 AI 初审，明确记录“AI 初审，未独立人工复核”；只有未参与原实验审读的人实际核对后，才更新独立人工复核状态。争议保留，初审不冒称独立金标准。
5. **封存独立复评。** 按既有 A1—A3 汇总两组共同命中、各自独有命中、共同漏项、合法关系误报及可执行反馈，另报研究稿纠错和同步负担。逐输入保留，再按四个独立任务汇总，版本重复不增加任务数。每个回答段和原要求均有覆盖记录、22 份报告和 23 条反馈全部有去重映射及裁决或未决状态，才报告相应审读范围完成。原 `v1` 不改，复评带新身份、来源校验和及审读／复核状态；不补写 A4 修复或 A5 用户结果成绩。

可复核示例为 N2 首稿：`a2` 写出《中华流行病学杂志》，该段九条绑定原文未出现期刊名；完整组报告了这一出处支持缺口，移除组为空。该关系记为答案的本单元支持不足，不据此判断期刊名事实上错误。`a5` 已有依据的内容被要求同步补回 claims，则单列同步职责，不计为答案错误。示例输入见[完整真实输入](../../../.tmp/claim-verifier-ablation-20261018/new-stage-inputs/N2-first-input.json)，反馈见[完整组](../../../.tmp/claim-verifier-ablation-20261018/new-shadow/N2-first-full-result.json)与[移除组](../../../.tmp/claim-verifier-ablation-20261018/new-shadow/N2-first-no_claim-result.json)；其他关系须按相同步骤审读，不能由这些示例推算整篇成绩。

闭环前先做零模型调用的恢复预检：核对原 Journal、版本、完整模型输入、原文及资源身份可还原，实际报告与来源状态相符。封存旧两臂报告作为起点，只证明消费这些真实报告后的条件 A4；若报告、状态或消费者不完整，不由脚本补稿、补证或生成理想反馈。该输入继续保留局部证据；整例比较另从正式入口取得新真实轨迹。N3 整例曾以 HTTP 500 结束，不能因有完整核验请求就假定其完整恢复状态可用。

新增调用前，在本节固定输入清单、两臂代码与模型身份、完整执行链、独立终稿判据、样本及重复次数、实际轮数／tokens／时间预算、恢复和停止条件。预算依据原物理调用及真实修订耗用估算，先做一个原子配对的可行性及成本观察，再决定是否准入更大比较；不把该 pilot 当成语义修复完成或概率改善。若后续提出局部语义修复，关键完整真实输入的基线与候选各至少十次，按 [QLT 重复验证](../../devSpec/quality-security.md#13-局部语义判断类修复的重复验证)预声明整组标准；不机械扩大为十轮完整 E2E。旧裁剪中文实验不能顶替完整阶段验收。协议错误、服务失败、未知用量、未执行和未到达均保留，不采样直到命中。

## 2026-10-15 Source、Coverage 与 Final 合并设计

### 1. 目标、范围与因果依据

服务 Conversation 研究用户。研究模型可逐步取得资料、编辑 claims，并在准备交付时生成最终回答。系统只交付同一研究版本中经统一核验通过的最终回答；中间研究稿不代表完成。

此前独立汇总只允许改写已通过研究。按用户选定方案，研究模型直接写出准备交付的整体解释，同一模型修订 claims 和回答；核验器比较实际回答与用户目标。这改变被评产物、生成责任和反馈路径；局部校准、修订连续链和正式原目标续验已通过。当前不再以已接受的 G1 放行证明目标漏放，也不把收益单独归因于某句 Prompt、Context 长度或字段本身。

适用范围为研究生成、研究核验、修订和完成交接。普通非研究回答的核验、权限、工具、Provider、传输和独立评分保持。只有一次当前产物语义核验，不新增核验后的复核或最终补审。

### 3. 唯一产物与生成协议

#### 3.1 当前研究版本

沿用当前 canonical `ResearchClaims` 及其 `resource_ref`，增加一个 `final_answer` 字段。类型复用现有 `ConversationAnswerSegment` 的有序集合，每段仍为 `text` 与 `references`；中间态允许 `None`。不再另外存放可独立编辑的汇总稿、已通过回答副本或第二套研究版本。

```text
ResearchClaims
  resource_ref
  claims: [现有 claim_id、text、references]
  final_answer: [现有 text、references 分段] 或 None
```

`final_answer` 是完整用户回答，标题、提纲、写作意图和“已完成”自述不能替代。claim 可包含完整过程或多个来源支持的关系，数量由任务决定。用户所需联系必须进入实际正文并有据，不能让核验器自行连接。

#### 3.2 写入、引用与失效

研究写作者继续使用现有创建、片段修订、增删和改引动作，公共提交同时可携带 `final_answer`。同一提交先准入 claims 变更及新增引用，再绑定并保存回答；任一结构、版本或引用错误导致整个提交零写入。仅修改回答时沿当前版本提交，沿用现有重交入口，不增加另一个生成 Agent 或成文阶段。

中间提交没有最终回答时，保存研究进展并反馈当前尚不具备交付产物，不把它判成研究事实错误。claims 变更而本次未同时提交新回答时，`final_answer` 置空，避免旧回答静默配上新 claims。新资料返回但正文未变时，可保留当前回答，但相关核验报告失效，按新实际输入重新判断。

最终回答引用只能来自同次准入后 claims 的合法引用集合。Runtime 依照当前引用恢复原文和 URL，逐段保留实际绑定范围；模型负责判断所引内容是否支持相应表述。claim 间、回答段间都不能借用其他单元未绑定的正文冒充本单元已有支持。

提交完整回答顺序时，未改段落可使用当前 `base_ref` 下的 aN 引用，由 Runtime 恢复正文与原引用；新段或改段才生成 `text`／`references`。aN 只出现在只读投影和提交引用，不新增持久段落身份；canonical `final_answer` 始终只保存实际有序段落。

### 4. 单一核验与反馈

#### 4.1 输入与调用时机

准备交付前，Runtime 先检查 `final_answer` 存在且有实质正文、版本与引用合法。通过后，沿唯一研究核验入口提交原会话、冻结 requirements、完整 claims 及片段、完整最终回答及有序段落、各单元实际绑定原文，以及实际返回资料和读取范围。

claims 说明研究依据，最终回答拥有用户将收到的实际内容。目标覆盖直接对照最终回答；claims 中相关事实齐全不能替代回答已经解释。核验器同时检查研究依据及两者一致性，不接受“多个角色分别出现，所以协作关系已回答”的自动推断，也不要求用户未指定的产品实现。

不注入旧通过标签、selector 的 answered 自评、评分反馈或期望类别。实际请求须经过生产物化与 Model Port，Schema 外壳只添加一次；资料与被评正文均作为数据。

#### 4.2 统一错误标准

语义核验共八类：保留既有六类，目标缺项使用原拟定的 `requirement_not_satisfied`，本次增加一类 `answer_claim_mismatch`。没有最终回答属于确定性结果契约失败，不增加第九个模型语义类别。

| 情况 | 类别与反馈对象 |
| --- | --- |
| claim 的绑定引用不支持其实际外部断言 | `citation_not_supported`，定位 claim 片段及当前引用缺口 |
| 稿件声称未取得某内容，实际返回原文明示该同一内容 | `evidence_presence_conflict`，定位实际取证声明 |
| 与明示原文存在事实、出处、规范性质或义务强度冲突 | 沿用 `factual_conflict`、`source_attribution_conflict`、`normative_status_conflict`、`obligation_strength_conflict` |
| 仅根据最终回答，原目标所需内容或关系没有交付；不论 claims 是否已写出 | `requirement_not_satisfied`，定位原 criterion_id，说明最终回答实际缺少什么 |
| 最终回答遗漏现有 claim 的实质内容，或改变／新增其结论、必要关系及限定 | `answer_claim_mismatch`，遗漏定位原 claim 片段；改错或新增定位回答段落 |

`requirement_not_satisfied` 的被评对象只能是 `final_answer` 按顺序拼接的完整正文；用户原话与冻结 requirements 拥有判断标准。claims 和资料可用于其他类别及后续补证，但不能补成最终回答已经说明，也不能仅因 claims 不完整而判最终回答未满足目标。最终回答中的未知或限制同样按原用户允许范围判断，不能从 claims 的限制说明替它补写。

一次实际缺口只报告最直接类别。最终回答遗漏用户要求的内容时，优先报告 `requirement_not_satisfied`，不因 claims 已有答案而降为融合错误；同一遗漏不再重复报告 `answer_claim_mismatch`。其他独立的 claims 遗漏、改错或新增仍按融合类别核查，修订者都是研究模型。

`answer_claim_mismatch` 判断两份实际正文之间的关系，不要求逐字复写或逐条附 claim 编号；正常合并、去重和压缩可以通过。最终回答新增有资料依据但尚未进入 claims 的实质结论时，研究模型须同步补入研究，或收回该结论，不能由核验器代写。
