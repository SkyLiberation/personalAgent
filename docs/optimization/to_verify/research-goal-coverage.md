## 研究阶段目标对照候选与取证边界

**研究阶段按同一用户目标逐项取得事实并形成 claims，覆盖核验消费其结果。** 2026-10-02 后续审计确认：研究 selector 已接收原会话与实际资料，但 `needs` 自由生成，当前拒稿可使其只追踪部分论断；writer 只看到本轮所选及已有引用原文。旧真实稿所处轨迹已抓取客户端条款所在页面，但实际研究输入没有这些条款的可引用读窗；较新轨迹已返回条款却仍有内容遗漏与额外 API 子问题阻塞。以下目标对照设计已在隔离候选中验证并撤回，局部成立条件及剩余取证边界见后续结果。

1. 复用现行 `ReviewCriteria.criteria` 的唯一冻结标准，按顺序只读派生 `rN` 编号与验收文本，同时传给现有 selector 和 writer。原始会话仍拥有目标及用户允许的未知边界；编号与文本随 canonical 标准重建。
2. selector 的 `needs` 对每个原项恰好返回一次，关联当前 claim 身份、所需信息、合适的实际原文、适合理由与必要缺口。`answered` 说明当前实质回答，`ready` 指向可以补入的原文，`needs_evidence` 说明必要信息增量，`delivery_check` 把呈现及提交过程交给最终交付。Runtime 拒绝编号遗漏、重复、新增及非当前 claim，语义充分性由模型判断并接受现有 Verifier 核验。
3. 研究模型逐项对照全部可见资料与当前稿，先复用已读原文、补入必要主体及职责；相邻条件、列表前提和例外保持。尚未读到必要事实时，经正式动作入口补看相关范围。每次修订重新对照原项，不让局部拒稿覆盖其他未满足需求。
4. writer 消费同一原项对照及本轮所选正文，创建、局部修订或增补具体事实；Runtime 保持版本、片段地址、原引用继承及新增引用准入。修改项全文仍进入来源支持，完整集合继续接受现行覆盖与最终交付核验。模型自评只帮助研究决策。
5. 在用户允许未知的前提下，模型区分核心职责缺证与核心问题已回答后的附加未知。取证需求解释缺口为何妨碍原项；已取得的必要原文优先写入。原文身份、URL 与读取范围由现有执行及 binder 拥有。
