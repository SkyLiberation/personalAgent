# 研究论断核验与最终交付验收边界

当前阶段分工已按 [ADR 0032](../../adr/0032-conversation-research-claims.md)接入 Conversation 主链。2026-09-30 的目标代码还把来源 URL 存在性移出研究事实覆盖判据，保留确定性 `ResearchBasis.sources` 交接。生产可达与结构化交接的局部证据不能替代完整用户结果；正式验收见[最新结果](../../evals/02-current-case-inventory.md#2026-09-29-研究来源-url-交接与事实覆盖职责复验)。以下早期隔离实验按原日期保留。

`CLAIM-VERIFIER-STAGE-SCOPE-001` 属于[研究论断反馈修订无法收敛](../claim-revision-nonconvergence.md)的独立子问题。本页记录已接入目标生产路径但仍缺完整验收的阶段分工：研究 Verifier 只判断当前完整 claim 集合的来源支持与事实覆盖；独立汇总者负责把已核验论断写成用户答案并呈现官方 URL；最终 Verifier 与 Completion Gate 再判断用户要求的完整答复。它不改变[相同输入来源支持核验不一致](../claim-verifier-consistency.md)的独立事实。

## 失败事实与最早责任边界

[MiMo v2.6 Flash 连续续接](../../../.tmp/claim-integrated-provider-continuation-20260926/result.json)从真实中文用户任务自主检索、创建与修订，到第 18 版时，15 项论断的来源支持核验全部返回空 `findings`。随后按原稿发出的[整组语义请求](../../../.tmp/claim-integrated-provider-continuation-20260926/call-256-request.json)在 480 秒超时，没有判决，也没有到达复合结构扫描。不能把来源支持通过算作研究阶段完整通过。

仅在[固定输入诊断](../../../.tmp/claim-semantic-thinking-20260926/plan.json)中，保持模型、消息、schema 和其他参数不变，只关闭深度思考，[97 秒后返回的报告](../../../.tmp/claim-semantic-thinking-20260926/report.json)确认多数事实与可见证据吻合，同时明确以 claim 稿没有把官方 URL 排进正文为由拒绝，并在总反馈中要求增加自检说明。另一个判据返回 `insufficient_evidence` 但没有反馈，原因尚不明确，不能都归于 URL。原研究阶段判据已经说明 URL 可由来源身份恢复、论断集合不是最终文章；用户确实要求最终答案给 URL 和中文说明，但只要求提交前自行核对，未明确要求正文展示自检过程。该诊断因此暴露**验收对象错位**，还可能把执行前自检误判成输出缺项。单次不同服务参数的诊断不能证明原超时请求一定作同一判断，也不能证明只是改提示即可解决。

接入前的隔离链复用正式 `verify_interaction_draft` 的完整答复判据，研究稿又被拼成 `draft` 输入。研究模型仅有搜索、阅读、claim 正文与引用修订动作；没有最终汇总工具。若把缺 URL、所谓自检文字的意见原样送回研究模型，它可能把 URL 或交付说明塞入某条 claim，污染可独立核验的事实单位。运行系统不能把最终 URL 与中文答复要求从真实用户任务中永久删掉；最终验收还须准确区分“执行前自行核对”和“必须在正文写自检过程”。

2026-09-28 的[正式入口复验](claim-evidence-selection.md#2026-09-28-正式失败与一次有界修正)进一步到达该边界：从中文自然问题和空状态出发，研究第 6 版现有 15 条论断的来源支持都通过，随后事实覆盖以“claim 正文没有官方 URL”为一项缺失事实拒绝。实发引用绑定来源身份，最终答复尚未生成，因此这一项与研究阶段的事实覆盖对象不一致；同一报告另外指出 OpenAI MCP 工具映射和 MCP Authorization 正文尚未读取，这是真实资料缺口，不能因 URL 误判一并抹去。选证据候选随后继续取证，整例因预算耗尽返回 `limitation`，用户结果 `0/1`。这条连续正式轨迹确认阶段边界问题实际阻断了研究转入汇总，但不能单独证明修正它就能补足资料或完成用户答案。

## 两个独立实现的机制边界

截至 2026-09-27，以下均为已发布官方文档的 A 级机制坐标，网页没有绑定本工程的依赖版本。它们说明不同验证对象应在各自的消费点接受判断，不构成本工程已经修复或应复制外部拓扑的证据。

| 实现与可复核坐标 | 构造、消费与失败语义 | 本工程采纳与拒绝 |
| --- | --- | --- |
| [LangGraph 的 evaluator-optimizer](https://docs.langchain.com/oss/python/langgraph/workflows-agents#evaluator-optimizer) | 生成节点写入当前候选，评估节点用结构化结果给出接纳或反馈；条件边据此返回生成节点或结束。反馈属于当次被评候选，不代表后续汇总产物已经合格。 | 采纳“当前研究产物接受研究判据并把反馈交回原生成者”；不照搬图节点数量，也不把研究接纳直接转为用户完成。 |
| [OpenAI Agents SDK 的 guardrails](https://openai.github.io/openai-agents-python/guardrails/) | 输入检查只针对首个智能体，输出检查只针对产出最终结果的智能体；工具检查运行在对应工具调用边界。最终输出触发拒绝时，候选最终输出不被接纳。 | 采纳“最终答复检查只消费最终答复”；研究 claim 在中间产物边界核验。不复制其异常或会话持久化语义，也不把最终输出检查前移到研究稿。 |

两者并未共同规定“必须有几个 Verifier”。这里的推论仅是按产物和阶段划定判据：研究阶段可有来源支持与整组事实覆盖检查，最终阶段另验用户实际收到的答复；每个判断须有唯一对象、反馈去向和通过含义。运行记录和工具成功不能替代任一阶段的语义判断。

## 待验证的最小候选

先统一三个责任主体的对象和输入，不预建新的 Goal 表、缓存或第二份事实台账：

1. **研究 Verifier** 的逐项来源支持检查接收当前版本的 claim、对应来源身份和实际可见证据，判断论断与证据是否对应。整组事实覆盖只接收原始会话和当前 claims，判断事实是否足以供汇总者回答用户所问；来源 URL 存在性和最终呈现不进入该模型判据。研究判据不要求 claim 正文承担 URL 排版、中文回复或公开自检说明。其通过结果只表示当前 claim 版本“可交给汇总”，反馈须绑定版本与受影响的 claim；缺事实或无据结论交回研究模型。
2. **汇总模型** 使用独立 Context，接收已通过的 claim、对应来源身份和原始用户的完整交付要求。官方 URL 从 canonical 来源身份确定性恢复，再供汇总模型安排引用与中文说明；最终答复不能新增无据事实。缺 URL、行文组织或中文说明属于汇总稿修订，不交回只会编辑 claim 的研究模型。用户要求“提交前自行核对”时，应检查最终结果是否满足可观察要求，不能无依据增加“必须公开自检过程”的验收项。单独汇总模型仍须通过正式入口 baseline 和连续依赖验证准入。
3. **最终 Verifier 与 Completion Gate** 只消费真实最终答复及其所依据的已核验 claim 版本。最终 Verifier 检查答复是否忠实于已核验论断、是否额外加入无据事实，以及用户要求的 URL、中文说明和其他可观察交付项；不把同一条未变的 claim 与来源重新判成另一份研究事实。它须区分“汇总表达缺陷”与“研究事实缺口”，使反馈回到对应产物的写入者。Completion Gate 确认最终答复、研究版本和两阶段核验结果相互对应且 required result contract 齐全，不能把研究通过当作最终通过。

这套分工保留一份规范化 claim、一份来源身份和一份最终答复契约。研究核验拥有 claim 对来源的支持判断，最终核验拥有答复对已核验 claim 的忠实性判断；两者不对同一事实建立竞争性结论。运行系统确定性绑定产物版本、引用身份、核验结果及阶段迁移，Verifier 不写替代正文。模型负责开放语义判断；Prompt 只定义通用的阶段判据，不写死 MCP、OpenAI 或本用例参考答案。接入时必须移除“研究稿也按最终稿核验”的旧调用方式，不以阶段开关保留双轨。

## 研究 claim 链路的目标 E2E

目标 E2E 从用户的中文自然研究请求进入正式目标智能体，并由生产 Composition Root 连续执行取证、模型创建与修订 claim、当前版本的结构核验和来源支持核验、独立汇总、最终答案核验及 Completion。测试只给用户任务与初始环境，不提供预制 claim、引用、核验反馈或汇总稿。原始通过条件是用户收到有官方 URL 支撑且符合实际来源边界的中文答案；claim 是否创建、结构反馈是否送达、修订是否保留其他项，以及两个核验阶段是否消费了对应版本，分别记录为机制检查点，不能代替用户结果。

2026-09-27 接入前，`.tmp/claim-integrated-*` 与结构先行实验只证明隔离 Offline 链中的局部机制，当时正式 Conversation 入口仍消费 `FinalMessage.segments`，没有上述 claim 研究与独立汇总的生产消费者。因此，续跑隔离脚本不能命名为目标 E2E。[旧 Conversation 用例的首轮记录](../../../.tmp/claim-stage-formal-baseline-20260927/evidence/conversation-research-delivery-001/baseline/20260927T153347.919877Z-27204-b3d5af2c/CONVERSATION-RESEARCH-DELIVERY-001.1.trace.json)在客户端等待 300 秒后超时，只证明该次评测未取得用户结果。随后以同一自然任务、正式 HTTP 入口和生产装配执行[当时 Conversation 路径的单样本 baseline](../../../.tmp/claim-research-formal-e2e-20260927/evidence/claim-research-e2e-001/baseline/20260927T155230.860121Z-25308-4ed02cdc/CLAIM-RESEARCH-E2E-001.1.trace.json)，客户端等待上限为 1800 秒。运行约 366 秒、8 个模型回合、207,949 tokens 后返回 `limitation`，用户答案 `0/1`；实际工具读取与搜索继续到了预算耗尽，没有研究 claim、汇总或最终核验。一次网页读取收到 HTTP 404，但后续动作继续执行，不能据此把终态全归于该错误。虽然该次归档名称含 `claim-research-e2e`，它只证明当时正式路径未交付，**不是研究 claim 链路的 target E2E**，不能证明本候选的收益或失败。

因这次用例复用了既有中文用户任务、正式入口、初始事实和用户结果契约，又没有实际的 claim 生产检查点，另建的同义 E2E 用例已撤回，保留原始失败归档供诊断。正式接入后应优先复用该用户旅程，在同一 Trace 中分别记录用户结果与研究 claim 的真实版本、核验和汇总检查点；只有既有用例无法承载不同用户目标或必要反事实时才新增 case。不能靠给现行通用旅程改名来声称研究 claim 的 E2E 已运行。

## 连续验证与退出

封存的旧正式样本证明第 18 版已引用来源的执行事实含架构页 URL，而当时覆盖输入缺少该来源绑定。首次来源绑定 target 中，研究覆盖通过并实际进入汇总，typed `ResearchBasis.sources` 与最终答复保留了官方 URL；然而该随机轨迹的 claims 也写有 URL，无法把覆盖通过归因于绑定，而且独立评测器没有给出有效判决。第二次同入口 target 使用事实覆盖专用 Prompt，在前置逐项来源支持与修订循环耗尽决策回合，覆盖与汇总未到达。两次原始用户结果均为 `0/1`，不能声称整个阶段方案验收通过；[完整计分与归档](../../evals/02-current-case-inventory.md#2026-09-29-研究来源-url-交接与事实覆盖职责复验)保持独立。

下一次准入必须先处理前置来源支持修订无法收敛的具体失败，再让同一中文自然请求从空证据连续到达事实覆盖、结构化来源交接、独立汇总、最终 Verifier 和 Completion。覆盖模型若仍仅因 claim 或来源正文缺 URL 拒绝，则重新判断阶段边界；用户答案缺 URL 则归汇总和最终核验。URL 可由来源身份恢复只证明结构机制，不证明资料内容支持、官方发布方身份或最终语义正确。两个独立 A 级机制坐标仍只支持职责分界；当前候选保留在本目录，不升为 `completed/`，也不以再追加局部 Prompt 处理前置循环。
