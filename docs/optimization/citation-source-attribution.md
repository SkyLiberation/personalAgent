# 逐行引用丢失来源归属

**独立问题 `CITATION-SOURCE-ATTRIBUTION-001`：执行记录能够确定引文来自 OpenAI 官方页，局部核验输入却只包含正文，核验器因此以无法确认来源为由拒绝。** 准入状态由 [Future 队列](../future/design-optimization-backlog.md)拥有；本次确定性修复已进入目标代码，契约与局部真实核验通过，完整 E2E 未验收；决定见 [ADR 0028](../adr/0028-preserve-citation-source-binding.md)。

## 正式输入与失败事实

2026-09-18 原中文研究用例从正式入口自主运行。第十八次验稿的比较段引用了两条工具调用定义，核验器返回“未指定为 OpenAI 文档”，并据此拒绝 OpenAI 与 MCP 的比较。原始用户结果另由[评测登记](../evals/02-current-case-inventory.md#取证充分性契约的正式验证)拥有。

按该稿之前的 `0057.json` 恢复可见引用目录，两条提交原文分别有 3 个、2 个完全相同的目录匹配，全部来自 `https://developers.openai.com/api/docs/guides/function-calling`。检查保留每个匹配的执行标识、全局引用编号、行号及带版本的 `ResourceRef`；没有猜测模型具体选中了哪个重复编号。执行记录中的来源归属明确，不能把核验器的“未提供 OpenAI 依据”直接解释成从未取得该来源。

## 信息丢失的责任边界

失败发生时的[引用构造](../../src/personal_agent/application/conversation/citations.py)在生成逐行 `AvailableCitation` 时保留 `line.text`，随后构造的 `CitedEvidence` 只有局部 `id` 和 `text`。[局部核验器](../../src/personal_agent/tools/interaction_verifier.py)只接收本段的 `CitedDraftUnit`，没有收到该行原有的来源归属。

引用目录仍能关联所属观察；来源读取投影也能从执行记录关联到官方 URL。缺口位于引用到核验输入的投影，不是模型声明“取证充分”改变了来源事实。完整观察引用和逐行引用的上下文不同，本条证据只定位逐行引用，不能概括为所有引用都会丢失来源。

## 非本轮引入的依据与证据限制

在修复之前，引用构造文件与取证充分性实验开始前的 `before.zip` 一致；当时来源支持核验主体和提示也未改动。以下审计属于已封存的历史代码状态。确定性审计、实际提交原文、全部可见来源匹配及核验意见见[来源归属审计](../../.tmp/evidence-sufficiency-20260917/citation-attribution-audit.json)，原执行命令为 `.venv/Scripts/python.exe -X utf8 .tmp/evidence-sufficiency-20260917/audit_attribution.py`，依赖归档中的修复前代码，不能在修复后覆盖重跑。

该检查没有调用模型，也没有补写失败 Final 的原始引用选择；重复原文只能恢复全部可能编号，但其来源一致。本次证明输入中省略了已有归属，并定位正式拒绝；尚未证明补全归属会使模型接受本段，更未证明完整研究可以交付。

## 失败 E2E 的 Context 责任定位

2026-09-18 对第十八稿做只读回放，定位到核验输入投影缺少来源绑定；没有证据支持“生成模型因 Context 太长而漏填 `source`”的解释。该轮生产输出契约只要求模型提交 `evidence_id`，没有要求或允许逐条输出 `source`。

回放以提交前的 `0057.json` 为前置状态，按原生产代码保留最新核验反馈，重新执行生成端的 Context 物化。重建的执行输入为 97,879 字符，与提交后 `0058.json` 中第 56 回合的实际测量一致；该回合记录的输入用量为 33,510 tokens。所有 5 个可能匹配的行引用均保留在物化结果中，其所在读取窗口的 `ResourceRef` 能连接到仍可见的 OpenAI 来源 URL。生成端没有在这条构造路径上裁掉该来源映射，但来源与逐行引用分属不同观察，并不是每条行引文都内嵌 URL。

实际 `tool.audit` 进一步显示，整体核验参数的 `source_reading_state` 仍有 OpenAI URL；局部来源支持核验只取本段 `CitedDraftUnit`，未接收该整体参数。该段的 `e001`、`e002` 是 261、251 字符的 OpenAI 原文，没有来源信息；`e003`、`e004` 是各 5,910 字符的完整 MCP 工具结果，均内嵌 MCP 官方 URL。因此，同一段的两方证据进入核验器时，来源信息不对称。这能够解释核验反馈为何声称有 MCP 依据却无法确认 OpenAI 归属，不能把两方差异归因于是否实际查阅了官方来源。

审计命令为 `.venv/Scripts/python.exe -X utf8 .tmp/source-context-audit-20260918/audit.py`，退出码为 0。源码身份与原 target 一致；[报告及输入重建](../../.tmp/source-context-audit-20260918/report.json)已独立封存。原始生成请求的完整 wire 内容未保存，本次是按代码和 journal 重建，并用运行测量、来源关联与实际核验参数交叉核对；字符数相同本身不能证明所有字节相同。没有调用模型，也没有验证补全来源后能否通过核验。结论仅定位该次来源归属拒稿，不解释整轮所有来源支持、引句绑定或修订不收敛问题。

## 模型输出来源的最小探测

2026-09-18 按用户要求，隔离检查模型在收到来源映射与明确输出 Schema 后，能否准确输出 `source`。这是 Offline Eval；不修改生产代码，不恢复历史 Final，也不代表生产核验已经修复。输入取自上述审计中的真实片段；重复编号中选一个匹配作为本次输入，不声称它就是历史模型的原始选择。

运行前的[固定计划](../../.tmp/source-output-probe-20260918/plan.json)规定 3 类输入各重复 3 次：真实片段、相同正文对应不同来源、来源缺失。后两类为合成反事实。通过要求是首次响应的结构合法，引用编号、URL、资源版本及行号精确匹配，来源缺失时输出 `null`；没有把正确来源写成 Schema 枚举或固定值。任一次错误、异常、超过 60 秒或累计超过 50,000 tokens 时停止新增调用。最多 9 次，每次最多输出 2,048 tokens，无结构修复和服务重试。

输入先经过生产 `JsonObjectStructuredAdapter` 的请求构造，再直接调用同一配置的 `mimo-v2.5`。实际请求是结构约束、任务说明、证据数据三个消息；使用 JSON mode 与配置中的 thinking，温度未发送。完整请求和原始响应单独保存，不注入 Conversation、Verification 或 Completion 链。来源事实仍属于执行系统，本测试只衡量模型复述事实的准确性。

实际结果为 9/9 首次响应通过，各类分别为 3/3；没有结构错误、来源错绑或缺失来源编造。共使用 17,470 tokens，整批耗时 342.03 秒，单次耗时 23.44 至 52.66 秒。生产源码校验和未变。该小组结果支持“模型能够按明确契约准确复述已给定的来源”，不能推出长期稳定率，也不能证明在长 Context 中自主选择引用、从拒稿反馈恢复缺失来源或通过最终核验。给模型来源后让它复制，与修复生产投影中的来源丢失是两个验证边界；本次不改变 Future 准入状态或来源事实责任主体。

执行命令为 `.venv/Scripts/python.exe -X utf8 .tmp/source-output-probe-20260918/probe.py`，退出码为 0；诊断脚本的 Ruff 检查通过。结果、逐次指标见[本批报告](../../.tmp/source-output-probe-20260918/summary.json)，Schema、输入、原始响应、脚本及源码身份共 33 个文件由[校验和清单](../../.tmp/source-output-probe-20260918/sealed-manifest.json)封存。封存复核通过，并逐次确认原始响应内容与解析结果一致。诊断脚本禁止覆盖重跑，未来新实验须使用新的独立归档。

## 确定性修复与验证

修复由代码保留来源，不要求模型生成。原始执行记录按完整 `ResourceRef` 关联 URL；引用目录和 `CitedEvidence.source` 保留资源版本、行号及起始列，局部、整稿和缺项核验均保留正文与来源。完整观察仍保留其原始内容，未知来源不凭文本猜测。旧的纯正文转换已删除，正式可达路径和取舍见 [ADR 0028](../adr/0028-preserve-citation-source-binding.md)。生成模型的物化输入和输出契约不变。

本次固定状态反事实覆盖历史两条引文的全部 5 个可能匹配编号：旧函数输出没有来源，新函数保持原文并恢复正确 URL、资源版本及行位置；生成端物化内容一致。隔离加载的是修复前的引用函数，使用当前共享类型，不是完整旧 E2E。9 个新增契约场景覆盖同文不同来源、不同版本及身份、缺失或失败来源、元数据冲突和两级语义消费者。相关 241 项测试通过，1 条既有 Pydantic 弃用警告；Ruff 初次发现测试文件 3 处单行分支格式，修正后检查通过。

真实局部核验仅运行预声明的 2 个样本，均为首次响应，无重试：

| 固定输入 | 实际结果 | 用量与耗时 |
| --- | --- | --- |
| 原第十八稿的比较段及引文，仅由修复后的代码恢复 OpenAI 来源 | 无核验问题，段落通过 | 6,734 tokens，56.80 秒 |
| 保留上述来源，正文改为无据的 OpenAI 全面权限保证 | 返回准确绑定的拒绝意见，未因来源正确而放行 | 6,775 tokens，62.76 秒 |

模型为 `mimo-v2.5`，局部核验提示仍是 `v1-writer-citations`。每次上限为 8,192 输出 tokens、120 秒，共 13,509 tokens；输入经生产 Adapter 构造并保存实际请求和原始响应。第二个样本耗时超过 60 秒，本批已结束，不追加样本。判定门槛、输入、源码身份、反事实及结果由[本次归档](../../.tmp/citation-source-fix-20260918)保存；真实结果见[结果文件](../../.tmp/citation-source-fix-20260918/results.json)。

这支持确定性来源恢复及该局部语义边界，不证明整稿交付或长期稳定率。本轮按用户要求不重复长 E2E；引句绑定和修订收敛仍是独立事项，不能据局部通过声明发布。剩余正式验收和退出条件见[活动设计](../future/citation-source-binding.md)。
