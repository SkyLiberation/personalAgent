# 多错误的渐进核验与修订

**已解决的明确问题：同一草稿存在多个错误时，现有循环能够逐轮发现、修订并重新核验，不需要 Verifier 一次找齐所有错误。** 2026-09-17 按问题固化；沿用已经接入的生产循环，本次没有新增 Prompt、Agent 或循环，也不重复实现已有能力。

这里固化的是经过真实模型验证的渐进修订能力。它不承诺每一份报告都正确、任意稿件都能修完，或原完整研究任务已经通过。只有直接否定上述适用边界的反例才重新打开本问题；其他问题独立登记。

## 采用方案与责任主体

**失败反馈进入下一轮 Conversation，新稿再次验证，通过回执绑定同一份最终正文。** Verifier 判断当前稿与实际证据是否一致；Conversation 决定怎样修订或补证；运行系统负责反馈交接、合法协议、有界运行和交付绑定。拒稿不是用户任务结束，预算耗尽也不是通过。

生产消费点为 [ConversationService](../../../src/personal_agent/application/conversation/service.py) 的 `_verify_before_send` 和后续 `respond` 决策循环，以及 [Interaction Verifier](../../../src/personal_agent/tools/interaction_verifier.py)。正式路径已消费该机制，当前行为由[验证专题](../../topics/verification-and-completion.md)拥有；已接入的来源支持必检见 [ADR 0020](../../adr/0020-require-conversation-source-support-verification.md)。本次生产复杂度变化为 0。

## 决定性验证

**2026-09-11 的组合稿 3 已直接证明逐轮补抓和修复。** 第一轮只发现 strict 条件错误；首份修订仍把参数保证扩大为工具执行结果保证；第二轮指出对象错误；再次修订限定了执行结果未知，同时保留原任务的两个主题，第三次核验通过。没有人工注入中间修订稿、正确反馈或成功回执。

同批三条错误稿最终均消除预声明的条件与对象缺口，一条有据控制稿直接通过。组合稿 2 一次识别两项；组合稿 1 的中间反馈有偏差，后续由 Conversation 重新审阅修好，不能算作 Verifier 每轮均准确。三条轨迹不等价，也不从小样本推导稳定准确率。

该批使用冻结来源与初稿，调用生产验证、反馈及 Conversation 循环，属于 **Integration + Offline Eval**，共 22 次模型调用、95,293 tokens。决定性证据见[语义与身份审计](../../../.tmp/source-support-20260911/verifier-revision-loop/review.json)、[运行入口](../../../.tmp/source-support-20260911/verifier-revision-loop/run_loop.py)及[归档目录](../../../.tmp/source-support-20260911/verifier-revision-loop)。原文档第 64 节的中间过程已移除。

正式用户入口还观察到一次“拒绝权限责任推断、修订、重验、同稿交付”，证明生产消费者实际可达。该研究任务的原始用户结果仍为失败，完整结果及其他问题由[正式评测记录](../../evals/02-current-case-inventory.md#真实修订循环在原研究任务中的迁移验证)拥有；本文不复制原第 65 节的综合失败流水。

### 2026-09-17 当前实现复验

**当前生产实现又完成一条三次核验、两次修订的真实模型轨迹。** 固定来源和初稿包含三项显式错误：不论 strict 都保证、把参数保证扩大为执行结果保证、所有结果都必须包含 `isError`。模型没有收到预期修订文本。

首轮发现 strict 条件问题并把真实反馈交给 Conversation；下一稿去掉两项保证错误，但仍保留 `isError` 普遍义务。第二轮的原始支持报告明确指出该义务超出示例。最后交付稿移除了三项原始显式错误，保留参数、执行结果与 `isError` 用法三个主题，通过第三次核验；最终文本与通过核验的稿件逐字相等。

本次只补充逐轮识别、显式错误删除及交付绑定的观察，不计为全稿语义验收通过，也不把所有修订归因于具体意见已送达。完整逐轮语义因果的直接依据仍是前述组合稿 3。实际报告、反馈交接和终稿的人工复核分别保留在归档，不用机器 `passed` 自证正确。

本轮仍是 **Integration + Offline Eval**，不是正式用户入口 E2E。真实 MiMo v2.5 thinking、生产 Prompt 与 Schema 保持；12 次模型操作、13 次实际请求、59,266 tokens，请求累计约 1,197 秒。一次动作协议修复属于额外请求，没有重跑挑成功。完整结果见[运行结果](../../../.tmp/verifier-multi-revision-20260917/result.json)、[机械审计](../../../.tmp/verifier-multi-revision-20260917/audit.json)、[独立语义复核](../../../.tmp/verifier-multi-revision-20260917/semantic-review.json)及[预声明](../../../.tmp/verifier-multi-revision-20260917/plan.md)。

## 失败尝试与纠正后的取舍

**失败经验收敛为方案、原因推理和结果，不永久保留中间稿及逐轮流水。** 与计划恢复、来源获取或其他独立职责有关的优化，留在各自问题记录，不混入本问题。

| 尝试方案 | 失败原因推理及确定程度 | 失败结果总结 |
| --- | --- | --- |
| 把首轮没有同时列出两个错误当作多错误无法识别 | 后续仍有合法拒稿和修订机会；组合稿 3 实际补抓第二项，原解释被后续证据否定 | 不再要求单轮穷举，不新增“一次找齐”的生产约束 |
| 把一次通过或最终修好当成各轮反馈都准确 | 组合稿 1 中间意见没有正确定位剩余对象错误；实际终稿正确由后续重新审阅取得 | 保留循环整体收益，同时不夸大每轮 Verifier 的准确性 |
| 在原正式研究仍失败时继续把渐进修订列为尚未证明 | 正式轨迹已消费拒稿并修订，其他支持判断失败有各自来源坐标；没有证据表明它们由循环引入 | 关闭重复证明循环能力的待办，完整产品结果另行验收 |

## 后续复用与重新打开条件

后续验证直接以现有循环为基础，保留来源支持核验、实际反馈、修订后重验及同稿绑定。若新的证据证明这条责任链没有按契约执行，按最早失败边界定位；不得为了已有能力再建立第二套循环。

本文只固化预声明边界内的收益，不用单次 `passed` 证明全稿所有事实有据。整稿语义泛化、独立协议失败与取证收敛分别由对应问题维护，不列为本问题的未完成子项。经验讲述见[开发踩坑第 6 节](../../interview/10-development-pitfalls.md#6-整体仍有错误不等于已验证的多轮修订无效)，目录规则见[固化准则](../README.md#已解决问题的固化规则)。
