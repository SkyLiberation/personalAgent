# 正文与新增引用的一次修订

问题编号：`CLAIM-REVISION-ATOMIC-REFERENCES-001`。原缺口来自[支持范围修订](../to_verify/claim-supported-scope-repair.md)：模型已经取得并选择新原文，却只能先修改正文，再独立替换引用；两次提交之间，新事实沿用旧引用，必然再次缺证。

## 方案与生产责任

现行 `ReviseClaimFragment.additional_references` 由模型明确提交本次正文所需的新依据。`admit_claim_change` 保留已有引用，去重合并新增项，检查本轮选择、实际可见坐标、版本和片段后生成一个新版；失败不写入。其他 claim 和范围外正文保持原样。默认空表达无需新增依据的正文编辑；独立引用替换仍负责只改引用或移除引用。

writer v17 与 Schema 同步，正式 Conversation 研究动作消费该契约，新版完整 claim 继续进入现行来源核验。没有新增阶段、持久化或生产开关。生产权威契约由 [ADR 0032](../../adr/0032-conversation-research-claims.md)拥有。

## 决定性证据与边界

两份真实失败状态的确定性回放及八个拒绝控制成立；合成新增字段只验证 Admission，不冒充模型输出。两条真实条件轨迹消费原实际输入：c2 同次绑定新引用后，来源发现独立范围问题；同一实际反馈经原 selector、writer、来源核验修订一次后通过。c6 首次原子修订来源通过。七份完成响应合计 147,114 tokens，见[输入与成本审计](../../../.tmp/claim-atomic-reference-repair-20261008/input-and-cost-audit.json)。

同一候选两个模块逐字迁入生产。原中文 HTTP E2E 中模型实际提交五次原子修订，**5/5** 经唯一 Admission 写入，**5/5** 被完整来源核验消费；新增引用、旧引用和其他 claim 的实际版本逐项核对成立，见[正式消费检查点](../../../.tmp/claim-atomic-reference-repair-20261008/atomic-product-checkpoint.json)。两份历史无新增依据的动作与旧结果一致。这个样本的完整用户结果为 **0/1**，由[正式评测](../../evals/02-current-case-inventory.md#2026-10-08-原子引用修订后的正式入口结果)单独拥有；局部机制成立不等于整体产品完成。

## 失败尝试汇总

原契约分轮改正文和引用，真实 c2、c6 新事实未绑定，来源反馈复现。原子候选首条 c2 的原资格 **0/1** 保留：缺证解除，但条件拼合链路与“完整职责”的范围声明仍无足够依据。随后消费真实反馈收窄范围，未更改核验标准、筛选成功输出或覆盖原失败。

经验讲述见[工程复盘](../../interview/10-development-pitfalls.md#正文修订与证据绑定保持一个版本)。

## 重新打开条件

同次明确提交且合法的新引用未进入唯一新版、旧引用或范围外内容丢失、拒绝动作产生写入，或实际新版没有被完整来源核验消费时，重新打开本问题。其他语义缺项继续由各自问题拥有。
