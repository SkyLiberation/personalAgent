# 可读性优先与功能模块化整理

问题编号：`CODE-READABILITY-MODULARITY-001`。2026-10-09 完成规范修订及严格保持行为的内部重构；证据基线为 `e8b28ff`（`核验能力优化`）。设计文档在生产修改前形成，随实现与证据更新后固化于本文。

## 问题与结论

现行 COD 已要求唯一职责，但没有明确可读性的优先级，也没有把控制 Code Agent 开发上下文作为功能模块化的目的。模型适配文件同时包含响应解析、SDK 调用、超时、协议修复、重试和观测，解析任务的阅读范围被其他职责扩大。

根入口及 [COD](../../devSpec/code-structure.md#3-模块职责规模与生产可达性)现已明确：可读性放在首位；模块化按稳定职责集中实现，使局部任务通过入口、typed 契约与直接协作者理解和修改代码。拆分同时核算查阅范围与新增跳转、协作成本。文档阅读结构由 [DOC](../../AGENTS.md#2-中文写作与结构门禁)和中文写作规范拥有。

## 采用方案与生产消费者

`infra/model_response.py` 集中原有 11 个响应归一化函数与一个内部异常，拥有 envelope、流内容、原生动作调用和用量归一化。`infra/structured_model.py` 的现行 Adapter、重试及流用量包装器直接消费这些实现；原定义已删除，公开工厂与 typed Port 保持现行契约。原模块继续拥有 SDK 调用、超时、协议修复、重试和观测装配；Application 保留业务准入责任。

源码阅读边界如下，模块数量与行数只解释这次职责抽取的查阅范围：

| 阅读任务 | 整理前 | 整理后 |
| --- | --- | --- |
| 响应解析与用量归一化 | 1430 行的混装适配文件，20 个直接导入来源 | 297 行的内聚模块，7 个直接导入来源；由 typed 模型契约和 JSON 解析边界提供依赖 |
| SDK 调用、修复与装配 | 同一文件，56 个函数 | 原入口保留 45 个函数、1261 行，通过显式导入消费响应解析 |

新增一个职责模块，函数总数仍为 56，没有新增包装类、委托层、配置或状态；原调用点只迁移导入，协作成本为一个明确模块边界。统一研究、核验及适配代码的格式，修正与实际诊断日志冲突的旧类说明。当前模型模块分工同步至[核心架构](../../summary/core-architecture-current-state.md#7-模型与服务提供方边界)。
