# 回答绑定当时目标与核验历史逐条呈现

2026-11-04。每次回答现在携带生成前实际生效的已核验 goal；后来修改目标不会改写旧回答的目标依据。目标、回答核验历史分别按原话、提交、判决和实际修订逐条呈现，通过判决精简为绑定对象的“核验无问题”。本次预声明用例已通过，关闭这三项上下文输入问题；不改变原 task2 的语义成绩。

## 问题与依据

旧回答核验只有一个全局 `active_goal`，无法说明不同用户轮及同轮目标修订前后的回答各自依据哪个目标。旧核验请求还将一轮内的提交、判决及修订包进单条 user 消息，主循环和核验历史反复携带完整通过报告。

基线来自正式 HTTP 轨迹 `.tmp/context-unload-task2-20261103/c-recovery/`：31 份实际核验请求均按用户轮打包。例示请求为 `sdk/38f06e179e8f414d87860ad704f25130.http.request.json` 和 `sdk/78e35ff721d04096a1791949c1f419c8.http.request.json`。第 9 个用户轮确有目标第 9、10 版及相应先后回答，作为同轮修订的固定反例；前 3 轮作为完整主循环与核验阶段组。源码和旧请求身份保存在 `.tmp/verification-context-format-20261104/baseline.json`、`goal-binding-baseline.json` 及 `baseline-code/`。

| 要求 | 现行机制与消费者 | 确定性验收 |
| --- | --- | --- |
| VCTX-1 逐条接续 | `verification_messages` 独立呈现 user 原话、真实提交、紧邻的 Runtime 判决及后续修订；当前待验稿无预造判决 | 原话和稿件逐字保持，提交先于其判决，判决先于修订，两类职责历史独立 |

局部阅读入口为 [Context 构造](../../../src/personal_agent/application/conversation/verification_context.py)、[typed 契约](../../../src/personal_agent/capabilities/contracts/verification.py)、[核验消息物化](../../../src/personal_agent/capabilities/contracts/verification_prompt.py)和[主循环观察投影](../../../src/personal_agent/application/conversation/citations.py)。每个用户轮首次采用或更换目标时展示完整目标及通过引用，每次回答显式引用该目标判决。目标正文和快照复用不可变 `SemanticVerificationReceipt`，没有第二份可写目标状态。

每轮原话为独立 user 消息，提交为明确的数据消息，真实判决为紧邻的 system 消息；后者明确是可纠正的运行记录，用户原话仍为权威。不伪造 assistant／tool 交互。中文和英文模板、版本及占位同步，原打包及未决判决占位已删除。仅加标题仍无法提供独立消息，按最新目标回填也无法恢复当时事实，均不采用。

实现复用原模块和装配：新增一个派生字段及一个接受目标回执解析函数，共享判决展示函数；新增两个正式评测入口。没有新数据库、工具、配置开关、服务、依赖或模型决策调用。核验判据、权限、目标写入与完成语义未改动。
