# 搜索执行参数的保真交接

**已解决的明确问题：成功网页搜索与本地正文搜索返回结果时丢失实际查询条件。** 本地两个不同关键词即使都返回零匹配，也能在下一轮输入中区分；查询条件与外部来源证据分别交接。固化日期为 2026-09-17。

本结论只覆盖执行事实与输入交接，不承诺模型避免重复搜索、及时扩源、完成修订或通过完整研究任务。整体 Context 候选的行为验收与产品结果分别由原问题记录和评测文档拥有，不能反过来扩大本问题的完成判据。

## 采用方案与责任主体

`WebSearchArgs` 由 Application 捕获契约拥有，网页输出复用同一参数定义，返回 `query/limit`。本地 `SourceSearchResult` 复用原搜索参数定义，返回 `keyword/regex/result_offset/resource_ref`。原执行函数是唯一写入者；不从计划、结果摘要或实验日志反解查询，不增加查询缓存或持久历史表。

`CitableInput.executed_query` 是当前请求内的只读投影。引用目录与 Verifier 的证据恢复排除查询字段，保留原 evidence ID、正文、版本和坐标；超大网页结果保存完整结果正文，查询留在有界执行元数据中。失败仍保留原失败身份，本方案没有为无成功结果的异常伪造成功查询记录。

正式消费者为 `/api/conversation/turn` 的 Composition Root 装配链、两个原搜索执行函数、Conversation 的 Context 组装与引用恢复。当前代码边界由[上下文专题](../../topics/context-engineering.md)和 [ADR 0026](../../adr/0026-separate-query-facts-from-cited-evidence.md)拥有；这里不维护第二份生产规范。

## 决定性证据与适用范围

- 修改前的五项 Contract 均因实际查询参数缺失失败；修改后对应反事实通过。零命中、不同关键词、正则、分页、资源版本、作用域以及超大结果卸载均有确定性检查。原始代码与结果保存在[本轮归档](../../../.tmp/query-context-integration-20260917)。
- 真实正式运行中，成功网页结果的 `query/limit` 与工具审计保存的调用输入逐项相等；本地结果保留 typed 参数。后者由执行代码和 Contract 证明，与独立捕获本地原始调用请求的证据强度不同，见[执行审计](../../../.tmp/query-context-integration-20260917/formal-target-v2/execution-audit.json)。
- 同一真实 Journal 经旧引用目录与新目录处理，排除新增查询字段后，全部来源文本和引用标识逐项相等。最新被拒稿与反馈也可完整还原，见[确定性反事实](../../../.tmp/query-context-integration-20260917/formal-target-v2/evidence-counterfactual.json)。这是正式记录上的 Runtime Conformance，不是额外 E2E 或模型因果消融。

完整候选相关检查为 244 项通过；Context 撤回后的实际相关检查为 230 项通过，保留原物化消费者上的查询及来源隔离。两者均包含相邻边界，不能当成本问题独有样本或相加。正式入口已消费查询与引用交接；完整用户结果仍以[原研究用例评测记录](../../evals/02-current-case-inventory.md)为准，不用局部通过覆盖原始失败。

## 失败尝试汇总

| 尝试方案 | 失败原因推理与结果 |
| --- | --- |
| 按相同零匹配结果推断查询相同 | 历史 `permission/consent` 参数不同而 payload 相同，结果内容无法反解请求；不采用基于结果猜测的查询去重 |
| 只为网页结果追加 query 提示 | 未覆盖本地搜索参数丢失，既有续跑也未取得完整交付；不把单句提示当作完整交接 |
| 将参数直接加入整条可引用 Observation | 会把查询文字带入来源证据，属于未经授权的语义输入变化；采用查询与来源的单向分离投影 |

两个独立 A 级实现的调用与结果配对机制见 ADR 的固定 Gemini CLI、OpenHands 源码坐标。它们支持实现方式，不证明本工程的搜索或修订策略收益。

## 重新打开条件

成功搜索的参数、资源身份或作用域在执行到模型之间丢失／混同，或者查询字段污染了引用恢复，均直接否定本判据，应按最早责任边界重新打开。模型仍重复搜索、选错来源或形成无据结论，应在对应决策问题中分析；若没有上述交接反例，不重复实现查询历史。经验回链见[开发踩坑](../../interview/10-development-pitfalls.md)。
