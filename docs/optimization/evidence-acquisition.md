## 70. 独立信息获取循环的外部实现与本地准入边界

**用户提出将大量信息获取从主 Conversation 隔离，先独立找信息，再由主对话汇总。成熟实现支持该职责划分，但本工程尚未验证它能修复当前错误。** 本轮属于只读机制研究与纯文档更新，没有新增模型调用、生产结构或 Product E2E；历史有效读取契约、来源支持必检和修订循环继续保留。活动候选由 [Future 来源支持设计](../future/conversation-source-support.md#33-独立信息获取循环的条件诊断)拥有，队列准入不升级。

失败事实分成两类：第 38 节取证缺口仍在输入，模型也提到补查，却在没有新增原文时转称充分；第 65 节有 OpenAI 读取不全以及成文扩大结论。它们支持检查信息获取职责是否被其他决策干扰。另一方面，第 45 节仅保留已读原文独立成文仍出现无据推导，第 69 节 Verifier 看到了 32/122 和禁止标准，仍把文档级否定改释为局部未见。不能把这两类事实合并成“全部因为资料太多或证据没到达”；独立取证可能改进前者，不能预先宣称消除后者。

本地已有 Conversation 的 AgentPort 委托及授权产物读取入口，不需要先创建通用多智能体框架。`application/conversation/service.py` 当前交回子产物引用及最多 6000 字符的 content_excerpt；这只是可核对的交接容量，尚未证明它导致了本轮失败。后续必须追踪原文引用能否继续读取，不能默认摘要足以支持全部结论。既有 `application/research/service.py` 也有研究循环，但同时承担研究运行、来源与事件持久化等生命周期；名称相同不证明它可原样承担本候选。

拟检查的职责是：工具拥有真实读取范围与失败事实；独立获取循环根据问题选择搜索、阅读及补查，交回原文位置、对应原句、适用条件、未解决问题和停止原因；Conversation 根据这些材料成文，必要时发起有界补查；Verifier 对最终原句与可见原文做一致性判断，不重新搜索全文。摘要是导航，不能成为第二份来源事实；Conversation 与 Verifier 应通过同一授权来源引用消费实际证据，而不是让 Verifier 只相信 Conversation 的取证自述。

以权限问题为例，“应用执行代码”的原句仍不足以证明“开发者负责权限验证”。隔离循环只有继续获得支持该责任的条款，或如实交回该问题未解决及已查范围，才算信息获取上的进展。把同一执行原句改写成权限结论再交回父会话，仍是原错误。停止也不要求机械地读完 122/122：已找到直接依据可以结束对应问题；未找到且仍有可查来源时须保持缺口；资源、权限或预算阻塞须如实交回，不能被包装为完成。

下一步先按 Future 的条件诊断固定原失败窗口和可访问来源，保持模型、既有读取状态、来源必检与修订循环，检查隔离获取是否找到此前缺少的直接依据、是否保留原文主体和义务强度，以及父对话是否忠实使用交回资料。还要包含已有依据足够、客观无法取得、原文有 SHOULD 或范围限制的控制，防止只延长检索或靠拒答制造通过。局部隔离调用只记 Offline Eval；只有正式入口、真实模型和 canonical 完成链路才能记 Product E2E。单独成文去掉历史的旧候选已失败，这次必须实际允许获取循环继续自主取证，不能换名重跑第 45 节。

外部网页快照、固定提交源码、来源摘要和本轮修改前文档保存在[本轮归档](../../.tmp/retrieval-loop-design-20260911)，来源坐标见 [sources.json](../../.tmp/retrieval-loop-design-20260911/sources.json)。本轮仅确立机制可参考和可反驳的候选边界，未取得新生产接入资格；不新建持久化、固定子任务数量或多角色编排，也不继续给 Verifier 追加同义标准。

文档检查覆盖 15 份相关文档、497 个本地链接及锚点，并核对表格与围栏；历史第 1 至 56 节迁移检查通过，第 47 至 69 节与本轮修改前快照完全一致。没有生产或测试代码变更，本轮未运行模型验证和产品测试。

用户进一步指出应优先复用 GPT Researcher A2A。只读核对确认当前 `.env` 已启用它，Composition Root 已有条件注册，Agent Card 实际可达，返回 GPT Researcher 0.14.7 和 Generate research report 技能；没有提交新研究任务。此前只称“已有委托入口”不够具体，候选顺序更正为先核对这一现成研究器，不能先自建同职责循环。原正式问题没有点名 provider；不能由未委托反推服务不可用，也没有本轮决策追踪证明模型为何不选它。

本地相邻 GPT Researcher 仓库的 `backend/server/a2a.py` 调用完整 `run_agent`，返回报告、source_urls、visited_urls、costs 和 images，没有调用 get_research_sources/get_research_context 将研究内容交回。personalAgent 适配器持久化文本报告时 source_artifact_refs 和 evidence_refs 为空，父级观察主要给出报告引用和最多 6000 字符摘录。URL 元数据在子运行 raw/result 中保留，但没有因此成为父级可核对原文。该代码边界支持优先检查证据交接，不能据此声称 GPT Researcher 库不支持来源内容；上游 [agent.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/agent.py) 实际区分 conduct_research、write_report、get_research_sources 和 get_research_context。也不能把 visited_urls 当作完整阅读证明。

历史 A2A 超时和父级不交付仍见[模型及服务配置记录](../env.md#gpt-researcher-a2a-配置)；后来角色绑定已将特定 MiMo 诊断从超时改善为报告完成，内容和 usage 尚未通过。保留这项改进，不用旧失败永久排除委托。下一候选先使用现有 A2A 获取实际报告及返回材料，检查与原问题的一致性；仅在交接缺项实际阻塞时限定修正该边界。只读核对见 [a2a-readonly-audit.json](../../.tmp/retrieval-loop-design-20260911/a2a-readonly-audit.json)；本地后端源码与运行容器镜像尚未对齐，服务可达不等于新研究任务通过。

## 72. 暂停 GPT Researcher 后的独立获取与原文交接验证

**独立获取能够自主调用现有读取工具，补充停止条件后也继续补读，但两版都遗漏可取得的关键段落，并在交接前扩大了已读范围。** 本轮按用户要求暂停 GPT Researcher 与 A2A；只验证本地 MiMo thinking 的独立获取。没有新生产结构或 Prompt 接入，既有读取状态、来源必检、成文 Prompt 与拒稿反馈路径保持。实验为 Offline Eval 加生产读取边界 Integration，不是正式 Conversation E2E，也不宣称上下文隔离的严格产品消融。

### 条件与边界

复用第 65 节同一中文用户问题和封存来源，OpenAI 初始已见 1–24、65–72，共 32/122 个片段；MCP 为 22/22。完整正文只在工具侧，模型选择关键词和起点，通过当前 `ConversationService._read_action_output` 读取。两份文件恢复原 CRLF 后 SHA-256 与历史保存值相符，初始 54 个已读片段逐行相同。独立获取输入包含原问题、标准、已读原文、未读区间与预算，不含旧草稿、Plan 或 Verifier 意见；没有答案示例或人工补入未读依据。

获取阶段只交回发现、引用、未解决问题和停止原因。程序拒绝未读引用，并从已读原文恢复对应片段；模型发现明确标记为非官方原文。成文继续使用当前生产 Prompt 与输入物化，将原已读材料、新读取结果及交接包输入；Verifier 只拿原文观察，不把获取摘要当官方证据。配置允许最多三次成文与核验，拒稿后回传真实 Receipt；未实现完整 Conversation 工具决策和自动回派获取，因此不能声称本轮验收了完整修订循环。

每版上限 16 次获取决策、32 次读取、1.2M tokens，单调用最多 32768 输出 tokens、480 秒、零重试。先固定一个来源样本；首版失败后只对取证停止条件做一次有界修正。修正版从首版实际补读后的同一边界出发，逐字段核对请求，仅新增一段 system 停止规则，来源、任务、历史、模型、Schema 与预算完全一致。规则要求：仍认为未读内容可能补足问题且有读取条件时，禁止仅以“如实说明证据不足”为由结束；不要求机械全文阅读。两条随机轨迹不能证明稳定因果收益。

第 58 段实际说明 function_call_output 通常传字符串、格式由应用选择，返回图像或文件时可传相应对象数组，没有返回值时应回传表示成功或失败的字符串。这是问题要求的结果格式直接材料，不能被未读即认定为导航。它不证明本页明确规定了权限责任，也不等于证明所有输出保证；本轮反例只需证明存在相关且可读的材料被错误排除。MCP 的可选 outputSchema、服务器 MUST 与客户端 SHOULD 在两版部分发现中保持正确，不能因整体失败否认这些已成立内容。

获取模型的可见解释与上述输出一致：首版把“需要更多阅读”用作 handoff 理由；修正版将跳过的区间概括为导航或已覆盖内容，继而宣布信息足够。这有助于定位停止决策和覆盖判断，不证明隐藏注意力机制。累计未读事实已经出现在请求里，原文引用也无损保留，因此“工具没提供进度”或“交接文本被截断”不能解释本轮失败。先发生的是获取模型未经核对就判定缺口无关，随后错误摘要被成文采用。

首版 Verifier 把文档级否定称为诚实反映证据缺失，继续复现第 69 节的范围误释。修正版原始报告同样出现“片段未出现，支持没有明确说明”的解释，以及把来源名称当作正文已给 URL，但报告本身协议无效，这些仅保存为未接纳输出的诊断线索。没有伪造 failed 反馈以强行启动下一轮：首版有效 passed 导致修订未触发，修正版协议失败阻断；本轮不新增修订收益结论，也不撤回第 64、65 节已有收益。

Open Deep Research 同时要求有把握回答时停止，并包含来源数量、搜索结果重复及调用次数的停止启发式。它也追求效率，公开代码不能证明它已经消除过早结束。本工程不采纳“找到若干相关来源即可完成”作为支持标准，也不通过固定增加读取轮次制造收益。Claude Code 的停止 Hook 只提供控制点；让另一个模型检查是否完成，仍需要证明它能识别当前错误，不能绕过已发生的 Verifier 误放。

针对当前反例，可验证的反馈应指出“现有原文是 Chat Completions 示例，尚不足以支持全部接口均采用该结构”，保留已成立事实及未解决范围；后续由主对话决定补查或限定答案。最终 Verifier 继续检查声明与已给证据的一致性，不负责重新搜索全文，不代写新的官方结论。这里是候选的反馈边界说明，不是向测试输入注入答案或已经实现的第二检查器。

已有系统具备最终 Verifier 和拒稿修订，第 72 至 75 节的隔离诊断还没有证明完整的父级接纳、反馈与再次委派获取。后续须区分“结束动作没有恢复通路”和“有通路但充分性被误判”，先复用现有主对话决策与最终验证，固定第 75 节反例测试具体范围缺口能否引发适当补查或忠实限定。没有独立检查收益及正式消费者证据前，不增加新 Verifier、持久缺口表或通用研究编排。

固定提交源码、本次复核坐标、资料等级和取舍保存在[外部比较归档](../../.tmp/research-stop-mechanisms-20260912)，见[来源清单](../../.tmp/research-stop-mechanisms-20260912/sources.json)和[复核记录](../../.tmp/research-stop-mechanisms-20260912/review.json)。官方网页通过浏览工具读取，本地完整快照下载返回 403，归档如实保留坐标和摘要，不冒称已有完整网页快照。本轮不改变第 75 节局部收益或剩余产品失败，也不授予新的工程接入资格。

## 77. 错误交接后恢复主对话动作阶段的验证

**恢复动作阶段后出现了补读和 API 范围纠正，但没有解决观察不足被写成文档结论。** 沿用第 75 节 B 的真实交接、相同的 94 个已读片段、任务和标准。直接成文与先回到动作阶段各运行一次；两者都保留当前 Final、来源必检及最多三份草稿的拒稿修订。模型自主选择读取，不注入错误反馈或缺失答案。预声明在模型调用前写入[实验计划](../../.tmp/parent-evidence-reentry-20260912/plan.md)，本节汇总入口在执行期间补入。

两条轨迹均使用 MiMo-v2.5 thinking、同一 Token Plan 接口，每条最多 16 次主决策、32 次读取、1.2M tokens，单请求 32768 输出、480 秒、零重试。仅动作阶段的有无是候选变量；随机轨迹不作为严格产品消融。通过条件是结论保持来源对象、接口范围和义务强度，不以读取次数或全文覆盖替代支持。首个通过回执后独立核对原文，错误通过仍算失败。

工具拥有读取事实，Conversation 拥有补查与成文，Verifier 只核验 Final。本轮直接复用 `ConversationService._decide`、生产工具声明和读取函数，但冻结初始上下文，未经过完整 Admission、Journal 和 Completion，归类为 Offline Eval 加读取 Integration。GPT Researcher 继续暂停。当前生产禁止重复委托已经返回产物的同一 Agent；本轮不解除该限制，先验证父级已有直接读取通路。

### 实际结果与分项判断

**补查通路被使用，完整来源支持仍失败。** 五次读取包含重复窗口和字面零匹配，不能全部计作新增证据；原文身份检查通过。

| 分支 | 实际行为 | 局部判断与剩余错误 |
| --- | --- | --- |
| 直接成文 | 零补读；三份 Final、三次 Verifier，均拒绝；275,002 tokens | 首稿复制通用 `role: tool` 与 `tool_call_id` 要求。反馈聚焦“必须”强度，第三稿再次无条件要求 `tool_call_id`；未形成稳定范围保持 |
| 先回到动作阶段 | 五次读取，新增 25 至 40 共 16 段，OpenAI 从 72/122 至 88/122；一份 Final、一次 Verifier，四项均 `satisfied`；305,541 tokens | 最终明确区分 Chat Completions 与 Responses 字段，纠正接口混用；仍断言“文档未规定结果内容的具体格式”，独立原文复核失败 |

动作分支没有收到手工指出 API 错误的反馈。模型自主检索 `tool`、`output`，之后核对 `tool_call_id` 与 `function_call_output`，再请求 Final。新取得的第 29 段 Responses 示例进入正文；但初始 65 至 66 段也已有 Responses 示例，不能把范围改善唯一归因于新读到第 29 段。两个独立随机轨迹也不足以证明稳定收益。

末稿在仍未读取第 58 段时，称“文档未规定结果内容的具体格式（仅说明可以是 JSON 或纯文本）”。封存的第 58 段实际区分通常返回字符串、图像或文件返回可用对象数组，以及无返回值时返回成功或失败字符串。字符串内部格式可以由应用选择，不等于所有执行结果只有 JSON 或纯文本，更不支持对整份文档作缺项结论。这是旧观察范围错误的延续，不能因为 API 对比正确就忽略。

Verifier 的通过理由明确把上述否定称为“准确反映了证据的边界”，因此没有反馈触发下一轮。它拿到初始 72/122 的读取事实和五份新读取结果；本轮未新增生产累计摘要，不声称它直接收到 88/122 汇总。只凭已见资料仍不能证明全文没有规定；无须先把第 58 段交给 Verifier 让它重新找答案，才能判定这个否定缺少覆盖依据。

### 最早责任与下一边界

**本轮修正的是隔离诊断对主对话的调用方式，没有证明生产缺少动作阶段。** 生产 `ConversationService.respond` 已通过 `_decide` 进入动作与 Final 两阶段；第 72 节隔离 runner 在交接后直接调用 Final，不能用它证明父级没有补查能力。后续独立获取诊断保留本轮真实动作、生产读取和来源必检的组合，不再退回只能改稿的交接链。

同一 Agent 的再次委托另受 `conversation.action` 和 `ConversationService` 中 `agent_artifact_already_returned` 限制。该规则防止重复委托，但本轮没有实际发起有缺口依据的回派，不能把它认定为此次语义失败的原因，也不能直接删除防重复边界。独立获取的正式装配与自动回派尚未证明；父级直接读取已经存在，不需要新增一个生产阶段冒充接入。

保留自主补读与接口区分的局部事实，停止将当前版本视为完整修复候选。下一步固定“内容格式自由”与“整份文档未规定”的区别，检查取证交接是否如实保留已支持范围与未解决义务；来源支持、任务完成和可继续获取分开判断。不得把本轮人工复核写成已经来自生产 Verifier 的反馈，也不重新追加同义禁令。相邻充分控制、客观不可取控制、同一获取任务回派及原完整任务 target 仍未执行。

### 用量、归档与检查

**本轮共 11 次真实模型调用、580,543 tokens、424.397 秒模型调用时间。** 没有服务、解析或 token 预算失败。直接成文达到预声明三稿上限；运行中 runner 将该终止误标为 `decision_budget_exhausted`，原结果保留，[复核记录](../../.tmp/parent-evidence-reentry-20260912/review.json)明确更正为三稿上限。只修正后续脚本的统计标签，未重采样、改变输入或丢弃响应；这不属于模型语义问题。
