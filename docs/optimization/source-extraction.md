## 41. 内置抓取的 HTML 正文边界审计

**2026-09-10 本轮核对导航文本的进入路径，不将主内容提取直接当作生成修复。** 当前 `Settings.from_env()` 实际选择 `builtin`，Firecrawl 密钥已配置但不改变显式选择。`CaptureService` 只装配选中的服务方；Firecrawl 路径已经传入 `onlyMainContent=true`，内置路径的 `ReadableHtmlParser` 只忽略 script、style、noscript，其余导航与页眉页脚文本可进入结果。密钥值不输出，配置身份只以摘要封存。

预声明读取当前 Function Calling HTML 一次，使用内置抓取器相同请求头与 4 MiB 上限，原始响应先保存。对同一 HTML 复用现有文本解析器，分别计算全页及实际 main/article 地标元素的文本；只读取 HTML 声明的结构，不按权限或结果关键词删内容。记录每个边界的原始字符位置、文字量、关键词所在位置及正文前后材料，核对地标是否包含或遗漏需要的内容。没有唯一且可靠边界时停止候选，不把最长节点或任意 CSS 选择器自动当正文。

该页面是当前外部快照，不能替换历史抓取产物或回填为模型已读。第 29、38 节的旧片段完整性仍保持，尚未读到要求不能因清理导航而变成规范没有要求。此次不运行模型、Firecrawl 付费抓取或 Product E2E，不改配置、生产解析器、Prompt 或评测器。分类为只读外部页面与代码分析、确定性解析诊断及文档更新；页面拥有 HTML 结构，抓取层拥有文本提取，模型继续拥有证据充分性，生产复杂度增减为 0、无删除项。脚本与原始证据仅存 `.tmp/source-support-20260910/html-main-boundary/`，结果用于决定是否值得提出独立正文候选。

**同页检查确认导航混入占用了读取窗口，尚未证明它造成最终越界。** 原始 HTML 有唯一 main 和嵌套的 `article#mainContent`。复用生产解析器所得 article 文本是全页唯一的连续子串，未在文章内部改写或省略文字。当前全页与历史抽取文本不完全相同，但差异只有导航新增的 Overview、Image prompting、Prompt cache diagnostics 三行；当前 article 的 108,579 个字符在历史文本中也逐字连续存在。只能确认提取后正文相同，不能还原或假定历史 HTML 结构相同。

| 同一 HTML 的解析范围 | 字符数 | 生产编码片段数 | Tool choice 标题所在段 | 前 60 段包含 Tool choice / Strict mode |
| --- | --- | --- | --- | --- |
| 全页 | 119,103 | 120 | 65 | 否 / 否 |

正文外共 10,524 字符，占全页约 8.84%。同样 60,000 字符窗口下，`Tool choice` 标题从 offset 64,628 前移到 54,144；这是一项可重建的容量反事实，不是模型实际选择并读取新正文的结果。正文仍有 49 段在此窗口之外，不能称为全文读取，也不能用关键标题出现代替最终有据交付。

四个 `permission` 文本匹配均位于 `div#drawer` 下的移动导航面板，包含指向 API RBAC、Codex permission modes、Codex workspace permissions 的链接及菜单文字。它们全部在 main、article 和所有 nav 元素之外。因此只剔除 nav 标签也无法消除本页这些无关匹配。正文关键词计数为零只描述字面检索结果，不能证明文章没有权限规定。原始 HTML、每个地标的范围与文本见[抓取检查归档](../../.tmp/source-support-20260910/html-main-boundary/run/20260910T060522.275825Z-8940-abb13c53)；编码、祖先路径与历史差异见[解析结果](../../.tmp/source-support-20260910/html-main-boundary/analysis.json)及[历史文本差异](../../.tmp/source-support-20260910/html-main-boundary/historical-text.diff)。

## 42. 成熟正文提取实现的保留边界

**2026-09-10 本轮审查正文提取是否会丢失技术资料，不预设字符越少越好。** 第 41 节证明导航混入和同容量下条款位置变化，但单页 article 边界尚不足以进入生产。本轮只读比较 Mozilla Readability 与 Trafilatura 已发布实现，固定版本与源码摘要，区分主算法与共享的 Readability 补救路径，不能将同一算法的移植当成两个独立机制。

预声明复用第 41 节已封存 HTML，不再抓取任务网页。在 `.tmp/source-support-20260910/main-extractor-comparison/` 隔离取得 Trafilatura 2.2.0 及其依赖，分别运行默认、favor_recall、fast 三个公开配置。按段落、代码、表格及正文标题的实际文本核对遗漏，保存完整输出和失败结果，不以字符串长度或抽取成功代替来源完整。Mozilla 先核对源码保留与删除规则；没有实际运行时只报告静态证据。安装仅在隔离目录，不变更生产依赖或配置，不运行模型或 Product E2E。

变更类型为外部机制只读分析、隔离组件诊断及文档更新。页面拥有来源内容，抽取实现拥有选择规则，模型仍拥有语义充分性；当前生产构造与消费者不变，净生产复杂度为 0、无删除项。外部规则若无法保留本任务关键原文，停止将相应默认配置作为候选，记录遗漏及正交边界；即使组件保留通过，仍须另验自主取证及最终用户结果。过程写入本节，Future 只同步采纳边界。

**两个实现的源码都表明正文抽取包含启发式清理，不能当作无损取文。** 2026-09-10 实际核对的 A 级坐标为 Mozilla Readability 0.6.0 的 [Readability.js](https://github.com/mozilla/readability/blob/0.6.0/Readability.js) 和 Trafilatura 2.2.0 的 PyPI 发布包源码。原始下载、URL 与 SHA-256 见[下载清单](../../.tmp/source-support-20260910/main-extractor-comparison/downloads.json)，完整依赖版本和分发包摘要见[隔离安装记录](../../.tmp/source-support-20260910/main-extractor-comparison/install-report.json)。

| 外部机制比较 | 构造、消费者与保留边界 | 本工程采纳与拒绝 |
| --- | --- | --- |
| Mozilla Readability 0.6.0 | `new Readability(document).parse()` 消费 DOM 并修改它，调用方需自行保留原始副本；`_grabArticle` 评分与删除候选，`_isProbablyVisible` 过滤隐藏节点，`_markDataTables` 标记数据表；`_cleanConditionally` 保护已识别数据表及 code 后代，但并非所有阶段均无条件保留它们 | 采纳原文与派生输出分开、表格代码须专门检查；拒绝把 reader 模式可见性当作研究资料完整性。未运行该实现，不报告本页实际效果 |
| Trafilatura 2.2.0 | `extract` 经 `core._extract_document` 消费 HTML；`main_extractor._extract` 按 BODY_XPATH 选择并修剪子树，按元素转换；公开参数控制表格、格式和召回倾向。默认可比较 Readability/justext，fast 跳过外部比较，但仍有内部规则与补救 | 自有 XPath 主抽取与 Mozilla 评分机制分别核对；默认的共享补救不算独立证据。拒绝直接引入其整套规则与依赖，先核对本页实际原文保留 |

上述实现的抽取结果由调用方消费，均不拥有本工程权限、来源事实或最终支持判断；解析本身无需新业务状态、网络重试或持久化。它们对 DOM 的变换及返回空值也不能替换原始来源生命周期。参考只说明机制，不证明部署或适配收益。
