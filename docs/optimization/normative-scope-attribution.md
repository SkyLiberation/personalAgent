# 规范要求的来源归属与表述范围

**`ANSWER-NORMATIVE-SCOPE-001` 单独跟踪规范主体、来源与义务强度的对应问题，不作为反馈 Context 优化必须一并修好的事项。** 当前没有活动实现候选，准入状态由[设计队列](../future/design-optimization-backlog.md)拥有。历史来源错配已经存在；本轮新增概括只确认有指代歧义，尚未证明模型将全部 MUST 理解为 SHOULD，也未证明反馈区改动引入了该风险。

## 问题事实与证据范围

这里区分两种表现，不能把它们认定为同一错误的重复发生。

| 表现 | 已有证据 | 尚不能推出的结论 |
| --- | --- | --- |
| 声明引用了不支持它的规范页面 | 历史稿称 Host 必须获得明确同意，却只附 MCP Tools 页面 `r21`；已读概述 `r9` 才直接支持该声明 | 不能认定声明本身为假，或模型必然把 SHOULD 扩大成 MUST |
| 混合主体后的总结指代不清 | 本轮改稿先列应用的 SHOULD 与服务器验证输入、访问控制的 MUST，再用“这些是规范中的推荐（SHOULD）和指导性原则”概括 | 后句还限定“不强制固定交互模式”，因此只能确认范围歧义，不能直接断定全部服务器义务被降级 |

历史核验意见见[原报告](../../.tmp/final-revisions-20260920/untouched-invalid-unit-report.json)。它只判断当次实际所附证据；另一页面存在支持，不能由该报告推成全局无据。完整来源及本轮人工审阅见[来源快照](../../.tmp/feedback-boundaries-20260921/decisive-evidence.json)与[审阅记录](../../.tmp/feedback-boundaries-20260921/manual-review.json)。相关对象与强度问题此前也由[第 92 节](answer-object-mismatch.md#92-草稿范围与证据规模的交叉诊断)记录；该历史识别问题不自动证明当前再次漏判。

本轮“强制所有实现采用固定确认对话框、任何调用都须逐次人工批准”是人工加入的 Offline 负例，不是历史 E2E 原句。模型收到针对该句的反馈后撤销了断言，并在解释时增加上述概括。完整输入、基稿与反馈见[固定输入](../../.tmp/feedback-boundaries-20260921/body-feedback.json)，完整新稿见[原始输出](../../.tmp/feedback-boundaries-20260921/body-final.json)。能够观察到反馈驱动目标修正，不能从这条随机轨迹推断隐藏注意力或 Context 改动的唯一因果。

## 独立责任与后续准入

Conversation 负责按所述主体、条件与规范强度选择依据和成文；引用物化代码负责原文与身份保真；现有 Verifier 判断实际提交的正文与附证。这里的模型选错来源不同于已修复的确定性代码丢失 `source` 字段，不重新打开引用传输问题。

后续若单独推进本项，先固定声明、实际附证与完整来源，区分来源错配、明确强度失真和仅有指代歧义。验证须保留应用建议、服务器义务与交互形式三者的边界，同时接受有据限定；不能仅按 MUST／SHOULD 字符命中判断，也不能要求固定措辞。当前只登记事实和诊断范围，不增加提示、第二个核验器、状态或修订规则。

## 与反馈 Context 优化分开验收

反馈项检查当前拒稿是否绑定正确基稿与对象、模型是否修正被指出的缺口、仍有效的正文和引用是否保留。未被反馈指向的旧问题不计为反馈消费失败；本项风险不阻塞该机制的对象绑定与正式消费验证。若后续证据证明 Context 候选错误绑定反馈、丢失有效依据或因果性地改变了要求，仍须回到该候选的责任边界处理，不能借“独立问题”豁免真实回归。
