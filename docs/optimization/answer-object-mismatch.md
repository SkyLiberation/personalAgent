这一后续契约尚未接入或验证。重新准入必须明确正式 Final 写入口、可见证据身份与消费点，保护本轮 e009/e010 断片、同单元多来源和 e011 条件遗漏反例，再以原中文正式任务验证用户结果。若仍从完整目录重新选证，只是本轮已暴露缺口的同一方案，不能通过换名称宣称解决。活动设计与条件见 [Future](../future/conversation-verification-false-positive.md#3-条件候选与因果准入顺序)。

**本轮十次离线对照已完成，相邻布局没有提高本组真实稿的引用合法率，不将“结构简单”写成已验证的通用准则。** 第 95 节第二稿提供了实际非法引用反例；本轮保留当时可见证据与原稿，在独立 Offline Eval 中只修正引用。它不经过完整 Conversation 决策与 Verification 链，不是 Product E2E，也不冒充生产完整 Prompt 对照。

### 唯一变量、责任与预声明

A 使用当前的 `observation` 加独立 `citations` 目录；B 将整记录 ID 放到 `observation` 上，将逐行 ID 放到对应 `line/text` 旁，移除重复目录。两组沿用相同复合 ID、原文、行号、元数据、顺序及可引用集合；没有改短 ID、重切片、增删证据、添加枚举或修改读取时机。转换必须逐值可逆，引用继续交给原生产恢复函数检查。

共同离线任务让同一个 MiMo v2.5 thinking 模型为固定草稿重选引用，原正文、段序与 disposition 必须保持；旧引用作为可能错误的数据提供。两组共用同一中文 Prompt、生产 `FinalMessage` 输出 Schema 和 JSON 适配器。该任务比生产自主成文更窄，若两组均成功，只能说明此边界可以完成，不能据此证明布局收益或已解决真实循环。

Conversation 继续拥有证据选择；运行系统拥有合法位置与原文恢复；本轮不新增补引用智能体或 Verifier 职责。生产源码、配置、读取优化、缺项门禁和修订循环保持，生产复杂度净变化为 0。实验代码与原始响应统一保存在[本轮目录](../../.tmp/citation-inline-layout-20260915)，机器预声明见[plan.json](../../.tmp/citation-inline-layout-20260915/plan.json)。

固定十次调用：真实第二稿两种布局各两次，另有多来源同行号、接续条件、无支持三个中文控制，各布局一次。先运行真实稿一对，再审查耗时与继续必要性。每次输出上限 32,768、360 秒、零传输重试、零结构修复；预计 200k 至 300k tokens，总已知预算 600k，模型调用耗时累计上限 1,500 秒。供应商失败或无法解析时停止新增调用；每次超过 60 秒或预计超过 10 分钟／200k 时独立重审，不重复成功样本或追加同义提示。

分别报告 Schema、正文保持、非法 ID、全部引用恢复、必要依据覆盖与历史稿语义审计。历史候选须 2/2 引用合法且正文保持，A 至少一次非法，才记引用合法性的方向性收益；控制不能出现候选独有的漏引或错引。原稿既有语义问题单列，不要求本轮修好，也不能通过删掉难句制造成功。所有控制题仅进入评测输入，不写成 Prompt 示例。

外部依据沿用 2026-09-15 核对的两个独立 A 级实现：[Claude 原生引用](https://platform.claude.com/docs/en/build-with-claude/citations)的正文块与来源位置契约，以及 [Gemini CLI 网页搜索工具](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/tools/web-search.ts)对结构化正文—来源关联的消费。它们支持显式关联与代码恢复的可实现性，不证明本轮相邻布局优于目录，也不将原生引用保障外推给 MiMo；链接为当日核对的动态文档或主分支，非固定发布版本。Prompt 输出修复是另一个变量，本轮不同时优化。

若出现可重复收益，再验证自主成文和正式消费者，最后考虑提炼为“共同消费的标识与内容直接关联，减少跨字段配对”的有限设计经验；单个局部实验不能建立所有 contract 越扁平越好的规则。若没有收益，保留阴性结果，不修改生产结构或开发规范。活动边界同步 [Future](../future/conversation-verification-false-positive.md#3-条件候选与因果准入顺序)。

### 失败定位与候选取舍

**给出合法 ID 且与原文贴近，没有阻止模型把旧稿中的错误位置当成有效证据。** 两份失败响应的可见解释都把不存在的 `o15:l39` 说成 strict 条款所在位置；A、B 的实际可引用集合都没有该 ID，`o15` 实际只返回 15 至 28 行。模型能够复述选择要求，却没有落实集合归属。这是可核对的输出模式，不证明模型隐藏注意力或旧稿锚定的唯一因果；移除旧引用的对照尚未执行。

原文位置合法仍不代表充分支持。例如 B 第一份新选的 `o12:l17` 是函数定义和参数代码示例，不能单独证明工具结果没有强制结构；同段其他引用及原稿既有范围问题必须另行审查。当前任务要求固定正文，没有运行语义 Verifier 或修复原稿已有结论，不能把合法引用当成核心语义通过。三个短控制的预固定必要事实均完整交接，不能据此称所有长稿不会漏引。

本轮否定的是“仅把引用 ID 放到原文旁边，就能稳定修正这个历史反例”的充分性主张，不证明所有结构简化都无效。没有更改生产 Context、Schema、工具返回、修订循环或开发规范，也没有增加补引用智能体。原生正文只存一次、运行系统恢复全部指定依据、缺项覆盖与修订机制仍按原证据保留。

下一条有据对照是固定布局和业务正文，只改变旧引用是否作为可见数据，区分新位置选择与旧错误沿用；仍须保护不同来源和条件，不同时增加枚举、改短 ID 或修复服务。工具第一次返回即携带引用、自主成文与正式局部 Verifier 消费均未在本轮验证，不能用这次离线诊断替代正式产品验收。经验摘要与[面试复盘第 3 节](../interview/10-development-pitfalls.md#3-引用协议要求模型重复维护正文)双向引用。

### 结论、边界与下一步

**“旧引用干扰”不足以解释全部错误，当前更明确的失败边界是模型没有稳定执行引用集合成员约束。** 旧引用可能影响选择或成本，但移除它们后仍产生新非法值，因此不能把清空旧稿当成解决方案，也不能继续将相邻布局的失败全部归因于旧稿锚定。该结论来自输入、输出及目录对照，不来自模型对隐藏推理原因的自述。

两个短控制均交接甲、乙来源和接续条件，并对无周日依据的固定句提交空引用。空引用留给后续语义审查，不代表周日结论得到支持。历史稿中的文档级缺项、权限责任推断、结果字段强度等既有问题按任务固定保留；本轮没有调用 Verifier，不能把合法 ID 当作充分支持或核心语义已解决。

原预声明的非标记字符检查仍严格执行。A 第二份只删除四处引用显示标记外围的空格与括号，论述及 URL 没变，仍记录字符检查失败。两组主要引用合法率本身相同，该显示差异没有决定候选取舍。与第 96 节相比，本轮共同 Prompt 提前允许显示标记同步，因此不合并样本或把跨轮变化归因于单一措辞。

不接入清空旧引用策略，生产目录、Schema、Prompt、读取和修订循环均未改。下一边界转向已有拒绝后的恢复：以本次自然产生的非法 Final 为反例，验证现有 Conversation 是否能消费明确的集合校验失败反馈并重提合法 Final；不是让 Verifier 找位置，也不自动将 `o10:l4` 猜成 `o10`。新的修正对照须另行预声明，尚未执行；取得恢复证据前继续暂停同样的整链长跑。活动方案同步 [Future](../future/conversation-verification-false-positive.md#3-条件候选与因果准入顺序)，经验与[面试复盘第 3 节](../interview/10-development-pitfalls.md#3-引用协议要求模型重复维护正文)双向引用。

## 98. 引用拒绝反馈的生产成文边界重放

### 执行前边界与判据

**本轮验证生产 Final 成文能否消费引用拒绝，不修改生产流程。** 原循环在引用拒绝后回到动作阶段，再由模型选择重新成文；本轮显式进入既有 `_decide(finalization_mode=True)`，只测该阶段恢复，属于 Offline Eval 与生产恢复函数的 Runtime Conformance，不能外推完整循环或 E2E。

### 补充：重审自由生成引用的职责

**现有证据足以否定“当前模型、上下文和引用协议能够可靠交接”的工程假设，但不能证明 Conversation 完全没有选证能力。** 多次已有合法输出，且本节旧 Prompt 轨迹恢复成功；与此同时，布局、清空旧引用、精确反馈及全量自检均未取得各自预声明的可靠性收益。应先改变失败责任边界，而不是继续叠加禁令或仅放宽停止条件。

代码已经提供合法目录，因此“让模型从目录选择”不是新方案。实际输出契约中的 `evidence_id` 仍是自由字符串，生成时没有闭集约束，目录只在生成后由代码精确检查。模型在完整研究成文时同时负责理解依据、组织论断、关联多个来源和转录位置；哪一项是唯一认知根因尚未证实。可以确认的是最后一项持续造成确定性交接失败。把字段改为整数或换成更短 ID 仍会允许生成不存在的值，不能直接宣称修复。

2026-09-15 核对两个独立 A 级官方接口后，进一步明确外部实现的保障边界：[Claude Citations](https://platform.claude.com/docs/en/build-with-claude/citations)说明 API 恢复原文并保证指向所提供文档的有效位置；[MiMo 结构化输出](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/structured-output)明确 `json_object` 只保证 JSON 语法，其示例中的枚举由客户端校验。前者的原生引用能力不能由本项目仿写返回字段获得，后者的客户端枚举也不能当成强制生成。此次只比较职责与接口，不更换模型，不声明其他未核对功能不存在。

优先考察的条件方向是：先有明确且范围受控的证据输入，再在该范围内成文；模型输出正文，系统沿用这次调用已绑定的原始证据，最后由现有局部 Verifier 判断这段正文能否由这些证据支持。绑定只证明本次提交了哪些依据，不证明每项依据都有支持力；未经语义判断不得把它写成已验证引用。

此方向没有实施，也不能将其描述为只需增加一个证据包字段。准入前必须分别证明：取证阶段能形成适当范围；成文时确实不再需要自由转录引用位置；多来源与接续条件完整；局部核验没有重回全历史 Context。若取证阶段仍需按同样方式自由拼接 ID，或系统把全部历史自动标为引用，则没有移除失败责任，候选应停止。代码不能根据正文猜来源、补邻片或静默丢弃坏引用。

这与已撤回的事后补引用器不同：后者先写完整稿，再由另一次模型调用寻找引用；新方向要验证的是生成正文之前已有可复核的来源范围，由调用边界保留关联。现有 Conversation 仍拥有取证、成文与修订，Verifier 仍只判断支持，不承担搜索；不因此新增 Agent、持久化或第二循环。实际可行性及外部同机制实现仍需补证，不能凭本次接口比较直接进入工程。

第 100 节停止策略事实继续保留，但不再是当前优先实施方向。已有读取、覆盖门禁、正文单一写入、全部引用恢复及局部语义核验收益保留；此次未撤回这些独立机制。结论联动 [Future](../future/conversation-verification-false-positive.md#3-条件候选与因果准入顺序)与[面试复盘第 3 节](../interview/10-development-pitfalls.md#3-引用协议要求模型重复维护正文)。本补充属于代码与既有证据的只读复核及文档调整，新增模型调用为 0，生产代码和配置不变。

**本轮验证移除成文阶段自由转录引用位置的可行性，不继续叠加输出禁令。** 第 95 至 100 节已记录正式及离线非法引用；当前生产尚无独立、按主题预绑定的取证交接。因此仅隔离“已有固定证据后写正文”的边界，不声称解决自主选证、完整 Conversation 或用户交付。

### 两个仍然可定位的语义边界
