# 中文文档与回答写作规范

> 本文拥有中文表达、术语与排版，事实治理及生命周期由 [DOC](AGENTS.md)拥有。新文档和修改段落立即适用；存量按受影响主题迁移，不因一次修改要求重写全库。

## 1. 目标与适用范围

所有工程文档和对用户的回答必须清晰、简单、不冗余，让读者直接理解结论、原因和必要限制。适用于说明、专题、接口、运维、ADR、摘要、Future、评测、面试、图表文字，以及进度说明、问题解释和交付报告；代码、路径、命令、协议、产品原名和机器日志保持原值。

## 2. 中文句子的强制结构

### 2.1 先给判断，再解释原因

先直接回应读者当前问题，再补必要的原因、责任、机制和证据。只保留帮助理解或决策的信息，删除无信息铺垫、重复结论和范围外扩展。索引、命令说明和检查清单直接给出入口或操作。

读者再次表示不理解时，定位原解释的歧义，用一个具体例子重新说明；不重复堆叠术语或原有措辞。

### 2.2 一个句子只表达一层主要关系

用常用词和具体动作，写清谁在什么条件下做什么、产生什么结果。一个句子表达一层主要关系，多个因果关系拆成句子或表格，修饰语紧邻对象；不按固定字数或并列数量判断可读性。简洁不能省略影响判断的条件、事实和证据限制。

### 2.3 并列关系必须同类

并列项应处于相同层次。业务能力、运行机制和业务项目不能混称一种能力；提议、执行事实与业务状态不能混作同一种结果。无法用同一上位概念概括时分别说明。

### 2.4 指代必须明确

代词应有唯一候选；跨段引用使用具体名称。“当前”须由文档状态、代码坐标或日期限定，历史计划不能长期充当现行事实。

## 3. 中文术语与英文保留规则

### 3.1 中文承担句子逻辑，架构角色名保留原文

引用代码实现或契约保留精确标识，描述一般含义使用中文。同一个词出现在代码中，不意味着所有正文都必须写英文；也不强制把所有架构术语翻译成中文。

| 语境 | 写法 |
| --- | --- |
| 代码类型、字段、枚举、命令或配置 | 使用原值和反引号，如 `Proposal`、`scope`、`in_progress` |
| 事实、权限与作用域的一般描述 | 使用中文，首次需要反查时补代码标识 |
| 产品、标准与协议名称 | 保留正式名称，必要时首次说明含义 |
| 指令、流程和机制论证 | 中文承担主谓宾和条件逻辑，不堆叠英文名代替解释 |

通用表达优先使用“智能体、工具、固定流程、运行系统、执行网关、服务提供方、责任主体、作用域、降级路径、同配置样本组、追踪记录、归档、评测器、发布门禁”。描述具体类或契约时保留其标识。

例如：“服务提供方通过执行网关返回 `Observation`，运行系统随后检查交付条件。”同一段同时讨论产品概念与机制时，先解释产品含义，再给实现坐标。

### 3.2 首次出现的外部协议术语说明中文含义

陌生行业术语首次可写“中文含义（英文原名）”，后续保持一致。常见产品名、正式协议名和代码标识不为满足格式重复翻译。

### 3.3 代码标识必须使用反引号

正文中的类型、函数、字段、状态、环境变量和命令参数用反引号。先说明事实或职责，再提供标识，不用对象清单替代设计论证。

## 4. 标点、数字与排版

- 中文句子使用中文标点，代码、URL 和协议片段保留原格式。
- 中文与英文、数字之间保留半角空格，中文标点两侧不额外加空格。
- 范围和章节引用在同一文档使用一致写法，标题清楚表达主题。
- 同一表格列或列表层级使用平行句法；用表格或列表帮助比较，不为排版制造层级。
- 代码围栏和 Mermaid 保持语法有效，图中解释性文字优先使用中文，标识不因中文化改写。

## 5. 事实、证据与时态

### 5.1 结论强度不能超过证据

| 依据 | 可支持范围 |
| --- | --- |
| 正式 E2E 归档 | 该输入、代码与配置下的用户结果和反事实 |
| 目标 clean revision 的完整发布证据 | 已声明发布契约及覆盖范围 |
| Offline Eval 或局部历史证据 | 指定样本和前置条件下的局部结论 |
| 代码、设计或外部参考 | 实现或候选机制存在，不能证明本工程用户结果改善 |

不将未执行写成通过，不将局部通过扩大为产品完成。单元测试及旧分类按根规范只读解释，不作为后续门禁。未知用量、未到达阶段和不可用证据明确标注。

### 5.2 当前事实与历史事实分开

历史结果按原身份和日期描述，现行说明只保留仍成立内容。正文落点和状态迁移执行 [DOC](AGENTS.md#3-事实强度与文档生命周期)，不在写作规范重复生命周期流程。

## 6. 各类文档的附加要求

| 文档类型 | 内容要求 |
| --- | --- |
| 接口与运维 | 原样保留字段和命令，说明前置条件、含义及失败语义 |
| ADR | 背景、决定、责任主体、证据、防护设计与退出条件；准入要求由 REL 拥有 |
| 当前状态摘要 | 先说明状态与证据限制，再给正式路径和权威链接 |
| 专题与固定流程 | 解释责任、信息流和协作，代码坐标用于反查 |
| 评测说明 | 保留机器编号与分类，中文说明结果、阶段和证据边界 |
| 未来设计 | 按第 6.1、6.2 节编写 Spec，说明需求、契约、方案与验收；实施状态和实际证据按第 5 节记录 |
| 面试材料 | 组织已有错误、机制、收益、证据与边界，不复制运行流水 |

### 6.1 设计文档写法

**设计正文说明怎样解决已确认的问题，并把防止设计出错的措施直接写进方案。** 本节适用于方案、候选、Future 详细设计和 ADR 的设计部分。

1. 先写具体问题、目标与事实依据，再按责任和信息流说明最小解决机制；字段、入口和契约只在帮助理解与反查时列出。必要性与复杂度按 [EVD](devSpec/change-evidence.md#5-复杂度说明complexity-justification)说明，模块组织按 [COD](devSpec/code-structure.md#32-功能模块化与开发上下文)说明局部阅读边界。
2. 把防护落实为明确责任、契约、不变量、执行约束与验证条件，不另列潜在问题清单。需要协作时直接说明动作与交接条件，不用“不能做什么”“不保证什么”等能力排除段落充实正文。
3. 失败、拒绝、证伪与退出写成可执行条件。已确认风险及例外按 [REL](devSpec/migration-release.md#2-adr-准入)记录依据与控制措施；假设、实现和已执行结果按第 5 节区分，不能用设计意图代替事实。
4. 开发顺序、阻塞复审、验收与重新打开统一引用 [EVD](devSpec/change-evidence.md#7-强制开发与设计流程)，核验输入诊断引用 [QLT](devSpec/quality-security.md#21-核验漏放先验证最小充分上下文)，正文更新与生命周期引用 [DOC](AGENTS.md)。本文只规定如何表达，不复制这些流程。

例如，版本防护写为“准入先精确比对 `base_ref` 与当前版本，过期动作拒绝且零写入”；正文保护写为“Runtime 按选中范围合并，其余正文和引用逐字保留”；内容验收写为“合并后的完整新版交给 Verifier 核验，通过后进入交付”。

### 6.2 Spec 结构与需求追溯

**后续新增或实质修改的设计文档必须采用 Spec，即可实施、可验收的设计规格。** 先说明系统在什么条件下必须产生什么结果，再说明怎样实现。适用于方案、候选、Future 详细设计和 ADR 的设计部分；在原有唯一正文中整理，不强制拆成多份文件或引入外部工具。

| 内容 | 必须写清的问题 |
| --- | --- |
| 目标、范围与依据 | 解决什么已定位问题，服务谁，哪些行为保持，事实与待证假设分别是什么 |
| 需求与行为规格 | 用稳定编号标识可独立验收的需求；写清触发条件、必须产生的结果及适用的失败行为，不用“更准确、合理优化”等意图替代结果 |
| 方案与契约 | 谁拥有事实和判断，输入输出、合法范围、不变量、状态变化及反馈由谁消费；说明最小机制如何满足需求 |
| 验收规格 | 将需求关联到真实用例，写清前置输入、触发动作、可观察结果和通过／失败判据；证据来源、预算及停止条件遵守 EVD、QLT |
| 实施与删除计划 | 按依赖顺序列出改动、消费者迁移和旧路径删除，各项引用所实现的需求及验收用例 |
| 状态与决策依据 | 区分已确定需求、候选方案、待定项、已实现和已验证；记录必要取舍、已有证据及尚未取得的证据 |

小改动可合并相邻小节或用短表表达，不为套模板增加无关内容。需求编号只用于设计追溯，不自动变成生产字段；需求、任务与用例的关联优先直接写入原表或正文，不另建重复账本。验收场景可以使用“前置条件—触发—预期结果”，语言以中文为主，语义比固定句式重要。

有影响实施的待定项时，写清缺失依据、影响范围和解决动作；受影响实现的准入仍由 EVD 判断，不把 Spec 存在等同于获准实施。改变需求、契约或方案时，同轮更新关联用例、实施项和当前状态，历史原始结果保留原身份；检查不能只核对标题齐全。

## 7. 存量文档迁移顺序

先核实事实与正文归属，再清理冲突，最后调整中文表达。不要全局替换术语或改写原始日志。按主题迁移并同步引用；范围外旧文字不阻塞局部交付，本次不继续新增同类问题。

## 8. 提交前门禁

检查文档和回答是否直接回应核心问题、用词是否易懂、有无重复或无关说明，再核对判断、指代、术语和证据措辞。文档的结构、生命周期与引用统一执行 [DOC 提交前检查](AGENTS.md#5-提交前检查)。机械检查通过不能替代内容审读。
