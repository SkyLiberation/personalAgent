# 证据、指标与发布资格

> **当前用例目录有 30 个用例：9 个进入 release selection，21 个进入 diagnostic selection。** 当前工作树也没有一份代码版本一致、工作树干净的完整发布矩阵。测试可以执行、产品证据合格和版本可以发布，是三个独立判断。

## 1. 三种证据回答三种问题

**产品结果、机制不变量和版本发布资格必须由不同证据回答，不能相互冒充。**

| 问题 | 证据责任主体 | 合格结论 |
| --- | --- | --- |
| 用户目标是否在生产主路径达成 | 正式入口的产品端到端测试 | 该次执行归档下，结果与反事实成立 |
| 机制是否遵守不变量 | 单元、契约、集成或运行一致性测试 | 指定机械边界成立 |
| 目标代码版本是否具备发布证据 | 发布门禁 | 发布矩阵、归档、提交、工作树和校验和相互匹配 |

工具返回成功、模型生成结构化数据、数据库新增、子智能体结束和追踪记录命中，都只是局部事实，不能替代用户结果。

## 2. 机器用例目录只负责执行分类

**编号、入口、服务提供方配置和机器发布候选集，只在 [evidence_catalog.py](../../evals/e2e_quality/evidence_catalog.py) 定义；目标用户、基线合法性和用户结果强度，以[当前用例盘点](../evals/02-current-case-inventory.md)与[基线优先审计](../evals/03-baseline-first-audit.md)为准。** 当前机械统计如下：

| 分类 | 数量 | 发布用途 |
| --- | ---: | --- |
| 产品端到端（Product E2E） | 9 | release selection |
| Application E2E | 9 | diagnostic selection |
| Runtime Conformance | 7 | diagnostic selection |
| Capability Profile | 5 | diagnostic selection |
| **合计** | **30** | **9 个 release，21 个 diagnostic** |

用例目录和发布门禁机械约束测试节点与必选集合；它们当前不检查真实需求来源、实现前失败基线，或最终断言是否真的是用户结果。

## 3. 当前机器发布候选集的代表用例

**代表用例只能说明各自入口和反事实，不能因为被机器选中就自动成为合格产品证据。**

| 用户旅程 | 用例 | 证明结果 | 关键反事实 |
| --- | --- | --- | --- |
| 对话 | E01 | 直接回答、澄清和多轮继续 | 混入旧路由与跨会话等多个契约，属于混合回归用例 |
| 有证据的回答 | ASK-001A、ASK-001B | 仅个人证据，以及个人证据结合官方网页，统一由当前对话回答 | 不跨用户、不写长期陈述、不产生第二条答案链 |
| 显式保存 | E08/E14 | 问答后显式保存用户原文片段 | E08 与 ASK/E14/L07 重叠，E14 是更强的自然入口 |
| 删除与恢复 | E04/E10/E22 | 删除一次、可恢复、可重放 | E04/E10 是业务或运行机制证据，E22 是自然语言入口 |
| 周期研究 | E05/E13 | 研究运行、摘要、投递和反馈记录 | 当前缺少摘要正确性或用户实际收到内容的强断言 |
| 后台持续请求边界 | INVESTIGATION-CONSOLIDATION-001 的历史归档 | 旧第二循环与四槽位候选均为 `0/20 delivered`；当前普通 Conversation 对照也为 `0/20` | 证明旧机制没有交付且需求 baseline 缺失，因此机制已删除；不证明普通研究质量已经修复 |
| 重启后的作用域隔离 | DUR-001 | 原用户可读取追踪记录，另一用户得到 404 | 安全和运维边界，不是普通对话用户结果 |

准确的测试节点与环境要求以用例目录为准。

`MEMORY-A0-001` 不属于发布用例目录，而是从正式对话入口执行的独立重复 baseline。三类自然旅程各五次，共 `15/15 delivered`；15 份归档的配置身份、评测器版本和工作树差异摘要一致，校验和错误为 0。该结果只支持本组输入下的未授权写入隔离、跨会话召回、纠正后答案和删除后检索一致性；它没有建立 target 或消融，也不能证明整套 Memory 设计相对其他方案提升正确率、成本或延迟。详细数据见[当前用例盘点](../evals/02-current-case-inventory.md)。

已删除后台调查路径中的相关性词表漂移、Plan ID 重复和结构修复只保留为历史诊断：它们可以说明“Provider JSON 合法不等于 canonical Proposal 合法”，不能进入当前发布清单，也不能证明第二循环有产品必要性。当前版本若要声称研究能力改善，必须从普通 Conversation 正式入口重新建立失败 baseline、单变量消融和真实 target。

后续两个 Memory 用例回答不同问题：`MEMORY-RETRIEVAL-SCALE-001` 证明固定 500 条候选窗口会漏掉 1,020 条事实中的尾部目标，查询级 `search_claims` target 能返回 `SCALE-TARGET-1000-7Q9X`；`MEMORY-WORKING-REAL-001` 在真实 GitHub 跨轮重启任务中为 target `5/5`、关闭绑定 Observation 消费的消融 `0/5`。后者只有无 Provider 故障样本的额外原始读取可计入机制因果，不能把外部失败算作 Memory 收益。

## 4. 复杂循环与诊断用例的边界

**复杂循环的用户输入不能指定工具、顺序、并发或终止方式；这些只能在执行后通过追踪记录或执行回执断言。**

- `L01/L07`：自然知识召回与跨会话保存后召回；
- `L02/L03/L04`：安全并发、进程恢复和父子智能体结果综合；
- `L05/L06`：预算不足时拒绝继续，以及运行系统负责的已验证修订；
- `CTX-001/RUN-001`：冻结外部边界后诊断上下文增长和批次预算，因此不参与产品完成率。

能力配置、长期项目一致性和边界评估可以精确指定服务提供方、检查点或故障注入；正因为它们是白盒机制证据，不能单独冒充产品能力。`GOV-001` 证明外部内容不获得控制权，`OBS-001` 证明作用域拒绝不泄漏且可定位，`E24` 保留周期研究边界的成对诊断。

## 5. 成对证据只支持对应设计

**基线与目标路径的差异，只支持同一输入下被改变的那条机制，不能外推整个框架更优。**

| 机制 | 基线 | 目标路径 | 可支持的结论 |
| --- | --- | --- | --- |
| 执行事实驱动知识读取 | 没有知识执行事实，返回澄清请求 | 命中本用户随机事实，并排除另一用户的冲突事实 | 已提交执行事实是回答依据；不证明所有工具选择都正确 |
| 原文片段、确认和写入口分离 | 控制语义被写入长期陈述 | 精确陈述新增 1 条；确认前、控制语义和重放产生的新写入均为 0 | 保存边界有效；不覆盖保存助手候选回答的场景 |
| 有界执行结果与重读 | 1,940,197 个字符、776,720 个令牌 | 12,138 个字符、26,424 个令牌，并得到精确地址和行号 | 卸载显著降低该类任务的模型输入；`CTX-001` 仍是诊断证据 |
| 前台工作清单的显式审阅与纠偏 | 单行消融丢弃已准入计划：`plan_ready` 响应没有可查看清单，后续没有可修订版本 | 目标路径返回可见清单，接受用户把“缺口”改成“冲突检查”并完成 | `CONV-001` v2 单案例证明控制面价值；两边最终答案都正确，不证明答案正确率提升；成本差异样本不足 |
| 工作清单绑定事实的跨轮消费 | 干净单变量消融关闭成功事实消费后，第二轮重复访问 BETA 和 GAMMA，重复原始读取为 `2` | 目标路径恢复同一清单绑定的成功事实，第二轮原始读取为 `0`；两边都交付三个结果、应用新阈值，简单问答不建清单 | `HARNESS-003` v3 建立冻结服务提供方场景下的运行一致性测试因果；后续 Completion 改动来自其他失败 baseline，不能归因于本用例 |
| 真实跨轮工作记忆 | 关闭绑定 Observation 消费后为 `0/5`；无 Provider 故障样本增加 GitHub 原始读取 | target 为 `5/5`，重启后复用同一 Plan 和已提交事实，只读取新的必要资料 | `MEMORY-WORKING-REAL-001` 支持该任务的连续性与重复读取结论；Provider 故障样本和其他任务不能外推 |
| 千条规模长期检索 | 只取前 500 条候选，最终答案漏掉尾部目标 | 查询级候选检索从 1,020 条事实中命中随机目标 | 证明固定窗口是该样本的失败源；不证明所有同义表达或更大规模性能 |
| 隐藏工具运行门禁 | 全量注册表可解析非公开工具 | 同一 `exposure` 规则在模型调用路径执行前拒绝 | `TOOL-AUTH-001` 证明曝光与调用一致；`GOV-001` 另证明一个自然攻击场景，不等于完整安全体系 |
| MCP 结果契约 | 已声明输出结构未被实际响应消费 | Draft 2020-12 校验、`isError` 和双表示冲突均 fail closed | 证明已声明结构的协议边界；不替代开放业务语义验证 |
| accepted SubGoal 到远端任务绑定 | 模型把完整协议研究目标缩写为 `sub-2` 或 `acq`，真实远端产物离题 | Application 编译 objective 与 required output，模型不再写目标，Admission 防绕过；两次真实 MiMo target 的绑定全部相等且产生 Artifact | 证明命令绑定生效；两次都是 `0` Outcome，不能声称用户结果改善 |
| Agent Artifact URL 候选 | 官方 URL 已在 admitted Artifact 中，旧派生仍让 `capture_url` 收到空参数 | 文本 URL 进入 candidate ID 投影，无候选时 fail closed；本地失败测试和消融成立 | 后续真实 target 改选第二次 Agent，没有消费 `capture_url`；只有 no-consumption 证据，不能升级为产品效果 |
| 最新 Plan 契约进入最终交付 | v4 baseline 在三类自然调整中复现陈旧义务、错误完成或最终结果不完整 | v51 从正式入口执行三类场景各五次，结果为 `15/15 delivered`、最终待完成项为 0、服务提供方失败为 0 | 当前配置样本组达到预声明结果门槛；不能外推其他模型、服务提供方、任务分布和更大样本 |
| 运行系统负责验证 | 同输入 5/9 | 9/9 | 用户明确要求审查的路径更稳定；不外推所有回答 |
| 用户身份与执行引用分离 | 重启后向另一用户返回私密内容 | 原用户恢复成功；另一用户得到 404；泄漏为 0 | `DUR-001` 范围内的作用域恢复成立；不证明完整的角色权限体系 |

执行归档坐标和更完整数字保留在对应的架构决策记录与追踪记录中，不在多篇面试文档重复。当前没有执行本框架与外部框架的同输入对照实验，因此不能声称整体完成率、成本、延迟或维护性优于其他智能体。

## 6. 当前版本已有分任务性能画像

**直接回答、Plan、Memory 召回、100 工具组和显式委托都已经达到 20 个同配置样本，但这些任务族不能合并为统一 P95。** 模型、服务提供方、提示词、预算、用例目录和测试数据都相同时，样本才能在同一任务族内聚合。当前正式结果如下：

| 任务族 | 用户结果 | 延迟 P95 | 总令牌 P95 | 证据边界 |
| --- | --- | --- | --- | --- |
| 直接回答 | `20/20 delivered` | 2.13 秒 | 7,573 | 公开标记确认，不代表复杂推理 |
| Plan | `20/20 delivered` | 4.33 秒 | 7,941 | 首次返回可审阅剩余步骤，不包含后续执行 |
| Memory 召回 | `20/20 delivered` | 3.68 秒 | 14,620 | 已有个人知识的检索与引用；知识准备时间作为 setup 单独记录 |
| 100 工具 | `20/20 delivered` | 当前文档不重复计算 | 每个样本不超过 32,000 | 只覆盖当前工具目录和场景分布 |
| 显式委托（历史组） | `10/20 delivered` | 全体 260.81 秒；成功样本 144.66 秒 | 全体 47,217 | 历史配置画像，不代表当前工作树 |
| 显式委托（2026-08-27 当前组） | `2/20 delivered` | 全体 202.786 秒 | 全体 56,055；总计 989,369 | 11 次子级超时、7 次子级完成但父级未交付；不是稳定准入证据 |

前三组归档位于 `data/e2e_traces/product_baselines_agent_perf_v1/`，60 份归档的 checksum 错误为 0。当前 HTTP 接口不是原生流式，所以首个用户可见结果时间等于响应完成时间。每份样本仍记录：

- 目标完成率与恢复成功率；
- 输入、输出和总令牌数；
- 模型轮次与调用次数、工具与子智能体调用次数；
- 用例延迟、恢复延迟和重放产生的新副作用；
- 测量完整度。

缺失用量时标记为“不可用”，不能记为 0；配置不同或代码状态不同的样本组拒绝混合，少于 20 个样本不输出 P95。显式委托历史组位于 `data/e2e_traces/product_agent_perf_delegate_v5/`，当前组位于 `data/e2e_traces/product_agent_perf_delegate_current_20260827/`，两组校验和错误均为 0。父智能体自行补答不能替代成功的子任务产物，子任务完成也不能替代父级交付，失败样本不能从延迟分布中删除。当前可以报告各任务族的独立画像，但委托组没有通过稳定性门槛，也不能声称存在跨任务统一性能。详见[观测指标](../evals/05-observability-metrics.md)。

## 7. 为什么当前不能说“可发布”

**发布门禁只有在证据、代码版本和工作树状态一致时才允许通过。** 至少核对：

1. 用例目录中的发布候选集合；
2. 必选用例全部通过且没有跳过；
3. 追踪记录、摘要和校验和完整；
4. 归档对应的代码提交与目标版本相同；
5. 归档和目标工作树都没有未提交修改；
6. 摘要记录的退出状态为 0。

当前准确说法是：

> 已有多条从正式入口执行的定向端到端测试和机制诊断；当前工作树尚未形成代码版本一致、工作树干净的完整发布矩阵，因此不能把这些定向结果升级为版本发布资格。

## 8. 可复现入口

**发布证据必须通过固定命令重新执行和派生，不能靠文档中的历史数字宣布通过。**

```powershell
$env:PERSONAL_AGENT_REQUIRE_LIVE_E2E = "true"
$env:PERSONAL_AGENT_E2E_TRACE_DIR = "data/e2e_traces"
uv run pytest evals/e2e_quality --e2e-scope=release `
  --e2e-require-complete-matrix -q -s
uv run python -m evals.e2e_quality.release_gate --trace-root data/e2e_traces
```

指标报告示例与测量配置约束见 [evals/e2e_quality/README.md](../../evals/e2e_quality/README.md)。

## 9. 证据边界不会自动变成开发任务

**证据边界不能自动升级成开发任务。** 当前不能声称用户级事实隔离等于完整工作区和角色权限体系，也不能声称助手候选回答可以安全自动写入、所有后台项目与服务提供方组合都通过了真实环境端到端测试，或检查点天然保证外部副作用恰好执行一次。只有真实业务扩展、失败产品基线或可量化工程约束成立后，候选方案才进入未来设计文档。
