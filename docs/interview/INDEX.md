# personalAgent 面试材料

> **本目录用于持续准备 AI 智能体开发面试：以面试官的不同追问检验当前工程与讲述是否经得住事实核对，并据此不断打磨工程和面试表达。** 它是当前实现的讲述投影，不是替现有智能体辩护的答辩稿、开发日志、未来设计或第二份状态账本。

## 使用原则

**面试问题既检验表达，也检验工程；结论必须按问题归属落到唯一位置。**

- 当前智能体确实存在产品或工程问题时，直接承认现状和证据边界，不为说服面试官追加解释；候选优化统一记录到 [design-optimization-backlog.md](../future/design-optimization-backlog.md)，并按工程规范补齐基线、目标结果和复杂度准入后再实施。
- 当前实现成立，但本目录表述不清、过期或容易误导时，核对权威事实后修正对应面试文档。
- 证据不足时明确写“尚未验证”或“需要执行基线”，不把设计意图、代码存在、单元测试或未来方案说成已交付能力。
- 通用设计逻辑只作为比较坐标；主讲章节必须映射到本工程的责任主体、生产消费者和证据充分性，并区分“已满足、已实现但证据不足、边界内映射、候选未准入、已证明缺口”。
- 每次补充都应提高事实准确性、可解释性或工程质量；禁止围绕单个面试问题不断堆叠互相兼容的答辩话术。

整套材料的技术主线是：**模型负责开放语义判断，确定性边界约束模型权力，业务责任主体保存事实，语义验证与完成门禁共同判断用户结果。** 正文先讲用户错误、设计判断和反事实；类名只在需要进入代码时作为定位坐标。

## 先记住七个判断

1. **运行外壳把模型建议接入受治理闭环；模型建议不等于授权，动作执行不等于目标完成，诊断记录不等于业务事实。**
2. **计划的能力价值不是列步骤，而是让有依据的计划、未完成结果、已提交事实和完成门禁在真实边界后继续共同工作；未映射的通用机制不自动构成工程缺陷。**
3. **用户可验收的业务动作与执行资源必须分开：前者拥有结果契约，后者只提供执行能力。**
4. **自然语言对话可以调用固定事务或创建长期项目，但不能接管它们的长期事实。**
5. **Memory 是受治理的跨时间上下文；当前覆盖工作记忆、跨轮事实复用、外部 Memory 和长期语义记忆，不把追踪记录或静态提示词冒充情景记忆和程序记忆。**
6. **知识必须从来源、证据位置进入可维护陈述；向量和图只负责可重建召回。**
7. **定向用例只证明自己的用户结果；版本发布还要求代码版本、完整矩阵和工作树状态一致。**
