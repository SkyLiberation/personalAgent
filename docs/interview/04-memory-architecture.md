# 智能体 Memory：跨时间的上下文与事实治理

> **当前工程的 Memory 不只有长期个人知识。** 智能体还需要维持本轮工作状态、跨轮复用已提交事实，并通过外部产物保存超出模型上下文的大内容。长期语义记忆和真实跨轮工作记忆已经分别形成定向产品证据；通用情景记忆、经验学习、动态程序记忆和滚动摘要尚未形成生产闭环。

## 1. Memory 是受治理的跨时间上下文

**从模型视角看，Memory 是跨时间的上下文工程；从系统视角看，Memory 还必须管理信息进入未来上下文的资格。** 模型只能使用本次调用可见的信息，因此任何记忆最终都要经过检索、选择和物化。系统仍需在模型调用之外决定来源、作用域、当前状态、纠错、删除和恢复，不能把“模型曾经看见”直接解释成“系统已经记住”。

```text
过去的信息
  -> 由事实责任主体保存
  -> 按身份、作用域和当前状态过滤
  -> 按本轮需求检索和选择
  -> 在预算内物化为模型输入
  -> 影响当前判断或回答
```

这一定义同时排除两个常见误解：向量数据库只是候选检索机制，不等于 Memory；完整聊天历史只是信息来源，也不自动构成可信的长期事实。

## 2. Memory 需要沿两个维度分类

**“短期或长期”描述信息保留多久，“语义、情景或程序”描述系统保留什么；两组概念不能压成一条分类树。** 同一条情景记录可以只服务当前任务，也可以跨任务长期保留。长期记忆也不只包含事实，还可能包含经历和程序，但每一类都需要独立的生产消费者和证据。

| 维度 | 类型 | 解决的问题 |
| --- | --- | --- |
| 时间与作用域 | 工作记忆 | 当前模型调用和当前交互正在处理什么 |
| 时间与作用域 | 对话内短期记忆 | 同一对话换轮次、压缩或恢复后如何继续 |
| 时间与作用域 | 跨会话长期记忆 | 哪些信息应跨对话继续影响未来请求 |
| 内容性质 | 语义记忆 | 当前认可的事实、概念和用户偏好是什么 |
| 内容性质 | 情景记忆 | 过去发生过哪些交互、动作和结果 |
| 内容性质 | 程序记忆 | 系统从经验中保留了哪些可复用做法 |

保存一条追踪记录不等于实现情景记忆；只有未来任务会按明确契约检索并消费过去经历，情景记忆才形成能力。静态 Prompt、Policy 和 Skill 也不是动态程序记忆，因为它们没有从执行经验产生受治理的更新。

## 3. 当前工程已经形成四条 Memory 路径

**当前工程已经具备工作记忆、对话内事实复用、外部 Memory 和长期语义记忆，但四条路径的事实责任主体和证据强度不同。** 统一称为 Memory 不表示把它们写入同一 Store；统一点只在于它们都让过去的信息在合法条件下影响后续模型调用。

| 当前路径 | 保存或投影的内容 | 解决的具体错误 | 当前证据状态 |
| --- | --- | --- | --- |
| 工作记忆 | 当前消息、工作项、`Observation`、反馈、预算和阶段 | 模型每一步都从零开始，遗漏当前义务或已取得结果 | `MEMORY-WORKING-REAL-001` 的真实 GitHub target 为 `5/5`，关闭绑定事实消费后为 `0/5` |
| 对话内短期记忆 | 已提交消息、当前工作项及其绑定执行事实 | 换轮次或恢复后重复读取、重复执行或丢失进度 | 真实跨轮重启用例证明复用；零消费者滚动摘要已删除，不等于完整对话摘要能力 |
| 外部 Memory | 大型工具结果和智能体产物的完整正文与 `ResourceRef` | 把完整大结果反复放入模型上下文，或截断后失去精确证据 | `CTX-001` 覆盖冻结服务提供方下的有界卸载和重读；`E21` 覆盖真实 GitHub MCP 集成 |
| 长期语义记忆 | 用户授权的原文、证据位置、`Claim`、关系和生命周期 | 无法跨会话召回，或把推测、越权内容和已删除事实当成当前知识 | `MEMORY-A0-001` 为 `15/15`；规模用例从 1,020 条事实中命中尾部目标 |

### 3.1 工作记忆维持当前交互的认知连续性

**工作记忆负责让模型知道“当前正在完成什么、已经得到什么、还缺什么”。** Conversation 把当前消息、工作项、已获准的执行结果、反馈和预算物化为本轮输入。工作记忆可以在下一轮重建，但不能成为个人知识的第二写入口。

```text
当前用户消息
+ 当前可验收工作项
+ 已提交 Observation
+ DecisionFeedback
+ 当前预算和阶段
-> 本轮有界模型输入
```

模型可以据此提出下一步，但确定性系统继续拥有权限、执行事实和完成门禁。历史助手回答只帮助理解指代；它不能替代本轮证据。

### 3.2 对话内短期记忆复用已提交事实

**短期记忆的核心不是保存更多聊天文本，而是让同一对话在换轮次或恢复后继续消费已经提交的事实。** `MEMORY-WORKING-REAL-001` 使用真实 GitHub、真实模型、Postgres 与正式 Conversation 入口：target 五次都在首轮读取两份资料并返回边界，Web 进程重启与用户 steering 后复用同一 Plan，只新增一次读取并交付答案。

单变量消融只关闭“按当前 Plan 消费已绑定成功 `Observation`”，结果为 `0/5`；前两个无 Provider 故障样本出现额外 GitHub 原始读取，后续 Provider 故障样本不计入机制因果。该证据说明已提交事实能改善这一真实跨轮任务的连续性，不能证明所有任务的普遍正确率、成本或 P95。

原代码中的 `ThreadSummary`、滚动摘要函数、专用 Prompt 和配置没有 Conversation 生产消费者，已经破坏式删除。删除没有新增摘要替代物，因为当前没有长对话失败 baseline；面试时应明确“结构化事实复用已交付，滚动摘要未交付”。

### 3.3 外部 Memory 让模型按需重读完整真源

**外部 Memory 负责保存超出上下文预算的大内容，并通过稳定引用支持精确重读。** 完整正文进入产物存储；模型只接收有界片段、省略信息和 `ResourceRef`。后续重读返回新的精确窗口，不复制第二份真源。

```text
大型工具结果
  -> 保存完整 Artifact
  -> 提交有界 Observation + ResourceRef
  -> 模型选择是否重读以及读取位置
  -> 返回精确窗口
```

`CTX-001` 在三份大型冻结资料并存时证明上下文保持有界，并通过重读得到随机事实。该用例属于 Context/MCP 一致性测试，不等于真实服务提供方交付。`E21` 证明真实 GitHub MCP 大文件路径可以返回目标地址和本次读取行号；它仍不外推所有外部资源和所有固定页数问题。

### 3.4 长期语义记忆管理当前有效的个人事实

**长期语义记忆负责把用户授权的信息转化为可跨会话维护的事实。** 当前链路保留原文、证据位置和可维护陈述。检索投影只提供候选；`Claim` 的作用域、支持状态和生命周期决定内容能否进入回答。

```text
用户明确原文
  -> 保存确认
  -> Artifact / EvidenceSpan / Claim
  -> 模型按当前目标选择 search_personal_knowledge
  -> 作用域过滤与跨会话检索
  -> 有界 tool_result
  -> 当前回答
```

个人知识不会仅因用户消息提到“个人资料”而自动进入模型上下文。Conversation 把 `search_personal_knowledge` 作为临时只读能力投影；模型决定当前目标是否需要个人证据，Knowledge Application 继续按当前 principal、作用域和生命周期选择事实。模型不能提交身份，也不能把检索结果写回长期知识。

当前 `MEMORY-A0-001` 同时观察长期状态、`search_personal_knowledge` 的 `Observation` 和最终答案：未授权推断不写入、不跨用户物化；明确保存后新会话可以召回；删除确认前事实仍可见，确认后旧值既不进入个人知识搜索结果，也不出现在答案中。按需搜索改动后的完整回归为 `15/15 delivered`。

自然纠正场景五次都采用了新值，没有发生用户错误或跨 principal 泄漏，因此候选在 A0 退出；内部生命周期差异保留为观察项，不能以代码形态代替失败用户结果。

规模用例另外证明了 Retrieval Index 的职责边界：旧路径只取前 500 条 `Claim` 再排序，在 1,020 条事实中漏掉尾部目标；当前 Store Port 通过 owner/scope 约束的 `search_claims` 先产生查询相关候选，再由 Knowledge Application 过滤生命周期并组织证据，最终回答命中 `SCALE-TARGET-1000-7Q9X`。这不是把索引升级为事实源；索引只改变“哪些 canonical facts 成为候选”，不能决定事实是否有效。

## 4. 五类存储职责不是五种平级 Memory

**模型上下文、对话日志、产物存储、长期知识和检索投影组成一条 Memory 使用链，而不是五个同类记忆库。** 分类依据是每个环节对过去信息拥有的不同权力。

| 环节 | 负责回答 | 不负责回答 |
| --- | --- | --- |
| 模型上下文 | 模型这一次真正看见什么 | 什么应被长期保存 |
| 对话日志 | 已经提交了什么、恢复时从哪里继续 | 用户当前认可什么长期事实 |
| 产物存储 | 原始正文或大型结果在哪里 | 内容当前是否有效 |
| 长期知识 | 哪些事实当前可跨会话使用 | 候选如何高效排序 |
| 检索投影 | 当前问题可能需要哪些候选 | 候选是否拥有事实权威 |

同一句话可以先出现在当前消息和对话日志中，确认保存后再产生长期 `Claim`。这些对象不是重复事实：当前消息证明用户说过什么，长期 `Claim` 才表达系统允许未来请求把什么作为当前个人知识使用。

## 5. 上下文物化是 Memory 影响模型的出口

**Memory 只有经过上下文物化，才能影响当前模型输出；检索命中本身不等于模型已经看见。** 当前上下文遵循“先可见性、再需求召回、随后语义选择、最后预算物化”的顺序。

```text
Visibility
  -> Requirement Retrieval
  -> Semantic Selection
  -> Budget Materialization
  -> LLM Context
```

可见性判断用户能否读取；需求召回产生候选；语义选择判断哪些候选有助于当前目标；预算物化决定最终放入哪些字段、引用、冲突信息和有界片段。物化结果是临时只读视图，不能反向写成长期知识。

当前长期知识路径只在模型选择 `search_personal_knowledge` 后，才把选中的个人证据包装为有界 `tool_result`。`MEMORY-A0-001` 同时断言随机值是否出现在该 `Observation` 和最终答案中，因此它证明的是长期语义记忆的 Application 级上下文物化边界，而不是服务提供方原始 HTTP 请求的逐字节形态。

`SECURITY-REAL-001` 补充了“不应物化”的反事实。旧链在五个“不要输出我的个人资料”样本中仍把个人知识放入模型上下文；按需搜索 target 五次都没有物化受保护值，同时仍完成公开 GitHub 读取。该对照说明 Context Materialization 本身是安全边界，不只是令牌优化。

## 6. 情景记忆和程序记忆尚未形成通用能力

**当前 Journal、Trace 和 Receipt 只应称为恢复或审计事实；当前 Prompt、Policy 和 Skill 只应称为静态执行定义。** 它们尚未形成“未来任务检索过去经历并改变策略”的生产消费链，因此不能为了面试完整而改名为情景记忆或程序记忆。

| 候选类型 | 当前已经存在 | 尚未形成的能力闭环 | 当前结论 |
| --- | --- | --- | --- |
| 情景记忆 | 交互日志、执行追踪、`Observation`、`Receipt` | 跨任务按目标检索 Episode，并证明复用经验改善用户结果 | 边界内用于恢复与审计，不建立通用 Episode Store |
| 程序记忆 | Prompt、Policy、能力定义和 Skill | 从已验证经验产生、审批、版本化和撤回新程序 | 静态配置不是动态 Memory；候选未准入 |
| 对话滚动摘要 | 当前无生产实现；原零消费者代码已删除 | Conversation 正式入口的失败基线与生产消费者 | 不称为已落地能力，也不为面试完整而恢复 |

未来只有在自然用户目标复现跨任务经验缺失、长对话丢失关键约束或重复犯错时，才应分别定义 baseline。实现前还要说明新事实的责任主体、写入口、失效条件和单变量消融，不能先创建统一 Memory Agent 或第二套事实库。

## 7. 外部实现的共同点是按生命周期分开

**成熟实现并没有把 Memory 统一定义成向量数据库；它们按会话状态、跨线程事实、模型可见块或时间性知识选择不同边界。** 以下 A 级坐标用于解释机制差异，不构成本工程新增功能的需求来源。

| 实现与坐标 | 机制定义 | 当前工程采用与拒绝的部分 |
| --- | --- | --- |
| OpenAI Conversation State，官方文档，核对日期 `2026-08-23` | Conversation 以持久标识保存 message、Tool call 和 Tool output；`previous_response_id` 可以串联响应 | 用作对话连续性的比较坐标；不把持久会话项自动视为个人长期事实 |
| LangGraph Persistence，官方文档，核对日期 `2026-08-23` | checkpointer 保存 thread 内 Graph State；Store 保存跨 thread 的应用数据 | 采用短期状态与长期事实分离的语义；不创建共享事实 owner |
| Letta Stateful Agents，官方文档，核对日期 `2026-08-23` | 消息、工具调用和 Memory 持久化；附着的 Memory Block 进入上下文，智能体可用工具修改 | 采用“Memory 最终进入上下文”的解释；拒绝无知识写入口的自由自修改 |
| Graphiti 主仓库，核对日期 `2026-08-23` | 时间性事实具有有效窗口，并回指产生事实的 Episode | 采用来源和失效语义作为比较坐标；图继续是可重建检索投影，不成为本工程事实源 |

复核坐标：[OpenAI Conversation State](https://developers.openai.com/api/docs/guides/conversation-state)、[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)、[Letta Stateful Agents](https://docs.letta.com/v1-sdk/concepts/stateful-agents)、[Graphiti](https://github.com/getzep/graphiti)。

## 8. 面试结论按证据强度表达

**面试时应介绍完整 Memory 坐标，但只能把存在生产消费者和相称证据的部分称为当前能力。** 最短回答如下：

> 当前工程把 Memory 定义为受治理的跨时间上下文。工作记忆维持本轮目标、执行事实和预算；对话内短期记忆在跨轮和恢复后复用已提交事实；外部 Memory 通过 Artifact 和引用保存大结果；长期语义记忆管理可跨会话纠错和删除的个人事实。长期语义记忆的产品证据最完整，跨轮事实复用和大结果重读分别有一致性证据；通用情景记忆、动态程序记忆和滚动摘要尚未形成生产闭环。

这套讲法既不能收缩为“Memory 只有长期知识”，也不能把所有持久化对象包装成已经交付的 Memory。面试官可以继续追问每一类信息的责任主体、写入口、失效条件、物化方式和证据边界，回答仍能落回当前生产路径。

## 9. 当前实现坐标

**代码坐标只用于反查上述责任，不定义 Memory 分类。** 工作记忆和长期个人证据在 `ConversationService` 中物化；已提交交互事实由 `InteractionJournal` 持有；大型结果由 `ArtifactService` 和 `context_materialization.py` 管理；长期知识由 `KnowledgeService` 与 `MemoryFacade` 提供写入和读取边界。零消费者的滚动摘要代码已经删除，当前没有对应生产坐标。

长期知识的领域生命周期见[领域设计](05-knowledge-and-domain-workflows.md)，上下文、恢复和受治理执行的通用机制见[智能体运行外壳](03-capability-axes.md)，证据资格见[证据与发布](06-evidence-and-release.md)。
