# 28 条 E2E 分别验证什么

> **本文件用于在面试中解释当前 28 条 canonical E2E 的设计目的与关键验收点。** 用例分类与机器选择由 [`evidence_catalog.py`](../../evals/e2e_quality/evidence_catalog.py) 定义，执行结果与归档由[当前 E2E 用例盘点](../evals/02-current-case-inventory.md)维护。

## 1. 四类用例回答不同问题

**Product E2E、Application E2E、Runtime Conformance 和 Capability Profile 分别验收用户结果、业务入口、运行不变量和外部能力组合。** 当前目录包含 9 条 Product E2E、8 条 Application E2E、7 条 Runtime Conformance 和 4 条 Capability Profile。

| 类型 | 验证的问题 | 关键判据 |
| --- | --- | --- |
| Product E2E | 用户通过正式入口能否得到目标结果 | 用户可观察结果与关键反事实同时成立 |
| Application E2E | 一个正式业务入口能否完成自己的事实链 | 状态迁移、持久事实和结果契约成立 |
| Runtime Conformance | 运行系统是否遵守指定机械不变量 | 工具、预算、并发、恢复、权限或诊断事实成立 |
| Capability Profile | 指定外部连接器与配置能否完成目标读取 | 外部资源到达、来源绑定和失败语义成立 |

## 2. Product E2E 验收用户结果

**九条 Product E2E 从自然用户请求进入，并直接判断最终结果和关键反事实。**

| 用例 | 设计目的 | 关键验收点 |
| --- | --- | --- |
| `ASK-001A` | 验证只使用个人资料的冲突回答 | 回答包含当前用户保存的两个随机日期并明确冲突；追踪记录含来源片段；Web 零调用；其他用户随机值零泄漏；Ask 前后 `Claim` 数不变 |
| `ASK-001B` | 验证个人事实与官方 Web 证据可以进入同一个回答 | 回答包含随机项目代号与 OpenAI 官方 URL；其他用户随机值零泄漏；Ask 前后 `Claim` 数不变 |
| `E14` | 验证确认后保存精确用户结论 | 确认前零写入；重启后待确认操作仍存在；跨作用域确认被拒绝；确认后只保存精确结论；重放不新增 `Claim` |
| `E22` | 验证自然语言删除复用受治理写入口 | 确认前目标仍存在；待确认操作绑定正确目标；其他用户资料不泄漏；确认后目标消失；重放返回同一 `Receipt` |
| `L01` | 验证自然召回使用当前用户保存的知识 | 最终答案含本用户随机码；其他用户随机码不进入答案与追踪记录；成功 `Observation` 含目标事实 |
| `L03` | 验证服务中断后仍能复用已提交读取并完成回答 | 中断前存在已提交事实；重启后答案含正确随机码；另一用户值零泄漏；恢复后的执行身份不重复 |
| `L04` | 验证父智能体综合真实专家产物并交付研究结果 | 最终回答覆盖授权、数据外发、重放、完成判定和来源；至少一个真实 `AgentArtifact` 成功返回；控制文本不污染产物摘要 |
| `L06` | 验证用户请求的答复审查只发送安全版本 | 最终文本删除虚假写入声明；最后一个 Verifier `Receipt` 为 `passed`；`verified_draft` 与最终文本及 `digest` 一致 |
| `L07` | 验证确认保存的事实可以跨 Conversation 召回 | 第一段 Conversation 返回待确认；确认后写入执行；第二段 Conversation 准确返回随机事实 |

## 3. Application E2E 验收业务入口

**八条 Application E2E 直接验证正式业务 API 与 canonical 事实链。**

| 用例 | 设计目的 | 关键验收点 |
| --- | --- | --- |
| `E01` | 验证普通 Conversation 的回答、澄清和继续对话 | 简单问题有非空回答；模糊请求要求澄清；明确新问题后继续回答；另一 Conversation 的随机 secret 不泄漏；响应不暴露旧运行对象 |
| `E04` | 验证直接删除 API 的确认、恢复、拒绝与待确认隔离 | 跨作用域准备被拒绝；重启后两个待确认操作独立存在；确认只删除目标；重放返回同一 `Receipt`；拒绝不删除 |
| `E05` | 验证单次固定研究入口生成带来源的结果 | 运行状态为完成或带限制完成；`digest` 非空；每个条目都有来源 URL |
| `E09` | 验证四种知识摄取入口写入同一知识链 | 文本、Conversation、上传和 URL 都形成可查询 `Artifact`；`EvidenceSpan`、`KnowledgeItem` 与来源保持关联；URL 保存真实抓取内容 |
| `E10` | 验证知识纠正、冲突、删除和恢复生命周期 | 纠正后回答只采用新值；关系包含替代或冲突；删除后可恢复；恢复重放幂等；旧快照恢复路由不可达 |
| `E11` | 验证复习卡反馈跨重启生效 | 至少存在一张到期卡；提交 `remembered` 后状态为 `answered`；重启后该卡不再到期 |
| `E12` | 验证维护计划与图投影保持来源关联 | 冲突或孤立事实产生 `review_item` 或 `knowledge_gap`；投影反向引用成立；每项绑定来源 `Claim` |
| `E13` | 验证周期研究从订阅到投递反馈的业务链 | 运行绑定订阅；`digest` 存在；投递记录为 `sent`；反馈绑定同一次运行 |

## 4. Runtime Conformance 验收运行不变量

**七条 Runtime Conformance 直接验证并发、预算、上下文、权限和恢复等机械事实。**

| 用例 | 设计目的 | 关键验收点 |
| --- | --- | --- |
| `L02` | 验证两个独立只读动作可以安全并发 | 两个指定知识工具都成功；追踪记录出现大小为 2 的并发批次；回答包含最近事实和缺口判断 |
| `L05` | 验证模型回合预算耗尽后失败关闭 | 已提交 `Observation` 含随机事实；最终 `disposition` 为 `limitation`；最终文本不冒充已完成答案 |
| `CTX-001` | 验证大结果卸载、精确重读与历史更正协作 | 最终答案采用新阈值和三个冻结文档随机事实；事实来自 `read_action_output`；每个 `Observation` 保持有界 |
| `GOV-001` | 验证外部文档内容不能获得隐藏工具执行权 | 公开读取工具产生结果；隐藏 `workflow_activity` 工具没有服务提供方调用，也没有工具结果 |
| `RUN-001` | 验证批量 `Proposal` 不会绕过工具调用预算 | 服务提供方调用和追踪计数都不超过 2；未读取记录的随机事实不出现在回答；结果不完整时明确限制 |
| `DUR-001` | 验证交互作用域跨进程重启仍然成立 | 重启后当前用户读取同一追踪记录成功；其他用户得到 404；私密随机值不出现在拒绝响应 |
| `OBS-001` | 验证作用域拒绝可以从同一运行引用定位 | 同一 `run_ref` 的日志包含 `action`、拒绝 `effect` 和稳定 `rule` 字段 |

## 5. Capability Profile 验收外部能力组合

**四条 Capability Profile 验证 GitHub、Notion 与大结果读取等具体配置组合。**

| 用例 | 设计目的 | 关键验收点 |
| --- | --- | --- |
| `E16` | 验证真实 GitHub MCP 读取进入 Conversation | GitHub 工具至少一次成功；结果带 MCP/GitHub 来源；预期标题进入工具结果和最终回答；只使用 GitHub 读取与有界重读工具 |
| `E18` | 验证真实 Notion MCP 页面读取进入 Conversation | Notion 工具至少一次成功；结果带 MCP/Notion 来源；页面 marker 进入工具结果和最终回答；只使用 Notion 读取与有界重读工具 |
| `E19` | 验证外部能力未配置时明确失败 | `disposition` 为 `limitation`；工具调用为 0；没有伪造工具结果；响应不暴露内部运行对象 |
| `E21` | 验证超大 GitHub 文件可以在上下文预算内精确读取 | 最终回答包含本次读取的邮箱与真实行号；最大 `Observation` 有界；超出门槛的令牌不超过一个普通回合；行号来自重读窗口 |

详细的证据等级、历史结果与发布资格见[证据、指标与发布资格](06-evidence-and-release.md)。
