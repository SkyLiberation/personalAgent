# 开发踩坑与优化经验

**这份文档总结开发中出现的具体错误、尝试过的修正和证据支持的收益。** 首项复盘是“把局部没有观察到，写成整份文档没有规定”。后续按问题补充，不按会话追加流水，也不把失败候选写成已落地能力。

本文是面试讲述与经验回顾入口。完整实验由 [optimization 总览](../optimization/conversation-source-support.md)和连续记录拥有，当前机制由专题与 ADR 拥有，产品验收由[评测盘点](../evals/02-current-case-inventory.md)拥有。工具参数协议的独立复盘见[第 08 篇](08-tool-calling-pitfall.md)，此处不重复展开。历史缺项门禁已经停用；下文保留原条件下的经验，并将取证、选证与修订缺口集中到第 14 节。

准备“Agent 常见错误有哪些、怎样排障、项目如何证明相关能力”时，先读[第 15 节](#15-agent-常见错误与排障)，再按案例进入对应优化记录。

## 1. 局部观察被写成全文缺项

**历史门禁曾拦截读取不足的全文缺项声明，并推动补读；2026-09-29 起独立缺项分类与覆盖拒绝已经停用。** 历史局部收益继续成立，现行停用由 [ADR 0033](../adr/0033-claim-deletion-and-document-absence-pause.md)拥有。不能把这次取舍写成当前仍有专门覆盖门禁，也不能据停用推断原经验无效。

### 1.1 错误是把观察范围扩大成了文档事实

**本次没有看到与所指文档没有规定，所需依据不同。** 历史首稿在只返回 23/121 个片段时声称官方页面未说明权限责任。未读内容是否含答案尚未确定，已抓取整页也不等于模型已经看到全文；可确认的问题是断言范围超出当次观察。

### 1.2 提供更多提示并没有稳定地变成约束

**读取摘要、禁令和模型复述各自有观察收益，仍出现实际范围误判。** 当轮尝试如下，样本身份不同，不合并为正确率。

| 历史尝试 | 结果与经验 |
| --- | --- |
| 提供未读数量和续读入口 | 模型能解释读取状态，完整稿仍出现漏判；信息可见不等于实际应用 |
| 强调禁止无据全文否定 | 有局部改善，后续生成和修订仍有反例；规则理解与实际交付分别验收 |
| 分开识别声明与判断支持 | 两份主稿命中目标，确定性覆盖反馈改变后续路径；能力依赖语义识别准确 |

详细尝试由[缺项问题记录](../optimization/document-absence.md)拥有，面试材料不复制逐轮实验。

### 1.3 生效的改动是拆分语义识别与确定性拒绝

**历史机制让模型识别文档级缺项表述，由代码按真实返回范围拒绝，再把反馈交给 Conversation。** 执行方拥有读取事实，模型决定如何补证或修订，整稿仍需语义验收。代码没有据此判断原文究竟有无条款，也没有把完整读取视为答案正确。

该机制的原契约见 [ADR 0021](../adr/0021-separate-document-absence-from-reading-coverage.md)，后续取证充分性决定见 [ADR 0027](../adr/0027-model-owned-evidence-sufficiency.md)；二者只解释历史阶段，当前按 ADR 0033 执行。

### 1.4 验证证明了拦截和恢复，完整任务仍失败

**历史正式轨迹从 23/121 时被拒，到补读并重验，证明了局部反馈消费。** 原研究任务仍失败，稿件还混淆参数约束与执行结果，语义核验没有拦住；完整结果由[正式评测](../evals/02-current-case-inventory.md#覆盖门禁生产迁移的验收边界)拥有。这里能讲拦截与恢复，不能讲研究质量已经可靠。

### 1.5 面试中需要明确的工程边界

**现行保护来自仍适用的来源支持、用户事实覆盖与最终核验。** 读取状态作为事实输入，未完整读取不再自动触发独立分类拒绝。限定到本次依据的未知可以合法表达，是否回答了用户问题仍需另判。保留语义验收有职责依据，独立缺项机制停用也没有解除研究模型的取证责任；现行契约见[验证专题](../topics/verification-and-completion.md)。

### 1.6 语义职责分开后，还要移除不必要的转录职责

**历史识别正确仍因逐字引句和来源身份复制失败而无法交接。** 改为模型按给定来源顺序作判断、Runtime 恢复身份后，局部交接成立，完整研究仍未交付。该经验支持让代码恢复已有对象身份，不证明分类与修订都准确；原依据见[第 104 节](../optimization/document-absence.md#104-按来源顺序返回缺项分类)。当前分类协议已随停用删除。

### 1.7 模型能复述反馈，不等于已经有效修订

**反馈进入请求、模型提到问题、实际修改和用户交付是不同事实。** 后续历史候选补充了读取数量与单位说明，但正式轨迹在触发该反馈前停止，因此没有修订收益证据。这个结果不能否定原交接机制，也不能证明增加说明即可改善研究；见[第 105 节](../optimization/document-absence.md#105-用自然语言解释未完整读取与修订边界)。

## 2. 这次经历如何改变开发方法

**设计判断沿目标、事实、责任和证据保持一致，具体反例只改变被它否定的边界。** 分析先核对用户到底需要什么，再审计实际输入与输出，最后定位最早失败及最小改动。

| 需要纠正的开发判断 | 依据与处理 |
| --- | --- |
| 模型知道规则就能保证交付 | 核对实际执行和当前产物，不以复述或自检声明作通过证据 |
| 核验拒绝说明核验设计有错 | 先审查拒绝是否有据；正确拒绝可能暴露生成、引用或取证缺口 |
| 整例仍失败说明局部机制无效 | 保留达到原判据的局部成果，独立定位后续失败 |
| 已有机制就必须继续补丁 | 候选被实际反例否定时停止该方向，复审责任与输入；不追加同义提示 |
| 面试官提出另一种方案就要改架构 | 比较用户结果、事实归属和已执行证据，合理设计保持，真实缺口进入唯一设计 |

这种方法同时允许保持、修文、补适用证据和修复具体缺口。已确定用例通过就关闭对应问题，不临时追加泛化或稳定性要求；正式入口的整体交付仍按原用户结果验收。

## 3. 引用协议要求模型重复维护正文

**正文定位、引用合法和证据支持是三种判断，重复转录会让它们相互阻塞。** 历史协议让模型同次生成完整回答与逐字草稿引句，模型曾把来源原文填进定位字段，多次任务在语义核验前失败。增加预算不能解除这个交接责任。

现行正文只生成一次，以段落或版本化片段关联引用，Runtime 恢复原文并校验实际可见坐标。研究新增引用的合法范围由当前选择约束；模型继续判断哪些原文适合支持断言。当前契约由 [ADR 0023](../adr/0023-native-answer-segments-and-visible-citations.md)、[ADR 0024](../adr/0024-plain-source-tools-and-inline-citations.md)与[研究阶段契约](../adr/0032-conversation-research-claims.md)拥有。

| 历史候选 | 已取得结论 |
| --- | --- |
| 将引用 ID 与原文相邻，或清空旧引用 | 两种布局仍出现非法引用，没有证明布局或全盘清空更可靠 |
| 指出非法 ID 并强化自检 | 有单次修正，也有新造坏值；定点消错不等于完整输出合法 |
| 固定原文范围后由代码绑定 | 来源可保真恢复，模型仍会产生无据结论，核验也有误拒；自动绑定不证明语义正确 |
| 统一搜索、读取与引用坐标 | 历史八稿引用都可还原，但整例未交付；交接改善与研究质量分别计证 |

这些失败和决定性证据由[对象错位记录](../optimization/answer-object-mismatch.md)与[坐标统一记录](../optimization/evidence-acquisition.md#103-正文行坐标统一与预编号引用联动)拥有。保留正确的坐标校验与反馈恢复，不将自由生成引用字段视为供应商原生位置保证，也不把引用可定位当成结论有据。

## 4. 把可修订进度误当成不可变执行事实

模型认为步骤完成，不代表答案已交付，更不代表这个判断不能被新证据推翻。工程曾同时规定
“全部完成后禁止工具”“完成项不可修改”“重开工作需新计划”，把一次判断失误变成恢复负担。
只解释字段或提醒提交 Final，不能解除这些联动约束。

已成立的经验是：应整体核对进度修订、工具准入、跨轮资料恢复和最终验收各自消费什么事实。
实际动作保持历史记录，进度可以重开，是否交付以已接纳的最终答案为准；不会因此增加第二个循环。
局部组合验证与完整研究结果须分开报告，详细记录与限制见
[优化记录 §108](../optimization/revision-feedback-loop.md#108-plan-生命周期整体修正)，当前机制见
[运行外壳 §2](03-capability-axes.md#2-按需工作清单提升复杂任务的跨轮完成能力)。

另一次真实运行暴露了内容层面的冲突：Plan 自称已读完全文，运行系统推导的覆盖仍明显不足。
计划状态可修订并不自动解决这一点。模型生成的计划依据不能代替执行事实；问题分析还要检查它
被放在什么消息位置、是否与权威反馈冲突。现有证据只确认并存，尚未证明移除计划自述能修好
决策；见[计划输入观察](../optimization/revision-feedback-loop.md#后续观察计划自述与读取事实冲突)。

## 5. 把减少文本当成保留有效正文

**正文提取先保护条件、代码和表格，再讨论输入成本。** 导航可能命中主题词，通用提取也可能删掉真正条款。历史候选使用页面声明的唯一主区域并保持内部顺序，还修复了 `noscript` 祖先语义丢失的问题；后续 Verifier 无法恢复已经丢掉的来源。

修正版的原文消费成立，研究仍有预算和成文失败。结论限定为提取保真与正式消费，原依据见[正文提取第 110 节](../optimization/source-extraction.md#110-唯一主区域选择的保真与正式消费验证)。格式错误也须核对实际原始响应，不能凭一次摘要就改解析器；诊断见[协议边界第 112 节](../optimization/action-final-protocol.md#112-final-原始响应与结构修复输入审计)。

查询参数与来源条款也有不同用途。仅凭相同零结果去重会丢掉本轮实际搜索条件；现行执行方返回真实参数，Context 单向投影，同一 Journal 的引用保真由[查询交接完成记录](../optimization/completed/query-execution-handoff.md)拥有。准确交接不能证明搜索策略合适，也不能替代生成稿的来源支持验收。

## 6. 整体仍有错误，不等于已验证的多轮修订无效

同一稿件有多个错误时，Verifier 可以先发现一个，Conversation 修订后再核验新稿，继续发现另一个。受控真实模型轨迹已经走通这个过程，已有生产循环保留，不需要额外要求一次列出全部错误。

开发中的误区是将后续独立失败重新归入已解决问题，导致不断重验旧能力。正确做法是按问题固化收益、条件与失败尝试摘要；确认不是该方案引入的问题另行登记。文档压缩删除过程流水，保留决定性证据，不能删除失败事实或把局部能力升级为完整任务成功。

这一经验的唯一详细结论见[多错误修订完成文档](../optimization/completed/multi-error-verification-revision.md)，整理准则见[固化规则](../optimization/README.md#已解决问题的固化规则)。

## 7. 让模型识别问题，让代码关联原文

核验器已经识别错误，却因为复述原句时少了反引号，被运行系统丢弃整份报告。这里缺失的是可靠的定位交接：既然调用已经限定当前段落，就无需再让模型抄一份原文证明位置。模型描述支持缺口，代码带回本次实际输入，减少一个容易失败的输出要求。

历史回放和正式观察支持这一局部收益；反馈完整不代表意见正确，更不代表修订收敛。原正式运行中断后完整临时日志未封存，也说明停止前必须先保存需要的证据，不能把尚未完成的复制当成成功。证据范围及限制见[核验绑定固化记录](../optimization/completed/verifier-finding-binding.md)，本文不维护第二份验收状态。


2026-10-02 同类责任错误又出现在最终验收项：模型漏句号或同义改写，导致五份正常报告全部被字符串身份检查拒绝。当前改为本次 criterion_id、Runtime 恢复原文，固定历史绑定 5/5、真实局部 3/3，正式一次回执到达同稿 Completion；完整研究语义仍由原验收判断。机制与经验由[验收项引用恢复](../optimization/completed/final-criterion-transcription.md)拥有，通用约束由 [COD 文本引用规则](../devSpec/code-structure.md#21-已有文字通过引用传递)拥有。

## 8. 要求保留引用之前，先交回完整基稿

提示模型保留旧引用，前提是下一轮真的拿到了原稿与引用关系。此前反馈只有正文和意见，丢失了逐段映射；在原日志保存完整提交并投影最新版本后，这个交接问题才有明确责任主体。局部修改由模型选择内容，代码保留未修改部分，合成后的完整稿仍须接受核验。

可复用的经验是把信息交接、机械保留、模型选择和用户交付分开验收。完整重写仍可能漏引，相同段落也不能证明模型采用了补丁；没有保存原始提交种类就应承认证据缺口。详细结论及边界见[完整基稿交接固化记录](../optimization/completed/complete-rejected-draft-handoff.md)，不把局部收益讲成完整研究已经成功。

## 9. 协议拒绝要能回到正确的恢复责任主体

同一次拒绝可能既阻止错误执行，又意外绕过已有恢复。检查动作目录应由 Application 使用当前声明统一拒绝并反馈；Adapter 负责 wire 结构，遇非法 JSON 时由模型在一次限额内重新生成，代码不猜参数。验证时分别检查坏批次零执行、反馈被下一轮消费、连续错误失败关闭与用量保留；其中一层通过不能代替完整用户结果。限定证据与生产接入见[动作协议恢复](../optimization/completed/conversation-action-protocol-recovery.md)。

## 10. 局部修订应继承已有绑定关系

正文片段只改一处时，Runtime 已保留整条 claim 的引用，准入却要求模型在本轮重新选齐全部引用。两个合法 ID 动作因此被拒，精确指出漏项后仍失败。修复将已有绑定与新增依据分开：已有引用从实际来源恢复，新增引用由模型选择，完整新版继续核验。

经验是沿动作的实际读写边界检查契约：保留字段的操作应继承其合法绑定，输入也应交回这些绑定对应的原文。原失败回放和正式模型动作共同验证这一交接；具体结论见[引用继承固化记录](../optimization/completed/claim-retained-references.md)。


### 正文修订与证据绑定保持一个版本

新事实已经读回并选中，旧协议却要求先改正文再改引用，使中间版本再次缺证。现在由模型同次明确提交新增引用，Runtime 校验并保留旧依据，整条新版继续交给语义核验。工程交接成立与语义正确分别计分；正式用户任务另有缺项时，仍能固化已经成立的责任边界。方案及证据见[原子修订完成记录](../optimization/completed/claim-atomic-evidence-revision.md)。

## 11. 按判断输入决定结果失效

修改集合中的其他项，不应让相同来源输入的已完成判断失效。先由 binder 恢复当前原文，再按正文、引用、来源身份和判据版本判断适用性；最新拒绝与通过同样保留，已修改项重新核验全部事实。判断事实继续由原 Journal 拥有，代码只决定适用范围。

反事实应消费同一真实轨迹的实际报告，只移除复用决定；两条随机模型轨迹的用量差异不能替代这种责任证据。具体机制及重新打开条件见[来源报告复用固化记录](../optimization/completed/claim-source-review-reuse.md)。


## 12. 评分预算应覆盖实际思考模式

评分正文很短，也需要为实际启用的思考预留输出额度。短预算下原六次请求都没有正文；扩大同一个真实请求的额度后，一次形成合法判决，实际只消耗所用 token。模型参数、评分规则和原始结果身份分别保持，避免把预算恢复变成放宽评分。

合法评分仍须审查参考覆盖和用户要求映射。原预算问题的唯一机制及证据见[评分输出预算固化记录](../optimization/completed/research-grader-output-budget.md)。

## 13. 评分器与控制标签都要受审查

评分理由不能把参考中的全部事实变成用户清单，也不能用评分者掌握的全文反推作者读过全文。缺项须说明为什么阻止用户获得所需结果，实际错误须定位答案断言与相应原文，参考缺页独立报告。模型选择引用，Runtime 恢复原文，代码聚合有效分类。

控制也可能写错：仅删除专门条款，若总结还保留同一职责，就没有形成干净反事实；只允许某种预定拒绝理由，也会把新发现的真实错误判成评分失败。原失败保留，先审查目标和控制，再独立预声明新身份；已完成报告以校验和复用，不重复采样寻找成功。具体机制、样本与成本由[评分资格固化记录](../optimization/completed/research-grader-qualification.md)拥有。

实际引用的页面或规范版本缺少时，先补齐独立来源并用明确正反控制校准，不能把单次缺项理由直接当成生产修复标签。2026-10-08 补齐参考后，原“协作未知必然导致未交付”的判断未获确认，相关覆盖候选保持隔离并撤回；旧产品失败和新文本重评分分别保存。评分依据修复、标签复核与生产收益各自需要证据，详见[精确引用资格](../optimization/completed/research-grader-qualification.md#实际引用页面与版本的参考资格)。


## 14. 核验优化不能代替研究能力优化

**研究与反馈的共同目标是减少首次产物中的错误、使准确反馈促成有效修订，并在预算内交付原用户结果。** 研究模型负责取证、选证、成文和语义修订，Verifier 检查实际产物并指出支持或覆盖缺口，Runtime 负责反馈、原文和版本的可靠交接。当前已有先选证再写作、引用继承与原子修订，但这些改动不能单独证明初稿质量或完整交付已经改善。

### 14.1 反馈必须改变研究决策并接受结果验收

当前来源拒稿绑定具体论断与原始版本；Runtime 从该次输入恢复反馈涉及的原文，交给下一轮选证与写作。模型据此选择补读、改引用、收窄论断、保留有据内容或表达实际未知；新版继续接受来源支持与事实覆盖检查，再进入汇总、最终核验和 Completion。反馈描述是待核对的判断，不是新增来源事实，也不自动成为下一轮必须照抄的答案。

```text
当前用户目标 + 已返回原文
  -> 研究模型取证、选证与成文
  -> 核验当前产物，反馈具体缺口
  -> 同版稿件、反馈与相关原文进入下一次研究决策
  -> 实际修订形成新版并重新核验
  -> 汇总、最终核验与同稿交付
```

这条链分别需要证据证明反馈实际送达、选证或取证发生变化、正文与引用完成修订、被指出的缺口解除，以及原用户任务交付。模型复述了意见、调用了更多工具或再次被拒，都不能替代实际产物改善。反馈在当前任务中用于纠偏；持续改善还需要把真实错误用于研究侧设计和评测，循环存在本身不代表之后的首次研究会更好。

历史真实模型回放中，strict 条件与参数／执行结果对象错误曾被逐轮发现并修复，支持[渐进修订能力](../optimization/completed/multi-error-verification-revision.md)。另一条汇总修订把部分列举写成完整清单，说明后续表达也能改变已研究事实的范围，见[实际枚举反例](../optimization/claim-revision-nonconvergence.md#2026-10-02-汇总将部分列举改为完整枚举)。保留已有验收和交接的限定成果，同时检查修订质量；这些证据没有证明独立核验整体优于加强研究自查。

### 14.2 现有研究侧不足有可定位证据

| 真实失败或观察 | 应审查的研究责任 | 证据边界 |
| --- | --- | --- |
| 授权建议进入稿件时，说明章节性质的相邻限定未进入来源请求 | 判断结论需要哪些前提，决定必要补读并选择完整适用语境 | 输入缺失已确认；原句不等于明确 MUST，不能制造强度冲突标签。见[规范性取证记录](../optimization/completed/source-proof-boundary-isolation.md#问题与机制) |
| 相关条款已在同次读取资料中，四条断言却未提交对应依据；修订还删除了有据内容 | 证据适合性、引用选择及修订时的事实保留 | 7 条当轮拒绝均有据，最早责任在生成侧；见[第 120 节审计](../optimization/evidence-acquisition.md#120-生成侧越界的最早责任边界归因) |
| 反馈指出“原文未把配置主体指定为应用”，下一修订却扩大成“原文未指定配置主体” | 区分缺少特定角色映射与不存在任何主体，按原文支持范围修订 | 历史首次修订错误与后续收窄分别保留；当前实际链已修订对应稿，不声称该错误持续未修。见[支持范围修订](../optimization/to_verify/claim-supported-scope-repair.md) |
| 新资料返回后，旧缺项句与总结仍保留，后置来源核验再次发现冲突 | 将新证据用于受影响论断及相关总结，而非只修改当前被点名句 | 2026-10-11 实际续接确认该状态；后续反馈消费已修复这一稿，不据历史反例声称现行普遍未修。见[真实消费记录](../optimization/completed/source-proof-boundary-isolation.md#生产接入与真实消费) |

历史反馈精确性对照补充了“哪条断言缺哪类条款”，但更精确的反馈没有带来更好的条款提交。该探索性对照样本很小、输入重建有已记录限制，只能说明当轮结果不支持“增加反馈线索即可修好”的假设，不能外推稳定收益或失败。原结果见[实际对照](../optimization/evidence-acquisition.md#反馈精确性对照的实际结果)。应回到取证、选证、写作和修订的具体决策，而非继续叠加同义提示。

正文与引用分两次提交的旧协议缺口已经[独立关闭](../optimization/completed/claim-atomic-evidence-revision.md)。它证明新依据能与正文进入同一新版；修订是否语义正确、是否保留其他必要事实以及用户是否收到完整结果，继续分别判断。

### 14.3 按真实失败选择最早修复边界

**已经核实正确的拒稿，应优先闭环研究侧的具体缺口；反馈本身有误判时先修判据，交接失守时修 Runtime。** 修改对象由同轨迹实际输入、决定和产物确定，不能从拒稿次数、改动数量或终态失败推导。

| 实际失败 | 优先处理的责任 | 应核对的变化 |
| --- | --- | --- |
| 必要标题、条件或例外尚未取得 | 研究侧取证 | 是否判断出所需上下文并取得必要原文，而非无目标扩源 |
| 原文已取得，但未阅读必要范围或未提交合适引用 | 研究侧选证与写作 | 论断是否与实际引用对齐，已有条款是否被正确使用 |
| 正确反馈和相关原文已送达，修订却扩大否定或丢失有据内容 | 研究侧语义修订 | 被指出的缺口是否解除，是否引入新错误或遗漏原用户要求 |
| 反馈误解原稿、漏放错误或误拒合法结果 | 核验输入与判据 | 判断和解释是否忠实于同一稿件、证据与实际支持范围 |
| 反馈指向旧稿，引用丢失或新版合并错误 | Runtime 版本与交接协议 | 当前对象绑定、原文恢复、机械保留和失败边界是否正确 |

近期真实反馈也出现过将含混的“实践建议”确定解释成“非规范性”的问题，见[同请求输出差异诊断](../optimization/completed/source-proof-boundary-isolation.md#失败尝试与取舍)。这种意见不能直接作为研究者应修正的事实。核验模型的分类、解释与原文仍需核对；取证与原稿已经足够时，不能为了迎合错误反馈编造新来源结论。

另一个边界是“看到了材料”与“为本条结论提交了依据”。正式 P1 中返回目录有客户端 SHOULD 引导句，本条引用却没有；Source 混看两者后漏放。职责内证明集合隔离保留完整真实材料，已有来源字段说明区分快照与网页正文；最终报告失真则消费已形成的真实报告作一次核对。机制、七项真实用例与成本由[固化记录](../optimization/completed/source-proof-boundary-isolation.md)拥有，实际修订和正式用户结果分别验收。

### 14.4 把修订暴露的错误前移到首次研究

**研究优化还要检查没有这条拒稿之前，研究者能否主动取得前提、选择合适证据并形成有据初稿。** 如果每次都依赖核验提醒后才补标题和适用条件，单次反馈修订成立仍没有证明主动取证改善。同样，已有条款能否在首次选证时进入正确引用、首次成文是否保持条件与义务强度，都是研究侧应解释和验证的具体能力。

推进时先回溯最早错误的实际模型请求，区分原文未送达、可重读但未读取、选证遗漏、语义误解和协议限制。候选只改变已定位的责任边界，用同轨迹完整真实阶段输入比较；依赖上游模型时消费它的实际输出，不能手工补正确反馈或修订稿冒充连续链。然后从原中文正式任务验收用户结果。停止条件和重复阻塞复审沿用 EVD，不增加重试寻找成功，也不为已关闭机制追加泛化门槛。

### 14.5 分别判断初稿、反馈后的修订和完整交付

**拦住更多错误只说明拦截发生，研究能力是否改善要按三个结果判断。** 以下是已有责任对应的比较维度，具体适用判据由各问题预声明，不是本篇新增的一套评测门槛。

| 结果 | 判断依据 | 不能替代它的观察 |
| --- | --- | --- |
| 首次研究产物 | 必要前提是否主动取得，同类条件遗漏、引用错配与无据推断是否减少 | 后续被指出错误并修好 |
| 反馈后的有效修订 | 当前反馈所指缺口是否解除，其他有据事实和用户要求是否保留；新错误独立归因 | 反馈已注入、模型复述意见、发生一次编辑或输出更短 |
| 完整用户交付与成本 | 原目标是否完成；对应轨迹的修订轮次、重复取证、tokens 和耗时 | 局部核验通过、拒稿次数增加、预算扩大 |

若准确反馈反复到达，却不能促成正确修订和预算内交付，研究与反馈的组合设计仍有问题，不能用职责分离解释为已充分。反过来，整体尚未通过不撤销已经达到原判据的交接或局部修订成果；应按最早责任定位剩余失败。

现有方案与准入继续由[设计优化队列](../future/design-optimization-backlog.md)、[选证候选](../optimization/to_verify/claim-evidence-selection.md)、[研究目标覆盖](../optimization/to_verify/research-goal-coverage.md)及[上下文取得与反馈消费](../optimization/completed/source-proof-boundary-isolation.md#生产接入与真实消费)拥有。面试材料不另存待实施方案或新验收门槛。

当前已有局部用例和实际研究消费的限定成果，完整用户结果尚未通过现行 target 验收，详见[评测盘点](../evals/02-current-case-inventory.md)。本节说明如何判断研究与反馈的贡献，不把这些维度写成已经全部达到的能力。

## 15. Agent 常见错误与排障

**Agent 排障要还原每轮实际输入、模型决定、工具执行和下一轮消费，找到最早可观察的错误。** 下面先按故障表现分类，再用已有优化记录说明定位过程。同一任务可以出现多类错误；模型判断、运行时缺陷和服务故障分别归因，不从最终失败反推根因。

### 15.1 先识别九类常见错误

以下分类归纳本工程实际记录及其检查边界，不是全行业故障频率统计，也不表示这些问题均已解决。

1. **任务目标跑偏。** 用户要求完成报告，Agent 最后只返回审阅意见，或把自己的修订工作交回用户。
2. **工具选择或参数错误。** 选错工具、使用当前阶段不允许的动作，或把引用参数放进正文修改工具。Schema 合法和动作符合当前任务分别检查。
3. **取证不足却停止调查。** 只读部分资料就声称读完全文，或把搜索零命中写成资料没有相关内容。
4. **Context 中的信息被混用。** 混淆旧自评与最新拒稿，借用其他材料支持当前引用，或把模型的计划判断当成实际读取事实。
5. **生成的结论超出证据。** 把示例写成普遍规则，把建议写成必须，或为结论附上不支持它的页面。
6. **修订无效或越改越坏。** 表示已经修改，实际缺口仍在；修正一个问题时丢掉此前正确的内容或引用。
7. **核验误判或不稳定。** 错误内容被放行，合法内容被拒绝，或相同完整请求得到相反判决。
8. **循环控制和结束判断错误。** 草稿被拒就结束整个任务，步骤全完成就宣布交付，或同批多个错误提前耗尽修复机会。
9. **反馈或执行结果交接失败。** 有效意见因解析、绑定、裁剪或超时没有进入下一轮；搜索结果没有保留实际查询条件，使后继模型无法区分查过什么。

实际反例入口：目标转移见[反馈消费 §51](../optimization/revision-feedback-loop.md#51-验证输入的读取边界与真实反馈的循环修订)，工具参数混用见[正文工具夹带引用](../optimization/claim-field-tool-mixup.md)，无据推断见[权限责任推断](../optimization/permission-inference.md)，核验波动见[相同输入判决审计](../optimization/claim-verifier-consistency.md)，查询丢失见[查询交接固化记录](../optimization/completed/query-execution-handoff.md)。其余代表案例见下文。

### 15.2 按 Trace 和实际 Context 排障

**先检查用户结果和评测判据，再定位失败轮次，最后核对该轮实际请求及其消费者。** Trace（运行追踪记录）用于串联发生顺序；模型请求与原始响应用于检查当轮实际看到和提交的内容。摘要或普通日志不足以恢复时，明确保留证据缺口。

| 步骤 | 实际检查 | 要回答的问题 |
| --- | --- | --- |
| 固定失败现场 | 用户请求、结果、判据、代码与 Prompt 版本、模型配置、原始产物及校验和 | 判据是否符合用户目标？是否混用不同版本或现场？ |
| 沿 Trace 找最早出错的一轮 | 模型动作、准入、工具执行、返回结果和下一轮决定 | 是模型选错、动作被拒、服务失败，还是正确结果没有被使用？预算耗尽前从哪轮开始无进展？ |
| 还原实际 Context | 最终消息、角色与顺序、工具 Schema、当前稿、反馈、历史记录、证据、裁剪和适配参数 | 必要信息未取得、未送入，还是已送入但被误用？模板与运行时拼接是否表达不同要求？ |
| 对照输出与后继输入 | 原始响应、解析结果、对象绑定、保存内容及下一轮实际请求 | 意见是否已产生？是否在交接时丢失、绑定旧稿，或传入后没有执行？ |
| 验证定位与修复 | 原失败的完整真实阶段输入、待验证差异、实际下游输出和用户结果 | 目标问题是否解除？前轮成果是否保持？局部通过与完整交付分别有什么证据？ |

Context 冲突分析要逐项核对：当前用户目标与历史任务、最新反馈与旧自评、当前稿与旧版本、执行事实与模型计划自述、当前引用与其他已读材料、允许的修订动作与实际状态限制。文本很长或信息同时出现只构成待验证线索，不能直接认定干扰的因果。

例如，[反馈输入审计 §125](../optimization/revision-feedback-loop.md#125-保留自检与最新反馈的输入审计)的实际系统消息含 146,145 个字符、24 个执行投影，末两项分别为最新完整稿和最新拒稿，旧核验回执已经过滤。这排除了该输入中“最新反馈丢失”的解释。重复基稿、旧充分性自评与拒稿并存，以及错误类型称不可恢复却允许修订，仍需分别核对；原记录没有把它们直接认定为唯一原因。

已有同轨迹推理记录时，只摘要核对模型注意了什么、采用了哪些依据，以及问题在哪个阶段被接受、放弃或遗漏。记录不足以解释决定时，可按[输入审计规则](../devSpec/context-memory-retrieval.md#121-利用-think-与中立追问核对决策依据)进行有界中立追问。可见理由与事后解释不能替代真实输出、执行事实或因果验证。

为区分 Context 干扰，可以在真实请求副本上做保留必要前提的裁剪诊断；优化验收仍按完整真实阶段输入执行。涉及前置模型决定时，后继阶段消费其实际输出，不能补入理想反馈或答案。具体边界见 [QLT](../devSpec/quality-security.md#21-核验漏放先验证最小充分上下文)。

### 15.3 用真实案例说明定位过程

以下案例提炼排障动作，完整尝试、机制状态和原始结果仍由链接的优化记录拥有。历史协议和局部观察不自动作为当前产品能力。

#### 15.3.1 只读部分资料，却声称全文已经读完

**对应取证不足和无据生成。** 原任务作出文档缺项结论，需要先区分必要条款没有读取，还是成功读取后在成文输入中丢失。

1. 沿成文前的读取结果检查同一资源，并与最终实际请求对照。
2. 核对 18 份模型输入、42 份 Journal 快照，确认成功读取并集只有第 1 至 60 段；必要的第 65 至 66 段从未进入该链路。
3. 已取得的 60 段完整进入最终输入，排除这次 Final 物化丢失必要条款的解释。
4. 对照相邻决定，发现关键词读取返回空窗口后，没有新增正文，模型却开始声称全文已读。

最早可观察的范围扩大在模型判断中出现，不是代码将空结果写成文档事实。明确续读的独立控制取得缺失条款，只证明工具能读到，不能证明原任务会自主补证，也不能与另一现场拼成产品成功。

原依据见[Action 到 Final 来源追踪 §29](../optimization/evidence-acquisition.md#29-缺失条款的-action-到-final-来源追踪)。该记录还限定了实际 seed 和追踪范围，范围之外没有归档的读取不推定成功。

#### 15.3.2 完整资料目录干扰当前引用核验

**对应 Context 误用和核验漏放。** 某句只绑定两项动作与目的，却概括为客户端的 SHOULD 建议；主体与程度引导句在其他已返回原文中，没有进入本条引用。

1. 还原 Source 请求，分别列出当前论断、已绑定引用和完整返回目录。
2. 确认必要前提在目录中存在，当前引用不足；两种材料回答不同问题。
3. 交叉普通／恢复消息头与目录有无做四格诊断：有目录的两格漏放，移除目录的两格识别。该组支持干扰观察，不证明唯一隐藏原因。
4. 统一核验明确材料用途：当前引用判断本条支持，返回目录检查稿件是否错误声称没有取得资料；再检查真实反馈是否推动选证、写作和目标修订。

2026-10-13 的固定十项真实阶段资格为 10/10，两份实际反馈的目标修订及完整目标 Source 为 2/2。它们分别支持局部核验与实际消费，不替代完整用户结果。曾把范围和引用拆成两次核验的候选已经撤回，不能讲成当前增加了两套检查。

机制、失败取舍及决定性证据见[来源核验的证据边界](../optimization/completed/source-proof-boundary-isolation.md)，其他研究责任见[§14.3](#143-按真实失败选择最早修复边界)。

#### 15.3.3 修正新问题时丢掉前轮有效引用

**对应修订退化。** 连续修订中，一段正文未变，之前补齐且前轮保留的配置依据却从完整新稿消失。

1. 对照上一版完整稿、下一轮实际输入、模型原始新稿和最终保存结果。
2. 确认必要引用 `d1:1697` 与相关原文完整进入下一轮请求，当前反馈对象与版本一致。
3. 在模型原始完整新稿中定位引用丢失；该次没有局部修订，合并器没有覆盖旧引用。
4. 对照剩余引用的实际条款，确认它们不能支持原配置事实，旧缺口确实重新出现。

该次丢失发生在模型完整重写，输入交接和机械合并没有复现失守。原连续保留轨迹为 0/1；模型回应反馈不能代替目标修正，也不能证明前轮成果保持。后续应在实际修订边界分析，不能据此重新宣称已经关闭的交接问题失效。

原依据见[连续修订保留验证 §128](../optimization/revision-feedback-loop.md#128-连续反馈中的修订保留验证)，完整基稿交接的独立机制见[§8](#8-要求保留引用之前先交回完整基稿)。

#### 15.3.4 已识别的核验意见没有进入下一轮

**对应反馈交接失败。** 原始核验响应已指出两项无据声明，后继写作却没有收到这些意见。

1. 先检查模型原始响应，确认发现已经产生，不能归为核验没有识别。
2. 检查解析和对象绑定，发现第二条引句转录少了反引号，旧逐字匹配把整份报告判为无效。
3. 检查后继输入，确认两条意见均未送达；这次没有证据评价写作模型消费该反馈的能力。
4. 改为由调用方关联当前原段落后，分别核对意见保持、下一轮输入和实际修订检查点。

采用机制与有限证据由[§7](#7-让模型识别问题让代码关联原文)和[核验意见绑定固化记录](../optimization/completed/verifier-finding-binding.md)拥有。报告完整、意见正确、实际修订与完整交付分别验收。

#### 15.3.5 模型尚未消费错误反馈，系统就提前停止

**对应循环控制错误。** 同一模型回合提出两个参数错误的读取，系统立即限制结束。

1. 沿 Trace 确认两个拒绝属于同一决策回合。
2. 检查错误反馈后是否有新的模型请求，发现没有消费机会。
3. 对照停止逻辑，确认原计数单位是反馈条数，同批两条被当成两次失败。
4. 按决策回合关联尝试后验证：逐动作错误完整保留，模型获得下一轮机会；跨轮重复无进展仍能停止。

历史恢复确实解除同批误停，但下一轮模型再次提交旧计划，仍未成功补读。误计数修复与后续语义无进展分别记录；增加预算不能替代这次计数修正，也不能证明任务已完成。

原依据见[完整循环计数 §53](../optimization/revision-feedback-loop.md#53-按完整循环修复错误尝试计数并接入已证实改动)。核验报告输出截断与外层工具超时另见[输出额度记录](../optimization/verifier-output-truncation.md)，没有有效报告时不计为语义拒稿。

### 15.4 面试中怎样证明排障能力
