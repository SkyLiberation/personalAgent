# 开发踩坑与优化经验

**这份文档总结开发中出现的具体错误、尝试过的修正和证据支持的收益。** 首项复盘是“把局部没有观察到，写成整份文档没有规定”。后续按问题补充，不按会话追加流水，也不把失败候选写成已落地能力。

本文是面试讲述与经验回顾入口。完整实验由 [optimization 总览](../optimization/conversation-source-support.md)和连续记录拥有，当前机制由专题与 ADR 拥有，产品验收由[评测盘点](../evals/02-current-case-inventory.md)拥有。工具参数协议的独立复盘见[第 08 篇](08-tool-calling-pitfall.md)，此处不重复展开。缺项复盘保留第 85 节正式覆盖收益，并补充第 104 节的分类交接修正；引用交接经验见第 103 节。

## 1. 局部观察被写成全文缺项

**已接入的缺项分类与覆盖门禁，在正式任务中拦住了未读完的全文缺项声明，并推动 Conversation 补读后重新验证。** 按本目录状态，整体来源支持仍属于“已实现，证据不足”：局部机制成立，完整研究任务尚未通过。不能再把覆盖拒绝当成未接入，也不能宣称所有来源错误已解决。

### 1.1 错误是把观察范围扩大成了文档事实

**“当前已读片段不足以确认”与“官方文档未明确说明”有不同的依据要求。** 前者限定本次观察；后者对所指文档作出缺项判断。只读部分片段时，未读内容仍可能提供相关条款。

正式任务的首稿写道：

> 官方文档在此页面未明确说明由哪一方负责权限检查。

当时同一来源实际只读了 23/121 个片段。问题不在于已经证明原文有权限规定，而在于现有读取范围不能支撑这句文档级否定。即使文档已经抓取并保存在本地，也不能将本地可取得的全文等同于已经返回模型的内容。

这类错误还会误导后续流程：Conversation 可能据此停止取证，整稿语义 Verifier 又把否定句当作谨慎措辞而放行。可定位的是范围判断与放行边界；模型的可见解释不能证明隐藏注意力或内部推理的唯一根因。

### 1.2 提供更多提示并没有稳定地变成约束

**此前多轮尝试改善了读取与局部识别，但没有保证最终答案保持观察范围。** 需要分别记录“信息给到了”“模型能解释”“实际继续读了”和“最终结论有依据”，不能相互替代。

| 尝试 | 观察到的效果与失败 | 留下的经验 |
| --- | --- | --- |
| 提供读取摘要和续读信息 | 早期输入中模型能识别未读区间；第 67 节把摘要迁移到 Verifier 后，十二次对照仍未修正完整稿的覆盖误判 | 保留工具事实，不能用模型复述未读数量证明交付会被约束 |
| 加入未读完禁止全文否定的规则 | 第 69 节独立标准仍被错误判为满足；第 78 节生成禁令有局部收益，后续修订仍出现反例 | 禁令可以表达要求，但不负责强制执行已知不变量 |
| 输出缺项列表，再由代码检查读取标志 | 第 81 节两份完整稿均漏列目标；第 82 节强调最高优先级后命中一份，另一份仍遗漏 | 代码比较正确的前提是分类命中；不能把门禁单测通过当作完整机制有效 |
| 将缺项识别与是否有据分开调用 | 第 83 节两份主稿均识别目标，其中一次代码拒绝改变了整稿语义审查全通过的方向 | 分类器先识别作者说了什么，避免因自认为有据而漏列需要检查的声明 |

以上样本来自不同阶段，不能直接拼成统一正确率。原始条件与失败均保留在[第 67 节](../optimization/document-absence.md#67-将已验证的读取摘要迁移到-verifier-并核对读取返回契约)、[第 69 节](../optimization/document-absence.md#69-将观察范围作为独立标准并验证完整读取边界)及[缺项问题的完整记录](../optimization/document-absence.md)；其中动作协议反例的完整条件见[第 79 至 80 节](../optimization/action-final-protocol.md#79-生成禁令在动作与真实拒稿修订循环中的迁移)。

### 1.3 生效的改动是拆分语义识别与确定性拒绝

**模型识别声明含义，代码依据真实读取事实执行覆盖约束，Conversation 负责后续取证和修订。** 三者在现有验证工具与对话循环中协作，没有新增研究智能体或第二套修订循环。

| 责任主体 | 具体职责 | 不由它决定的事情 |
| --- | --- | --- |
| 读取执行与覆盖投影 | 按来源身份和版本，从成功返回的完整窗口去重推导读取范围 | 不接受 Conversation 自报已经读完，不以抓取成功证明全部内容已展示 |
| 缺项分类调用 | 从完整待验稿判断每个来源是否被声称存在文档级缺项，按输入来源顺序输出布尔数组；与整稿语义审查共用模型配置，使用独立 Prompt | 不复制原句与来源身份，不重新搜索原文，不判断是否有据，不代写答案 |
| 代码覆盖门禁 | 校验布尔数组数量并按位置恢复来源；命中且对应 `fully_read=false` 时直接拒绝 | 不判断原文究竟有没有规定，不让 `satisfied` 覆盖拒绝 |
| Conversation | 消费拒绝反馈，自主补读、补证或准确限定结论，再提交修订稿 | 不拥有读取事实，不以自述替代真实执行 |
| 整稿语义 Verifier | 门禁未拒绝时，继续检查任务完成与来源支持 | 不把 `fully_read=true` 当作结论正确的证明 |

核心不变量是：**识别到文档级缺项声明，且对应来源版本未完整读取，就拒绝交付该稿。** 拒绝解释只说明当前覆盖不足，不宣布原文存在或不存在相关规定。只针对该条件拒绝，不能要求所有回答先读完全部来源。

当前机制及范围由 [ADR 0021](../adr/0021-separate-document-absence-from-reading-coverage.md)与[验证专题](../topics/verification-and-completion.md)拥有。实现坐标是[读取覆盖投影](../../src/personal_agent/application/conversation/source_reading.py)、[分类与覆盖契约](../../src/personal_agent/capabilities/contracts/verification.py)和[现有验证工具](../../src/personal_agent/tools/interaction_verifier.py)。

### 1.4 验证证明了拦截和恢复，完整任务仍失败

**正式运行展示了拒绝如何改变后续行为，但没有取得完整研究答案的通过证据。** 第 84 节先在恢复历史状态的集成验证中走通反馈与修订，第 85 节再接入真实读取事实和生产工具，由原自然请求进入正式 HTTP 链路。

有效预算的正式轨迹中，首稿在 23/121 时被拒绝；Conversation 随后补读同一来源至 121/121，再提交新稿，经过整稿语义审查并绑定交付。第 85 节另有 219 项低层检查通过，覆盖窗口去重、身份与版本、截断、空结果、网关拒绝和后续语义审查等边界。这些检查支持确定性行为，不能替代真实用户结果。

原 E2E 仍为失败：后置评测没有产生有效的结构化语义结果；人工复核还确认答案用输入参数约束解释执行结果契约，整稿语义 Verifier 未拦住。局部机制收益与独立语义失败必须分别保留，不能因后者撤回前者，也不能用前者宣布产品完成。详细执行身份、成本与原始失败见[正式评测记录](../evals/02-current-case-inventory.md#覆盖门禁生产迁移的验收边界)，历史取舍见[第 85 节](../optimization/document-absence.md#85-覆盖门禁接入真实读取事实与生产工具)。

### 1.5 面试中需要明确的工程边界

**这次优化的收益是约束一类错误的交付条件，生成模型仍可能写出这类错误。** 讲述时需要保持以下边界：

- 全量读取只指当前保存来源版本的覆盖，不证明抓取完整覆盖网站，也不证明模型理解了所有条款。
- 分类器仍可能遗漏表达或关联错来源。当前覆盖目录面向卸载来源，短文直接展示与长文卸载混合的归属属于待补测边界，不是已有机制失效的证据。
- 读完后仍可能用错对象、接口或要求强度，这些继续由整稿语义审查负责。Verifier 不承担重新遍历全文找答案的职责。
- 已读材料足以支持一个限定结论时，可以正常回答；诚实说明本次证据不足也不等于原用户任务已经完成。

### 1.6 语义职责分开后，还要移除不必要的转录职责

**分类器识别正确，也可能因为复制原句或完整来源身份失败而无法触发门禁。** 第 103 节的正式轨迹出现五次此类绑定错误。原协议把语义判断和精确复制混在一次输出里，不能把这些格式失败解释为分类器没有理解缺项。

第 104 节改为给定有序来源，模型只返回同序布尔判断，运行系统从输入恢复身份。源码参考提供的是“模型选择、代码恢复对象”的分工，而非通用正确性保证。数量和类型可以由代码强制，是否选对来源仍须用真实模型和来源换序控制验证；只缩短字段不能证明语义准确。

十一份真实模型分类控制通过，五份历史复制失败稿恢复交接；原正式任务中五次分类交接有效、四次覆盖拒绝，但最后仍因生成器连续无进展动作而停止。交接成立与修订成功必须分别记证。详细验证范围、实际结果与取舍由[缺项问题第 104 节](../optimization/document-absence.md#104-按来源顺序返回缺项分类)拥有，并反向链接本节。完整读取仍不证明答案有据，反馈进入修订循环也不证明最终完成用户任务。

### 1.7 模型能复述反馈，不等于已经有效修订

**模型在计划里写出“覆盖不足”，仍可能只修改措辞，而没有撤回全文缺项结论。** 第 104 节已有明确中文拒绝；后续审计发现计数字段缺少单位说明，但不能据此断言模型完全不知道未读完，更不能认定这是唯一根因。

第 105 节用运行系统生成的自然语言讲清来源、累计返回行数、总数、剩余量和修订边界，机器判断仍消费 typed facts。确定性检查证实这些说明进入动作与成文请求；真实任务却在触发反馈前因终止计划下继续申请读取而停止，所以没有证明修订收益。经验是分别验收“实际发送了什么”“模型做了什么”和“用户最终得到什么”，不把源码存在或模型复述当成后两者。完整证据及取舍见[第 105 节](../optimization/document-absence.md#105-用自然语言解释未完整读取与修订边界)；规范由 [CTX](../devSpec/context-memory-retrieval.md#11-模型输入优先表达语义机器消费保持结构化)拥有。

## 2. 这次经历如何改变开发方法

**最有价值的经验是把失败拆到责任边界，并让每次已成立的改善进入工程和后续验证基线。** 仅把提示词写得更强，或看到整例失败就重新设计全部流程，都会丢失已经获得的因果证据。

| 开发中容易踩的坑 | 这次采用的做法 |
| --- | --- |
| 把“模型知道规则”当作“运行系统能保证规则” | 分别验证规则识别、真实执行事实、代码拒绝和后续恢复 |
| 把读取状态也交给模型决定 | 由执行事实推导覆盖，让模型只承担声明含义识别 |
| 为了修复假阴性，不断追加最高优先级提示 | 在实际反例中拆分分类与支持判断，保留正例与误拒控制 |
| Verifier 拒稿后顺手代写结论 | 反馈只定位原句与证据边界，Conversation 自主决定如何补证和修订 |
| 把一次正确拒稿当成整答可靠 | 分开记录局部检查点、原 E2E 结果与独立的语义残留 |
| 整例仍失败就撤回全部修复 | 保留已证明的读取、覆盖拒绝与修订机制，只继续定位实际残余错误 |

后续新增复盘应继续按“错误、机制、收益、证据、边界”组织，并链接相应优化记录；未经验证的 Prompt 候选不写成开发成果。


## 3. 引用协议要求模型重复维护正文

**引用可定位与证据能支持结论是两件事；二者应由不同边界验证。** 第 94 节要求同次生成完整回答及逐字草稿引句，模型却把来源原文填入定位字段。扩大预算后仍有一段无法匹配，三次正式任务都没进入 Verifier。这说明当轮交接协议不可靠，不能据此说 Verifier 的语义判断失效。

后续候选让正文只生成一次，每段附全部引用；代码提供可选择的来源目录并恢复原文。取证、成文与补引用由 Conversation 负责，Verifier 只检查提交的正文与依据。引用目录还要保留原本合法的整窗口和逐行范围，不能为了定位方便增加没有用户依据的限制。

第 95 节最新五份成文交接合法，但其中仍有把充分条件反推成必要条件的回答。一次局部核验明确拦住该错误，因此交接改善与语义拦截应分别计证。正式五稿仍有三次引用非法，两次止于前置核验；长跑约 68 分钟后主动停止，未交付结果。教训是合法目录不能代替输出值校验与有效恢复，同一引用错误反复出现时应及时收束验证边界，不能将这些控制写成产品已修复。完整失败、成本与最终取舍见[对象错位记录第 95 节](../optimization/answer-object-mismatch.md#95-原生正文分段与引用交接验证)，候选责任边界见 [ADR 0023](../adr/0023-native-answer-segments-and-visible-citations.md)。


后续还单独比较过引用 ID 与原文分列或相邻。真实稿两种布局均有一次修正、一次沿用错误 ID，短控制均通过；没有证明相邻布局更稳定，因此未将“结构尽量简单”写成强制 contract 准则。需要减少的是已经证实会出错的配对或重复维护责任，结构看起来更扁平本身不是收益证据。两次引用修正还同步了正文中的显示标记，业务文字未变；原逐字失败保留，避免把显示一致性修正误称为业务退化。完整对照及证据限制见[第 96 节](../optimization/answer-object-mismatch.md#96-引用标识与原文相邻表达的离线对照)。


随后清空旧引用再对照，两组仍各有一次非法引用，清空组还新造目录外的行 ID。因此“旧稿复制错误”不是充分解释，也没有依据把全盘清空引用写成规范。可选位置是否存在由代码准确拒绝，模型还必须完成拒绝后的合法重提；生成合规、确定性拦截与恢复成功要分别验证。这次未改变生产契约，详细反例与控制见[第 97 节](../optimization/answer-object-mismatch.md#97-旧稿引用线索的移除对照)。


第 98 节进一步把实际拒绝交给生产 Final 成文：泛化反馈两次都未修好，明确指出非法 ID 时一次修好、一次仍错。已有精确反馈应保留，但一次成功不能写成稳定恢复；阶段内能修正，也不能替代完整提交和动作至 Final 的验证。另一个短控制出现补写周一时间却未附引用，提醒我们把“位置合法”“依据齐全”“结论受支持”分别检查。完整比较和未覆盖边界见[第 98 节](../optimization/answer-object-mismatch.md#98-引用拒绝反馈的生产成文边界重放)。


补看已有 think 后还发现：失败响应停留在一般规则复述，成功响应虽核对了具体坏值，却又过度概括为所有逐行引用都不可用。其最终引用合法，仍不足以证明正确理解整个契约。模型自述适合提出待验证假设，必须再与真实目录、输出和正反例核对；详见[第 98 节补充审计](../optimization/answer-object-mismatch.md#补充可见决策说明与输出的一致性)。


第 99 节把规则重组为完整 ID 成员资格、合法逐行边界和拒绝后必须实际修正，再做三次新调用。两份历史稿都移除原错值，但一份新造另一非法 ID，整体合法率仍为 1/2。因此定点消错不等于完整输出合规，Prompt 说得更具体也不能替代确定性检查；该候选未替换生产 Prompt。完整结果见[第 99 节](../optimization/answer-object-mismatch.md#99-引用输出限制的-prompt-候选)。


第 100 节进一步跑过实际反馈提交、动作选择与再次成文。旧 Prompt 有一条合法恢复；新候选修掉原坏值，却制造两个新坏值。运行系统随后按现有“两个回合同类失败”策略停止，新的拒绝没有再进入模型。这说明生成合规和恢复机会是两层问题：加强自检提示不能强制合法；反馈确实生成，也不代表后续一定有修订回合。该停止符合现有 ADR，是否调整要单独验证有界恢复，不能把改变错误自动认定为进展。完整结果和反事实见[第 100 节](../optimization/answer-object-mismatch.md#100-全量引用重查与反馈循环恢复)；本轮没有替换生产 Prompt 或宣布来源支持已解决。


进一步复核发现，“模型从合法目录选择”仍可能只是自然语言要求：本项目的 ID 字段是自由字符串，生成后才能检查。供应商原生引用接口的有效位置保障，不能通过仿写返回字段自动获得。后续设计应先证明引用身份转录责任已被移除，同时保留模型对证据支持的判断；把问题转移到另一个自由选 ID 的阶段并不构成修复。条件方向见[第 100 节职责复核](../optimization/answer-object-mismatch.md#补充重审自由生成引用的职责)。[第 101 节](../optimization/answer-object-mismatch.md#101-固定证据范围内成文与系统绑定的对照)随后完成两组固定范围成文及核验：调用端可以原样保留来源，生成器仍会写出无据结论，Verifier 也会因没有列全格式而误拒已有直接依据的“可以”陈述。教训是输入来源关联、逐句支持与内容覆盖是三个不同判断；自动绑定不能把检索输入变成已核实引用。该轮没有证明自主证据范围形成，未接入生产。


第 103 节进一步把搜索、读取和引用作为同一个表示问题审视：原存储按字符切 JSON 片段，工具用记录行号，引用又要求观察序号和行号，模型需要跨多套坐标理解。参考源码后的试接入保存原正文，让搜索和读取共用自然行，引用编号直接附在证据旁；仍保留生成后校验。过程中还复现 Windows 自动换行转换，改用字节读写保留原文。确定性接口通过不等于模型语义通过，完整结果和限制由[第 103 节](../optimization/evidence-acquisition.md#103-正文行坐标统一与预编号引用联动)拥有，当前责任边界见 [ADR 0024](../adr/0024-plain-source-tools-and-inline-citations.md)。

同轮正式轨迹的八稿都能还原引用，原文窗口也保持一致，但任务最终仍未交付。收益在于消除了本条轨迹里的答案引用绑定阻塞，不是保证结论正确；生成器仍把零命中扩大成全文缺项，缺项分类又多次卡在逐字引句或来源版本校验。经验是对不同责任边界分别验收：简化模型需要转录的结构可以解决交接问题，不能顺带宣称语义判断或反馈修订已完成。Plan 中的错误判断及不可改写反馈也已保留为线索，尚未完成因果验证。
