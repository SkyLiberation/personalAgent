# 文档模块规范（DOC）

> 适用于 `docs/**`，继承根 [AGENTS.md](../AGENTS.md)。修改前阅读本文、[文档索引](README.md)、[中文写作规范](chinese-writing-spec.md)和目标文档；涉及 Future、优化记录或评测说明时，另读对应目录规则。

## 1. 文档是受治理的工程资源

文档解释行为、责任、使用方式和证据边界，不能替代运行证据。新增前查索引确认正文归属，能更新原文时不建立第二份权威说明；其他文档只保留读者所需摘要和链接。

业务语义、契约、配置、部署或正式路径变化时，同一变更更新权威文档。纯文档修正定位代码、配置、既有执行证据或外部规范；无法核实的内容标待核实。规范整理可依据可定位的重复、冲突、过期条款，不为文字清理制造产品测试。

设计与优化项的文档先行和验收顺序由 [EVD 流程](devSpec/change-evidence.md#7-强制开发与设计流程)拥有。每轮方案、实现或证据改变机制、契约、范围或状态时，必须在同一轮修订对应设计文档及受影响权威正文，区分假设、已实现和已验证范围，并同步索引与引用。直接删除或改写过期、冗余及冲突正文，不能仅追加纠偏段落，也不能等到任务完成或发布时补写；原始证据按原身份保留。

## 2. 中文写作与结构门禁

修改段落遵守[中文写作规范](chinese-writing-spec.md)。设计正文按[设计文档写法](chinese-writing-spec.md#61-设计文档写法)说明解决机制与具体防护。先清理过期、重复和无来源内容，再按读者任务组织。术语、路径或标题变化时搜索全部引用并同步，不在文末追加纠偏掩盖冲突正文。

可读性放在首位：先说明问题或判断，再按职责和信息流解释机制、交接与验收，使读者能定位需要修改的唯一正文。设计涉及代码模块时，按 [COD 模块化](devSpec/code-structure.md#32-功能模块化与开发上下文)说明局部任务的阅读入口、契约和直接协作者；索引与摘要只提供必要导航，避免复制正文扩大开发上下文。

## 3. 事实强度与文档生命周期

正文落点由[目录分工](README.md#目录分工)确定：当前事实、历史诊断、候选、评测证据分开保存；当前说明不得把历史意图写成已交付能力。

- Future 准入、状态收敛与退出由 [Future 规则](future/README.md)拥有。
- 优化记录、候选保留、失效清理和已解决问题固化由[优化规则](optimization/README.md)拥有；不在入口重复流程。
- ADR 结构由[中文写作规范](chinese-writing-spec.md#6-各类文档的附加要求)拥有；评测说明引用 [QLT 分类](devSpec/quality-security.md#1-测试职责与覆盖)和 [EVM 归档](../evals/AGENTS.md#5-比较身份与归档)，不维护第二份发布清单。
- 移动或重命名正文须更新索引及全部引用，删除旧正文；支撑有效结论的原始证据仍按归档规则保留。

## 4. 主文档与模块规范维护

正文归属和路由同步执行[开发细则维护规则](devSpec/README.md#4-维护规则)。修改规范是本任务的文档工作；受影响实现须采用修订后的唯一规则，不保留冲突双轨。

根 `AGENTS.md` 与 `CLAUDE.md` 逐字一致，各自少于 32 KiB 且不超过 200 行；根入口加各模块入口的组合少于 32 KiB。这是工程的保守尺寸门禁，不是 Codex 不可配置的限制，也不代表所有手动读取的细则都应挤入同一入口。

## 5. 提交前检查

- 核对修改段落的事实坐标、中文表达、唯一正文归属和生命周期。
- 涉及设计或优化项时，核对实现前的设计文档、可执行验收计划与依据，以及本轮事实变化后的正文同步；未验证内容不得写成通过。
- 检查本次范围内本地链接、标题锚点、代码块和表格；涉及 Mermaid 时检查语法和含义。
- 路由或入口变动时运行[规范检查](devSpec/README.md#5-识别评测边界)，报告样本分子、分母和误判；固定关键词样本不代表模型理解全部规则。
- 如实报告检查范围与限制。只涉及文档时不运行产品 E2E、真实模型或停用的单元测试。
