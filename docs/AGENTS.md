# 文档模块规范（DOC）

> 本文件适用于 `docs/**`，继承根 [AGENTS.md](../AGENTS.md)。修改前必须完整阅读本文、[文档索引](README.md)、[中文写作规范](chinese-writing-spec.md)和目标文档；修改 `docs/future/**` 还须读取[Future 规则](future/README.md)。其他任务域按根路由加载。

## 1. 文档是受治理的工程资源

代码拥有可执行行为；权威文档解释行为边界、责任主体、使用方式和证据限制，两者必须指向同一设计。文档不能替代运行证据，代码存在也不能替代必要的设计说明。

- 新增文档前，按[目录与主题索引](README.md)确认已有正文归属；能够修改原文时不得创建第二份说明。
- 其他文档只能保存面向特定读者的摘要与链接，不复制容易漂移的状态表、流程、配置或证据结论。
- 业务语义、事实归属、公开契约、状态迁移、配置、部署或正式路径变化时，同步更新权威文档；没有文档影响时，也须在变更说明中明确判断。
- 纯文档修正必须给出代码、配置、测试、执行归档或外部规范坐标；无法核实时标为待核实，不把设计意图写成当前能力。

## 2. 中文写作与结构门禁

中文表达、术语、证据措辞和排版统一遵守[中文写作规范](chinese-writing-spec.md)，新文档和本次修改的段落立即适用。

先删除过期、重复和无来源内容，再按读者任务重组。公共术语、路径或标题改变后，须搜索旧表述并以可重复命令检查引用；不得在文末追加修正段落掩盖冲突正文。

## 3. 事实强度与文档生命周期

当前事实、历史诊断、未来候选和评测证据按[目录分工](README.md#目录分工)分别保存。当前状态文档只保留目标代码状态下仍成立的事实。

- 验证优化过程与经验按 [optimization 记录规则](optimization/README.md)集中维护；已解决问题按[固化规则](optimization/README.md#已解决问题的固化规则)迁入 `completed/`，删除中间过程正文，保留最小可复核证据归档；已否决候选不得继续列为活动设计。Future 的状态、正文缩减与退出由[Future 规则](future/README.md)唯一拥有，状态改变时在同一变更清理。
- ADR 按[中文写作规范](chinese-writing-spec.md#6-各类文档的附加要求)组织；评测文档按[证据分类](../evals/AGENTS.md#1-证据分类不能混用)区分产品失败 baseline、指标 baseline、回归 E2E 和 supporting evidence。
- 移动、重命名或迁移正文时，更新文档索引与全部引用方，搜索旧路径并删除旧正文或入口，不保留“最新版本”式双轨。

## 4. 主文档与模块规范维护

规范分层、正文归属和路由同步由[开发细则索引](devSpec/README.md#4-维护规则)统一规定，模块规范不得放宽根门禁。

根 `AGENTS.md` 与 `CLAUDE.md` 必须逐字一致，各自少于 32 KiB 且不超过 200 行；根入口与各模块入口的组合也须少于 32 KiB。验证命令与识别边界见[规范检查](devSpec/README.md#5-识别评测边界)。

## 5. 提交前检查

文档交付必须通过以下检查，并如实报告范围与结果：

- 按中文规范检查本次修改段落的表达、术语、证据措辞和排版。
- 核对正文归属、事实坐标、生命周期及适用的 Future 清理；没有重复、冲突、孤立或过期文档。
- 检查本地链接、标题锚点、代码块、表格与 Mermaid。
- 规范入口或路由变动时，按开发细则索引检查主入口同步、规范覆盖和识别样本；不能把固定样本通过外推为模型理解全部规则。
