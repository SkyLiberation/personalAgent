# 文档模块规范（DOC）

> 适用于 `docs/**`，补充根 [AGENTS.md](../AGENTS.md)。修改前阅读本文、[文档索引](README.md)、[中文写作规范](chinese-writing-spec.md)和目标文档；涉及 Future、优化记录或评测说明时，再读对应目录规则。

## 1. 文档是受治理的工程资源

文档说明行为、责任、使用方式和证据边界。新增前按索引确认唯一正文，优先更新原文；其他入口只保留必要摘要和链接。文档不能替代运行证据。

行为、契约、配置、部署或正式路径变化时，同轮更新权威正文。讨论或评审中发现设计缺项、需求澄清、方案调整或证据变化，也须先更新唯一设计及受影响的需求、职责、流程、契约、验收、状态与引用，再推进依赖它的工作。直接改写失效内容，不把纠正只留在聊天或文末追加说明。

事实、决定、候选假设、已实现和已验证范围分别表达。依据不足时写清待证问题、影响及下一核实判据；纯文档修正给出代码、配置、证据或规范坐标。设计顺序与准入由 [EVD](devSpec/change-evidence.md#7-强制开发与设计流程)拥有，纯文档整理无需新建独立设计或制造产品失败。

## 2. 中文写作与结构门禁

表达、设计写法与 Spec 结构由[中文写作规范](chinese-writing-spec.md)拥有。按读者任务和信息流组织正文，使读者能定位职责、交接、验收与唯一修改位置；删除过期、重复和无来源内容。术语、路径或标题变化时搜索并同步全部引用。

涉及代码模块时，按 [COD 模块化](devSpec/code-structure.md#32-功能模块化与开发上下文)说明局部阅读入口、契约和直接协作者；索引不复制实现或设计正文。

## 3. 事实强度与文档生命周期

正文落点按[文档目录分工](README.md#目录分工)确定，当前事实、历史诊断、候选与评测证据分别保存。

- `architecture/` 拥有现行全局架构、代码地图和横切装配事实；设计开发约束由开发细则拥有。专题维护详细契约，`summary/` 保留明确身份的历史审计。框架变化按 [ARC](devSpec/architecture-ownership.md#8-架构基线与持续演进)同步。
- Future 的准入状态、收敛与退出由 [Future 规则](future/README.md)拥有。
- 过程记录、候选保留、失效清理与成果固化由[优化规则](optimization/README.md)拥有。
- ADR 结构由[写作规范](chinese-writing-spec.md#6-各类文档的附加要求)拥有；评测分类与归档分别遵守 [QLT](devSpec/quality-security.md#1-测试职责与覆盖)和 [EVM](../evals/AGENTS.md#5-比较身份与归档)，不在文档中重建发布清单。

移动、重命名或删除正文时，同步索引和全部引用，保留支撑有效结论的原始证据及用户改动。已无独立正文、导航或历史证据职责的文件按此规则清理。

## 4. 主文档与模块规范维护

根入口保留全局门禁和任务路由，详细规则进入唯一细则，目录入口只补充局部要求。入口说明适用目录、前置阅读、职责与检查命令，按明确动作和条件组织；维护流程见[开发细则索引](devSpec/README.md#4-维护规则)。

根 `AGENTS.md` 与 `CLAUDE.md` 必须逐字一致，各自少于 32 KiB 且不超过 200 行；每条仓库内根到目标目录的指令链（含文件间分隔）少于 32 KiB。手动读取的细则不计入文件发现链，仍按任务控制阅读范围；客户端加载机制见[官方机制与工程选择](devSpec/README.md#3-codex-官方机制与本工程选择)。

规范整理按纯文档验收；实际产品行为同时变化时，另取对应类别的依据。

## 5. 提交前检查

- 核对事实坐标、中文表达、唯一正文归属与生命周期。
- 设计或优化项核对先行设计、可执行验收与依据，以及本轮状态和引用同步；未验证不能写成通过。
- 检查本次本地链接、标题锚点、代码围栏、表格及适用 Mermaid。
- 规范整理从仓库根运行 `.\.venv\Scripts\python.exe scripts/check_dev_spec.py`，按[检查范围](devSpec/README.md#5-识别评测边界)报告样本命中数与误判；关键词命中不代表模型理解全部规则。
- 报告实际检查范围与限制。纯文档任务不运行产品 E2E、真实模型或停用的单元测试。
