## 1. 开关与事实归属

| 配置键 | `true` 的预期含义 | `false` 的预期含义 | 当前接入状态 |
| --- | --- | --- | --- |
| `features.goal_verification` | 接入目标核验及其真实反馈、修订复验链路 | 关闭这项语义核验及其反馈；保留目标维护和确定性准入 | 已接入 |
| `features.answer_verification` | 接入回答核验及其真实反馈、修订复验链路 | 关闭这项语义核验及其反馈；保留其他确定性交付检查 | 已接入 |

配置文件唯一拥有当前布尔值。本文的两臂取值定义实验方案，不是第二份可写配置。关闭核验不产生 passed 回执，也不等于核验无问题。目标关闭但回答开启时，回答输入使用当时已接纳、明确标为未核验的目标快照；默认开启时仍要求真实通过回执。开关在新进程启动时读取，并在同一对话及运行中固定。

现行目标、回答核验分别见[目标核验上下文](../context/goal-verifier.md)、[回答核验上下文](../context/goal-compliance-verifier.md)，主循环见 [Agent loop 上下文](../context/agent-loop.md)。配置读取入口为 [feature_flags.py](../../src/personal_agent/kernel/feature_flags.py)，经 Runtime 注入[回答模块](../../src/personal_agent/application/conversation/answer_results.py)，由 [Conversation Service](../../src/personal_agent/application/conversation/service.py) 的 `_verify_goal_maintenance`、`_verify_before_send` 及原研究写作链实际消费。

### 接入规格（2026-11-05）

本轮实现实验组 1 的配置消费，不评价两类核验的收益。已定位缺口：`Settings.from_env → AgentRuntime → ConversationService` 不读取 TOML，目标写入与 Journal 又强制要求通过回执；仅修改配置无法运行 B 臂。配置接入与关闭路径属于本轮行为变更，默认开启继续使用现有核验链。

| 需求 | 行为及验收 |
| --- | --- |
| FLAG-1 配置与默认 | `config/feature_flags.toml` 唯一拥有两项开关；默认均开启。通过 `PERSONAL_AGENT_FEATURE_FLAGS_CONFIG` 可选择独立 TOML。严格校验布尔值、未知键和缺项；显式文件不存在或格式错误时启动失败。 |
| FLAG-2 目标核验 | 开启时创建、修订、沿用必须绑定实际通过回执；关闭时保留目标维护和确定性准入，保存 `verification_ref=None`，不调用目标核验、不生成语义判决。Journal 按本运行绑定的开关校验写入。 |
| FLAG-3 结果核验 | 开关统一控制 direct、claims 及 Python 回答的语义核验和修复链。关闭后保留引用、权限、执行与交付检查；删除 `AnswerResultConfig.verification` 及旧环境配置中的重复核验值。 |
| FLAG-4 独立绑定 | typed 配置经组合根注入，在 Journal 绑定；同一 run 恢复及同一对话新轮次不得改变开关。开启结果、关闭目标时，结果核验明确接收当时已接纳但未核验的目标快照，不能冒充已通过目标。 |

架构沿用现有边界：kernel 拥有不可变配置类型与 TOML 读取，Settings 持有配置快照；Runtime 显式注入；Conversation 和回答模块拥有消费点，Journal 是目标操作及运行绑定的唯一写入口。核验上下文从操作派生已通过回执或明确未核验快照，不新增存储、工具或业务写入口。新增复杂度限于两个配置值、运行绑定和必要分支；不复制循环，不保留旧核验配置双轨。核验协议的受控消融决定见 [ADR 0050](../adr/0050-verification-feature-flags.md)。

实施顺序：先固定此规格和上下文模式；复用现有两轮中文算术正式 HTTP 用例，先以关闭配置取得未接入 baseline；实现配置、装配、Journal 和上下文；迁移现行评测配置；检查默认全开及全关的真实连续两轮用户结果、开关绑定和真实核验调用。自然请求、数值结果及错误答案反事实沿用 `run_verification_context_target`，原始配置与源码身份分别封存。每次两轮最多 1,200 秒、500,000 tokens，失败后停止该次，不反复补采；用户结果和开关机制检查分别记录。静态检查覆盖 TOML、依赖、导入、模板及文档，历史真实轨迹回放检查默认开启的投影保持；不运行单元测试。混合开关仅在有实际正式轨迹时报告已验证范围；不以静态检查宣称模型行为通过。若绑定不一致、伪造通过或默认路径回归，停止相应准入并修正最早责任边界。

当前状态：FLAG-1 至 FLAG-4 已实现。中文 direct Python 正式入口的全开与全关两轮用户结果、核验开关消费和未核验事实已核实；恢复、同对话新轮次和 Journal 的两项开关变更均被拒绝。混合开关仅完成实际目标的输入物化检查，未执行混合模型链；claims 的关闭分支已静态走读，未新增真实 claims 用例。实验组的完整收益比较仍未执行。

默认全开首轮实际交付了正确数值、`result = 37 * 43; print(result)` 及方法解释；旧评测只接受 `print(37 * 43)`，错误归为方法缺失。原 `target-on` 失败和费用保留，按 QLT 修正评测器：允许赋值中的实际乘法表达式，仍拒绝缺方法的纯结果；用封存答案及错误反事实复核后，在生产源码不变、同一配置和授权下复制原 Journal，续接第二用户轮。原话、目标、模型结果及判决全部沿用同一真实轨迹，不重新采样首轮。续跑新增上限仍为剩余约定额度：累计 500,000 tokens、1,200 秒。

### 执行条件与记录

两臂使用相同任务集、原始自然请求、材料、模型、参数、非机制提示、工具、权限、其他开关、评分器及预算上限；各自从独立空会话开始，后续连续消费本臂真实产物，不交叉复用另一臂的目标、答案或判决。关闭核验后减少核验消息和修复过程属于被比较机制的直接差异，须据实保留。

执行前补齐固定用例、样本量或重复次数、用户结果和必要反事实断言、评分资格、两臂预算、停止条件及配置实际消费的验证方式，再按 [EVD](../devSpec/change-evidence.md)、[QLT](../devSpec/quality-security.md)和[正式评测运行规则](../evals/04-running-and-release.md)准入。本次不选择数据集、不派发模型或预填通过结论。

每个实际运行至少记录：实验组与实验臂、源码和配置原件及摘要、数据与模型身份、独立会话、已知与未知调用用量、用户结果及反事实、核验和修复情况、总延迟、失败与未执行样本、原始证据位置。正式入口的完整用户结果与真实阶段回放分别计量，历史成绩不回写。

## 3. Feature 生命周期同步要求

**对应 feature 新增、变更、重命名或移除时，必须在同一变更更新配置及本文所有相关实验组。** 使用[控制 skill](../../.agents/skills/manage-feature-flags/SKILL.md)按开关键检索引用，核对开关语义、接入状态、比较条件及实验组可执行性。

功能移除后，删除当前配置项，并将受影响组标为失效、注明原因；原实验编号和历史证据保留，不再把原实验组列为可执行。重命名迁移引用；语义变化更新比较定义，新执行与旧语义结果分开保存。单纯切换当前值只影响所选实验臂，不改写已完成实验的配置与结论。

涉及上下文模式变化时必须调用[上下文管理 skill](../../.agents/skills/manage-model-context/SKILL.md)维护对应正文。新增其他实验组时继续在本文登记稳定编号、相关开关、两臂差异、状态和证据引用，索引只保留入口。
