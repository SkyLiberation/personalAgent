## 1. 当前结论

**额外claim有局部帮助，但本轮没有证明稳定的整体优势或净收益。**四个独立任务的11份完整阶段输入中，完整组多查出了部分本单元引用支持缺口；海岸聚焦诊断也出现完整组独有命中。移除组在另一些输入中有独有发现，完整组还会提出不改善当前答案的双份一致性修订。发现条数、空报告和拒稿都不等于用户结果。

新增六个主配对的预设关系成绩相同：四个严格精度／范围负例实例均未识别，十三个合法关系实例均未误拒。负例实际只有数量限定、海岸范围两种关系，分别在同题两版本重复；不是四个独立错误，更不是整稿正确率。聚焦诊断的局部收益没有迁移到完整场景。

这些成绩**不支持“claim 没有任何帮助”**。它们只说明预设关系子集未显示增益：N2 完整组另发现了答案中的三个引用支持缺口，以及未进入答案的一个研究稿地域排序错误。前者属于预设外的局部观察，后者属于研究资源验真，均不能外推稳定整体收益。当前新增成本已测，完整修复与用户结果收益未测；因此额外复杂度的净收益仍缺依据，未测项目也不能用来给机制背书。

[机制诊断](#22-机制诊断与因果边界)进一步确认了输入重复和额外一致性修订；部分漏检存在判据取舍问题。输入变长是否导致特定漏检仍是待证假设，不能把所有不足都归因于 claim 或模型注意力。

**同一输入也会一漏一中。**[逐组加回](#211-最简输入逐组加回)中的 G1 与 repeat-C 实发 SDK 完全相同，海岸结果却分别为漏报、准确报告。单次命中只能证明该次能够识别，不能证明相关改动有效或可靠性已改善；不同输入间的一次差异也不能排除原有波动。当前生产仍依赖一次核验报告，已有空报告漏放轨迹说明它有实际风险，不能用再次调用直到拒稿或通过来代替修复。2026-10-20 用户要求的[20 次固定输入重复](#217-固定输入的二十次重复)已完成：B0、G1 各形成准确可用海岸反馈 3/10；输出定位失败单列。这只测两份裁剪载荷的表现，不重写旧成绩或宣称随机性是唯一根因。[逐轨审计](#218-海岸漏报的逐轨判断审计)进一步区分六次名称／地点整体接受和一次发现缺证后放过，不能把所有漏报都归为没有看见或主动忽略。随后按用户要求加入[临时 reason](#219-临时-reason-输出诊断)，十次准确可用反馈 4/10；四次原生漏报的理由均省略海岸限定，说明增加理由仍不保证核对完整，不作为生产修复。[语言对照](#220-整体中文翻译的语言对照)的海岸四项完整反馈为混合4/10、中文7/10；按已有渐进核验契约复核，至少报告一处真实且定位正确的问题为混合6/10、中文10/10。中文两次未报海岸也有其他真实缺证，不能视为整轮失败；单点覆盖、引用完整性与最终错误放行分别判断。

## 2. 比较规格

正式入口为 `POST /api/conversation/turn`。当前生产请求由[研究实现](../../src/personal_agent/application/conversation/research.py)构造，沿用[模板](../../src/personal_agent/kernel/prompt_templates/research.py)的 `conversation.research.support:v36-preserve-execution-results`；现行契约由[核验专题](../topics/verification-and-completion.md)拥有。本报告保存该版本的隔离实验，不另建生产契约。

| 组别 | 模型收到与承担的内容 |
| --- | --- |
| 完整组 | 现行请求：claims、片段定位、最终回答、目标及证据；检查研究来源支持、回答与 claim 一致性、原目标满足 |
| 移除组 | 删除 claims、claim 定位和 `answer_claim_mismatch` 职责；直接检查同一最终回答的来源支持与原目标满足 |

| 规格 | 实验约束与验收 |
| --- | --- |
| C1 | 每个配对的会话、冻结要求、最终回答、回答绑定原文、完整返回资料及读取状态逐字段相同；保存 SHA-256 |
| C2 | 移除组不补规则、不改稿、不补证；保存两组 Prompt、Schema 和实发 SDK 请求，检查无残留 claim 消费 |
| C3 | 先依据原请求、完整答案及实际原文封存关系标签，再运行配对；歧义、claim 独有错误和事后发现分别记录 |
| C4 | 新场景从空资料、新用户会话经生产装配、真实模型和真实工具取得中间产物；不注入理想稿、参考答案或 rubric |
| C5 | 识别必须忠实说明同一差异并合法定位；同一错误从 claim 或回答定位可计同一语义关系，不按关键词或发现数量评分 |

claim 独有错误没有进入最终回答时，只计额外研究诊断；移除组未检查它不算漏放用户错误。合法关系控制只保护相应关系，不预标整稿正确。所有新增反馈仍逐项审读，不能用预设控制通过掩盖其他误拒。

移除组也不再验真仍由上游生成的研究资源，因此本轮不是保持原研究资源契约的无损替换。N2的claim独有纠错有资源验真的价值；该价值与当前答案改善分开计量，后续复用的影响尚未验证。

比较对象是现行 claim 消费契约整体；本轮没有分别消融重复正文、重复证据、定位粒度和一致性职责，不能把观察差异归为其中某一项的独立贡献。

[FActScore](https://github.com/shmsw25/FActScore/blob/f28272deffcf33efc1f1117d5479c10bb75221a9/factscore/factscorer.py#L125-L184)默认从待评生成文本提取 atomic facts，也允许预标注 facts；[SAFE](https://github.com/google-deepmind/long-form-factuality/blob/9d27158d198ced0a9d8271a80147cae580614601/eval/safe/search_augmented_factuality_eval.py#L182-L192)从实际 response 提取事实后评分。这与并行写作的额外 claims 及其保真职责不同，不能用外部方法采用原子事实直接证明本机制有收益。[固定源码清单](../../.tmp/claim-verifier-ablation-20261018/method-references/manifest.json)已保存，本轮未执行外部评测器。

### 2.1 具体评估指标

本次补充解决一个可定位的评估缺口：原实验只给少数关系预标标签，尚未完整判断答案问题、所有反馈和实际修订，无法据此计算整稿准确率或净收益。指标定义版本为 `claim-verifier-metrics:v1`，正文由本节唯一维护，沿用当前核验职责与架构。补充只增加评估规格和派生统计，生产字段、Prompt、评分器与旧归档保持原身份。

以**独立的语义关系**计点。例如，同一句中的地区排序和调查年份可以分别判断；同一地区排序被两个 finding、claim 和回答同时指出，只计一个问题。关系以原问题、完整答案和实际证据为依据，claim 自己不能作为真值。当前 claim 不是稳定的原子事实单元，不能用 claim 条数作正确率分母。

| 编号 | 必须回答的评估问题 | 对应指标与范围 |
| --- | --- | --- |
| M1 | 额外 claim 是否改善实际答案核验 | A1、A2；比较相同完整答案与相同证据 |
| M2 | 反馈是否能使答案正确修复 | A3、A4；同轨消费实际反馈，检查完整新版 |
| M3 | 是否改善用户交付，代价是否合适 | A5、A6；用户结果与成本分别报告 |
| M4 | 研究稿自身及上游选证有什么价值 | R1、R2、R3 单列；本轮消费侧消融不外推上游作用 |

#### 六项核心指标

下表的 TP 是被正确识别的真实答案问题，FN 是漏掉的真实答案问题；FP 是把已标注的合法关系错报为问题，TN 是允许该合法关系成立。必要证据未物化、关系本身有歧义或标签未完成时标为无法评分，并报告数量和原因；原文不足以支持现有断言，本身仍可形成有效的“引用支持不足”问题，不能一律排除。语义判断服务失败另记可用性失败，不填成合法关系通过。

| 指标 | 具体计分规则 | 解释与比较方向 |
| --- | --- | --- |
| A1 答案错误召回率 | `TP / (TP + FN)`；分别统计事实冲突、来源支持、主体／范围／强度保真、用户目标缺项 | 越高越好。报告两组百分点差，以及完整组独有命中、移除组独有命中、共同命中、共同漏放数；这些计数的分母是同一批真实错误 |
| A2 合法关系误报率 | `FP / (FP + TN)` | 越低越好。必须保护合法改写、限定下的推断、用户允许的未知及执行事实；局部合法关系通过不等于整篇答案正确 |
| A3 反馈可执行率 | 在已确认的答案问题反馈中，错误说明忠实、类别与说明一致、定位合法且相关证据正确的反馈数／已确认的答案问题反馈数 | 越高越好。四项分别保留计分，全部成立才算可执行；反馈准确性另报 `正确答案问题反馈数 / 全部声称答案有问题的独立反馈数`，防止用精确定位的误报提高成绩。是否真正修好由 A4 判断 |
| A4 闭环修复率 | 首次稿中已标注的真实错误，经过实际核验、写作与必要取证后被修正，且完整新版保留原用户必需内容、无新增已确认错误的数量／首次稿真实错误数 | 越高越好。未识别、未修好、错误反馈造成退化均不进成功分子；另报含新增错误或必需内容丢失的修订版本数／全部实际修订版本数 |
| A5 用户结果通过率 | 满足原用户结果契约及必要反事实的 Product E2E 数／计划执行的 Product E2E 数 | 越高越好。保留服务失败、未执行和未到达数量；`answer` 终态、核验空报告及 HTTP 成功不能替代用户结果。阶段续跑只计 A4，不升级成 Product E2E |
| A6 成本与修复效率 | 分别报告输入／输出／总 tokens、物理调用及恢复次数、每任务墙钟时间；闭环效率为 `A4 成功修复数 × 1,000,000 / 核验及其后实际修订链的总 tokens` | 相同质量与工作负载下成本越低、效率越高。另报每个成功用户结果的整例 tokens；成功数为 0 时单位成功成本不可计算。采样准备费、核验费和修订费分账；未知用量、缓存及币值不能填零 |

“保真收益”归入 A1 的保真维度，须有独立的答案语义问题。例如有据的地方样本被扩大成全国结论。若答案新增结论本身有据、满足用户要求，只因 claims 未承载而要求同步两份表述，该反馈归 R2，不算 A1 命中，也不据此宣称 A2 误报。真正误导、删去必需事实或推翻执行事实的反馈仍按 A2 和 A4 判断。

#### 与最终回答质量的关系

这组指标主要评价 claim 对质量控制链的贡献，不能直接合成 Agent 的总体回答质量分。最终回答质量首先看交付正文是否正确、是否回答原问题、关键结论是否有据、限定与未知是否诚实，以及是否满足该任务的表达和使用要求。A5 用原用户结果契约验收这些要求；契约未覆盖的质量维度，不能由其他指标自动补作已测。

| 指标 | 对回答质量提供什么证据 | 单独成立时的限制 |
| --- | --- | --- |
| A1、A2 错误召回与合法关系误报 | 核验能否发现实际问题、允许正确表达，是质量控制的过程证据 | 相同稿件可用来比较核验器；不同稿件的原始错误数量不同，召回率高不等于终稿更正确 |
| A3 反馈可执行性与精确率 | 正确问题能否转成忠实、可定位且有证据的修订依据 | 写作者可能未消费反馈或改错，不能据此计答案改善 |
| A4 闭环修复 | 实际完整新版纠正了原始问题，并保留必需内容、没有新增已确认错误，是局部答案改善证据 | 修复部分错误不等于所有用户要求已经交付；初稿没有错误时不以无修订判失败 |
| A5 用户结果通过 | 完整交付正文满足原用户要求及必要反事实，是本组最直接的整例质量证据 | 结论受具体任务、契约覆盖与评分资格限制；不能只读取核验器的空报告或完成自述 |
| A6 成本与修复效率 | 在质量与用户要求相同时，判断取得结果的资源代价 | 少用 tokens、更快返回或单位成本低，均不能代替内容正确和目标满足 |
| R1—R3 研究资源、同步负担与选证 | 解释机制在哪一层产生作用，帮助定位收益或额外负担 | 研究稿变好或取得更多资料，只有进入实际回答并改善用户结果时，才成为答案收益 |

例如，原文只支持地方调查，回答却推广到全国：核验正确指出范围问题计 A1；反馈给出正确位置与依据计 A3；写作者实际收窄回答且保留原任务必需内容才计 A4；完整交付是否满足用户允许的未知边界及其余要求，由 A5 判断。如果只修正未进入答案的 claim，而答案未改变，则只计 R1。上述为计分解释，不是新增实验样本。

这些指标可供参考，依据是可追溯的用户要求、实际正文、原文及同一轨迹的修订；比较保持输入和声明变量之外的条件相同，区分独立任务、阶段、版本与未测项。它们允许检验“发现问题—形成反馈—实际修复—完成交付”是否发生，某一步未成立时就限定对应收益，不能直接假定过程分数会转化成用户收益。

参考价值还依赖裁判正确。答案评分须依据原问题与真实来源，独立判断实际正文，不能把被评核验器的结论当作真值；使用语义评分器时，沿用既有评分资格要求。固定公式和校验和只保证口径与证据可复核，不能保证标签本身正确。现有标签未另作独立人工复核，也未完整测量 A4、A5，尚未建立过程指标与独立终稿评分的对应证据。因此当前只能作局部诊断参考，不能据此给 Agent 总体回答质量或用户满意度定级。本节澄清解释边界，不改变冻结的 `v1` 公式、判据或历史成绩。

#### 标注、汇总与判定

1. 评分数据保存任务、轨迹、完整阶段输入校验和、关系、正文位置、原文依据、适用范围与判断结果。每个关系明确属于答案问题、claim 独有问题或合法控制；资料缺失和标签歧义单列。同一错误的重复反馈先去重，已在 claim 定位的错误只有实际也存在于答案时才能计入 A1。预标关系之外的反馈先记未裁决，不能仅因没有匹配标签就算误报；后续补审保留独立复评身份。
2. 下一批候选执行前冻结标签、判据、样本清单、重复次数、模型与预算。评反馈时隐藏组名；公开是否有独立复核。为旧归档补完整标注属于事后复评，形成新身份，不回填原预声明成绩。本轮只消费既有标签，不新增语义裁判。
3. 每个独立任务分别报告分子、分母及两组差值，再报告任务等权均值；没有该类关系的任务不填 0。版本和重复次数在任务内汇总，不能把 11 份输入当成 11 个独立任务，或把同题重复关系当成新的缺陷类型。现有单次回放不估计稳定方差；后续重复计划与置信边界须在执行前确定。
4. A4 从同一真实阶段状态分支，实际消费各组核验反馈，经过同一写作、准入、取证和复验边界；不能注入理想反馈或稿件。首次错误清单保持固定，完整新版按原目标和真实证据验收；前置失败与后置未到达分开记录。上游或整个 claim 机制的删除另立比较变量，不能与本轮消费侧消融合并归因。
5. 对下一批指定用例，声明“改善答案识别”须满足 A1 提高且 A2 不升；声明“改善修复”另须 A4 提高且有害修订率不升；声明“提高效率”须在相同用户结果要求、质量不退化时 A6 修复效率提高。报告阈值为严格比较，等于基线不算改善。出现质量、误报与成本的取舍时分别列出，保持净收益待定，不用临时加权总分抵消；这些判据不追溯改变既有局部结论。

### 2.2 机制诊断与因果边界

本节基于同一归档解释“为何没有形成已测的稳定质量增益”，不把未测的 A3—A5 判成无效，也不改写 `v1` 标签与成绩。复查了 11 份完整输入、N1 的实际生产反馈与修订，以及 6 个配对调用的既有同轨记录；没有新增模型调用或生产改动。

#### 两稿同错时，claim 的帮助停在哪里

“两份稿件可以共享错误”只解释了相互对照的局限，不能作为漏检的完整原因。N3 的原文 `d3:59` 写的是 `Colombia Costa Rica`，claim 和回答都写成“哥伦比亚与哥斯达黎加海岸”。两稿之间没有这项差异，因此一致性检查不能发现它；但核验 claim 自身的原文支持仍应发现这一限定缺证。该判断不要求增加资料，也不要求证明真实地点一定不是海岸。

实际请求已经包含 `citation_not_supported` 的来源支持规则，以及“研究本身断言有误且回答沿用同一错误，定位原错误”的要求。首稿完整组还报告了同一 `c3.f1` 的声景性质缺证，末次完整组报告了声景与测试独立性缺证，却都没有报告海岸。这说明该单元实际进入了核验，失败落在其中具体关系的判断或报告上；不能说核验器只检查两稿一致，也不能把漏检解释成缺少这条规则。完整组对海岸的具体取舍依据仍未知。

claim 的整理作用在这个例子里也有限：一个 `c3.f1` 同时包含时长、数据集数量、多个地点、声景类型和独立性，共绑定 49 条原文。核验器仍须从整段中找出各个断言，再判断哪些引用支持哪个限定；片段编号只提供定位，不能代表各关系已逐项查证。较粗的整理粒度可能削弱帮助，但本轮没有单独改变粒度，不能据此断言它导致了漏检或拆细即可修好。

N3 末次移除组进一步暴露了判断取舍。其实际 Context 中，用户要找训练量达到数千小时、鸟类覆盖广、具有不同生态环境独立测试集、能区分定向鸟鸣与固定声景的数据集，并询问发表信息和 Hugging Face 加载路径。原文 `d3:59` 只有国家名称，回答 `a3` 加上“海岸”；同轨记录注意到了这个差异，却将其视为轻微修饰而放弃单独报告。实际报告仍指出了声景性质、测试独立性等缺口。这些是该次实际请求与输出能直接确认的事实。

这次任务同时包含两种判断：目标满足检查用户需要的内容是否交付；来源支持检查已经写出的外部断言是否有据。该次原记录表明模型用“是否值得单独报告”筛选了来源缺口。“海岸”可能不影响推荐哪个数据集，但它仍增加了原文未支持的地理范围。此前将实际 Prompt 的“必要关系”“不要求……穷尽资料全部细节”列为可能影响；前者属于来源支持的表述，后者本用于防止扩大用户要求，均不构成放过已写出无据事实的授权。第 2.3 节的定向删除没有修复该漏检，因此不能将这句 Context 当成已确认根因，也不能将原次取舍外推为每次漏检都采用相同理由。

实际请求没有限制只能输出三项发现，响应正常结束；本次没有输出截断或发现数量上限的证据。能够定位的偏差是“已发现原文没有这个限定，却没有把缺口交给修订者”。增加 claim 不能自动纠正这种取舍。该直接记录来自移除组，不能据此替完整组补写同一原因；完整组的具体取舍仍未知，也不能将共同核验任务的问题独占归因于 claim。

“不要求……穷尽资料全部细节”的作用是限制目标覆盖，防止将用户未问的资料细节升级为必答项；该意图与已写事实需要有据可以同时成立。实际请求还明确“不从资料新增必答项”，并允许核心已回答后的附加未知，所以这一意图并非只由该句承担。保留这项目标边界是必要约束，但不能据此认定这段具体文字不可删除。已有记录没有将放弃报告直接归因于该句，当前只能作为待证措辞假设。

零模型静态对照确认，可以只删除“或穷尽资料全部细节”9 个字符，保留“不要求未指定的产品实现。”及其余目标、未知和来源支持约束。后续已实际执行该单变量删除，结果见第 2.3 节；未通过预设目标，不进入生产。先前整体重组来源判据及 claim 组织的方向仍需新的因果依据，不因该候选失败自动准入。

#### 上下文负担与真正的漏检原因分别判断

完整组多用 36.4% 核验输入 tokens；N2 首稿完整调用还产生了 83,926 reasoning tokens，而移除组为 1,877。这些是实际开销，不能从可见反馈数反推其全部成本。模型有效采样温度、权重快照与缓存没有被控制，单次耗时不构成稳定性能结论。

N3 的聚焦诊断中完整组识别“海岸”、移除组未识别，但完整输入的两版本两组均未识别，说明局部判断没有迁移到完整任务。裁剪同时改变其他正文和资料目录，不能分离输入长度、其他目标、重复表示与随机采样的作用。N1 聚焦诊断只输出裁剪造成的目标缺项，不能据此证明模型完全不会判断数量限定。现有证据不足以把漏检统一归因于长 Context 或模型能力。

#### 取舍与下一步验证方向

定向删除未解决目标漏检，当前停止该候选，不继续加同义提示或整轮重跑。应先复审实际稿件与绑定原文的对应及报告取舍，再确定新的最小候选；完整组的具体漏检原因仍不能由移除组记录代替。具体候选与验收由[统一核验 Spec](../optimization/to_verify/research-goal-coverage.md#2026-10-18-claim-消融后的优化顺序)唯一维护，本节只说明与本次消融的对应关系，生产实现保持。

| 优先级 | 要区分的假设与最小方向 | 必须保留与验证的结果 |
| --- | --- | --- |
| 1：定向删除已停止 | 只删除“或穷尽资料全部细节”，保留其他规则及真实输入，两组海岸仍各 0/1 | 未达到 A1 目标，N2 按预声明未执行。不进入生产；也不据此证明原句绝对无影响或不可删除 |

| 独立成本项 | 减少重复物化，另行复审同步研究稿及执行事实的必要职责 | 去重检查 A6 与质量保持；同步职责从 N1、N2 真实边界单独验证，不能把删除整个 claim 消费契约的 26.7% 记为纯去重收益 |

同类外部实现只提供比较方向：第 2 节固定提交的 FActScore 默认从实际生成文本抽取事实再评分，SAFE 从实际 response 抽取事实后检查相关性与支持。它们的抽取对象由待评答案决定，与另行维护一份研究稿不同；FActScore 也允许外部提供 facts，不能把其默认路径说成唯一方式。两份源码只能支持“对实际交付内容形成检查视图”的候选，不证明本工程删除 claims、增加抽取阶段或换模型会提高质量，本轮也未运行外部评测器。

本节只读诊断与删除候选的真实运行分别保存；后者的实际次数和结果见下节。新的候选仍须先封存隔离模板、命令、实际配置、预算及停止条件；连续阶段另须具备可还原状态与真实消费者。当前冻结指标、原始输入及结果保持原身份。

删除后的完整组正确区分了部分未绑定原文，并报告声景／独立性缺证；但它把地点差异概括为不同环境可推断，未独立报告海岸限定。记录还把“同一单元”与只报一项联系起来。实际规则是同一待修关系只报告一次、多个独立错误分别输出；一个片段可同时有地点与声景两项缺口。这里观察到的是关系与单元混淆，不能断言模型已经认定海岸有错、随后才把它合并删除。

代码核对也排除了两项解释：[报告校验](../../src/personal_agent/application/conversation/research.py)没有“同一单元最多一项”的限制；两份新响应的 JSON 正文与保存报告逐字段一致，未发现后处理丢弃海岸反馈。校验只能检查实际报告的类别、目标及证据身份，不能据空报告证明每个事实都已查证。

**“海岸”出现在输入里，不足以解释漏检。**原 MN3 聚焦完整组保留了与 N3-final 逐字段相同的 `c3`、`a3`，同样含三处海岸，却成功指出 `d3:59` 不支持该限定，还分别报告了同片段的声景问题。原归档哈希及这一对照见[聚焦审计](../../.tmp/claim-persistent-analysis-20261018/counterexample-audit.json)。聚焦输入删除了其他被评单元，不能替代完整阶段通过，也不能由此证明缩短输入即可解决。
