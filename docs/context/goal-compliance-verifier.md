# 目标遵循核验器上下文模式

目标遵循核验在 Python 执行前检查待执行动作，在回答交付前检查回答。Runtime 为两个检查时点生成同一条核验时间线，并在末尾标明当前待验对象。动作判决仍绑定调用及资源版本，回答判决仍绑定本次草稿。目标定义核验独立核对用户要求与 goal 的变更。[目标定义核验](goal-verifier.md)

## 1. 目标与责任

`features.answer_verification` 控制分析路径上的两个时点。开启目标定义核验时，正常回答须绑定已通过的目标。关闭时，使用实际接纳的目标。通用来源支持核验沿用其原有契约。

唯一业务判据是当前待验动作或待交付回答绑定的生效 goal。历史 goal、判决、反馈和执行结果按原归属展示，供核对前序做法、修订和依赖。原始用户问题、背景、无关工具历史及原始数据文件留在拥有它们的环节。核验器不能调用主循环工具。

执行前逐笔判断待执行代码是否与当前 goal 的明确条件冲突。可识别的冲突退回原调用，Runtime 阻止执行，主模型修改后重新提交。交付前逐项检查草稿里可见的结果与计算方法。计算方法与 goal 冲突时，即使稿件自称合规也应退回。无法独立查证不构成退回理由，核验反馈不索要额外证据。

## 2. 按轮次接续

```text
系统提示与当前核验时点
历史轮次，按发生顺序
  当时生效的 goal 与版本
    动作提议 → 判决 → 退回反馈或执行结果
    回答草稿 → 判决 → 实际修订或交付
  同轮更新 goal 时，追加新版本及之后的事件
当前轮次
  生效的 goal 与版本
  该版本下已发生的动作和回答事件，按实际交互顺序接续
  当前待验的动作批次或回答草稿
```

同一轮的动作修复可能发生在回答退回之后。按主循环决策顺序恢复事件，在原提交下配对已产生的判决和反馈。历史已审稿与已交付答复使用 Journal 事实。重新提交后的动作和回答各自形成新记录。最新待验对象只出现一次。核验仍在原入口同步执行，失败反馈进入主循环下一次请求。未形成相关事件的历史轮次仅在有已生效 goal 或真实交付时形成区块。

## 3. 历史范围与压缩

回答正文从会话记录完整进入核验请求。核验回执绑定并保留同一正文，供交付和后续轮次使用。正文可否送审由完整模型请求的容量预检决定。用户消息的入口长度校验独立于回答正文。

同一授权会话分支的相关前序轮次按原顺序滚动保留。Runtime 在发送前用正式模型容量计算输入、输出和协议预留的总量，预计达到配置窗口才压缩。Task2 的窗口为 100 万 token。压缩最早的已结束轮次，保留最近两个已结束轮次、当前轮次及本批直接绑定的历史执行结果。压缩版保留版本、事件顺序、回答、判决、反馈及执行结果引用，缩短早期目标正文并省去旧代码和执行输出预览。每次重新估算后才推进共享覆盖轮次。同一 Journal 保存可恢复的原件。若仍放不进模型窗口，沿容量失败路径处理。[工程上下文管理](context-management.md)

## 4. 实现与验证

基线第 20 轮执行前请求只包含动作历史，第 12 轮回答核验请求只包含回答历史。改动以这两个实发请求为对照。离线使用同一真实会话恢复两个阶段，断言同一历史顺序、同轮修订位置、独立的当前待验对象和其生效 goal、无原始问题、同一容量计算与覆盖。第 12 轮草稿的精度自相矛盾作为语义验收点。语义结果由真实模型验证独立记录。[执行前请求](../../.tmp/agv20roll-s/c-recovery/sdk/b1c797c88c25492d8dff19a1ccffe092.http.request.json) · [交付前请求](../../.tmp/agv20roll/c-recovery/sdk/e81936f6cedc4ff887bbb1a9615c430b.http.request.json)

[统一历史投影](../../src/personal_agent/application/conversation/goal_compliance_history.py) 从真实决策、目标变更、执行观察和回执恢复顺序。[请求构造与容量预检](../../src/personal_agent/application/conversation/goal_compliance.py) 提供两个时点共用的历史和覆盖检查。Runtime 入口为 [ConversationService](../../src/personal_agent/application/conversation/service.py)，原始记录由 [Journal](../../src/personal_agent/application/conversation/journal.py) 保存。授权、调用身份、答案回执和恢复沿已有执行边界绑定。

中英文存档回放已核对第 14 轮的「回答退回 → Python 修复 → 回答复验」和第 12 轮精度冲突原文。第 20 轮完整请求含预留估算约 161–165 万 token，压缩前 12 轮后低于窗口，最近两轮和当前待验对象保持原文。恢复后两阶段采用同一覆盖边界。本次验证为真实轨迹离线回放，新增模型调用为零，模型能否识别并退回精度冲突仍待验证。[回放报告](../../.tmp/goal-compliance/report.json)
