# 上下文管理

当前工程按四类手段管理模型输入：摘要压缩概括旧过程，裁剪减少无关与重复内容，卸载移出可恢复的正文，按需加载补回当前需要的细节。完整交互由会话记录保存，大段正文由文件资源保存；每次模型调用使用面向当前任务的输入视图。

本文按 2026-11-05 工作树及现行记录概括已接入的行为，重点说明各类手段用在什么场景、何时介入。具体任务的输入顺序、契约和验证状态仍由对应正文维护。

## 1. 摘要压缩

**使用场景：** 长任务、多轮对话或多次修复使历史持续增长，旧过程仍有参考价值，但反复携带全部细节已经挤占当前任务空间。

**介入时机：** 主循环在完整请求组装后检查容量，计入消息、工具说明、历史、反馈和正文，并预留输出与协议空间。达到约 80% 的本地估算压力、且存在可安全概括的旧交互前缀时触发摘要，单次决策前最多尝试两次。目标核验和回答核验则在各自输入超过预算时，摘要本职责内已经结束的旧过程。

**处理行为：** 以完整交互为边界，将旧调用、结果、反馈、修复及历史交付概括为工作摘要，说明已完成、未解决事项和原件位置。用户原话、当前有效目标、待验结果、当前未决反馈及近期完整交互受到保护；调用与结果保持配对，未覆盖部分继续按原时间接续。两类核验分别维护摘要，不混用彼此或主循环的全部历史。

主循环先保存可恢复原件，再生成候选摘要并重建完整请求。来源一致、摘要完整且实际输入确实缩小后才激活；保存失败、摘要截断或未缩减时保留原视图。没有安全前缀但仍在硬容量内时可以继续，超过硬容量则明确停止；核验没有可压缩旧过程时报告容量问题。容量是本地估算，摘要调用也消耗任务预算。

## 2. 裁剪

**使用场景：** 不同模型职责需要的信息不同，或同一内容以多种形式重复出现。即使请求尚未接近容量上限，也有必要减少这些输入。

**介入时机：** 每次按职责构造请求、投影历史和准备工具结果时执行，无需等到整体窗口不足。

**处理行为：** 主循环保留实际行动过程；目标核验只滚动加入目标提交、判决和修订，回答核验加入对应目标、候选回答、判决和修复，避免各职责共享无关的全量历史。工具结果已经进入原生调用历史时，不再在其他输入区重复携带；搜索结果的重复来源描述只展示一份。

已通过的任务核验在主循环中保留简洁结论、判决身份和对象对应关系，完整报告留存，失败反馈保持完整。裁剪只改变本次展示，原始事实和保留交互的时间顺序仍以会话记录为准。

## 3. 卸载

上下文卸载指正文退出模型请求，原始记录继续保留。单次工具结果过大时按[工具输出超限的处理](tool.md)外置原件。历史摘要激活后，卸载其覆盖的旧交互。

被摘要覆盖的旧调用、配对结果和旧回答正文整体退出后续请求。再次从会话记录重建输入时，仍沿用相同覆盖范围，避免已卸载内容重新全部装回。近期交互、必要反馈和当前修复过程继续保留；卸载不改变执行、核验、授权或完成事实。主循环同时保留简短的逐条回执定位，已有外置原件直接读取，含可引用内容的内联回执从已有历史快照按位置恢复。两条路径见[压缩后如何定位工具原件](agent-loop.md#31-压缩后如何定位工具原件)。

## 4. 按需加载

**使用场景：** 模型需要查证某个细节、取得可引用原文，或者摘要与现有预览不足以支持下一步判断。

**介入时机：** 当前决策确实需要具体材料时，由模型使用已有读搜能力取得；不因原件存在就提前加载全文。

**处理行为：** 把本次实际取得的片段及来源追加到新交互。工具原件的定位与分段读取见[续读与跨轮保留](tool.md#3-续读与跨轮保留)。

搜索零命中、预览或读取了局部窗口，都不代表全文已经读完。后续需要更多材料时继续加载相应片段；判断是否执行成功、核验通过或任务完成，仍消费原始事实，摘要及历史快照本身不取得业务证据资格。

四类手段在任务中配合使用：请求构造时持续裁剪，大结果产生后外置并卸载，历史形成容量压力时摘要，决策需要细节时再按需加载。它们已经接入现行会话链路，但各任务触发的分支和验证程度不同；请求变短本身不能证明答案正确或净成本下降。
