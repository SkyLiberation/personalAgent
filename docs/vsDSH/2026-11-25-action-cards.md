# 跨轮操作卡片与工作区确认

DeepSeek Harness 会把不同轮次的操作提案保留在各自答复下。用户可以回到旧提案操作，后续模型请求会收到已记录的状态。personalAgent 的工作区确认 API 已冻结清单、校验决定并保存回执，当前浏览器却只保留答复文字。用户在聊天界面收到审核提示后，缺少可点选的清单和确认入口。

## DeepSeek Harness 如何保留并消费提案

1. **装配与提交。** Web 默认组合同时装配 Host 操作卡片、浏览器渲染插件和个性化页面种类。`enabled` 默认开启，控制技能的发现和加载。关闭开关后，已投影的卡片仍可操作，模型若仍输出合规卡片块也会被投影。`personalized-pages` 技能指导主模型在答复末尾写入包含动作、标题、摘要和详情的 `action-card` JSON 块。[Web 装配](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/bundle/web-app/cordis.patch.yml#L414-L427) · [开关默认值](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/index.ts#L140-L177) · [技能目录](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/index.ts#L200-L211) · [页面提案指令](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/extensions/creation-recommendations/skills/personalized-pages.md#L48-L54)
2. **提案与决定来自 Session 日志。** 投影从每轮读取第一个通过通用结构校验的卡片块，以该助手消息的 ID 标识卡片。子智能体会话、被中断的消息和分叉继承的日志前缀不会产生新卡片。此前新提案会把尚无决定的旧卡设为 `replaced`。当前投影保留旧卡和它原有的决定。浏览器隐藏原始代码块，按轮次在已结束且有答复的轮尾显示对应卡片。[旧投影](https://github.com/deepseek-ai/deepseek-harness/blob/bfa074a3644533c9cdbfd254c80725a72d972f45/packages/experimental/action-cards/src/projection.ts#L103-L116) · [当前投影](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/projection.ts#L73-L129) · [轮尾装配](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/client/ui-action-cards/src/client/mount.ts#L37-L56) · [按轮次取卡](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/client/ui-action-cards/src/client/Card.tsx#L68-L114)
3. **用户操作绑定原卡。** 浏览器调用 `actionCards.act(sessionId, cardId, verb, payload)`。Host 解析 Session，在当前根 Agent 的投影中定位卡片，校验动作种类、详情及适用权限，并合并同一张卡的并发操作。以计数器为例，用户点「暂不需要」只记录该卡的 `dismissed`。用户点「创建」且权限与位置有效时，页面处理器才启动后台 Creator。`accepted` 表示已受理。安装事实由 Plugin Manager 持有，处理器据此记录结果和恢复中断状态。[Session 解析](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/api/session-controller/src/agent.ts#L125-L178) · [详情校验](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/index.ts#L220-L240) · [操作、权限与记录](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/index.ts#L285-L355) · [创建动作](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/extensions/creation-recommendations/src/index.ts#L209-L255) · [安装结果](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/extensions/creation-recommendations/src/index.ts#L358-L372) · [重开核对](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/extensions/creation-recommendations/src/index.ts#L141-L179)
4. **下一次决策收到状态。** 写入 `action-cards/decision` 只更新 Session。下一次进入主循环时，`agent/pre-step` 把待告知决定加到输入末尾，附加标题、阶段及允许报告的字段，并说明这是运行事实。Loop 以带 `action-cards` 来源的 `user/message` 写入日志后构造请求。投影以通知的 `through` 序号移除已报告项，之后的新阶段仍可产生更新。[通知组装](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/index.ts#L171-L197) · [通知消费](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/interaction/action-cards/src/projection.ts#L85-L121) · [写日志后构造请求](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/core/agent-loop/src/agent.ts#L431-L480)

## personalAgent 的同类路径

1. **正式入口生成待确认清单。** 在部署已绑定认证主体、会话和独立 stdio 文件系统的条件下，Runtime 装配 `WorkspaceChangeService`，并将底层写工具从普通工具集合移出。`POST /api/conversation/turns` 进入 `ConversationService` 后，主模型可提交 `prepare_workspace_changes`。应用校验路径及权限，冻结原调用、作用域和有序清单，返回 `confirmation_required` 与 `pending_confirmation`。[Web 入口](../../src/personal_agent/adapters/web/routes/conversation.py#L193-L235) · [Runtime 装配](../../src/personal_agent/orchestration/runtime.py#L440-L464) · [部署绑定](../../src/personal_agent/orchestration/workspace_changes.py#L43-L80) · [主循环分支](../../src/personal_agent/application/conversation/service.py#L1375-L1398) · [预查、冻结和存储](../../src/personal_agent/application/conversation/workspace_changes.py#L154-L204)
2. **用户决定与原工具调用配对。** 已认证的客户端可向原轮次的 `/workspace-changes/decision` 提交清单摘要和决定。应用锁定会话及运行，复核绑定，逐项记录派发与终态。重复提交同一决定返回原回执，已开始但结果未知时停止继续派发。批准并执行成功后，客户端用原轮次 `/resume` 续跑，保存的 `ActionObservation` 以原调用 ID 拼回工具交换。拒绝或结果未知时，应用从已存状态返回限制说明。[决定入口](../../src/personal_agent/adapters/web/routes/conversation.py#L170-L190) · [原轮次续跑](../../src/personal_agent/adapters/web/routes/conversation.py#L309-L312) · [轮次与会话锁](../../src/personal_agent/application/conversation/service.py#L1703-L1731) · [回执与恢复](../../src/personal_agent/application/conversation/workspace_changes.py#L206-L279) · [限制交付](../../src/personal_agent/application/conversation/service.py#L591-L611) · [模型适配配对](../../src/personal_agent/infra/structured_model.py#L299-L327)
3. **浏览器缺少确认交接。** Web 的 SSE `done` 带 `disposition` 和 `pending_confirmation`。`decodeConversationEvent` 只保留轮次、会话和答复文字，恢复 API 的浏览器适配也只保留文字。`App` 把该轮作为 `done` 展示并清掉待运行状态。在当前 `frontend/src` 未找到工作区决定端点的调用。用户可看到「请审核清单中的工作区变更并确认是否执行」，但无法在该聊天界面查看、批准或拒绝清单。[SSE 响应](../../src/personal_agent/adapters/web/routes/conversation.py#L281-L303) · [流事件解码](../../frontend/src/api.ts#L259-L296) · [恢复结果解码](../../frontend/src/api.ts#L364-L391) · [轮次收尾](../../frontend/src/App.tsx#L440-L465) · [答复渲染](../../frontend/src/App.tsx#L810-L826)

## 差距与最小验证

**取舍。** 上游允许用户保留多个可选页面提案，单卡操作绑定答复 ID。本地文件写入有顺序及恢复约束，未决或结果未知的命令会阻止在同一部署绑定下准备下一份清单。最相近的差距在浏览器呈现和动作绑定。若复现，只需让现有浏览器消费原轮次的 `pending_confirmation` 并调用现有决定接口，再由原轮次续跑。文件清单、授权和回执仍由工作区用例负责。[同绑定的未决检查](../../src/personal_agent/application/conversation/workspace_changes.py#L179-L197) · [工作区确认契约](../mcpDesign/README.md#523-工作区变更确认与接续)

**最小验证。** 复用上述单文件输入和隔离夹具。用同一认证主体提交一次浏览器对话，同时捕获服务端的 SSE。预期基线返回 `confirmation_required` 和原清单，浏览器只显示提示，批准前远端移动次数为零。在客户端读取同一份确认数据后，验证用户能看到精确源路径和目标路径，批准一次只移动一次，续跑答复给出确切位置。另用独立的拒绝样本核对源文件保留且无移动。用批准样本的同一摘要重放决定，核对返回原回执且无新增移动。若基线浏览器已能完整完成该操作，则这项差距不成立。此次验证限于源码与历史样本，该浏览器用例尚未执行。[评测的单文件入口](../../evals/Toolathlon/workspace_case.py#L115-L202)
