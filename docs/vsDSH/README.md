# DeepSeek Harness 与 personalAgent 每日源码对照

每天对照一个 DeepSeek Harness 模块，说明其架构与对智能体能力的影响，并定位 personalAgent 对应场景中仍缺的能力或工程条件。报告以 `YYYY-MM-DD-<模块>.md` 保存于本目录。发布日期按上海时区计算。

## 同步源码

从本工程根目录核对 `evals/deepseek-harness/` 的独立 Git 检出和官方 `origin`。抓取上游默认分支并记录更新前后的提交。工作区干净且当前提交是目标提交的祖先时，切换到目标提交的 detached HEAD。上游未变更时沿用已确认版本。有本地改动、独有提交或同步故障时保留当前检出，报告具体阻塞及实际分析版本。

日常同步更新源码供阅读。共用评测运行时须使用和源码提交匹配的构建产物，[部署与固定版本](../../evals/deepseek-harness-deployment.md)说明了复现条件。

## 选题与记录

优先从上次已核对版本以来的变更中选择一个有实际消费者的模块。没有合适的新增变化时，从上游装配与本工程现有业务中选择一个尚未覆盖的同类能力。已分析模块出现实质变化时可重访，说明变化和已有报告的关系。

1. 记录 DeepSeek Harness 提交和 personalAgent `HEAD`，注明是否读取了本地未提交实现。用固定提交源码链接和本地文件、符号或行号定位依据。[开源参考入口](../agentRef/README.md) · [当前工程架构](../architecture/README.md)
2. **架构。** 沿真实入口、装配、调用与结果消费解释职责、输入输出、状态归属、依赖和失败边界。标明实际默认启用、按配置启用或未接入的分支。
3. **智能体能力。** 用一个具体任务说明模块怎样改变智能体可见信息、可选择动作、反馈修复、接续或交付。用源码解释条件，以及条件失效时用户会看到什么。
4. **当前工程差距。** 在相同场景下核对 personalAgent 实现，说明已具备的环节、具体不足及用户影响。区分刻意的职责取舍、源码已证实的差距和需要真实用例验证的假设。对最相关的一项差距给出最小验证及预期结果，原有运行证据保留原身份。
