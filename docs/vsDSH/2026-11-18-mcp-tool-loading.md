# MCP 工具按需加载

DeepSeek Harness 可以先给模型看一份工具目录，再让模型按任务选择要加载的完整工具定义。personalAgent 在业务动作可见的阶段，将通过部署映射和当前权限筛选的 MCP 工具直接作为完整定义发送。两者都能读取同一个 PDF。差异在于，工具较多时，personalAgent 的主请求缺少在不缩小授权范围的前提下减少无关工具定义的途径。

3. 每个模型步骤开始前，`preStep` 解析该步允许使用的工具集并组装提示词。原生工具执行器从这个集合生成 Schema，`buildRequest` 将工具与会话历史一起送往服务提供方。加载回执按调用 ID 进入会话，新增工具在下一步的工具集中生效，同一批次仍使用原步骤的集合。实际 MCP 调用由已注册的桥接定义执行，回执继续供模型决策。以 DeepSeek 服务为例，适配器将本次定义序列化为 `tools` 后发往 Messages API。[步骤工具集](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/core/tools/src/index.ts#L264-L296) · [原生执行器](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/core/tool-executor-native/src/index.ts#L9-L24) · [请求与工具增删记录](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/core/agent-loop/src/agent.ts#L662-L749) · [调用与回执](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/core/tools/src/batch.ts#L245-L264) · [MCP 执行](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/mcp/mcp-client/src/tools.ts#L176-L208) · [服务方序列化](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/llm/llm-deepseek/src/serialize.ts#L151-L168) · [出站调用](https://github.com/deepseek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/llm/llm-deepseek/src/adapter.ts#L127-L157)

## personalAgent 的同场景路径

以 Toolathlon 的 `detect-revised-terms` 为例。用户需要比较多份案例 PDF 与新法条文，找出影响原判决的实质变更并交付 `revised_terms.csv`。在一台工具较多的服务器上，DeepSeek Harness 的配置路径允许模型先按简介选择 PDF 信息、页段读取与搜索，再从后续请求的完整参数确定调用。模型可以在同一次加载里选多个工具。直接曝光则允许模型在业务动作首次可用时调用 PDF，无需额外的加载步骤。

1. 正式 `POST /api/conversation/turns` 解析身份，经 `AgentService` 和 `AgentRuntime.converse` 到 `ConversationService.respond`。装配时，`bind_mcp_tools` 连接已启用且存在显式映射的服务器，从 `list_tools` 返回中匹配每条映射，再经 `register_mcp_tools` 注册进 `ToolExecutor`。部署拥有准许映射、风险和权限配置，远端提供原始定义和执行结果。映射缺失或重名会使装配报错。[Web 入口](../../src/personal_agent/adapters/web/routes/conversation.py#L184-L248) · [服务装配](../../src/personal_agent/orchestration/service.py#L40-L63) · [Runtime 装配](../../src/personal_agent/orchestration/runtime.py#L435-L485) · [对话入口](../../src/personal_agent/orchestration/runtime.py#L998-L1006) · [MCP 映射](../../src/personal_agent/orchestration/mcp_bindings.py#L15-L70)
2. `ToolExecutor.list_interaction_tools` 按 `public_agent` 和主体策略筛选工具。`_effective_capabilities` 投影当前可用项，`_build_decision_request` 应用 Goal 阶段与执行模式限制，并由 `build_model_action_definitions` 生成完整工具定义。结构化客户端按提供方约定发送定义。对审核通过且当前可见的 MCP 工具，生产链路到此直接生成完整 Schema，模型动作中没有从目录选择加载的步骤。[可见性与治理](../../src/personal_agent/governance/registry.py#L99-L133) · [能力投影](../../src/personal_agent/application/conversation/service.py#L2668-L2702) · [阶段筛选](../../src/personal_agent/application/conversation/service.py#L2110-L2152) · [动作定义](../../src/personal_agent/application/conversation/model_actions.py#L147-L173) · [服务方参数](../../src/personal_agent/infra/structured_model.py#L298-L350)
3. 模型选择 PDF 工具后，准入核对调用，`invoke_interaction` 经执行网关复核并调用 MCP 适配器。适配器按绑定的 Schema 校验参数，再发起 `tools/call`。Conversation 把结果或拒绝与动作 ID 配对，从日志物化到后续请求，最终走 Web 结果响应。[执行入口](../../src/personal_agent/governance/registry.py#L211-L233) · [MCP 适配器](../../src/personal_agent/tools/mcp.py#L47-L100) · [动作结果](../../src/personal_agent/application/conversation/service.py#L3499-L3548) · [Web 响应](../../src/personal_agent/adapters/web/routes/conversation.py#L210-L225)

## 差距与最小验证

- **设计取舍。** personalAgent 的显式映射和主体策略用于约束可见和可调用范围，应作为分阶段曝光的前置条件。直接给出完整定义节省一次加载决策，适合工具少或几乎全会用到的场景。按需路径缩短的是完整定义的集合，还要付出目录、加载往返和工具列表变化的成本。
- **源码已证实的差距。** personalAgent 可以按部署、主体和 Goal 阶段筛选工具，缺少对同一个已授权工具集按任务逐步曝光完整定义的能力。当同一部署接入多个工具组时，未使用的完整 Schema 仍占据主请求空间。需要多大的目录才有净节省，以及缓存命中、工具选择和 CSV 交付是否改善，均待验证。
- **最小验证。** 先复用上述第 3 次逻辑请求做一次无网络的请求物化对照。固定用户原话、历史、模型配置、部署映射和主体，比较全量定义与只含已授权目录和加载动作的首步。随后用一个固定的合法加载输入物化下一步，断言只新增选中的 PDF 工具，原参数 Schema 与远端绑定一致。再以一个未授权工具名作反事实，核对当前主体的目录中无该工具，加载与执行均被拒绝。比较服务方序列化后的请求字节、输入容量估算及相邻请求的前缀变化，并计入一步加载开销。若目录加加载开销抵消定义节省，就暂缓采用。只有请求层收益成立且已有用户问题可定位时，才用原题、原评分器和相同预算核对 CSV 交付与实际用量。本次证据为源码走读及历史归档复核。[可见性边界](../devSpec/context-memory-retrieval.md#3-capability-projection-与服务提供方绑定)
