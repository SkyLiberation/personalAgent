# 网页发现与指定来源读取分离

本文只描述 `CONVERSATION-RESEARCH-STOP-001` 的最小候选，准入状态由
[优化队列](design-optimization-backlog.md)唯一维护。历史结果由
[当前评测用例盘点](../evals/02-current-case-inventory.md)拥有。

## 目标与准入依据

变更类型为新 Runtime 工具机制，不按缺陷修复豁免消融。用户结果仍是原显式验收研究请求的中文比较正文、
官方引用支持和未扩大保证范围。原用例经过正式 HTTP 入口，未指定工具、查询、次数或措辞，结果断言合理，
继续使用 `CONVERSATION-RESEARCH-DELIVERY-001/tool-protocol-explicit-review`。

候选实施前已核对 251 个生产源文件与封存的 source-index target 一致，原请求重建哈希一致；该 target 未交付。
轨迹多次通过不同搜索重复抓取同一正文；既有工具只能附带抓取前两个结果，模型不能直接指定已知 URL。
固定 Context Offline Eval 还观察到猜测长句导致零命中，但不能据此证明证据已充分或预算必然不足。
本步骤只解决前一工具表达缺口，导航问题保持独立，不把相关性冒充全部超预算根因。

## 未闭环的因果主张与边界

候选代码和工具协议由 [Context 工程](../topics/context-engineering.md#网页来源正文保留与重读)拥有；
本文不保留已完成的实施清单。唯一变量仍是模型可调用的发现/抓取契约从耦合变为分离，必要的参数、返回类型、
描述和装配迁移属于同一机制。

待证明的主张是：模型直接选择来源后，能避免为了抓取而反复搜索，并在原预算下交付原用户结果。
已能调用指定 URL、成功保存正文或实际读取一份窗口，都不能单独证明这一主张。新的失败没有否定正文抓取和
保真机制，也没有证明增加语义检索、缓存、预算或强制停止就是正确下一步。

模型拥有来源、窗口、证据充分性与 Final 决策；抓取层拥有来源执行事实，Conversation 拥有物化和读取授权，
ArtifactService 是卸载正文唯一写入口。后续归因不得让 Runtime 编造支持关系或替模型完成取证。

生产改动的范围外保持：`web_find`、语义检索、重排、主内容提取、缓存、强制停止、预算判定机制、Final-only、Verifier、
模型及个人知识工具。按用户调整的顺序，先核对独立宽预算样本的交付质量，再决定是否继续 Context 优化；
用户选定的后续运行配置由[对话运行预算](../env.md#对话运行预算)拥有；配置调整不作为工具拆分的消融。
当前不叠加 Context 生产机制。

## 后续修正的准入边界

来源覆盖、Final 的支持关系判断、旧稿传播与独立评分错误已有可定位反例；
责任链与证据限制见[根因定位结论](C:/pae/root-cause-synthesis-20260908/conclusion.md)。
尚无针对这些边界获准的生产修复，不得借搜索/读取分离候选安装新的 Context 或 Verification 机制。

后续候选必须同时验收证据覆盖时的准确完整交付，以及缺证据时的如实限定；
不能把一段正文当成全文、把通用知识归给本次读取，或把真实引文当成相邻结论必然有依据。
关键词零命中可支持精确查词的负结果，不能证明整份资料不存在某项语义要求；
不得用全局非空窗口门禁或否定词规则替代模型的支持关系判断。

每次仅对一个明确责任边界准入，覆盖完整生成、缺证据限定、精确负查询、其他主题与真实改稿。
输入选择候选必须区分来源原文与模型旧结论，并保留真实改稿必要的正文细节和失败反馈；
不能全局删除草稿、评审回执，或同时删除反馈、补正文、改 Prompt 后声称单变量收益。
Conversation 不改来源事实、原始日志或完成判定。没有独立证据，不新增判别阶段、事实抽取、引用协议、来源状态或模型调用。

支持关系错误、输出不完整与服务截止必须分别验收。非空截断被解析器接纳的确定性缺口不属于本工具候选，
不得将其修正混入工具分离消融，也不能用增加输出预算或只返回标题规避完整性验收。
局部正确、全部拒答和窄任务判别均不能替代原用户结果；禁止复制固定答案、变更原 E2E 标签或省略用户要求制造通过。
历史重建输入不能冒充原请求逐字回放，现有首次 Final 完整请求反事实也不是产品 E2E。

后续如需新样本，须同时审查 token、模型轮数和工具次数，预声明有界配置、单样本成本与停止条件。
真实 target 保持原用户输入、正式生产链、模型、工具、Verifier 和结果评测契约；仅允许已独立准入的候选变量。
离线固定输入不能冒充正式 target；正式链不注入中间结果，不强制 Final。
哪个上限实际命中，由已提交用量和生产边界确定；是否完成，仍由原用户结果判断。
后续诊断不新增状态、Port、表、模型调用或生产开关；显式记录实际预算，不改写历史样本的配置身份。

完整正确性核对成立后，再将该配置作为质量基准，定位实际高成本阶段，为 Context 候选定义独立单变量对照。
宽预算通过不代替原配置的修复验收，也不能直接关闭工具拆分的收益门禁。
若仍因其他限制、服务失败或语义错误中断，记录最早阻塞并停止该样本，不能直接归为 Context 设计失败。
不同随机轨迹和不同预算配置分别报告，不以偶然通过证明原预算必然不足，也不以局部输入变短代替净收益。
单次体积上限和累计资源上限仍保留，禁止恢复预算触发的工具隐藏或替代答案。

实际结果和失败位置见[本候选评测记录](../evals/02-current-case-inventory.md#网页发现与指定来源读取分离候选)，

[离线诊断归档](C:/pae/web-read-contract-offline-20260904/audit/20260904T155835.866223Z-12436-4ebb276c/read-contract-window-audit.1.trace.json)。
主指令冲突的固定输入对照及未准入原因见
[正文定位对照记录](C:/pae/read-navigation-system-20260905/conclusion.md)。Future 不复制运行流水。尚需完成：

1. 验收条件的任务中性投影及删除强制 `answer` 分支已有责任边界检查；宽预算样本已进入 Final，原预算用户结果及交付质量仍待验收。
   本步骤按恢复既有用户目标边界的缺陷修复验收，不替代工具拆分的新设计消融；正式结果与定位线索见
   [边界修复记录](../evals/02-current-case-inventory.md#验收条件不再推导改稿任务的边界修复)。
   用户消息拥有目标，模型拥有语义判断，Conversation 拥有反馈投影。单次草稿错误与完整修订链失败分开判定；
   不以单次改稿回答正确作为删除错误任务假设的唯一门槛，也不把允许 typed 失败当成用户成功交付。
   `InteractionIntent` 提取与 `FinalMessage` Schema 说明的独立疑点仍待归因，不随本次边界修复一并修改；
   相邻输入证据见[修订链与上游提取验证](../evals/02-current-case-inventory.md#既有修订链与验收标准提取的离线验证)。
   原研究 E2E 通过前不扩大修改或运行其余昂贵 E2E，不新增任务分类字段，不把随机配对当作确定性收益。
   原文消费、来源权威性、完整产物和服务提供方截止信息仍需分别核对；定位词冲突不能解释全部失败。
   来源执行事实归抓取层，请求投影归 Conversation，来源选择和支持关系归模型；没有责任主体证据时，
   不添加索引、语义检索、来源过滤、预算或 Verifier 补丁，局部 Plan 或进入 Final 不作为用户结果门禁。
2. 新设计的独立 target-minus-mechanism 正式入口对照。使用实施前独立代码身份及同一用户输入、初始事实、
   配置和独立 grader，复核差异只属于该候选；没有生产 flag、兼容别名或第二入口。低成本工具 Contract
   不是正式消融，两条随机轨迹也不证明确定性收益。
3. 原 `CONVERSATION-RESEARCH-DELIVERY-001/tool-protocol-explicit-review` 的真实用户结果。
   不降低比较正文、官方支持和未扩大保证范围的原断言，不固定工具、查询、次数、顺序或措辞。

指标分别报告交付、错误保证、代码/配置身份、局部消费、Agent/grader tokens、时延及 Provider 失败。
局部检查点要求模型自主选择 URL 取得正文并由后续模型实际消费原文或精确窗口；索引存在不算消费。
用户结果必须通过、错误保证为零；成本作诊断，不设任意比例或次数 gate。

后续 live 仍先 collect-only、impact routing 和单样本成本登记，遵守既有超过 60 秒停止新增样本规则；
没有通过局部准入的生产变更时，不为重复取样运行昂贵 E2E。没有证据时不扩大样本刷通过。
候选自身检查点失败、引入回归或无法归因时停止叠补；
一次有界修正后仍复现则重判边界，只撤回被直接否定的部分。产品失败与已成立局部事实分开保留。

## 准入收敛

不增加层、Port、表、缓存、Provider 或模型调用。后续若需要新增结构，必须重新说明其针对的失败事实、
唯一 owner、生产消费者、删除反事实及验证顺序，不能借本候选直接扩展搜索工具全栈。

新设计验收后，机制取舍迁入权威专题或 ADR，删除本文中过期候选；原用户结果全部成立才移除队列问题。
若只验收局部机制，剩余问题独立登记，不以“工具拆分完成”冒充“研究及时交付完成”。
