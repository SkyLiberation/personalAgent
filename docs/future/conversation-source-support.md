# 研究回答的来源支持关系修正

**修正目标是让最终答案的论断不超出来源能够支持的对象、条件和范围，而不只是附上真实 URL。** 本文覆盖[设计优化队列](design-optimization-backlog.md)中研究交付项的来源支持修正及其评测前置条件；准入状态只由队列拥有。Verifier 已接入后的语义缺口仍由[语义验证设计](conversation-verification-false-positive.md)拥有，网页工具分离仍由[工具设计](conversation-web-research-tools.md)拥有。

每轮验证的输入条件、结果、候选取舍和结论更正统一维护在[优化推进记录](../optimization/conversation-source-support.md)。继续本设计前先核对该记录，保留已有局部成功条件；本文只维护活动方案及剩余准入证据。

## 1. 基线与目标边界

**已有反例足以准入有界候选，但不能证明某一句 Prompt 是唯一原因。** 历史正式研究请求要求中文比较工具选择、权限和结果契约，引用能够支持结论的官方资料，不扩大保证。Final 把未读到要求扩大为规范没有要求；Verifier 又把这种否定陈述当成谨慎限定。完整原始响应的独立反例还把结果解释当成工具选择依据。原始结果、输入缺失限制及责任链见[根因定位报告](C:/pae/root-cause-synthesis-20260908/conclusion.md)。

本项恢复既有带来源研究回答契约，按缺陷修复处理。每一步保留原始反例、责任边界反事实和同入口真实 target；不把独立随机轨迹当作单变量消融。若引入额外运行机制并声明新的效率或能力收益，必须另行按新设计准入。

当前生产生成模型为开启 thinking 的 MiMo，配置由[模型配置](../env.md#llm-配置)拥有。用户授权的模型对照固定已封存的 Final 请求，单独记录服务提供方、模型及适配器参数差异；分析结合可见推理文本，必要时对话追问具体推断依据，再用输入前提反事实核验解释。事后自述不能成为来源事实或因果证明。诊断预算不足时先扩大并保留原始失败，成本优化后置；组件结果不能替代产品验收。范围外：不恢复预算触发的 Final-only 工具隐藏，不增加知识写入、后台任务、委托或数据库；不要求固定工具、查询、读取次数、标题、篇幅或答案措辞。

## 2. 先定位并修正生成，独立评测后置

**按用户最新要求，先处理 Final 为什么超出来源支持范围，暂停独立评测器候选。** 生成定位和组件资格使用已封存原文、明确的人工标签及同输入反事实，不再以评测器校准作为开始生成工作的前置条件。人工审计不能改写历史 E2E 或替代自动用户结果验收；生成候选取得独立证据后，再处理必要的评测校准与正式验收。

### 2.1 后置的参考覆盖边界

- 失败事实：真实 Final 已取得授权规范正文，但独立评测只收到三个有限摘要。已有只增加授权原文的反事实消除了特定的参考缺口拒绝理由，却没有解决整体误判，见[评分器诊断](C:/pae/grader-order-diagnosis-20260908/conclusion.md)。
- 责任主体：评测资产拥有版本化参考；来源工具拥有抓取事实。生产草稿、Plan 和 Verifier 通过意见不是官方事实。
- 条件修正：恢复评测工作后，将已封存并核对的官方授权章节纳入评测参考，保留版本、OPTIONAL、传输和受保护服务器等适用条件。不让评测器联网，不用答案自称的来源填充事实，也不把生产总结作为参考。
- 因果路径：消除评测输入缺口，使后续支持判断有机会判断同一论断。参考未覆盖的新论断仍须报告无法确认，不能被判成已证伪或默认通过。
- 反事实与退出：固定历史答案，对照加入前后输入；只验收参考到达与授权条款判断，不要求整份答案通过。保留历史原判，不合并不同参考版本的分数。

### 2.2 重新区分局部支持判断与全答聚合

**本节条件方向暂停，不再继续局部判别或逐块评测试验。** 同一单缺陷在局部输入中被拒绝，在完整输入中被接受；实际请求对照及单样本限制由[局部与完整输入诊断](../evals/02-current-case-inventory.md#局部与完整答案的支持边界诊断)拥有。该观察不能证明全答聚合是唯一根因，也不能用局部通过恢复已失败的仅分类候选。以下条件仅在生成问题取得独立修正证据后重新审查。

- 失败事实与必要性：只移除其他答案块后，模型能够拒绝同一句无据断言；保留完整答案时仍漏放。尚不能区分删去上下文的影响与判别职责收窄的影响，不能直接增加分阶段调用。
- 责任主体：模型拥有开放语义判别，评测资产拥有原文、参考与人工标签，确定性代码只校验协议并合并判定。两个正式消费者只读取 `ResearchAnswerVerdict.passed`，没有自动修订消费者；生产 Verifier 所需的反馈不能照搬本评测取舍。
- 下一条件方向：保留同一完整答案、全部参考和原文块编号，只将一次请求的被判定对象明确为其中一个原文块；其他答案块仍可用于理解主体、条件、否定和引用。该诊断只改变判别对象范围，不删除其他原文，不生成第二份论断事实。
- 最小因果路径：完整上下文中的局部职责能够正确判别，才有资格研究全答覆盖与确定性聚合；仍失败时，不能用本次裁短输入的成功准入逐块机制。选择块的坐标只能用于隔离诊断，正式评测不得只检查预先知道有错的块。
- 排除与复杂度：不恢复自由改写抽取，不把原文分块当成完整论断清单，不增加来源过滤、投票、模型切换或输出额度。尚未准入逐块生产调用、额外状态或通用评测编排。后续若提出逐块候选，须先证明全部原文覆盖、跨块条件保留及全部调用的成本，而非只报告最后一次调用用量。
- 证伪与退出：目标块自身的无据断言必须拒绝，但其他块独有的错误不能污染该块判断；指代、条件或引用跨块时不得丢失。下一诊断须包括这两侧反事实，不能仅拒绝当前已知错误。无新的责任证据时停止该方向；候选整体仍须接受完整正例、拒绝原负例和全部单缺陷长对照，并验证覆盖合并、其他中文表达、标题缺正文与不可信指令边界。

外部分类协议只说明消费者边界可行，不能证明当前模型判别可靠；已核对源码与调用者见[来源补齐审计](C:/pae/source-support-candidate-20260908/version-audit/20260908T121659.620496Z-24280-31043b1e/audit.1.trace.json)。独立诊断运行前须重新固定唯一变量、输入、模型、协议、样本量、完整成本与停止条件。全部校准前不替换 canonical grader，不将候选接入生产 Verifier，不启动原 target。用户新授权的生产 Verifier 隔离验证由第 4 节与其独立设计拥有，不恢复本节离线评测候选。

## 3. Final 修正只改变支持范围的生成责任

**Final 直接修正与交付拦截分别记录，不通过 Verifier 的局部拒绝掩盖上游生成问题。** 用户于 2026-09-10 授权先开展[生产 Verifier 的隔离资格验证](conversation-verification-false-positive.md#3-条件候选与因果准入顺序)，本节生成候选与其他旁支暂不同时修改。固定原文和人工标签用于组件资格验证；生产闭环仍须使用可靠的自动结果验收。Final 模型仍拥有语义合成；Context 代码只能忠实投影已观察内容，不能替它判断证据足够或规范没有要求。

### 3.1 从实际生成请求定位无据推断

**来源越界已定位到取证范围判断和成文支持关系，当前没有获准进入生产的生成修正。** 阶段协议不是已证明的唯一原因，现有无进展反馈也不能被当作缺失机制重建。原始反例、候选取舍和模型对照由[Action 取证诊断](../evals/02-current-case-inventory.md#action-取证充分性与来源范围诊断)及[MiMo thinking 记录](../evals/02-current-case-inventory.md#mimo-thinking-成文与对话反问诊断)拥有；不再叠加同类 Prompt。用户新授权的 [DeepSeek 固定输入对照](../optimization/permission-inference.md#16-固定最终答案禁令输入的-deepseek-模型对照)暴露空正文与阶段理解错位线索，未取得可比较的最终论断；后续先独立核对历史动作记录与当前 Final 能力边界，不以模型档位轮换或增加思考量代替归因。

- 必要性：独立组件请求已暴露“用未读页面的假设缩小取证范围”和“将来源条款用于不同主体或对象”；[连续链路基线](../evals/02-current-case-inventory.md#mimo-thinking-连续链路与意图输出预算)又观察到思考截断使验收条件丢失，取证失败后采用研究报告仍产生权限责任扩展。须先消除已证实的输出额度阻塞，再判断来源支持关系；完整 JSON 和带提示的对话纠错均不能证明独立生成可靠。
- 责任主体：用户请求拥有任务范围；模型拥有资料相关性、证据充分性和答案合成的语义判断；来源执行系统拥有实际读取结果，Conversation 拥有阶段切换及 typed 输入投影。评测器只拥有测量，不能选择生产取证动作或补写答案。
- 已成立的前置修正：意图及 Action/Final 输出额度扩大后，同入口恢复了用户验收条件、合法动作与完整成文；当前额度由[模型配置](../env.md#llm-配置)拥有。扩充运行仍出现来源越界，不能把预算修正声明为语义修复。后续遇到必要诊断预算不足，继续按用户授权扩大并保留旧结果。
- 下一责任边界：依据[读取识别与工具使用记录](../optimization/document-absence.md#4-读取摘要已证明局部范围识别)，保留已有效的真实读取信息及其位置，固定当前工具接口，核对这些信息确实进入被测 Action 或 Final。然后分别检验自主取证与成文论断的来源支持，不把摘要存在、模型表达理解和最终回答正确混为一谈。诊断须区分原文明确否定、关键词检索未命中和本次尚未观察；新候选必须在原任务中保持有据交付，不能只在明确补读或定向纠错后通过。不重复叠加同类摘要、Final 提示或删除计划候选，也不使用无摘要的旧回放来否定范围识别改善。不要求全文读完或遇空自动续读，工具语义与成文规则不同时调整；评测器继续后置。
- 局部检查与原始结果：分别核对错误是否在恢复后仍成立、实际新增原文是否补足缺口、最终论断是否保持来源主体与条件。原 E2E 结果保持原验收契约；人工来源审计只用于定位，不覆盖评测结果或宣称交付通过。新问题是用户授权的独立诊断，不替代原原子用例验收，也不扩展昂贵矩阵。
- 当前归因重点：依据[末尾摘要进入 Final 的验证](../optimization/document-absence.md#8-保留末尾读取摘要的-final-验证)与[单句计划前提干预](../optimization/document-absence.md#9-计划中的否定结论是否是必要前提)，范围识别与语义否定仍可同时出现，清除计划中的对应否定也不足以修复。后续固定已有读取信息，具体核对字面零新增匹配到单页没有规定、应用执行到权限归属的错误推导，以及总结时丢失限定；不继续移动摘要或扩大删除计划。原文审计须按来源与连续 offset 处理跨片段引文，避免把检查器漏拼接当成生成错误。新候选必须区分所问属性缺依据与已有有据结论，尚未准入新增 Prompt、状态或强制检查阶段。
- 新候选取舍：依据[同次生成绑定论断与来源的验证](../optimization/permission-inference.md#10-同次生成中绑定论断与来源)，当前 `cited-units-v1` 虽能返回合法引用位置，仍将无据权限结论标为 supported，未获准进入生产。引用可定位与论断受支持须分别成立；不继续增加标签、引用字段或同义自检。结合[原始思考与决策反问](../optimization/permission-inference.md#11-根据原始思考记录反问引用决策)，优先区分支持判断标准被放宽和原文位置读取不准确：模型复核时仍认可无据权限推断，同时错配引用内容。完整性压力仅为带提示自述假设，不能据此削弱任务。先核对旧选材、蕴含试验的覆盖，再决定新的责任对照；持续用思考与反问获取线索并逐项核对，不直接新增第二模型判定阶段。按用户偏好保留明确“禁止”的措辞，但[显式禁令验证](../optimization/permission-inference.md#13-显式禁止经验补齐的固定输入验证)已经显示当前整段规则不足以修复原失败输入，未获准进入生产；不继续增加同义禁令或机械加长思考。[约束理解反问](../optimization/permission-inference.md#14-反问模型如何理解显式证据约束)显示模型可以解释主要禁令，却在具体前提判断上仍含糊；后续分开测量一般理解、具体论断应用和独立成文，保留原文定位核对，不以规则复述或定向纠正代替交付。[最终答案范围验证](../optimization/permission-inference.md#15-将禁止直接限定到最终答案的验证)亦未通过，不能继续仅以禁令缺少适用对象解释失败；重点核对未观察到如何被误判为来源明确否定。
- 前提取用与支持判断分开：既有读取摘要、明确续读和真实条款补入的局部收益保留，但都不能自动证明完整正文得到支持。当前生成、来源与展示责任已核对，模型返回时已经存在的错误仍由生成边界负责，Verifier 继续后置；实验引用协议不准直接迁入生产。[完整推进记录](../optimization/permission-inference.md#17-完整上下文中的权限前提敏感性)保存前提对照、反问、复核与模型试验的全部取舍，本文不重复运行流水。
- 当前事实与停止条件：[同输入 Pro 首次生成](../optimization/permission-inference.md#35-同一正式形状请求的-pro-首次生成对照)看到了未读范围，仍将文档级否定当作谨慎表达。[思考强度对照](../optimization/thinking-context-transport.md#37-思考控制参数与原生会话回传边界)正常结束仍失败，停止该强度分支。旧相邻示例已经覆盖观察缺项与整体否定，不再追加同输入模型轮换、同义禁令、引文顺序和同类示例，不恢复普通复核矩阵或改变默认 MiMo。[全文条件回查](../optimization/permission-inference.md#36-全文条件下的责任推断与补充来源范围审计)确认完整抓取正文与旧稿删除后仍存在执行职责推到权限职责、总结丢失限定的问题；不得以强制全文读取或局部三项正确作为总修复。[搜索摘要前提干预](../optimization/permission-inference.md#40-搜索摘要中的-sdk-校验否定是否是成文前提)删除相似 SDK 否定句后仍失败，停止该句删除分支，不扩大到全部搜索资料。不同组件的官方条款不能互相替代责任或验证机制前提。
- 下一准入边界：分别核对来源覆盖、具体谓词的支持关系，以及正文到总结的限定保持。候选须消费最早可定位的转换，保持完整中文任务及有据事实，提出能区别既有局部前提诊断和定向纠正的可反驳预测；仅换措辞、缩短题目或复制本题答案不准入。[相邻信息保持审计](../optimization/evidence-acquisition.md#38-相邻决策中的未完成取证信息保持审计)确认缺口仍在输入、后续推理仍提到补查，却在无新 OpenAI 原文时改称充分。[计划修正反事实](../optimization/revision-feedback-loop.md#39-误判完成后的计划修正通路反事实)确认不能重开旧完成项，但新增补证项与沿当前活动项读取仍有合法通路。不能以完整遗忘或协议封死补证解释该窗口，也不据此准入历史回传或取消完成项保护；新候选须解释缺口可见且允许补查时的充分性转换。未知可诚实限定，但不覆盖原成功交付 E2E。当前没有新增 Schema、生成阶段或事实结构获准进入生产；不迁移独立评测器、不固定全文读取，也不把人工补证当作自主取证。
- 条件修正：只有连续证据能定位一个最早责任主体后，才准入该边界的最小改动。若取证前已用无依据假设排除来源，修正范围判断；若充分原文已到达而成文仍错配或扩张，修正生成时的支持关系。两者不同时更改，不迁移独立评测器候选，不重新添加已有无进展反馈。
- 来源边界的暂缓候选：[HTML 正文审计](../optimization/source-extraction.md#41-内置抓取的-html-正文边界审计)确认内置全页提取混入移动导航，占用读取窗口；同页正文视图可让工具选择条款提前进入原容量范围。[成熟提取实现比较](../optimization/source-extraction.md#42-成熟正文提取实现的保留边界)的三个已测 Trafilatura 配置均删除任务相关原文，停止直接替换。按用户最新范围要求，核心来源支持问题解决前暂停正文提取及其泛化测试；保留已有证据，不继续核对其他页面，不将输入清理当作核心修复。
- few-shot 的当前边界：按用户授权完成[当前完整输入对照](../optimization/permission-inference.md#43-当前完整输入下的-few-shot-成文对照)，四个跨领域完整示例保留现有 thinking、读取信息和所有来源；仍从应用执行推出访问控制必须由开发者实现。本版本不进入生产，不追加示例或用当前测试用例及其答案做示范；不能外推 few-shot 普遍无效。后续须区分一般规则表达与具体前提判断，新的示例候选需要明确不同的假设和独立验证。
- 原文独立成文边界：[全部已读原文验证](../optimization/permission-inference.md#45-保留全部已读原文的独立成文验证)移除整段 Plan、发现摘要和执行反馈后仍有执行到权限、格式到约束缺失的推导。它们不是错误的必要输入，停止该投影及回添分支；原文内部导航与较长输入仍保留，不能宣称全部干扰已排除。生成问题保留，第 4 节独立验证交付拦截；其余旁支保持暂停。
- 反事实与退出：固定实际来源与用户范围，覆盖依据充分、不足且能继续取证、客观不可取得及用户明确限定来源的中文场景。候选必须保留完整用户任务、合法执行和诚实限定；仅拒答、计划自述或定向反问后承认错误不能通过。新候选失败则保存反例并撤回，只以新的责任差异重新准入，禁止拼接已失败候选重跑。

生产验收仍是原正式 `tool-protocol-explicit-review` target。`limitation` 可以证明诚实表达，不能替代原成功交付契约；诊断请求不冒充当前 192k 正式运行。

### 3.2 旧稿传播必须作为独立变量

补全正文仍复用旧稿的反例支持单独检查模型可见的 Verification Receipt。进入实现前先确认每个 `verified_draft` 的后续真实消费者及失败恢复用途。候选只能移除已经不再用于修订的旧通过稿在后续研究输入中的重复投影；journal、Receipt 绑定与真实待修订稿不得删除。

验证固定同一输入，只改变非权威旧稿是否投影；同时保留失败草稿加反馈的真实修订控制和用户明确改稿控制。若必须删除用户正文或修订上下文才能通过，则否决投影候选。该步骤不能声称解决首次生成的证据误配，也不与第 3.1 节同时更改。

### 3.3 独立信息获取循环的条件诊断

**按用户 2026-09-11 最新方向，先检查信息获取职责隔离，再决定是否需要改变生产编排。** [第 70 节机制比较](../optimization/evidence-acquisition.md#70-独立信息获取循环的外部实现与本地准入边界)核对 Claude Code 与 Open Deep Research 两个独立 A 级实现；这里只准入候选诊断，不以外部架构证明本地收益，也不改变第 1 节本轮不新增生产委托的范围。

- 失败与必要性：缺口可见且有合法补查通路时仍无新证据宣布充分，适合检查获取任务与主会话其他决策混合的影响；已读资料误释另行保留，不能全部归因于 Context 长度。
- 责任与最小边界：工具拥有读取事实，隔离循环拥有有界信息获取决策，Conversation 拥有最终答案，Verifier 拥有语义验证。先使用现有工具与授权来源做一个获取循环的隔离诊断；模型、预算条件及有效读取机制保持，不预建新 Agent 框架或持久化，不把研究摘要当官方原文。
- 因果链与反事实：从同一历史失败窗口启动，保留原问题与相同可访问资料，对比继续由主会话获取和独立任务上下文获取；允许模型自主继续读取，不人工注入缺失证据。记录实际找到的直接依据、保留的主体与条件、未解决范围、交回后答案支持关系及全部用量。独立随机轨迹只能作为带方差的诊断，不能宣称严格单变量产品消融。
- 用户结果与退出：不仅要求能指出缺口，还要求可取得时自主补证，并通过原问题的成功交付契约；来源客观不可取时的诚实限制单独报告。若只增加读取、摘要丢失条件、仍以主题相关代替支持，停止该版本并定位获取或交接的最早失败，不继续叠加 Verifier 标准。不得以全部读完、固定查询或固定调用次数替代结果。
- 当前验证结果：按用户要求暂停 GPT Researcher，包括其预算配置与 A2A 交接优化；第 71 节原始失败保留。[第 72 节](../optimization/evidence-acquisition.md#72-暂停-gpt-researcher-后的独立获取与原文交接验证)使用同一 MiMo thinking、历史原文与生产读取函数，独立获取后交回原文及发现，再用当前成文 Prompt 和来源必检核验。首版补读但提前结束；仅修正停止条件后继续至 72/122，仍将未读 25–64 判为导航，遗漏第 58 段结果格式依据。原文交接无损，模型摘要却扩大已读范围。首版有效误放，修正版协议失败，均没有触发有效拒稿后的新修订。本轮为 Offline Eval 加读取 Integration，不含外网搜索、自动回派和完整生产 Admission/Completion。
- 下一最小边界：当前版本经一次有界修正仍失败，停止追加同义规则与直接接入。重新区分工具实际覆盖和模型对“相关范围已核对”的判断；候选必须证明能自主找到被错误排除的相关材料，保持未知范围，并保护依据充分和客观不可取两种控制。读取次数增加、原文交接无损不等于关键补证成功；不能硬编码读满所有片段、向测试题人工补入答案，或把取证职责交给 Verifier。下一设计须重新固定最早责任、唯一变量与撤回条件，沿用已成立读取及修订机制，不从头重做。
- 对象诊断取舍：[第 75 节](../optimization/answer-object-mismatch.md#75-明确取证对象后的补证收益与范围残留)在明确执行结果的两种等义问法中均未复现参数对象混淆，其中一条自主取得并引用遗漏条款；另一条仍将 Chat Completions 示例推广为全部工具结果的结构，参数控制仍扩大保证条件。保留对象澄清与实际补证的局部事实，停止当前版本，不把人工改写题目当作生产自动澄清能力，也不据此新增通用取证阶段。
- 下一范围边界：覆盖门禁已按 [ADR 0021](../adr/0021-separate-document-absence-from-reading-coverage.md)接入目标代码，正式入口已取得未读拒绝、补读全文和回执绑定检查点；下一主线是整稿语义 Verifier 的对象与支持关系残留，以及原用户结果；长短来源混合时的缺项归属作为后续回归边界。保留第 83 节分类收益和第 84 节循环收益，不重复验证机制是否完全无用；普通未知误拒、转述扩展分类与 API／字段范围误判独立保留。若正式任务未触发缺项拦截，只记录实际达到的检查点，不以读取数量或最终回答状态代替拦截证据。过程见[第 85 节](../optimization/document-absence.md#85-覆盖门禁接入真实读取事实与生产工具)。
- 停止与恢复边界：[第 76 节外部比较](../optimization/evidence-acquisition.md#76-过早结束的外部研究循环与停止检查比较)支持具体缺口反馈与父级继续决策，不证明另一检查模型更可靠。后续隔离诊断须复用动作、读取、Final、现有来源必检和生产适配器的 `generate`，记录器只在传输边界观测；不能由诊断旁路推断生产没有补查或恢复。同一 Agent 再委托仍受现有防重复约束；本轮未证明该约束导致此次失败，解除限制须另有真实缺口恢复证据。最终 Verifier 不重新搜索全文，不新增未经证明的 Hook、额外 Verifier 或来源数量停止规则。
- 接入条件：局部职责收益成立后，先核对现有 AgentPort 与研究循环的装配和产物消费者，沿最小正式入口实现，按新增运行机制补足适用消融及真实 target；保留现有来源必检和修订循环。未完成证据门禁前只记候选，不变更队列资格。

## 4. 后续阻塞按责任逐项处理

**按用户 2026-09-10 最新要求，已将中文验证契约与独立来源支持标准接入正式 Verifier，在正式路径继续定位，不以上游生成完全修复为前提。** 按[Verifier 设计](conversation-verification-false-positive.md)固定同一草稿与真实可见证据，验证它能拒绝无据否定和错误支持关系、接受有据完整正文。独立离线评分器仍后置，其分阶段机制不能未经准入直接复制进生产；字段或调用次数由原反例和独立责任证明，不预设需要三次调用。局部拦截与生成器修订后的完整交付必须分别验收。

非空截断接纳、Verifier 漏计 token、MiMo 关闭 thinking 时温度未传递是另三个确定性缺口，不作为语义错误的总解释。thinking 开启时服务方固定温度，补传温度不能据此成为当前语义修复。若独立缺口阻塞当前步骤，分别在 Adapter 输出完成状态、模型用量归集或参数序列化边界建立独立 Contract，再回跑原 target；不得在本次语义候选中同时修改。对应历史反例见根因报告，参数条件见[思考控制核查](../optimization/thinking-context-transport.md#37-思考控制参数与原生会话回传边界)，不把人工扩大预算设为默认修复。

| LangChain Classic v1.4.0 文档所指 [listwise_rerank.py](https://github.com/langchain-ai/langchain/blob/79cab2dc7f58be720cac43db3677b4c1fd971f91/libs/langchain/langchain_classic/retrievers/document_compressors/listwise_rerank.py)，`_get_prompt_input`、`_parse_ranking`、`compress_documents` | 模型接收原文与文档 ID，返回排序 ID；代码以 `docs[i]` 恢复同一文档，调用方消费选中原文 | 采纳只选择、再恢复原文的职责，不采用固定 `top_n`、负索引或越界映射，不复制 Runnable 编排，不改正文和来源 |

这些机制均不赋予外部文本指令权限。评测输入只来自公开参考和当前答案；生产仍先按身份和作用域做可见性投影。此次没有新的外部副作用、恢复协议、缓存生命周期或跨用户存储。

## 6. 最小复杂度与证据计划

**先只实现隔离诊断，生产可达性没有变化。** 后续获准的修正必须沿 `ConversationService._decide -> Context materialization / conversation.final -> StructuredModelClient -> FinalMessage -> Verification -> Completion` 被消费，并有原反例与用户结果证据证明必要性。输入投影只在现有 materialization 边界实现，不增加新的事实 owner；不能因为新增选择 Schema 就默认加入生产阶段。

评测候选限制为一个模块中的覆盖、支持请求及确定性合并，不建通用评测编排框架。候选校准前不增加 canonical case 或生产依赖。若迁移成功，替换 `research_answer_outcome.py` 的整体判定请求及全部调用方，不保留新旧开关；分阶段全部用量必须合计，不能伪装成最后一次请求的用量。

当前按第 4 节验证已接入 Verifier 的来源支持判别与真实修订，第 2 节评测候选后置，不同时修改第 3.1 节生成链。新候选运行前固定原文标签、唯一变量、完整输入、成本与停止条件，不能续跑旧候选刷通过。已失败候选的原始代码与请求保留在隔离归档，过程取舍集中记录在 optimization；本节已失败的生成与独立评测候选未被生产或 canonical eval 采纳；另行获准的 Verifier 接入由其专题与推进记录拥有。原 target 的自动评测问题独立保留，不能被人工组件通过覆盖。

生产验收复用 `evals/product_baselines/test_conversation_research_review_001.py`；运行前完成 collect-only、代码身份和成本估算，保留原始用户请求。新 target 不沿用 384k 诊断结果作默认预算。机制检查点、原始用户结果和评分器自身错误分开归档。

每轮推进按 [optimization 联动规则](../optimization/README.md#与-future-的联动规则)记录实际条件、结果和经验，并同步本设计受影响的下一边界；仅在准入事实改变时调整队列。正式评测结果由评测权威文档拥有，Future 不保存重复调试流水。全部用户契约与适用门禁通过前，不声明修复或发布完成。
