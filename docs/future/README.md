# 未来设计索引

本目录只保存尚未闭环且未冒充当前事实的准入项。[待优化设计总清单](design-optimization-backlog.md)唯一拥有问题、状态和详细设计入口；专题文档不得维护第二份状态队列。

当前生产事实进入[当前核心架构](../summary/core-architecture-current-state.md)及对应专题或固定流程文档。验证优化过程和经验集中在 [optimization](../optimization/README.md)，原始证据独立封存，正式评测结果和发布门禁状态由评测权威文档拥有；这些历史记录不留在 Future 正文。

## 状态变化必须在同一变更收敛

实现或证据改变准入状态时，必须在同一变更更新总清单并整篇审计对应 Future 文档，不能等到发布或下一轮优化再清理。

| 状态变化 | 必须执行的文档动作 |
| --- | --- |
| 已进入目标代码，但候选检查点或其他门禁未过 | 只保留未闭环问题、候选边界、剩余证据与撤回条件；删除已完成步骤、已过门禁和失效替代方案，运行结果链接评测文档，过程取舍链接优化记录 |
| 局部机制已满足 EVD 验收条件，后续仍有独立产品失败 | 机制迁入当前事实文档；后续失败作为独立问题留在总清单，原始 E2E 保持失败，不声明产品完成或可发布 |
| 全部产品门禁通过 | 当前行为迁入权威文档，从总清单移除该项并删除 Future 详细设计；优化过程记录继续保留 |
| 候选被否决、撤回、基线否定或失去准入依据 | 从总清单和 Future 删除候选；取舍与经验进入优化记录，原始证据保留归档，跨模块决策按需进入 ADR |

总清单的数量、准入级别、问题和剩余门禁必须与正文逐项一致。已修复问题不能仍列为未解决，已通过验证不能仍列为待办。

全文审计必须删除失效的实施清单、门禁、调试流水、已迁出的机制说明，以及没有剩余决策、动作或退出条件的空壳设计。不得只追加“已完成”“最新状态”或纠偏段落，也不得用“历史”标记保留这些失效正文。清理 Future 不删除 optimization 中已记录的有效经验。

## 进入与退出规则

产品问题进入总清单或详细设计前，须按[EVD](../devSpec/change-evidence.md)取得最简单生产路径的失败 baseline、追踪记录和产品根因，并明确：

- 用户可观察结果、至少一个反事实，以及基线失败后定义的正式入口 target E2E；
- 所需能力盘点，每项缺失能力的责任主体、契约、入口、消费者、实施阶段、失败语义与测试；
- 决策与事实归属、唯一写入口、旧路径删除计划；
- 相对基线的收益指标及证据方案；验收时须有实际对照证据，不能只看对象存在或拼接独立用例。

文档、评测工具、静态分析和构建门禁等不改变产品行为的工程扩展，不编造产品 E2E。必须从真实命令行、CI 或文档入口执行可重复工程基线，自动证明当前输出不满足开发者目标，再定义工程验收、复杂度预算和删除路径。

仅做准入审计的文档可在 baseline 执行前登记，但必须同时满足：

- 总清单标为 `A0`，唯一允许动作是执行 baseline；
- 结构风险只写为待验证假设，不写为当前用户错误；
- 条件设计不得进入编码；baseline 已满足目标或根因不符时整份删除；
- 不提前创建接口、模型、伪实现、配置或测试旁路。

状态变化后的退出与清理统一按上一节执行。

## 详细设计必须是因果决策链

每个步骤必须完整填写[EVD 因果决策项](../devSpec/change-evidence.md#7-强制开发与设计流程)，不能只列“新增字段、调整 Prompt、扩大预算、增加重试”。前一步未取得预声明证据时，后续步骤只作为条件候选。

无法说明删除后哪条 target 会失败的结构，须合并、删除或保留为问题假设。E2E 阻塞时执行[QLT 阻塞处理](../devSpec/quality-security.md#2-e2e-阻塞按目标阶段和单变量处理)并引用审查结论，不在本目录复制第二套流程或运行流水。
