# 未来设计索引

本目录只保存尚未闭环且未冒充当前事实的准入项。[待优化设计总清单](design-optimization-backlog.md)唯一拥有问题、状态和详细设计入口；专题文档不得维护第二份状态队列。

未充分证明的机制候选正文按具体问题保留在 [`optimization/to_verify/`](../optimization/to_verify/README.md)，本目录只拥有准入决策与剩余门禁并链接候选，不能复制第二份方案。直接证伪候选的专属记录清理按[优化规则](../optimization/README.md#待验证方案与失效方案的保留规则)执行；未覆盖不等于否决。

优化验收与重新打开由 [EVD](../devSpec/change-evidence.md#14-真实用例驱动优化与验收闭环)拥有；准入状态变化后按下表收敛活动文档。

当前生产事实进入[当前核心架构](../summary/core-architecture-current-state.md)及对应专题或固定流程文档。验证优化过程和经验集中在 [optimization](../optimization/README.md)，原始证据独立封存，正式评测结果和发布门禁状态由评测权威文档拥有；这些历史记录不留在 Future 正文。

## 状态变化必须在同一变更收敛

实现或证据改变准入状态时，必须在同一变更更新总清单并整篇审计对应 Future 文档，不能等到发布或下一轮优化再清理。

| 状态变化 | 必须执行的文档动作 |
| --- | --- |
| 已进入目标代码，但候选检查点或其他门禁未过 | 只保留未闭环问题、候选边界、剩余证据与撤回条件；删除已完成步骤、已过门禁和失效替代方案，运行结果链接评测文档，过程取舍链接优化记录 |
| 局部优化的已确定真实用例达到通过条件，后续仍有独立产品失败 | 关闭对应局部问题，按实际接入状态维护当前事实，问题经验按[固化规则](../optimization/README.md#已解决问题的固化规则)进入 `completed/`；独立后续失败另立问题，原始 E2E 结果保持，不追加范围外门槛 |
| 全部产品门禁通过 | 当前行为迁入权威文档，从总清单移除该项并删除 Future 详细设计；优化结论与失败尝试摘要固化到 `optimization/completed/`，移除中间过程正文 |
| 候选被否决、撤回、基线否定或失去准入依据 | 从总清单和 Future 删除候选；取舍与经验进入优化记录，直接证伪方案的专属记录按优化清理规则处理，共享支持与产品证据保留，跨模块决策按需进入 ADR |

总清单的数量、准入级别、问题和剩余门禁必须与正文逐项一致。已修复问题不能仍列为未解决，已通过验证不能仍列为待办。

全文审计必须删除失效的实施清单、门禁、调试流水、已迁出的机制说明，以及没有剩余决策、动作或退出条件的空壳设计。不得只追加“已完成”“最新状态”或纠偏段落，也不得用“历史”标记保留这些失效正文。清理 Future 不删除 optimization 中已记录的有效经验。

## 进入与退出规则

产品候选进入生产设计与实施准入前，须按[EVD](../devSpec/change-evidence.md)取得最简单生产路径的失败 baseline、追踪记录及最早责任边界，并明确：

- 用户可观察结果、至少一个反事实，以及基线失败后定义的正式入口 target E2E；
- 所需能力盘点，每项缺失能力的责任主体、契约、入口、消费者、实施阶段、失败语义与测试；
- 决策与事实归属、唯一写入口、旧路径删除计划；
- 相对基线的收益指标及证据方案；验收时须有实际对照证据，不能只看对象存在或拼接独立用例。

文档、评测工具、静态分析和构建门禁等不改变产品行为的工程扩展，不编造产品 E2E。工程实现以真实命令行、CI 或文档入口的可重复依据证明约束，再按 EVD 定义验收与删除路径；纯文档整理可依据可定位的重复、冲突、过期条款，按 DOC 检查，不强制制造失败命令。

取得 baseline 前，按 [docs-first 流程](../devSpec/change-evidence.md#7-强制开发与设计流程)先登记问题、待证假设与可执行验收计划。该文档只进入准入审计，必须同时满足：

- 总清单标为 `A0`，进行基线准备、事实审计、baseline 及 [EVD 探索边界](../devSpec/change-evidence.md#13-探索与生产准入边界)内的隔离诊断，不准入生产实现；
- 结构风险只写为待验证假设，不写为当前用户错误；
- 条件设计不得接入生产；baseline 已满足目标或候选因果假设不成立时，撤回对应设计，必要诊断经验按优化规则保留；
- 不提前创建生产接口、模型、共享业务状态、配置开关或测试旁路；隔离原型只支持已声明的诊断边界。

状态变化后的退出与清理统一按上一节执行。

## 详细设计必须是因果决策链

生产设计按[EVD 因果决策项](../devSpec/change-evidence.md#7-强制开发与设计流程)说明问题、责任、机制、防护与证伪；同一因果改动可合并说明，不为每个字段或文件重复完整模板。不能只列“新增字段、调整 Prompt、扩大预算、增加重试”。前置依据未成立时，后续生产实施只作为条件候选。

设计正文按[设计文档写法](../chinese-writing-spec.md#61-设计文档写法)说明问题、解决机制和具体防护，相关验收条件由 EVD 拥有。

新增结构的必要性与可达性执行 [ARC](../devSpec/architecture-ownership.md#7-生产可达性)，证据选择与升级执行 [EVD](../devSpec/change-evidence.md#12-按实际影响选择证据)。职责或消费者无法确认时保留为问题假设，已确认无职责或消费者的结构合并或删除。E2E 阻塞时执行[QLT 阻塞处理](../devSpec/quality-security.md#2-e2e-阻塞按目标阶段和单变量处理)并引用审查结论，不在本目录复制第二套流程或运行流水。
