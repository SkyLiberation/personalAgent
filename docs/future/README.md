# 未来设计索引

**本目录只保存尚未落地且未冒充当前事实的准入项。** 当前生产事实归
[当前核心架构](../summary/core-architecture-current-state.md)和对应专题或固定流程文档所有；历史调试记录、
已完成阶段、已否决候选、测量报告和发布门禁当前状态都不能留在未来设计目录。

全部待优化问题、状态和详细设计入口由
[待优化设计总清单](design-optimization-backlog.md)统一管理；专题文档不得维护第二份状态队列。

## 进入与退出规则

产品行为问题进入总清单或创建独立详细设计前必须同时给出：

1. 已实际执行的最简单生产基线、失败结果、追踪记录和产品根因；
2. 用户可观察结果以及至少一个反事实；
3. 基线失败后定义的、从正式入口进入生产主路径的目标端到端测试；
4. 所需生产能力盘点，以及每个缺失能力的责任主体、契约、入口、消费者、实施阶段、失败语义和测试；
5. 决策责任主体、事实责任主体、唯一写入口和计划删除的旧路径；
6. 相对基线的收益证据，不能只验证新增对象存在，也不能把独立用例拼成组合能力证据。

## 详细设计必须是因果决策链

**详细设计中的每个步骤都必须解释为什么需要、为什么由该责任主体处理，以及怎样解决已经证明的问题。** 实施顺序不能只罗列“新增字段、调整 Prompt、扩大预算、增加重试、运行 E2E”；完整规则由[变更证据与设计准入](../devSpec/change-evidence.md#7-强制开发与设计流程)拥有。

每个步骤至少包含：

1. 它消费的 baseline 或最早失败事实；
2. 不处理时无法满足的用户结果或工程约束；
3. 决策责任主体、事实责任主体和唯一写入口；
4. 最小改动到下一个可观察边界的因果路径；
5. 同时出现但不属于本步骤的错误与范围外事项；
6. target、关键反事实、适用消融和撤回条件。

上一步没有取得预声明证据时，后续步骤只能写成条件候选，不能进入实现。无法说明“删除该步骤后哪条 target 会失败”的结构必须合并、删除或继续停留在问题假设，不得为了设计形式完整而保留。

详细设计被 E2E 阻塞时，必须引用[测试、评估、观测与安全细则](../devSpec/quality-security.md#2-e2e-阻塞按目标阶段和单变量处理)保存审查结论。顺序固定为：先确认用例目的和断言合理，再定位用户结果链上的最早关键失败；随后只修复一个责任主体，并先回跑原阻塞用例。该用例通过前，不得扩展生产修改、叠加第二机制或运行其余昂贵 E2E。

文档、评测工具、静态分析和构建门禁等不改变产品行为的内部工程扩展，不编造产品端到端测试；它们必须从真实命令行、持续集成或
文档入口执行可重复工程基线，自动证明当前输出无法满足开发者目标，再定义目标工程验收、复杂度预算和删除路径。

仅用于准入审计的文档可以在基线执行前登记，但必须同时满足：

- 在总清单登记为 `A0`，唯一允许动作是执行基线；
- 结构风险只写成待验证假设，不写成当前用户错误；
- 条件目标设计不得进入编码，基线通过或根因不符时整份删除；
- 不为该文档提前创建接口、模型、伪实现、配置或测试专用旁路。

能力落地后必须把当前事实迁入摘要、固定流程、接口或运维文档，并删除对应未来设计文档。
禁止在原设计后追加“已落地状态”“阶段完成记录”或服务提供方调试流水账。
