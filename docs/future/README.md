# Future 设计索引

**本目录只保存尚未落地且未冒充当前事实的准入项。**当前生产事实归
[当前核心架构](../summary/core-architecture-current-state.md) 和对应 topic/workflow 所有；历史调试记录、
已完成阶段、已否决候选、测量报告和 release gate 当前状态都不能留在 future。

全部待优化问题、状态和详细设计入口由
[待优化设计总清单](design-optimization-backlog.md) 统一管理；专题文档不得维护第二份状态队列。

## 进入与退出规则

产品行为问题进入总清单或创建独立详细设计前必须同时给出：

1. 已实际执行的最简单生产 baseline、失败结果、trace 和产品根因；
2. 用户可观察结果以及至少一个反事实；
3. baseline 失败后定义的、从正式入口进入生产主路径的目标 E2E；
4. 所需生产能力盘点，以及每个缺失能力的 owner、契约、入口、消费者、实施阶段、失败语义和测试；
5. Decision owner、Fact owner、唯一写入口和计划删除的旧路径；
6. 相对 baseline 的收益证据，不能只验证新增对象存在或把独立用例拼成组合能力证据。

文档、评测工具、静态分析和构建门禁等不改变产品行为的内部工程扩展，不编造产品 E2E；它们必须从真实 CLI/CI/
文档入口执行可重复工程 baseline，自动证明当前输出无法满足开发者目标，再定义目标工程验收、复杂度预算和删除路径。

仅用于准入审计的文档可以在 baseline 执行前登记，但必须同时满足：

- 在总清单登记为 `A0`，唯一允许动作是执行 baseline；
- 结构风险只写成待验证假设，不写成当前用户错误；
- 条件目标设计不得进入编码，baseline 通过或根因不符时整份删除；
- 不为该文档提前创建接口、模型、Fake、配置或测试专用旁路。

能力落地后必须把当前事实迁入 summary、workflow、API 或运维文档，并删除对应 future 文档。
禁止在原设计后追加“已落地状态”“Phase 完成记录”或 Provider 调试流水账。
