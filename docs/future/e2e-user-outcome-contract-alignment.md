# E2E 用户结果契约对齐方案

> **本设计只保留 `ASK-001B` 尚未解决的评测缺口，不改变生产行为。** 准入状态由[设计优化队列](design-optimization-backlog.md)中的 `E2E-USER-OUTCOME-CONTRACT-001` 唯一拥有；`ASK-001A` 已落地的 typed grader、Application Integration 分类和实际检查结果由[当前评测用例盘点](../evals/02-current-case-inventory.md)拥有。

## 1. 当前只剩工具机制解释没有结果级判定

**`ASK-001B` 仍可能在只返回项目代号和 OpenAI 官方 URL、却没有解释工具使用机制时得到通过。** 当前用例已经从正式 HTTP 入口经过生产 Composition Root、真实模型和目标 Agent 完整链路；缺口只在最终回答 grader，不授权修改 Agent、Prompt、工具、Context 或预算。

| 当前自然目标 | 当前可执行断言 | 尚未验收的用户结果 |
| --- | --- | --- |
| 结合个人资料与 OpenAI 官方 Agents SDK 文档，说明 Agent 如何使用工具并逐项给来源 | 随机项目代号、至少一个 OpenAI 官方 URL、作用域隔离和零写入 | 回答是否基于相关官方来源解释工具定义或选择、调用和结果使用，而不是只附带 URL |

`ASK-001A` 已由 case-specific grader 判断两条随机原文是否完整进入最终回答。`E05/E13` 已归类为 Application Integration，只证明研究与投递流水线事实。上述已落地事实不在本文维护第二份实施计划。

## 2. 结果判定不得固定 Agent 的实现策略

**候选 grader 只能判断用户看到的技术解释及其证据关系，不能规定 Agent 怎样取得答案。** 允许判定的结果原子只有：

- 回答给出当前用户保存的项目代号；
- 回答解释工具定义或选择、工具调用、工具结果如何进入后续回答；
- 至少一个相关 OpenAI 官方来源能够支持这些解释；
- 回答不泄漏其他用户资料，也不因 Ask 写入知识。

grader 不得要求固定标题、固定术语、固定句式、固定工具、固定 `Plan`、固定查询、调用次数、调用顺序或逐字复述模板。`Trace` 中的 Web Search、工具名和 URL 只能作为执行后路径证据；除非它们属于上述公开结果契约，否则不能阻塞 Product E2E。

## 3. 当前没有获准的 grader 机制

**确定性字符串规则与现有模型 grader 都没有达到当前准入条件。** 字符串共现会把“定义、调用、结果”等措辞固化为回答模板，无法可靠接受同义表达；仓库现有模型 grader 会再调用一次真实结构化模型，因此引入独立概率判断。用户已要求概率性问题后置，本项不能用未校准模型 verdict 替代缺失证据。

未来重新开启概率性评测时，候选必须先固定以下离线契约：

| 控制样本 | 必须得到的判定 |
| --- | --- |
| 正控制 | 项目代号正确，官方来源支持工具定义或选择、调用与结果使用说明 |
| 表达变化正控制 | 列表、表格、自然段及同义中文表达都通过 |
| 缺结果负控制 | 只有项目代号和官方 URL，没有工具机制解释时失败 |
| 断裂证据负控制 | 解释存在，但官方 URL 与解释主题无关时失败 |

模型 grader 还必须固定输入投影、模型与服务提供方版本、Prompt 版本、typed 输出 Schema、失败语义、重复次数和可接受方差。全部正控制稳定通过且全部负控制稳定失败后，才允许把 verdict 接入现有 `ASK-001B`；离线控制本身不是 E2E，也不能产生产品通过证据。

## 4. 最小边界与退出条件

**本项继续停在 `A1`，没有活动实现候选。** 重新准入时只允许增加 `ASK-001B` 的 case-specific grader、版本化控制数据和现有用例断言，不新增 live 旅程、通用评测工作流、生产模型、Prompt、工具、状态、数据库表、运行分支或测试旁路。

出现以下任一情况就撤回候选：

1. 表达变化正控制不能稳定通过；
2. 只有 URL 或证据断裂的负控制仍可通过；
3. grader 只能靠固定关键词、固定措辞或内部执行路径区分结果；
4. 候选需要修改生产 Agent 才能让评测通过；
5. grader 的模型、版本、输入、Schema 或失败语义无法固定。
