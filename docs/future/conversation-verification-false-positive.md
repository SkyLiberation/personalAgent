# Conversation Draft 语义验证隔离设计

本文是[设计优化队列](design-optimization-backlog.md)中
`CONVERSATION-VERIFICATION-FALSE-POSITIVE-001` 的条件详细设计。准入状态只由总清单拥有；
本文只保存尚未闭环的语义缺口与后续验证；已接入的来源支持检查由当前验证专题拥有。

## 1. 尚未解决的问题与证据边界

**当前需要解决的是：Conversation 根据反馈修掉一项无据推断后，Verifier 仍错误放行含其他来源支持错误的完整修订稿。** 第 65 节正式任务已经走通语义拒稿、Conversation 修订与重验；产品结果及独立后置评测失败见[正式迁移验证](../evals/02-current-case-inventory.md#真实修订循环在原研究任务中的迁移验证)。后续对象误判诊断以第 85 节最新完整失败稿及当时实际可见证据为依据；第 65 节保留为历史回归，不以旧短例或完整 Artifact 替换实际输入。

当前核心残留是正确条款已读到却被用于另一对象或被扩大要求强度。局部读取不足以支持全文否定的覆盖拒绝已在第 85 节接入并取得正式检查点，不再作为同一未解决拦截问题。已有读取与循环尚不足以保证完整语义修复，也不能证明上下文、注意力或规则表述的唯一因果。历史 Schema 对象扩大和标题与 Evidence 串扰仍分别保留，不能与最新不同错误混为同一反例。过程及旧候选取舍由[问题总览](../optimization/conversation-source-support.md)和[第 65 节](../optimization/revision-feedback-loop.md#65-原正式研究任务的循环收益迁移验证)导航，本文不复制实验流水。

既有摘要、同义禁令、独立标准与聚焦原句的失败取舍保留在[方法索引](../optimization/conversation-source-support.md#已尝试的方法与未证实假设)。已验证的覆盖分类与拒绝现已进入目标代码，正式入口的未读拒绝、补读和回执绑定检查点已成立，下一步优先定位整稿语义 Verifier 的对象与支持关系误判，混合长短来源归属作为后续回归边界；不能以独立语义错误否定该局部机制，或让 Verifier 重读原文。

范围外：本项语义设计不更改模型、传输、生产预算机制、Final-only、工具权限或 Completion；不规定标题、表格、
篇幅、工具、查询和读取次数；不把正确但有保留的回答一概拒绝；不修复独立的 Intent 来源跨度
问题或以扩大 Context 预算代替事实支持判断。

## 2. 责任主体与当前可达边界

| 责任主体 | 权威事实或决策 | 本项约束 |
| --- | --- | --- |
| `InteractionIntent` | 从用户原文派生验收要求 | 本次已经保留不得扩大保证的要求；暂不修改上游 rubric |
| Action 与 Final 模型 | 选择要读取的证据，并合成用户答案 | 全文存在不代表已经消费；不由 Runtime 伪造读取或答案 |
| Capture、Artifact 与 Context Materialization | 保存来源、提供实际成功读取的窗口 | 不能静默把未读全文加入原 baseline 的边界输入 |
| Semantic Verifier | 判断 Draft 是否满足要求、外部论断是否有据 | 不得用 URL 存在、主题相关或另一对象的保证代替论断支持 |
| Runtime 与 Completion | 校验报告、聚合判定、绑定已验证文本、执行结果契约门禁 | 不推断开放世界事实，不重新开放预算外工具，不生成答案 |

唯一生产写入口继续是 Runtime 调用的 `verify_interaction_draft`。正式路径已有可复核的请求
digest 与 Receipt 文本绑定；本次没有证据表明错误来自聚合、文本被替换或 Completion 绕过。

## 3. 条件候选与因果准入顺序

**保留已接入的中文验证契约、独立支持项和修订循环；分类结果的合法交接已恢复，下一步定位拒稿后为何仍不正确修订。** 当前行为见[验证专题](../topics/verification-and-completion.md)，工程决定见 [ADR 0020](../adr/0020-require-conversation-source-support-verification.md)。不再把接入必检、接通失败反馈或首次证明修订能力列为待办。

按用户 2026-09-16 要求接入的正文行坐标与随文引用已取得正式轨迹的局部检查点，见 [ADR 0024](../adr/0024-plain-source-tools-and-inline-citations.md)。原用户结果仍失败。已有 `FinalMessage.segments`、来源支持核验、缺项与覆盖门禁、修订循环保留。旧逐字复制协议、事后补引用器、同义禁令与固定范围自动绑定都不恢复为第二活动方案；历史失败与仍成立收益由[对象记录](../optimization/answer-object-mismatch.md)拥有。

原自然中文入口已经观察到自主搜索、按行读取、八稿合法引用交接及拒绝后补证；不能再把这些列为尚未执行。第 103 节下一最早阻塞是缺项分类返回内容的准确绑定：一次来源版本错误、四次引句非逐字错误，使这些稿件未完成语义核验。[第 104 节](../optimization/document-absence.md#104-按来源顺序返回缺项分类)已接入等长同序布尔输出，由代码恢复来源；局部控制及正式五次交接有效，四次未读缺项被正确拒绝。原任务仍因连续无进展动作停止，生成器修订未收敛；不恢复旧复制协议为并行方案。生成器仍可能从关键词零命中推到全文缺项；Plan 中也保留该判断，但尚未证明 Plan 是唯一或主要原因。后续按合法交接与语义修订分层验收，不让 Verifier 代写答案或重读全文。短编号仍是自由字符串，单轨迹不证明非法引用已经消失；原第 95、100 节失败保持。

当前分类交接的原子 target、预算、原始失败及停止原因见[第 104 节](../optimization/document-absence.md#104-按来源顺序返回缺项分类)；读取与引用机制的历史依据仍由第 103 节拥有。旧读取工具按用户要求暂留，但不暴露且准入拒绝；不通过降级路径或放宽缺项门禁来迎合。第 104 节最终连续无进展动作停止。第 105 节只把覆盖不足改为明确的中文计数、范围及修订反馈；实际请求契约已检查，但原正式用例在反馈触发前因终止计划下继续读而失败，行为收益没有取得覆盖。候选反馈保留为待验收改动，不改变循环或门禁；下一步先定位计划终止后仍申请取证的前置失败，不能把本次零反馈触发写成修订有效或无效。若后续再次重复全文缺项，不继续添加同义提示。后续仍须区分收到反馈、增加读取、真正修订与满足用户要求，不把改变坏引用或重复检索自动当成进展。过程与取舍见[第 105 节](../optimization/document-absence.md#105-用自然语言解释未完整读取与修订边界)。

若新边界仍漏判，保存原稿和反馈，重新判断所需的最小语义职责；不能预建第二验证服务、投票、固定三阶段、持久化或循环状态。文档缺项识别与覆盖判断的接入依据由 [ADR 0021](../adr/0021-separate-document-absence-from-reading-coverage.md)拥有；其他机制的准入以其独立证据为准，已撤回引用候选的证据与取舍见 ADR 0022。旧独立支持调用、提示重组、Context 裁剪及多问题对照的取舍见[方法索引](../optimization/conversation-source-support.md#已尝试的方法与未证实假设)，不恢复为并行活动方案。

拒稿反馈只定位原句、支持边界和缺失前提，不代写无据替代事实。诚实承认本次证据不足可以满足来源支持，却未必完成用户任务；不能通过删掉困难主题改变原交付契约。已有受控循环成功与真实修后误放分别保留，不把其中一项覆盖另一项。

## 4. 外部机制核对与复杂度约束

第 66 节已固定并核对 RAGAS 的
[`_faithfulness.py`](https://github.com/explodinggradients/ragas/blob/298b68274234c060deacab3cf5fb52aa3a20e885/src/ragas/metrics/_faithfulness.py)
和 FActScore 的
[`factscorer.py`](https://github.com/shmsw25/FActScore/blob/f28272deffcf33efc1f1117d5479c10bb75221a9/factscore/factscorer.py)。
前者分离声明生成与 NLI，仍可批量判别；后者逐事实请求模型。它们支持窄职责判别的实现可能性，
不能替代本工程收益；不采用自动抽取、平均分或启发式解析来宣布完整稿通过。后续若提出不同机制，
须重新核对其机制域，不能只凭框架名称增加阶段。

生产实现前还必须以本次完整可见输入预估并预注册调用数、token、延迟、样本量和停止条件。
旧短输入候选的成本上限不能套用于含多份读取窗口的真实输入，也不得为满足上限静默截断证据。
新增结构必须各有生产消费者和删除即失败的确定性判据，不增加数据库、缓存、Plan 或状态表。

后续候选须同步收敛替代路径；旧读取本轮按用户明确要求保留，边界与期限由 ADR 0024 拥有，禁止自动回退或长期无期限双轨。已完成的旧英文 Prompt 和标题拼接输入删除见当前专题，不在本目录继续列为待办。

## 5. 停止与退出条件

- 新候选只有取得局部收益并接入后，才验收同入口 target；已有正式运行不列为待执行。保存原始结果和独立检查点，不重复抽样直到出现期望轨迹，保留已接入的局部机制。
- 候选在事实支持检查点失败时，保留原反例，只停止或撤回被直接否定的部分，不全盘否定
  二态聚合、来源保存或其他已有独立证据的机制。
- 若错误必须先通过证据选择或解析边界解决，须记录该最早责任主体和对应反事实；不得把
  完整 Artifact 可用等同于当前 Verifier 已有充分证据，也不得同时叠加第二项生产修正。
- 真实 target 的独立失败只按其因果位置阻塞闭环，不能覆盖原失败或改成通过；原阻塞用例
  通过前不扩展其他昂贵 E2E，不声明修复完成或可发布。
