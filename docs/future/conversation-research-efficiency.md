# 普通对话研究效率优化方案

**本项只处理已经交付用户结果后的搜索、Context、token 和延迟效率，不参与 `CONVERSATION-RESEARCH-DELIVERY-001` 的完成判断。** 准入状态由[设计优化队列](design-optimization-backlog.md)中的 `CONVERSATION-RESEARCH-EFFICIENCY-001` 唯一拥有；执行数字和归档坐标由[当前 E2E 用例盘点](../evals/02-current-case-inventory.md)唯一拥有。

## 1. 当前证据只准入效率诊断

**已交付的 `tool-protocol-boundary` 样本显示工具结果和动作定义持续占用后续模型输入，但现有证据不能把问题简化为重复搜索。** 搜索结果中的 URL 大多不同，原始查询也没有进入 canonical Trace；当前只能确认广泛取证与累计 Context 同时存在，不能断言模型重复了相同语义动作。

失败的交付 baseline 不能充当公平的成本对照。它在生成完整用户结果前停止，成功 target 则包含最终综合与答案成本。任何效率候选进入 `A2` 前，必须先建立成功路径之间可比较的资源 baseline，或者预先声明独立于失败路径的产品资源包络。

## 2. 效率事实与用户结果分别归属

**用户结果由产品 E2E 判断，资源事实由运行系统与服务提供方记账。** 运行系统不得因为 token 较少就把不完整答案判为成功，也不得因为成功答案成本较高就否定已经成立的交付结果。

| 事实或判断 | 唯一责任主体 | 本项边界 |
| --- | --- | --- |
| 回答是否覆盖用户要求和官方来源 | 产品 E2E 评测器 | 固定用户结果与关键反事实 |
| 模型、工具和智能体调用量 | 运行系统 | 记录已提交执行事实 |
| 输入与输出 token | 目标服务提供方及其适配器 | 使用同口径 usage，不按字符猜测 |
| 动作定义和 typed inputs 的组成 | Context 物化边界 | 记录每轮组成，不决定语义完成 |
| 最大资源包络 | Policy | 限制不可突破的上限，不作为任务复杂度评分 |
| 是否采用效率候选 | 设计准入 | 只依据成功路径 baseline、单变量 target 和用户结果保持证据 |

## 3. 先定位主导成本，再选择一个变量

**当前不得同时实现动作投影、结果卸载和 Context 压缩。** 下一步只从既有归档和重复成功 baseline 判断哪个组成稳定主导输入；没有稳定主导项时，本项退出，不为降低单个样本数字增加生产机制。

候选必须按以下因果条件选择：

| 条件候选 | 必须先观察到的成功路径事实 | 为什么可能解决该事实 | 证伪与撤回条件 |
| --- | --- | --- | --- |
| 收缩动作定义投影 | 相同用户结果下，早期输入持续由当前阶段不可用的动作定义主导 | 删除无消费者的 Schema 可以直接减少每轮固定输入，不改变模型已取得的证据 | 固定输入不再主导、用户结果退化或资源指标未达门槛时撤回 |
| 复用 `ArtifactRef` 或有界重读 | 已提交工具结果在后续回合重复物化并稳定主导 typed inputs | canonical Artifact 保持事实不变，只按当前需要读取有界窗口 | 出现证据缺失、重复外部调用或资源指标未达门槛时撤回 |
| Context 压缩 | 真实服务提供方可重复出现窗口压力、错误截断或请求无法发送，前两项不足以恢复 | 压缩只在已证明的发送边界减少历史表示，不改变 canonical facts | 没有真实窗口失败、摘要成为第二事实源或用户结果退化时不得准入 |

两类组成均不稳定时，只继续收集最小成功 baseline，不实现候选。每次只能选择表中一行作为唯一变量；上一候选未取得 target 与消融证据时，不得叠加下一候选解释收益。

候选不得通过用户关键词硬编码工具选择，不得丢弃仍属于 required result contract 的证据，也不得新增可写摘要副本、通用 Budget Planner、任务复杂度分类器或三档 token 表。

## 4. 准入前必须建立公平成本 baseline

**效率 baseline 必须比较能够交付同一用户结果的路径。** 在任何生产实现前，评测设计必须固定正式入口、自然输入、身份、初始事实、服务提供方、评测器、用户结果和关键反事实，并预先声明样本量与成本指标。

baseline 至少记录：

- 用户结果是否交付；
- 模型决策回合、工具与智能体调用量；
- 输入、输出和总 token；
- 每轮动作定义、能力投影与 typed inputs 组成；
- Conversation call 延迟和外部服务等待时间；
- usage 是否完整，以及服务提供方或入口错误。

只有用户结果达到预声明门槛后，成本分布才参与候选判断。未交付样本继续作为产品失败事实，但不与成功 target 直接计算成本改善比例。

## 5. 最小验证复用现有 E2E

**本项不创建第二条研究旅程，也不增加完整发布矩阵。** baseline、target 和 target-minus-mechanism 消融复用 `CONVERSATION-RESEARCH-DELIVERY-001` 的自然输入和评测器；效率报告只读取同一密封归档中的用户结果与资源事实。

候选进入 `A2` 前必须预先定义：

1. 唯一生产变量及其消费点；
2. 用户结果保持门槛；
3. token、调用量或延迟的对照指标与样本量；
4. `provider_failure` 与产品失败的分离规则；
5. 独立消融代码身份和退出条件；
6. 预期删除的旧注入或投影逻辑。

target 若降低资源数字但损害用户结果，候选失败。target 若保持用户结果但没有达到预声明效率指标，候选同样失败；不得把多个未通过的机制叠加成一次成功。

## 6. 复杂度与退出条件

**本项只允许删除或收缩现有 Context 物化，不预建新的运行系统。** 候选不得新增持久状态、Repository、Router、固定流程、智能体、通用缓存或第二份 usage 事实。

重复成功 baseline 无法复现稳定成本问题时，直接从设计优化队列删除本项。单变量候选通过用户结果、成本指标、独立消融和受影响回归后，把当前事实迁入 Context 专题与评测权威文档，再删除本文和对应队列项。
