# 开发与设计细则索引

> 根目录的 [`AGENTS.md`](../../AGENTS.md) 与 [`CLAUDE.md`](../../CLAUDE.md) 是逐字一致的主文档，也是所有任务的规范入口。本目录只承载主文档按任务类型链接的细则，不能脱离主文档独立解释或放宽门禁。

## 1. 渐进式披露规则

每项任务先阅读一份主文档，再按主文档的“任务路由”读取命中的细则。一个任务命中多个任务域时，必须读取这些任务域的全部细则；不能只选约束更少的一份。未命中的细则无需预先加载。

规范采用以下三层披露：

1. 主文档保存适用于所有任务的最高铁律、任务分类、细则路由和完成门禁；
2. 本索引解释细则之间的责任边界，不重复规则正文；
3. 各细则保存只在对应任务域内需要的完整契约、反例、模板和检查项。

当主文档与细则发生冲突时，以主文档为准，并在同一变更修复冲突。`AGENTS.md` 与 `CLAUDE.md` 必须逐字一致；两者不同属于规范入口损坏，不得继续实现。

外部智能体参考不是第四层规范。只有任务明确比较外部机制时，才经根 `REF` 路由读取 `docs/agentRef/README.md`，再按组件信号加载相关资料；这些资料不能放宽前三层规范。

## 3. Codex 官方机制与本工程选择

本工程采用“根入口保持精简、任务命中后显式读取细则”的结构。该结构基于以下 A 级官方资料，访问与复核日期均为 2026-08-27：

| 官方坐标 | 可复核契约 | 本工程采纳 | 本工程不采纳 |
| --- | --- | --- | --- |
| [OpenAI Docs：Custom instructions with AGENTS.md](https://developers.openai.com/codex/guides/agents-md) | Codex 在工作前读取 `AGENTS.md`；从项目根目录向当前目录组装指令；更近目录的指令后加载；`project_doc_max_bytes` 默认上限是 32 KiB；规则应简洁，格式检查应交给 CI | 根 `AGENTS.md` 保存仓库级门禁；`docs/AGENTS.md` 与 `evals/AGENTS.md` 保存目录局部规则；主文档控制在 32 KiB 内；可机械检查的入口同步、行数、链接和路由交给脚本 | 不在 `docs/devSpec/` 为每个任务域创建嵌套 `AGENTS.md`。跨目录细则按任务语义生效，因此由根入口显式路由读取 |
| [OpenAI Docs：Model guidance / Favor leaner prompts](https://developers.openai.com/api/docs/guides/latest-model#favor-leaner-prompts) | 精简重复指令；每条指令只陈述一次；只暴露任务相关上下文；用代表性任务重新评测 | 每条细则只有一个正文 owner；主文档不复制细则；任务路由只加载命中内容；固定样本测量识别准确率 | 不把官方内部样本的收益比例外推为本工程收益；本工程只报告自身字节数、覆盖与识别样本结果 |

Codex 不会因为 Markdown 链接而自动加载细则。主文档因此使用强制动词要求“分类、打开并完整阅读”命中的文件；链接只提供可定位坐标，不能替代这条执行指令。`docs/AGENTS.md` 和 `evals/AGENTS.md` 同时由根入口显式路由，避免从仓库根目录启动时漏读目录规则。`CLAUDE.md` 是面向另一编码智能体的等价主入口，不属于 Codex 官方发现链；本工程仍按用户要求与 `AGENTS.md` 保持逐字一致。

## 4. 维护规则

- 一条规则只能在一份细则中主讲。其他细则需要该规则时只链接到对应标题，不复制正文。
- 新规则先判断是否适用于所有任务。只有适用于所有任务且会改变任务分类、证据准入或最终完成判断时，才进入主文档；其他规则进入唯一细则。
- 修改任务域、文件名或路由信号时，必须同步更新主文档、本文索引和规范识别评测样本。
- 移动规则时必须删除旧正文，并检查所有旧标题、相对链接和引用。
- 纯文档变更不制造产品失败，但必须保存规范覆盖、入口一致、链接有效和识别评测的执行结果。

## 5. 识别评测边界

[`recognition-cases.json`](recognition-cases.json) 保存任务描述与首选细则的固定样本。根目录的 [`scripts/check_dev_spec.py`](../../scripts/check_dev_spec.py) 从主文档任务路由表提取识别信号，对样本执行首选细则识别，并检查入口一致性、行数和本地链接。

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/check_dev_spec.py
```

合并门槛是首选细则识别 `24/24`、目录模块覆盖识别 `6/6`、两个主入口逐字一致、仓库根入口与各模块入口的组合少于 32 KiB，以及本次治理范围内的本地链接全部有效。失败输出必须列出误判样本或损坏坐标。

该评测只回答“给定样本能否从主文档准确找到第一份细则”，不能证明模型理解了全部正文，也不能替代具体变更的产品 baseline、E2E 或人工设计评审。评测结果必须同时报告命中数、样本数和准确率，禁止只报告百分比。

| 主入口一致性 | `AGENTS.md` 与 `CLAUDE.md` 逐字一致 |
| 仓库内模块指令链 | 根入口加 `docs/AGENTS.md` 为 17,188 字节；根入口加 `evals/AGENTS.md` 为 17,718 字节 |
