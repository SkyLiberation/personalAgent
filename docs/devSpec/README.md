## 1. 渐进式披露规则

## 3. Codex 官方机制与本工程选择

本工程采用“根入口保持精简、任务命中后显式读取细则”的结构。该结构基于以下 A 级官方资料，访问与复核日期均为 2026-08-27：

| 官方坐标 | 可复核契约 | 本工程采纳 | 本工程不采纳 |
| --- | --- | --- | --- |
| [OpenAI Docs：Custom instructions with AGENTS.md](https://developers.openai.com/codex/guides/agents-md) | Codex 在工作前读取 `AGENTS.md`；从项目根目录向当前目录组装指令；更近目录的指令后加载；`project_doc_max_bytes` 默认上限是 32 KiB；规则应简洁，格式检查应交给 CI | 根 `AGENTS.md` 保存仓库级门禁；`docs/AGENTS.md`、`evals/AGENTS.md` 与生产 Prompt 模块的 `AGENTS.md` 保存目录局部规则；主文档控制在 32 KiB 内；可机械检查的入口同步、行数、链接和路由交给脚本 | 不在 `docs/devSpec/` 为每个任务域创建嵌套 `AGENTS.md`。跨目录细则按任务语义生效，因此由根入口显式路由读取 |
| [OpenAI Docs：Model guidance / Favor leaner prompts](https://developers.openai.com/api/docs/guides/latest-model#favor-leaner-prompts) | 精简重复指令；每条指令只陈述一次；只暴露任务相关上下文；用代表性任务重新评测 | 每条细则只有一个正文 owner；主文档不复制细则；任务路由只加载命中内容；固定样本测量识别准确率 | 不把官方内部样本的收益比例外推为本工程收益；本工程只报告自身字节数、覆盖与识别样本结果 |

Codex 不会因为 Markdown 链接而自动加载细则。主文档因此使用强制动词要求“分类、打开并完整阅读”命中的文件；链接只提供可定位坐标，不能替代这条执行指令。`docs/AGENTS.md` 和 `evals/AGENTS.md` 同时由根入口显式路由，避免从仓库根目录启动时漏读目录规则。`CLAUDE.md` 是面向另一编码智能体的等价主入口，不属于 Codex 官方发现链；本工程仍按用户要求与 `AGENTS.md` 保持逐字一致。

## 4. 维护规则

先确定规则的唯一正文归属，再修改入口；不能靠复制正文维持同步。

- 只有适用于所有任务且改变任务分类、证据准入或完成判断的规则进入根入口；其他规则进入对应细则或最近的模块 `AGENTS.md`。
- 新增规则先检查是否已有正文。其他入口需要时只链接到标题；移动时删除旧正文并检查旧标题与全部引用。
- 修改任务域、文件名或路由信号时，同步根入口、本文责任表和规范识别样本。
- 根入口与细则冲突时依根规范修正。两个主入口不一致属于入口损坏，不得继续实现；入口尺寸与模块组合限制由[DOC](../AGENTS.md#4-主文档与模块规范维护)规定。
- 纯文档变更保存规则覆盖、入口同步、结构与链接检查、识别评测结果，不制造产品失败，也不把文本缩减声称为模型能力提升。

## 5. 识别评测边界

[`recognition-cases.json`](recognition-cases.json) 保存任务描述与首选细则的固定样本。根目录的 [`scripts/check_dev_spec.py`](../../scripts/check_dev_spec.py) 从主文档任务路由表提取识别信号，对样本执行首选细则识别，并检查入口一致性、行数和本地链接。

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/check_dev_spec.py
```

合并门槛是首选细则识别 `33/33`（含模型输入审计的三个样本及单元测试停用、离线回放两个样本）、目录模块覆盖识别 `8/8`、两个主入口逐字一致、仓库根入口与各模块入口的组合少于 32 KiB，以及本次治理范围内的本地链接全部有效。失败输出必须列出误判样本或损坏坐标。

该评测只回答“给定样本能否从主文档准确找到第一份细则”，不能证明模型理解了全部正文，也不能替代具体变更的产品 baseline、E2E 或人工设计评审。评测结果必须同时报告命中数、样本数和准确率，禁止只报告百分比。

以下为 2026-09-02 的历史检查快照，不代表当前文件尺寸；当前结果以本节命令的实际输出为准：

| 指标 | 结果 |
| --- | --- |
| 单个根主入口 | 从 47,848 字节、497 行降至 16,016 字节、111 行；字节数减少 66.53% |
| 主入口一致性 | `AGENTS.md` 与 `CLAUDE.md` 逐字一致 |
| 仓库内模块指令链 | 根入口加 `docs/AGENTS.md` 为 21,239 字节；根入口加 `evals/AGENTS.md` 为 28,585 字节；根入口加生产 Prompt 模块 `AGENTS.md` 为 18,254 字节 |
| 任务路由 | 9/9，其中 `REF` 再按 8 类能力组件渐进披露 |
| 首选细则识别准确率 | 28/28，100.00% |
| 目录模块覆盖识别准确率 | 8/8，100.00% |
| 本地链接 | 135 个链接通过存在性检查 |

这组结果没有可比较的切分前识别准确率，因为旧主文档没有任务路由和固定识别样本；禁止把 target 的 100.00% 伪装成相对提升。字节压缩只描述单个根入口，不代表全部规范正文的总字节数减少。
