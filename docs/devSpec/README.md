## 3. Codex 官方机制与本工程选择

2026-10-10 核对 [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：Codex 启动时先读取全局指令，再从项目根到当前工作目录加载；每级依次查找 `AGENTS.override.md`、`AGENTS.md` 和配置的 fallback，最多选一个非空文件。较近目录的内容后加载，可覆盖早先指令；合并上限由 `project_doc_max_bytes` 配置，默认 32 KiB。动态页面按复核日期解释。

本仓库用根入口保存全局门禁，目录入口仅补充局部规则；这是项目自己的内容治理选择。不得把“根门禁不得放宽”解释为客户端先加载子目录或强制根文件最后生效。`CLAUDE.md` 是镜像入口，Codex 默认发现名不包含它，配置 fallback 后才可能参与发现。

从仓库根启动不会自动加载所有子目录入口。修改跨目录文件前，按根规范检查目标文件的祖先目录并显式读取适用入口；普通引用文档也需显式读取。工程尺寸门禁由 [DOC](../AGENTS.md#4-主文档与模块规范维护)拥有，检查不包含仓库外全局指令、用户配置或实际模型 Context 总量。

## 4. 维护规则

- 修改前确认唯一正文归属。只有全局门禁、任务分类和路由进入根入口；详细规则进入任务细则，目录特有约束进入模块入口。
- 清理重复条款时保留必要摘要与有效链接；移动正文或改标题时同步所有引用，不建立“最新版”双轨。
- 路由、任务域或目录入口变化时，同步根表、本文责任表和受影响识别样本。样本验证真实任务边界，不能只为迎合关键词得分改写。
- 规范整理先定位重复、冲突或过期条款，保持有效门禁及正文归属；有独立职责的入口和细则保留，无独立职责的文件按 DOC 删除并修复引用。纯文档检查不要求产品失败或独立设计文件。
- 两个主入口不一致时先修复同步，再继续受影响实现；规范本身的清理不被这一问题阻止。
- 文档整理报告检查与尺寸变化，不制造产品失败，也不声称模型理解或产品质量得到提升。

## 5. 识别评测边界

[`recognition-cases.json`](recognition-cases.json)拥有固定导航样本；[`scripts/check_dev_spec.py`](../../scripts/check_dev_spec.py)检查主入口字节同步、仓库指令链尺寸、9 个任务域与标题、首选细则、目录入口、本地链接及 Markdown 标题锚点、代码围栏配对。来源范围为根入口、模块入口、文档索引、开发细则、引用的治理索引与参考目录。

```powershell
.\.venv\Scripts\python.exe scripts/check_dev_spec.py
```

门槛是已登记样本全部命中、9 个任务域完整、入口一致且满足尺寸要求。样本总数以 JSON 为准，实际尺寸与链接数量以命令输出为准，不在规范重复维护历史快照。

任务样本采用关键词启发式，只检查导航首选，不代表 Code Agent 的实际语义识别或完整任务域并集。目录样本检查文件位置与适用入口；不加载模型、不运行产品评测或单元测试。报告命中数、样本数与误判，尺寸变化只与本次修改前的工作树比较，不用历史拆分快照计算当前收益。

脚本检查 Markdown 标题生成的锚点，HTML 自定义锚点、表格含义和 Mermaid 另按 [DOC](../AGENTS.md#5-提交前检查)审读。机械检查不能替代规则一致性评审。
