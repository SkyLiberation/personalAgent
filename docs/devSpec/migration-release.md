# 迁移、ADR 与完成门禁细则（REL）

> 适用于迁移、兼容、ADR 和交付判断。分类证据由根规范与 EVD 拥有；本文拥有迁移例外和完成检查，所有条目按实际影响范围适用。

## 1. 迁移与兼容边界

正式兼容期前，内部契约按[根规范第 2.3 节](../../AGENTS.md#23-只实现最小生产纵向切片)在同一变更替换全部调用方、受影响数据与旧写入口。没有数据或 Schema 变化时不制造迁移；回滚依靠版本与必要备份，不保留无消费者旧链。

真实外部契约、存量生产数据或混合版本部署需要兼容时，ADR 记录消费者、范围、原因、风险、验证、迁移计划、观测、退出条件和删除日期。兼容期须有真实消费者，不能为未来可能性永久保留双轨。

## 2. ADR 准入

以下实施决策需要 ADR：

- 跨模块责任或信任边界的实质调整，或引入、替换影响主链协议、部署、持久化或运维责任的框架或基础设施。
- 新增 Planner、通用状态、持久化权威事实、多智能体拓扑等主链机制，或以持久化投影改变主链一致性、授权或恢复语义。
- 引入事件溯源、Saga、兼容窗口，或改变 Command、digest、replay、Approval、Verification、Completion 语义。
- 实施偏离规范“必须”“禁止”的例外。

ADR 按[中文结构](../chinese-writing-spec.md#6-各类文档的附加要求)组织，说明决定、责任、复杂度、替代方案、适用外部依据、验证及防护设计。设计部分遵守[设计文档写法](../chinese-writing-spec.md#61-设计文档写法)。规范文档自身的去重、过期清理和边界澄清由 DOC 验收，不为每次文字修订创建 ADR；规范整理不能伪装实际产品行为变更。

保持职责与契约的文件移动、模块内封装、普通依赖升级，以及既有模块内的派生缓存，按 [EVD](change-evidence.md#12-按实际影响选择证据)和适用 [ARC](architecture-ownership.md#61-派生缓存与投影)规则准入，不因目录、库版本或存储形式变化单独触发 ADR；涉及上述任一实施决策时仍须 ADR。

例外须有退出条件；兼容或临时例外有移除日期，长期架构决定不编造到期日。未执行证据明确标记，不能把接受 ADR 当作生产准入或发布通过。

## 3. 完成检查表

先确认变更类型，再检查以下适用项。不适用项可合并说明；未执行不能写成通过。纯文档和只读任务不需要产品 baseline、真实模型、生产可达性或完整发布矩阵。

| 范围 | 交付检查 |
| --- | --- |
| 所有变更 | 目标、实际影响和类别明确；按 [EVD](change-evidence.md#12-按实际影响选择证据)说明所选证据、覆盖与升级条件；用户改动保留，报告实际命令、结果与未验证限制 |
| 设计与优化项 | [EVD 流程](change-evidence.md#7-强制开发与设计流程)中的设计文档和可执行验收在实现前形成；分类依据与实际结果满足门槛，设计及受影响权威正文已同步，不保留过期、冗余或冲突描述 |
| 文档变更 | [DOC](../AGENTS.md#5-提交前检查)的事实坐标、唯一正文、生命周期、中文表达、引用与结构检查通过 |
| 规范入口或路由 | 主入口同步、尺寸和适用[路由检查](README.md#5-识别评测边界)通过，不把样本命中外推为模型理解 |
| 产品行为或能力收益 | [根第 4 节](../../AGENTS.md#4-变更准入速查)的分类证据及门槛达标，[EVD](change-evidence.md#2-产品-e2e-的最低资格)的 E2E 资格与依赖链边界满足 |
| 内部重构 | 可重复工程约束下降，按 EVD 的行为保持判据验收；证据复用满足 EVM，依据不足的边界已升级验证，不冒充新产品能力 |
| 架构或模型 | [ARC](architecture-ownership.md)的事实、决策、唯一业务写入口、适用派生存储规则、依赖方向、契约一致性和可达性通过；新增结构有真实消费者 |
| 代码或 Prompt | [COD](code-structure.md)的类型、不变量、错误与模块边界明确；Prompt 通用、版本化，实际输入审计及适用模型评测通过 |
| 执行或恢复协议 | [EXE](agentic-execution.md)的准入、执行事实、Verification、Completion 分离，权限、幂等和恢复反事实通过 |
| 迁移或兼容 | 第 1 节要求满足；被替代的旧字段、路径、权威镜像、旁路和 fallback 清理，例外有真实消费者与期限 |
| 新机制或复杂度 | [EVD](change-evidence.md#5-复杂度说明complexity-justification)的最小改动、复杂度及适用外部比较有依据 |
| 验证与安全 | [QLT](quality-security.md)规定的适用 E2E、Offline Eval、真实 smoke 及工程静态检查通过，未维护或运行停用单元测试 |
| 评测或发布声明 | [EVM](../../evals/AGENTS.md#5-比较身份与归档)的身份与封存满足；发布另有目标 clean revision 的完整矩阵，不由定向或局部通过替代 |
| 优化记录或活动设计 | [优化](../optimization/README.md)及 [Future](../future/README.md)的候选、失败总结、固化和引用收敛满足，不将未覆盖记为失效 |

生产变更的 lint、类型、依赖、配置及 dead-code 检查按实际工具与影响适用；文档修正不要求无关代码检查。报告新增与删除的净复杂度及真实样本量，不能复用旧测试数充当当前验收。

局部机制通过须满足 [EVD 归因](change-evidence.md#1-用户结果与工程约束的可执行基线)并保留原始 E2E 失败。完成声明必须限定到已验证范围，产品完成与可发布仍需各自全部门禁。
