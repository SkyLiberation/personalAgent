# 上下文、记忆与检索细则（CTX）

> 本细则在任务涉及 Context、Memory、RAG、Artifact、检索、权限过滤、预算物化或 Capability Projection 时生效。通用事实归属见[架构边界与事实归属](architecture-ownership.md)，测试要求见[测试、评估、观测与安全](quality-security.md)。

## 1. Context 的处理顺序

必须遵守[根规范第 2.4 节](../../AGENTS.md#24-决策执行与完成不得混装)的处理顺序：先按权限与作用域筛选可见内容，再按需求召回、由模型选择语义相关内容，最后按预算压缩并注入模型 Context。

### 1.1 模型输入优先表达语义，机器消费保持结构化

**面向模型的任务说明、运行状态、工具反馈和修订要求，应优先用简洁自然语言说明其意义；面向运行系统的模型动作与判别结果，必须遵守对应 typed contract。** 这种区分取决于消费者，不取决于传输外壳是否为 JSON。自然语言正文可以装在结构化工具消息中，模型输入也可以保留更适合精确比较的表格、列表和结构化数据。

- 运行系统产生的关键反馈必须说明涉及哪个对象、发生了什么、适用范围及对下一步的约束。模型需要据此修订时，说明允许的处理方向；禁止代替模型补写业务答案或把未知事实写成否定结论。不得只返回错误码、布尔值或未解释的内部字段名，让模型猜测其业务含义。
- 模型可见的计数和状态必须交代单位、范围及影响决策的未知或缺失语义。说明必须进入实际模型请求；Python 注释、未发送的 Schema 描述、日志和仅向用户展示的文本不能算作模型已获得说明。
- 引用 ID、资源引用、URL、行号、可直接调用的参数和协议字面量按原值保留，并按需解释用途。证据原文、代码、原始 JSON 和多模态内容保持所需保真度，禁止为追求自然语言而改写证据、丢失对应关系或掩盖截断；来源数据须与运行系统指令清楚分隔。
- 模型可见说明由既有 Context 物化边界依据 canonical typed facts 生成，只是可重建的只读投影。运行系统继续依据 typed facts 准入、执行和判定覆盖，禁止从这段说明反向解析控制流、建立第二事实源，或要求模型复述系统已经拥有的执行事实。
- 同一信息只保留当前决策所需的表达，避免把完整内部对象和同义长文重复注入。模型供程序消费的输出使用最小必要结构，字段语义与校验遵守 [COD](code-structure.md#6-生产-prompt-是版本化代码契约)；用户可见正文无需为了形式统一拆成无消费者字段。

例如，累计读取反馈可以表达为：“此来源共 120 行，累计完整返回 30 行，尚有 90 行未完整返回。读取覆盖不足不能支持全文缺项结论；可继续取证，或将陈述限定于已返回片段。”这里的计数由运行系统计算；完整返回不代表模型已理解全部内容，也不自动证明文档确实缺项。总数未知时应明确说未知，不能计算或编造剩余量。

依据与适用边界见[外部源码比较](../agentRef/context-engineering.md#4-模型可见反馈与机器协议的表达分工)。该规范不证明自然语言总比 JSON 有效，也不证明现有修订失败由字段表达导致。修改生产物化或 Prompt 时仍须按 [EVD](change-evidence.md) 验证实际发送内容、事实保真及用户结果；没有失败证据时不得据此批量改写工具协议或新增通用转换框架。

## 2. 存储边界

- Agent State：保存当前运行所需的结构化状态；
- LLM Context：保存当前模型调用实际可见的内容；
- Checkpoint：保存恢复执行所需的快照；
- Artifact Store：保存大文本、文件和中间产物；
- Long-term Memory：保存跨会话可召回的事实或经验；
- Retrieval Index：保存检索投影，不作为事实权威源。

State 优先保存 `ArtifactRef`，不得复制大型 Artifact。RAG 只负责检索和证据组织，不得成为隐藏的 Router 或 Planner。检索策略必须由数据与评测驱动，禁止为单一 benchmark 硬编码；中间检索指标不能替代最终答案与证据正确性。

## 3. Capability Projection 与服务提供方绑定

Capability definition 由对应 Application owner 管理。模型可见 capability、工具 schema、服务提供方可用性和检索结果都是临时只读投影，必须先经过 visibility 或 policy，再进行 materialize。投影可以帮助模型选择 Application Capability，不能替智能体完成开放语义选择，也不能反向成为定义或可用性事实源。

只有完整满足同一 `CapabilityEquivalenceClass` 的服务提供方才能确定性绑定。存在语义差异时，必须由模型或外部权威选择。
