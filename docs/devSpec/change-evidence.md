# 变更证据与设计准入细则（EVD）

> 适用于产品行为变更、机制收益、缺陷修复、内部重构和机制选择。最低分类证据由[根规范第 4 节](../../AGENTS.md#4-变更准入速查)拥有；本文拥有证据取得、因果归因与设计准入。

## 1. 用户结果与工程约束的可执行基线

初始文档先登记问题、待证假设与验收计划；生产方案先证明问题，再准入候选，按[第 7 节流程](#7-强制开发与设计流程)推进。产品变更从真实用户、自然表达、可见信息、缺失结果和反事实出发，选择当前最简单正式入口，不能为既定机制编造需求。

- 新增能力或公开契约变更取得正式入口失败 baseline 后预声明 target 与指标。主张目标机制带来独立质量、成本、延迟或恢复收益时，另声明比较变量及适用消融或因果反事实；单纯能力验收不强制正式消融。当前路径已满足目标及声明约束，或失败只来自环境、评测时，不进入对应产品实现。
- 缺陷修复定位既有权威契约或确定性不变量。可还原历史失败可作为依据，固定失败输入的回放只证明该前提下的责任边界；真实 target 仍验收用户结果。
- 重构用可重复命令证明职责混装、依赖、可达性、耦合或复杂度约束，按第 1.2 节取得行为保持证据；行数或主观“不优雅”不能单独准入。
- 文档修正核对事实坐标，规范整理定位重复、冲突或过期条款，按 [DOC](../AGENTS.md)验收；只读分析报告已核实事实和限制，不制造产品失败。

原始 E2E 与预声明机制检查点分别记录。失败归因至少写明原始结果、发生阶段、因果责任、被否定主张及仍成立部分：

| 事实 | 取舍 |
| --- | --- |
| 评测或环境错误 | 保留原失败，优先修正评测或环境并恢复原验收；该错误不能作为原方案生产修复 baseline |
| 候选反例、因果回归或未进入生产消费点 | 撤回被否定或无消费者的生产部分，不保留双轨 |
| 检查点成立，后续失败因果独立 | 限定验收局部机制，另登记并优先解决产品阻塞，随后继续原方案验收；原 E2E 保持失败 |
| 未到达、服务中断、预算阻塞或因果未明 | 标记未验证边界并保留证据，主动定位责任；确认独立后按第 7.1 节优先解决，候选不自动失效 |

局部验收须真实到达生产消费点、检查点成立且排除候选回归；无法排除因果责任时不作通过声明。候选可换责任边界、输入事实或恢复协议重新准入，不能挑成功、放宽评分或叠加同义状态。文档保留与固化由[优化规则](../optimization/README.md)拥有，活动设计收敛由 [Future](../future/README.md#状态变化必须在同一变更收敛)拥有。

### 1.1 模型依赖链必须连续验证

后置结果依赖前置模型如何规划、分段、选证、生成参数或消费反馈时，验证范围必须覆盖最早相关不确定决策及实际消费者；只在最后一步使用真实模型不足以证明整链。

1. 运行前列出前置事实、生成者、模型不确定性与消费者。身份和原文等初始事实可固定，模型产生的稿件、划分、计划或反馈不能预设正确。
2. 同一轨迹直接消费实际输出，经过适用正式校验和恢复。不能由脚本补齐、重分段或替换中间结果；正式确定性转换须保持原契约并记录。
3. 跨进程或正式恢复可以续跑，但状态、输入、输出身份可追溯到同一链。不能拼接独立采样、模型版本或筛选后的成功前稿。
4. 预声明样本、重试、恢复、成本与停止条件，前置失败进入整链分母，后置未到达单列。后置条件通过率可另报，不能替代整链通过率。
5. 收益涉及反馈生成、对象选择与修订时，同轨迹经过实际核验及消费；人为反馈、理想稿与固定历史输入只支持声明前提下的局部反事实。
6. 封存相关实际请求、原始输出、转换、拒绝、恢复和最终结果。连续部分模型步骤仍可只是 Offline Eval；只有满足完整正式入口与用户结果契约时才是 E2E。

固定历史状态可以复现问题并审计后续行为，不能证明该状态稳定可达或整条模型方案有效。联合验证不等于联合归因，局部机制和独立失败仍分别计分。

### 1.2 按实际影响选择证据

**证据强度由受影响行为、信任边界和所声明结论决定。** 分类最低门槛由[根规范第 4 节](../../AGENTS.md#4-变更准入速查)拥有；代码量、目录位置、修改者自称“重构”或评测成本不能代替影响判断。权限、事实归属、真实 E2E 资格与结论强度始终适用。

在对应设计文档或 ADR 中简述改动、受影响消费者与契约、所选检查及覆盖范围、未覆盖边界与升级条件；复用证据时给出原始坐标和适用理由。说明按改动规模合并，不新增独立审批流程或评分系统。

严格保持行为的内部重构须证明受影响范围内的用户结果与公开契约、模型输入及工具语义、权限、状态迁移、副作用和恢复行为保持。可使用职责与依赖前后对照、调用关系、类型及静态检查、契约对照和适用离线回放，并按 [EVM](../../evals/AGENTS.md#5-比较身份与归档)复用已有产品证据。声明 Prompt 或输入构造仅迁移位置时，须对照实际发送字节、工具定义、消息角色与顺序；静态检查本身不证明模型行为。无需为每个类或辅助模块重新运行完整用户旅程。

出现以下影响时升级受影响边界的验证：

- 实际模型请求、工具定义、反馈语义或服务方协议改变，按模型语义变更执行实际输入审计、真实模型评测及适用 E2E。
- 用户结果、公开契约、权限、状态、副作用或恢复协议改变，适用对应产品或安全门槛；不得继续按纯内部重构验收。
- 调用关系、装配、外部依赖或错误处理改变且行为保持依据不足，或回放出现未解释差异、已有证据未覆盖影响范围时，执行定向真实 E2E；真实接入仍由适用 smoke 或 E2E 核对。

已经证明不受影响的边界不重复运行。离线回放只支持其真实前提下的局部结论；未解决证据缺口只阻塞受影响实现或主张，独立工作可继续。定向或历史证据不替代目标版本完整发布矩阵。

### 1.3 探索与生产准入边界

问题或根因尚未确认时，可在用户授权范围内开展只读调查、基线准备及有界隔离诊断或原型，用于区分假设与取得分类依据。运行前说明问题、隔离代码身份、输入、判据、成本和停止条件；纯静态调查合并说明适用项。

探索代码不得接入生产装配、写入口或共享业务状态，不保留生产开关、别名和旁路，也不绕过权限、副作用与成本约束。临时源码和产物按 [EVM](../../evals/AGENTS.md#5-比较身份与归档)归档，验证类别及单元测试停用边界按 [QLT](quality-security.md#1-测试职责与覆盖)执行。

原型或条件局部证据只支持其已执行边界；进入生产仍须取得根规范第 4 节的对应依据与 target，不能把原型通过改称产品 baseline、真实接入或完成。已有用户失败但根因待定时，可记录因果假设并诊断，不把未证明原因写成事实。

## 2. 产品 E2E 的最低资格

入口、真实决策与用户结果资格由[根规范第 2.1 节](../../AGENTS.md#21-证据先于设计)拥有，替身边界由 [QLT](quality-security.md#1-测试职责与覆盖)拥有。证据设计还须满足：

- baseline、适用消融和 target 固定入口、用户输入、身份、初始事实与结果契约；消融只移除目标机制消费点。
- 真实 target 使用生产领域模型、状态迁移、装配、持久化，以及结果依赖的真实模型和外部执行边界。
- 可用明确命令重复执行，并由 Trace、事件或报告定位最早失败；内部路径仅作预声明检查点或执行后观察。
- 原输入、比较身份、代码状态、报告与 checksum 按 [EVM](../../evals/AGENTS.md#5-比较身份与归档)封存。代码身份有 commit、tree 或 patch，不能只有版本标签。

冻结模型、直调组件或注入结果按实际边界分类，不能因 HTTP、数据库或故障注入形式取得 E2E 资格。

## 3. 删除优先与兼容边界

生产只保留获准目标路径，兼容例外由 [REL](migration-release.md#1-迁移与兼容边界)拥有。baseline 保存不可变证据，消融保存在独立 commit、tree、patch 或 worktree；不能为了实验保留生产 flag、别名、双写、测试旁路或永久 deprecated 字段。

## 4. 禁止无证据优化、过度设计与能力空转

新增复杂度必须解决已证明产品缺口或工程约束。没有独立职责、消费者、信任或事务边界的 Model、状态、digest、表或层不准入；不能为对齐框架复制 Planner、Task、Event 或拓扑。对象与 Trace 存在不是收益，产品收益看预设结果与适用成本，重构收益看已测工程约束。

生产可达性由 [ARC](architecture-ownership.md#7-生产可达性)检查。发现已有无消费者结构时先核实引用与生命周期，再在相应变更清理，不能借一次局部任务无界删除无关代码。

## 5. 复杂度说明（Complexity Justification）

新增架构机制的设计说明至少覆盖：

1. 变更类别、基线、目标结果或约束，适用反事实、消融及门槛。
2. 已有、需扩展和缺失能力，正式入口到用户结果的路径、消费者与真实接入状态。
3. 每个新增事实、状态、模型或流程不可合并的职责、生命周期或边界。
4. 最小替代方案、净复杂度增减、同步删除、实验隔离、文档迁移和退出条件。

说明可放入现有设计或 ADR，不机械新增一份文档。Port 用于真实依赖或信任边界；单纯只有一个实现、没有外部边界和已发生变化需求时，不创建 Factory、Registry 或空接口。Command、Event、Receipt 与投影按 [EXE 消费者](agentic-execution.md#3-toolcommanddigest-与-receipt)选择，不成套创建。

## 6. 外部参考的证据分级

外部参考用于机制选型，不是每次局部修正的固定前置任务。引入或替换架构机制、采用外部运行协议或借行业实践主张收益时，按机制域优先比较两个独立 A 级实现。参考不足时记录已检索范围、可确认机制、缺口和不确定性，以隔离原型及预声明的本地证据验证候选；参考数量不足本身不否决候选，生产准入仍须满足分类证据、边界与适用 ADR。外部协议、权限或关键持久化与恢复事实无法确认时，停止受影响实现，不能用原型通过补足未知契约。

恢复已有确定性契约、行为保持重构和文档整理，可直接依据工程事实；涉及外部契约时仍核对其权威来源，不为凑数量搜索无关项目。没有独立比较时，不声称已证明行业共识或相对机制优势。

| 等级 | 来源与边界 |
| --- | --- |
| A | 已发布可读源码、协议规范、官方产品文档，能定位具体文件或契约 |
| B | 官方博客、发布说明或演讲，需与 A 级或独立来源交叉核对 |
| C | 论文、教程、宣传、示例、个人转述、未合并 PR 或 issue，只辅助提出候选 |

引用记录等级、提交或版本、日期和可复核坐标；动态页面不可冒充固定版本。多个链接来自同一实现不构成两个独立实现。比较记录包括生产装配与消费者、事实及信任边界、生命周期、权限、恢复、失败成本，以及对应本工程失败阶段的采纳和拒绝理由。

不能因同名推定等价或照搬对象数量。检索入口由 [REF](../agentRef/README.md)拥有；协议核对官方规范，编排核对项目锁定版本，恢复核对实际 replay 与幂等契约。参考目录不是固定依赖清单，也不拥有本工程行为规则。

## 7. 强制开发与设计流程

**所有设计和优化项按 `docs-first` 先形成唯一设计文档，产品项与 `e2e-first` 同步推进。** 顺序如下：

1. 在候选实验或实现前创建或更新对应设计文档，并登记到所属索引。写清要解决或优化的具体问题、用户目标或工程约束、事实坐标、待证假设、目标结果、范围和责任主体；已有文档时修订原文。文档落点按 [DOC 目录分工](../AGENTS.md#3-事实强度与文档生命周期)选择，同一问题不因一轮尝试新建第二份方案。
2. 先把验收计划写入设计。产品项定义目标用户、中文自然请求、初始事实、最简单正式入口、可自动断言的用户结果和必要反事实，形成可执行 baseline 用例。预声明样本、指标门槛、模型与外部边界、成本、停止条件及命令；使用语义评分器时先验证其允许合法结果通过、拒绝代表性错误结果。重构或工程优化先定义可重复工程命令及行为保持判据，纯文档修正按 DOC 验收。
3. 取得根规范第 4 节所需依据，核对最早失败和责任边界。未证明问题时，文档中的原因与方案保持假设或条件候选；按第 1.3 节开展有界探索。基线已满足目标时结束对应生产实施；只存在环境、评测错误时先修复该阻塞并恢复基线，原方案在分类依据成立后进入生产，同步文档。
4. 依据证据补齐下表因果决定，固定 target 的比较身份、用户结果判据与适用检查点，再实现最小切片、迁移消费者并清理旧路径。验收不可执行或所需准入依据不足时，不进入对应生产实现；不能根据候选输出放宽成功标准。
5. 按预声明计划验证，分别记录原始用户结果和局部检查点。每轮方案、实现或证据变化时，同步修订对应设计文档和受影响权威正文；更新机制、接入状态、已验证范围、剩余条件及撤回决定，按 DOC 清理失效正文和引用，再进入依赖这些事实的下一步。

设计内容与改动规模相称，可写入现有方案、候选或适用 ADR；纯文档修正和无方案实施的只读分析按第 8 节记录，不机械新增独立设计文档。设计文件存在、用例已定义或局部通过都不代表验收完成；完成判断仍由 [REL](migration-release.md#3-完成检查表)拥有。

生产设计步骤须是一条可证伪的因果决定：

| 必填项 | 内容 |
| --- | --- |
| 依据与必要性 | 已执行失败事实、最早阶段、不修改时缺失的结果或约束 |
| 责任主体 | 语义、确定性事实、唯一写入口和真实修正边界 |
| 模型输入依据 | 涉及语义行为时的 [CTX 实际输入审计](context-memory-retrieval.md#12-system-prompt-与-context-的设计及问题分析)、候选差异及保留事实 |
| 因果与防护 | 最小改动怎样消除失败；如何通过责任、契约与执行约束保护既有行为，并验证这些约束 |
| 证伪与退出 | 区分偶然通过的反事实、target 或适用消融，失败撤回范围与重新准入条件 |

上一步未成立时后一步仅为条件候选；不能为分步归因切断第 1.1 节模型依赖链。

E2E 遇阻转入 [QLT](quality-security.md#2-e2e-阻塞按目标阶段和单变量处理)。一次有界修正仍复现、补丁增长或责任跨层漂移时，按第 7.2 节先停止受影响路径并复审方案。已确认的独立阻塞按下节优先处理，原方案保持；候选调整与撤回按第 1 节因果证据决定。

### 7.1 独立阻塞优先解决并保持方案一致性

**落地过程中，已确认非本方案引入且阻断实施或验收的问题，必须优先解决，解除后继续原方案。** 该规则适用于环境、外部服务、评测、工具链及既有生产缺陷；因果未明时先定位，不能仅凭失败发生在另一模块就认定独立。

1. 封存失败，核对实际输入、代码与配置身份、最早责任边界及原方案差异。区分方案引入的回归、独立阻塞和待证假设；涉及模型语义时按 CTX 审计实际请求。原始失败、未到达阶段及未知成本保留。
2. 独立阻塞在自身责任边界内取得分类依据，补齐最小修复或恢复方案及验收条件，优先实施；随后检查原失败边界，恢复原方案的验证入口。同一阻塞经一次有界修正仍复现时，先执行第 7.2 节方案复审，再决定修复方向；优先解决不等于持续追加尝试，也不直接结束原方案落地。
3. 原用户目标、职责边界、核心机制、事实与权限契约、验收标准和已成立机制保持。阻塞修复分别记录改动、输入及验证身份、实际成本和证据；改变模型、服务、配置或协议时按实际影响补齐评测与比较说明，不将多项变化的结果单独归功于原方案，也不以缩减真实输入、注入理想结果或放宽判据绕过阻塞。
4. 同步唯一设计文档中的阻塞归因、修复责任、保留条件及恢复入口。设计或契约确需调整时，先依据新证据修订同一方案，再迁移全部受影响消费者与权威正文，保持唯一现行路径。独立阻塞的修复事实按自身问题归档，既有已成立证据按原适用身份保留。
5. 在现有授权与预算内主动解决；确实依赖不可控外部恢复、缺失权限、必要用户决定，或触及预声明成本硬限且无法继续时，说明已执行排查、无法自行解除的条件及可执行恢复入口，只中止受阻执行并继续可独立推进的工作。用户明确要求停止时遵从；条件解除后继续原方案剩余验证，完整验收前保持未完成状态。

### 7.2 重复阻塞先复审方案再继续

**同一阻塞经过一次有界修正仍复现，必须先停止受影响路径，重新分析具体优化或修复方案，完成重新准入后再继续。** 该门禁覆盖设计、隔离候选、开发和验收，也适用于优先处理的独立阻塞；达到预声明停止条件或出现直接候选反例时提前停止。

1. 按最早失败边界和待解决的因果问题识别同一阻塞，汇总已有尝试、实际差异、输入与结果、已知和未知成本。更换 Prompt 措辞、版本、模块或责任层不自动成为新问题，不重置尝试和成本记录。模型与服务恢复按原预声明执行，不能通过新增恢复或重新采样覆盖原失败。
2. 停止该路径的新候选实验、生产补丁、扩大 E2E 和无信息增量的重复运行。继续封存、只读输入审计及不依赖该阻塞的工作；需要区分原因的隔离诊断按第 1.3 节预声明，不计为修复资格。原方案及已成立机制按实际证据保留。
3. 在唯一设计文档中复审用户目标与验收、原假设、最早责任主体、实际输入输出及完整依赖链。逐项说明已有尝试改变了什么、哪个检查点成立、什么反例否定机制，区分环境、评测、信息缺失、事实归属、契约和机制问题。涉及模型时审计实发请求及构造链，不以可见理由代替因果证明。核验漏放先执行 [QLT 最小充分上下文诊断](quality-security.md#21-核验漏放先验证最小充分上下文)，充分准确输入仍漏放时重审当前核验任务的合理性和契约。
4. 下一方案写清新的因果依据、此前方案为何未切断失败链、最小修正边界、既有契约防护及可区分旧假设与新假设的反事实。仅改提示措辞、移动责任、增加预算或重复同一比较不构成重新准入依据；涉及机制选型时按第 6 节比较。证据尚不足时保留待证假设，先诊断，再决定实现。
5. 同步清理失效设计与候选状态，重新声明下一步输入、实际消费者、样本、累计尝试与成本、停止条件、撤回范围和原方案恢复入口。取得根规范第 4 节对应准入依据后，从原失败边界验证；局部成立再恢复原正式入口。原始失败和未知用量保留，重新准入不能放宽用户结果或替换为理想中间状态。

复审是继续推进前的门禁，不要求追加用户审批，也不撤销已有授权。无法自行解除的外部条件按第 7.1 节报告；受影响方案保持未完成。

## 8. 变更分析最小模板

说明内容与改动规模相称，合并相关字段即可，不要求每项成为标题。产品或架构变更说明目标与范围、基线及最早责任、解决机制、防护设计、证据计划、事实归属、可达性、复杂度、删除及文档影响；证据选择、覆盖及升级条件按第 1.2 节合并说明。涉及模型输入、依赖链或外部选型时补充对应审计。设计表达统一按[设计文档写法](../chinese-writing-spec.md#61-设计文档写法)组织。

文档修正只需说明对象、可定位问题、修订原则、引用影响和检查结果。重构不编造产品失败；不适用项可合并说明，不能用模板制造虚假复杂度。

## 9. E2E 最小模板

```markdown
## E2E：<名称>
目标用户与公开契约：<需求来源、自然表达、用户可见结果及禁止结果>
前置事实与入口：<身份、初始事实、正式入口、模型不可预知数据>
依赖链与检查点：<相关决策、实际消费、局部判据及未到达计分>
比较设计：<baseline、适用消融或责任边界反事实、target、固定与改变项>
真实边界：<生产装配、模型、执行、持久化及证据限制>
指标与执行：<门槛、样本、重复、成本、停止条件和命令>
归档：<代码及配置身份、原始结果、报告与校验和>
```

用户结果与路径证据分开；任何替代边界按 QLT 降低证据分类，不藏在 E2E 标题下。
