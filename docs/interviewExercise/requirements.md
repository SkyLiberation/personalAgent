# Agent 开发每日面试训练要求

## 交付

每天在本地 personalAgent 项目生成一组可直接练习的中文面试题。按上海时区取日期，把完整题组保存为 UTF-8 Markdown 文件 `docs/interviewExercise/YYYY-MM-DD.md`，目录缺失时创建，同日重试复用同名文件。在本次 Codex 运行结果中同时交付完整题组和本地文件路径。

## 讲解依据

这条规则适用于每道题的完整答案、运行结果及后续追问。

- **讲解标准做法必须依据优秀开源项目或组件的实际源码。** 优先核对 DeepSeek Harness。找不到同一机制的实现时，检索其他成熟开源实践，固定版本并核对源码。出题时若找不到可核对的实现，换成有源码依据的题目。已发布题目的追问如遇证据缺口，说明已查范围和能确认的结论。
- **personalAgent 只用于分析本题对应的工程不足。** 使用本地生产代码、运行轨迹和评测说明现行行为、已确认的不足或证据缺口，限制在问题分析所需的范围。改进设计可标注拟改位置和验证方式，参考做法仍以已核对的开源实现为依据。

## 选题与来源

- 先上网查找牛客网等面试网站公开发布的 Agent 开发面经，优先选近期、问法可核对的复盘。
- 每组题的岗位依据以中国国内岗位描述（JD）为主。优先查找 BOSS 直聘等国内招聘平台上招聘方发布的 Agent、LLM 应用或智能体岗位，也可使用国内企业的官方招聘页。优先引用近期、内容可核对的职位原页。海外岗位可补充个别主题。
- 根据面经中的真实问法和岗位能力要求提炼题目，轮换主题。用自己的话转述，分别说明面经追问和岗位正式要求，附上来源链接。日期可查时一并注明。
- 每组恰好五道主问题，按第 1 题到第 5 题编号。前四题是 Agent 开发理论和工程设计题。第 5 题是唯一的 AI 编程实践题。每题给出完整中文答案，题组到第 5 题结束。
- 第 5 题给出一个具体的 AI 辅助开发场景，说明如何拆解任务、约束修改范围、审查差异并验证结果。用开源参考的实际源码说明应如何修复。用本地源码、提交差异、评测归档或可复现检查定位个人工程的问题，并区分已取得的结果和待验证的做法。

## 每题的答案结构

每题依次使用四个三级标题。题组文档和运行结果采用同样的结构。

1. **理论分析。** 先用一句能直接口述的结论回答问题，再解释机制、适用条件、关键取舍和一个具体失败场景。题目涉及识别、比较、选择、阻断或停止时，说明实际检查哪些输入或状态、采用什么判据、命中后执行什么。用具体输入或前后状态演示一遍判断。
2. **代码实践。** 按「讲解依据」选定开源实现。沿正式入口、装配、核心处理和结果消费讲通一个例子，写清实际字段、判断规则和触发条件。附 Git 提交及可复核的源码坐标。区分手写示例、可选装配、实际生效路径和运行证据。
3. **当前工程的不足。** 读取 personalAgent 的对应生产代码和已有证据，以同一场景说明现行做法、已确认的不足或证据缺口及其影响。给出一句改进方向，并链接到本题的「本工程改进设计」。工程缺口须有本地依据。
4. **本工程改进设计。** 紧接本题的「当前工程的不足」，在同一道题内展开。围绕该题的一个具体问题，说明拟采用的最小改动、借鉴的开源机制、实际源码落点和责任边界。写清触发条件、输入、输出及消费位置，指出怎样隔离变化并保护相关的准入、执行、状态和恢复流程。给出可执行的验证方法、通过条件和至少一个反例，标明已证、待验证和引入条件。证据只够确认缺口时，优先设计验证。工程业务范围不涉及该题时，写明适用边界和引入前提。

## 表达与排版

- 用二级标题标明题目，三级标题保留四个固定答案部分。每一道题各有自己的「本工程改进设计」。可为重复标题设置独立锚点，确保本题的不足链接到本题的设计。确有助于扫读时再加简短小标题。
- 每部分开头先给一句核心判断，适度加粗关键结论或判据。一个短段讲一个观点。并列要点用项目符号，有先后关系的流程用编号。
- 把具体例子、已有证据和待验证方法各自独立成段。来源和源码坐标放在对应段落末尾。读者应能快速找到结论、判断依据、操作步骤和证据限制。
