## 第 1 题｜Agent 连续调用工具却没有推进，怎样让循环收敛？

### 理论分析

**我会用重复调用做通用提醒，有明确交付契约时，再用待交付缺项判断实际进展。**

- **判断。** 给 CSV 补价格时，每次收到工具回执后更新“仍缺可核验价格的商品 ID”集合。核验了 A 的价格，集合从 `{A, B, C}` 变为 `{B, C}`，就记一次进展。换三个关键词却只拿回同一条旧记录，集合始终不变，连续三次未推进。
- **处理。** 把缺项和已尝试的路径反馈给模型，例如“还缺 A、B、C 的价格，这三次查询只找到原记录，请换数据源”。参数错误可以给一次明确的修正机会。异步轮询依服务状态退避，同参数调用可能是正常等待。
- **退出。** 结果满足验收条件就交付。换策略后仍无进展，或达到时间、步数、token 上限，就停止并报告未完成项。

## 第 2 题｜上下文接近窗口上限时，怎么压缩才能继续原任务？

### 理论分析

**我会保留可按权限回读的原始记录，按请求容量逐级缩小模型工作集。**

先估算整份请求并预留输出空间。可重读的大结果可以外置。仍接近上限时，把较早且工具调用与回执完整配对的历史压成摘要，保留当前目标、未解决项、近期完整交互和原件引用。生成摘要会增加模型调用和延迟，候选请求需要再测一次大小。

**失败场景。** 用户要求只看 2024 财年，摘要只留下“已检查财报”，下一轮可能拿 2023 年的数据回答。验收摘要时除了测大小，还要核对年份等关键约束是否保留，必要时依引用回读原件。

## 第 3 题｜接入大量 MCP 工具时，怎样控制模型可见的工具集？

2026-10-12 字节面经追问了 Function Calling、MCP 分工以及大量能力如何匹配。EnCharge AI 的 Agent Harness 岗位要求处理工具 Schema、调用校验和 MCP 服务开发，岗位页未标注发布日期。 [牛客面经 03](https://www.nowcoder.com/discuss/940390952902914048?sourceSSR=subject) · [EnCharge AI 官方岗位页](https://job-boards.greenhouse.io/enchargeai36/jobs/4409175009)

### 理论分析

**我会先筛权限和任务阶段，再按工具规模与使用频率决定直接曝光还是按需加载。**

Function Calling 让模型表达工具名和参数。MCP 让客户端发现和调用服务端工具。工具能否执行由运行时根据当前授权和参数决定。

- **少量工具。** 直接发完整 Schema，省去一次加载决策。
- **工具很多、单题只用少数。** 先提供有区分度的简短目录，再加载选中工具的完整定义。要把加载调用、下一次请求和缓存变化一起计入成本。

**失败场景。** 目录把“搜索 PDF 内容”和“按页段读取 PDF”都写成“查询文档”，模型可能选错工具。目录应说明输入和用途的关键差异，执行仍按已绑定 Schema 校验。

**我会让 AI 先解释并定位错误的去重范围，再把补丁限于申请准入，最后按原审批入口验证行为。**
