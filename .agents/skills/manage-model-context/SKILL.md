# 模型上下文管理

按模型承担的任务查找上下文模式，沿实际请求与构造链核对，再维护对应正文。上下文模式指输入由什么组成、谁产生、按什么顺序接续，以及反馈、修复、跨轮和压缩如何处理。

## 1. 按任务检索

| 模型任务或识别信号 | 上下文正文 |
| --- | --- |
| agent loop、主决策循环、用户多轮任务、业务工具调用与结果修复 | [Agent loop 上下文模式](../../../docs/context/agent-loop.md) |
| 目标核验器、goal verifier、目标定义核验、目标维护结果与 goal 修订复验 | [目标核验器上下文模式](../../../docs/context/goal-verifier.md) |
| 目标遵循核验、执行前待验工具调用及动作修订、待交付回答和回答修订复验 | [目标遵循核验器上下文模式](../../../docs/context/goal-compliance-verifier.md) |
| Runtime 拦截、拒绝原因、模型可用的修复动作 | [Runtime 拦截反馈清单与审查](../../../docs/context/runtime-feedback.md) |

先区分主循环、目标定义核验和目标遵循核验；主循环收到核验反馈，不等于核验器需要接收主循环的全部工具历史。其他任务先查[上下文索引](../../../docs/context/README.md)与实际消费者；未收录时定位现有权威契约，再新增对应任务正文和索引，不套用主循环模式，也不预建无消费者的任务条目。

## 2. 快速定位实际上下文

1. 确定任务、入口、用户轮次和具体模型调用。优先读取已有实际出站请求，取得消息角色与顺序、工具定义、动态区块及适用的历史／压缩身份；没有实发请求时明确只是预期模式。
2. 从任务文档的源码入口追到唯一事实来源、投影、请求组装及服务方适配。逐项核对必要输入是否真正发送、来自哪个对象和版本，不能以模板、日志或配置存在替代实发证据。
3. 按原时间顺序还原“用户输入 → 模型决定／工具调用 → 真实结果与核验反馈 → 实际修复 → 再核验”。核对当前分支、调用配对、跨轮继承及未决反馈，不只检查最新反馈是否存在。
4. **拦截反馈必须能指导修复。** Runtime 拦截动作并交由模型修复时，必须把具体反馈拼接到负责修复的下一次实际模型请求，并与被拒动作配对。说明被拦截的动作或字段、实际值或缺失信息、违反的具体条件，以及当前允许的修复动作或取值范围。禁止只传错误码或“参数有误，请重试”等笼统提示。以实发 Context 核对模型是否收到作出修复决定所需的信息。

输入审计与同轨迹推理的使用执行 [CTX](../../../docs/devSpec/context-memory-retrieval.md#12-system-prompt-与-context-的设计及问题分析)；一般语义设计与输出契约按需使用 [LLM 决策设计](../design-llm-decisions/SKILL.md)。

## 3. 上下文模式修改必须同步维护

**多轮上下文必须滚动保留前序会话。** 每次请求都须保留同一会话内属于该模型职责的此前各轮交互，并按实际发生顺序追加本轮已发生的交互。只有触发上下文压缩且确需缩减历史时，才可用摘要替换或移除旧信息。压缩时仍须保留当前目标、仍有效的用户约束、未决事项，以及后续判断所需的工具调用与结果配对。

修改输入组成、角色／顺序、任务历史、核验反馈与修复路径、裁剪、摘要或恢复模式前，必须调用本 skill，并先更新 `docs/context` 中对应任务正文。正文写清目标模式、变化原因、事实来源、消费者、循环条件、实现状态与适用验证；任务名称或落点变化时，同步本表、目录索引和受影响权威契约。

实现核对沿正文给出的既有入口进行，不新建可写上下文镜像。发现实际实现与目标模式不符时记录可定位差异；生产修改仍按 [EVD](../../../docs/devSpec/change-evidence.md#12-按实际影响选择证据)准入和验收，不能以文档已经维护宣称模型输入或行为已经修复。

报告聚焦任务入口、实际／预期上下文顺序、维护位置及未核实差异。仅维护 skill 与文档时检查格式、链接、锚点和规范同步，不调用产品模型或单元测试；涉及生产模式修改时，另外核对实际请求、适用反事实和用户结果。
