# 模型上下文管理

按模型承担的任务查找上下文模式，沿实际请求与构造链核对，再维护对应正文。上下文模式指输入由什么组成、谁产生、按什么顺序接续，以及反馈、修复、跨轮和压缩如何处理。

## 1. 按任务检索

按模型承担的决策职责查[上下文索引](../../../docs/context/README.md)。同一用户任务可包括主循环及不同核验调用，分别核对它们的输入。索引未收录时，沿正式消费者查找已有契约和请求组装。

排查技能发现、可见范围、目录、加载回执、重复调用或压缩后重读时，先读 [Skill 处理流程](../../../docs/context/skill.md)，用实发请求核对目录、正文、提醒与原调用的位置。

## 2. 快速定位实际上下文

1. 固定任务、入口、用户轮次和模型调用。读取实际出站请求，取得消息角色与顺序、工具定义、动态区块及历史或压缩身份。只有设计或模板时，记录为预期模式。
2. 从任务文档的源码入口追到唯一事实来源、投影、请求组装及服务方适配。逐项核对必要输入是否真正发送、来自哪个对象和版本，不能以模板、日志或配置存在替代实发证据。
3. 按原时间顺序还原“用户输入 → 模型决定／工具调用 → 真实结果与核验反馈 → 实际修复 → 再核验”。核对当前分支、调用配对、跨轮继承及未决反馈，不只检查最新反馈是否存在。
4. 对交给模型修复的拦截，核对下一次实发请求是否把反馈与原动作配对。合读原提议和回执，定位被拒对象、实际值或缺失、具体约束和合法修复出口。[拦截反馈清单](../../../docs/context/runtime-feedback.md)
5. 定位模型决策问题时，以本次目标、约束和判断所需依据为参照，审计完整实发 Context。检查重复注入的冗余信息、与当前决策无关的内容，以及与有效来源、版本或实际执行事实不符的错误信息。对每项发现记录消息或区块位置、产生来源和对决策的可能影响。区分已确认的输入偏差与仍待验证的因果解释。未发现问题时说明已核对的范围。

输入审计与同轨迹推理的使用执行 [CTX](../../../docs/devSpec/context-memory-retrieval.md#12-system-prompt-与-context-的设计及问题分析)；一般语义设计与输出契约按需使用 `design-llm-decisions`。

### 2.1 用具体用例展示 Context 原文

问题描述或工程总结涉及 Context 时，必须用与结论直接相关的具体用例，交代用户任务、运行入口、轮次、模型调用及预期与实际差异。以该用例的实际出站请求为依据。涉及多次调用时，按发生顺序逐次展示。没有取得实发原文时，标明缺失和未核实的结论。设计或模板只能说明预期 Context。

- 给用户展示每次请求的关键结构。按原顺序标明消息索引、角色和区块来源，展示实际出现且与判断有关的系统指令、用户目标与约束、历史、工具和 Schema、回执及核验反馈。保留工具调用、结果与反馈的对应关系。缺失的必要区块注明未发送。
- 逐字引用支持判断的原文。长区块选取连续原文片段，按原位置和顺序显示，在省略处标 `……`。整块略去时保留区块标识并注明原因。原文与分析分开。审计使用完整实发请求，省略仅用于报告展示。

## 3. 上下文模式修改必须同步维护

按 [CTX 表达分工](../../../docs/devSpec/context-memory-retrieval.md#11-模型输入优先表达语义机器消费保持结构化)组织模型可见信息，原生角色、工具配对、引用和原文保真沿相应协议处理。结构化数据的字段语义、单位及缺失含义应从同一次请求中读到。

按决策职责滚动接续相关交互，保留原时间顺序和工具、结果、反馈的对应关系。若服务方协议要求调整发送顺序，记录适用条件并保留原顺序的追溯依据。按[上下文管理](../../../docs/context/context-management.md)处理裁剪、摘要、卸载和重读，检查有效目标、用户约束、未决事项及后续决策所需事实仍可取得。

**上下文设计必须保护 Prompt 缓存的可复用前缀。** System Prompt 只承载稳定职责和通用规则。工具描述说明稳定用途，Schema 声明参数形状和稳定约束。同一模型任务的版本和契约未变时，保持这些定义及其顺序稳定。禁止随请求、轮次或步骤把变化的任务数据写进 System Prompt、工具描述、Schema 的枚举、默认值或示例。

时间戳、剩余预算、当前计划、文件清单及新出现的路径或资源 ID，按其来源交给当前用户消息、Step Context 或工具回执。在服务方协议允许的位置将新增内容接续到可复用前缀之后，保留来源、消息角色和反馈配对。工具可让模型提交材料或回执中出现的引用，由 Runtime 校验有效性和授权。避免把本次可引用对象复制成变化的 Schema 枚举。[主循环的 Step Context](../../../docs/context/agent-loop.md#1-目标与输入责任) · [会话文件契约](../../../docs/context/tool.md#会话文件替换决定)

已发送且仍适用的历史按原样接续。权限或工具可用性变化、必要压缩或 Prompt 契约升级时，以当前正确输入为准，说明哪些变化会截断前缀。及时移除已失效信息，保留必要反馈。

在对应任务正文说明稳定前缀、动态区块位置及前缀可变条件。选动态数据变化且工具契约一致的相邻实发请求，按服务方协议定位 System Prompt、工具定义和历史的首处差异。验证缓存收益时固定模型、端点及无关输入，分别报告实际前缀与实测命中率。用量和命中率汇总使用 `compare-agent-benchmark-performance` 的指标口径。

修改输入组成、角色、顺序、历史、反馈、压缩或恢复前，先更新第 1 节定位的权威正文。说明目标模式、变化原因、事实来源、消费者、实现状态和适用验证。涉及多个上下文契约时同步受影响正文和引用。

实现核对沿正文给出的既有入口进行，不新建可写上下文镜像。发现实际实现与目标模式不符时记录可定位差异；生产修改仍按 [EVD](../../../docs/devSpec/change-evidence.md#12-按实际影响选择证据)准入和验收，不能以文档已经维护宣称模型输入或行为已经修复。

报告聚焦任务入口、实发与预期顺序、维护位置及未核实差异。
