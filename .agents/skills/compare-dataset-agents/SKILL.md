# 数据集 Agent 对照评测

先核实答案隔离和操作环境，再独立运行双方。只有两项检查通过且双方均有有效评分的配对才用于逐题归因。

## 1. 选择对照方并冻结评测计划

1. 按发布方正式入口或版本化说明确认官方 Agent，记录依据、版本和入口。没有可执行的官方 Agent 时，使用固定源码提交、依赖和配置的 DeepSeek Harness。官方 Agent 已发布但接入失败时，记为官方对照未执行并定位接入阻塞。[评测入口与 DeepSeek Harness 接入](../../../docs/evals/README.md)
2. 固定本 Agent 的目标代码与正式入口、数据集版本、用例 ID 和试次数、原题原件、初始事实、评分器与通过判据。尽量固定双方的模型版本、服务方、采样参数、可用 seed、轮数、token、工具调用与超时预算。事前声明比较变量和停止条件，记录官方强制条件及所有无法对齐项。Conversation 用例沿用现有正式 HTTP 流程。[运行入口](../../../docs/evals/04-running-and-release.md#conversation-评测共用入口)

## 2. 先通过答案隔离检查

- 给每题每方各建干净会话和独立的数据、工作区及输出。两边仅收到原题、允许使用的任务资料和工具。标准答案、隐藏标签、评分器及日志、能直接导出参考结果的预处理配置、解题轨迹和其他运行产物留在独立评分或分析环境。工具可达的文件挂载、检索库、记忆和网络同样执行这个边界。题目要求联网时，按任务授权访问原始资料，封住能查到本题答案或解法的来源。[官方 Agent 的评测材料隔离](../../../docs/evals/04-running-and-release.md#官方-agent-的评测材料隔离)
- 启动前用双方实际权限检查题目资料可读、评分材料和其他会话的结果不可达。通过挂载与工具访问检查验证隔离。凡出现答案可达、已经暴露或隔离无法证实，停止受影响配对，保留原归档并从有效统计剔除。封住来源后，用新会话和干净的初始环境重新跑双方。评分或分析阶段取得的信息禁止进入后续试次和复跑的输入。

## 3. 对齐双方实际可用的操作环境

| 边界 | 配对检查 |
| --- | --- |
| MCP | 以一份清单装配双方。核对服务及版本、数据与操作语义、工具参数、实际授权与审批、作用域及超时。检查实际模型请求中的工具声明，并用任务允许的探测确认关键工具可调用。工具同名只提供定位线索。 |
| 沙箱 | 核对镜像、执行依赖、运行身份与文件权限、网络可达性、初始文件摘要及可读写路径。确认 MCP、命令执行和评测器分别看见本方同一份工作区终态。 |
| 外部状态 | 两边从等价初始状态启动，分别使用隔离实例或命名空间。只有共享服务可可靠重置时才串行使用，记录复位结果。 |

业务条件对齐后，双方沿各自的正式入口、Prompt、工具调用和核验机制运行，并记录实现差异。Toolathlon 复用已有的 MCP 清单及沙箱装配。[共用 MCP 清单](../../../docs/evals/04-running-and-release.md#toolathlon-共用-mcp-工具清单) · [执行环境对齐](../../../docs/mcpDesign/README.md#可比的执行环境)

发现环境不一致时，先停下受影响的比较，在原题许可、隔离与审批边界内统一配置。环境检查通过后，从同一份初始状态的独立副本上，让双方重新跑全部受影响用例。共用配置改变时，以配置实际覆盖的用例为复跑范围。保存新配对及旧结果，禁止把旧的一侧与新的一侧拼接。环境无法对齐时，报告具体阻塞及受影响用例，暂停对应能力归因。

## 4. 跑完双方并逐题核对处理流程

1. 在正式终态或预算终点封存双方答复、交付物及外部终态。由隔离流程使用同一评分器和通过判据。评分依赖待重置服务时，可以先评并封存。双方产物封存后才向分析者开放本题评分和轨迹。启动失败、服务异常、无有效评分及未执行按原始状态记录。
2. 按用例 ID、试次和比较身份配对。从有效配对中取「对照方通过、本 Agent 未通过」的用例。若对齐后双方均通过，记录原差异在本次复跑中未复现。若评分缺失，先查评分边界。[评测阻塞归因](../../../docs/devSpec/quality-security.md#2-e2e-阻塞按目标阶段和单变量处理)
3. 对入选用例按时间线对齐双方实际收到的任务信息、关键决策、工具调用与结果、产物或外部状态、核验和最终交付。找到最早影响评分目标的差异，指出责任边界、上下游传导及双方证据位置。检查本 Agent 当时是否拿到同等信息、是否可执行关键动作，以及执行结果是否进入后续决策。合法的不同路径沿用原评分判据。模型、预算或追踪缺口限制归因时，明确缺口及能验证判断的最小下一步。模型请求和语义判断定位按 `manage-model-context` 与 `troubleshoot-llm-decisions` 执行。

报告记录计划配对数、有效评分及通过数、无效原因，以及入选用例的最早差异、责任边界和双方证据坐标。按 EVM 第 5 节独立归档并保存校验和。已有结果的得分、用量和耗时汇总使用 `compare-agent-benchmark-performance`。[运行归档](../../../docs/evals/04-running-and-release.md#新运行的归档位置)
