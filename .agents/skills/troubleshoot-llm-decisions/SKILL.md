# LLM 决策问题排障

从已有失败定位最早偏差，再选择修正和验证边界。

## 1. 取得能分流的最小证据

从已有轨迹取得本次决策职责、期望结果、实际出站请求、原始响应和首个不符的字段或消费结果。核对模型、服务方、输出模式与本地校验。决策依据按 [CTX](../../../docs/devSpec/context-memory-retrieval.md#121-利用-think-与中立追问核对决策依据)结合同次已有推理记录和实际输出核对。

只读取与当前失败相关的调用和构造链。证据不足时说明缺哪项、它影响哪个判断，并继续可独立开展的定位；用户描述可以用于匹配候选方法，不能写成已定位的工程根因。

## 2. 按失败边界路由

先按模型、症状和协议匹配[工程经验索引](../../../docs/experience/README.md)，核对对应经验的适用条件。再按最早成立的偏差选路径。

| 实际症状 | 处理方法与阅读入口 |
| --- | --- |
| JSON 不完整、字段缺失、分支或工具参数形状错误 | 核对截断、实发 Schema、服务方适配和校验反馈。按 `design-llm-decisions` 的「核对实际协议与修复出口」修正 |
| 必要事实、历史、摘要或工具结果缺失、失真，缓存命中突变 | 用 `manage-model-context` 定位实发输入与构造链。缓存核对相邻请求及原始用量 |
| 必要依据已进入请求，但模型选错目标、动作或判断分支 | 按 `design-llm-decisions` 核对本次责任、字段语义和相邻边界；依据仍不清楚时按[同轨迹推理与中立追问](../../../docs/devSpec/context-memory-retrieval.md#121-利用-think-与中立追问核对决策依据)定位 |
| 模型决定正确，但没有执行、真实结果未回传或反馈后未修正 | 按 `design-llm-decisions` 的「Runtime 怎样支持纠错和完成」核对准入、调用绑定、结果回传及下一次实际请求，分别归因模型选择与执行事实 |

服务方能力和本地声明不一致时，分别核对官方契约、实际请求和原始响应。

## 3. 选择修正并验证对应边界

说明匹配依据、适用前提、最小修正及其消费者。区分表示转换、语义重决策和执行恢复；确定性转换只处理契约已允许且含义唯一的表示差异，业务缺值或选择错误交回负责的决策环节。

实施前按[变更证据要求](../../../docs/devSpec/change-evidence.md#12-按实际影响选择证据)取得准入并更新唯一设计；经验文档不直接授权生产补丁。验证围绕原失败与必要反事实展开，涉及前置模型决定时消费同轨迹实际输出。具体重复次数与验收由 `analyze-proposal-progress` 的「方案验证与重复次数」拥有；同一阻塞有界修正后仍未解除时按[重复阻塞复审](../../../docs/devSpec/change-evidence.md#72-重复阻塞先复审方案再继续)处理。

按“失败与证据 → 责任和修正位置 → 实际验证及剩余条件”报告，只读分析明确候选状态。可复用的具体症状与方法写入工程经验及其索引。
