# Feature flag 控制与实验组维护

通过[开关配置](../../../config/feature_flags.toml)登记功能开关，通过[实验组记录](../../../docs/ablation/experiment.md)查找语义、接入状态、比较条件和实际结果。配置拥有当前开关值，实验文档拥有比较方案与证据，不复制第二份当前配置。

## 配置实验

1. 读取配置与相关实验组，确认开关对应的功能范围及实际接入状态。当前由 `Settings` 读取 TOML，经 `AgentRuntime` 注入回答模块和 Conversation；两项默认开启。配置路径可通过 `PERSONAL_AGENT_FEATURE_FLAGS_CONFIG` 指定，格式或布尔值错误时拒绝启动。
2. 按本次实验臂修改对应布尔值，其他开关保持原值。实验组 1 的两臂组合以实验文档为准；改变当前配置不改写该组的比较定义。
3. 运行实验前，确认正式入口确实消费这些值并实现相应行为，固定其他比较条件，保存每臂的配置原件与源码身份。配置在进程启动时读取，并在 Journal 的 run 与对话边界绑定；切换实验臂使用独立进程及空会话，不通过修改文件改变已有运行。关闭不产生 passed 回执；目标关闭但回答开启时，回答核验消费明确标为未核验的已接纳目标快照。
4. 执行需有用户授权和工程准入，记录实际结果、费用与未执行范围；完成后恢复约定配置并报告恢复值。仅请求创建或修改配置不等于授权真实模型实验。

## Feature 变更必须同步实验组

新增、移除、重命名或改变已登记 feature 的语义、默认值、适用范围、依赖及接入状态时，**同一变更必须更新配置及所有受影响的实验组记录**。先按开关键搜索引用，再调整对应组的比较条件、可执行状态和依据；最后核对没有实验组仍引用已删除或旧语义的开关。

- 移除 feature：删除其配置项，将依赖它的实验组标为失效并说明原因；原运行配置、结果和证据保持历史身份，不补造一个“关闭”来替代不存在的功能。
- 重命名或改变语义：迁移当前引用，更新实验组；语义变化后的新执行使用独立身份，不能与旧结果直接合并。
- 仅临时切换值：保留组定义；若实际执行，记录所选实验臂、配置快照、结果及恢复情况。
- 涉及模型输入、历史或反馈回环：同时调用[上下文管理 skill](../manage-model-context/SKILL.md)，维护对应 `docs/context` 正文。仅切换已定义实验臂的配置值不改写上下文契约。

检查 TOML 可解析、开关值为布尔值、实验组引用有效及接入状态准确。纯配置与文档维护只做技能、配置和链接检查；实际运行及因果比较按实验文档引用的工程门禁执行。交付说明修改了哪些开关或组、是否实际生效、实验是否运行及证据位置。
