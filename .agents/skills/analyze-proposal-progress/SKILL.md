# 方案推进分析

围绕一个目标问题，固定验证计划，核对实际差异，再决定保留、修正或撤回。通用规则只写一次，按验证目标选择自主决策或语义修复的判据。

## 1. 固定已有方案与保留依据

- 固定目标问题、方案版本和原 baseline，链接实际结果、初步效果及其适用范围、已核对的参考方案。分清已成立机制、待证假设和未验证部分，局部结果与整体用户结果分别记录。
- 已有初步效果且有参考支持的具体方案及成立部分应保留。新验证未通过但参考仍适用时，先保留候选，完成差异分析后再决定去留；明确反例否定的生产部分按 EVD 撤回，保留候选不代表验收通过。

## 2. 分层核对差异

按下表组织分析与证据，缺少依据的关系标为待证，不凭终态或同轮发生推断因果。

| 核对层次 | 参照要求 | 当前事实与差异 | 处理依据 |
| --- | --- | --- | --- |
| 参考方案与当前设计 | 原始来源、版本、成立条件、机制与反馈消费方式 | 采用、简化或偏离了什么，是否破坏参考前提 | 参考存在不等于本地有效 |
| 当前设计与实际实现 | 正式入口、契约及实际消费者 | 装配、配置、实际输入输出与 Trace；机制是否完整实现、触发并被消费 | 定位最早责任边界；模型请求按 CTX 审计 |
| 验证方法与原 baseline | 预声明变量、固定条件及结果契约 | 实际比较身份是否一致，是否到达目标机制，断言能支持什么结论 | 区分验证错误、方案错误及未验证边界 |
| 新问题与当前问题（如有） | 原目标、责任边界与必要反事实 | 同一问题复现、方案回归、独立阻塞或无关问题 | 相关问题回到对应边界；独立阻塞先解除，无关问题单独处理，禁止并入当前方案或追加验收条件 |

## 3. 方案验证与重复次数

先依据实际输入规则选择第 3.1 或 3.2 节。纯确定性校验、行为保持重构和文档修正按 EVD 的实际影响验收，不适用模型调用次数要求。

以下规则用于制定和执行验证计划，只声明本次实际涉及的字段与条件：

1. **预声明。** 在唯一设计中固定输入与对照、目标契约、合法决策范围、错误判据及适用的反馈标准与误拒门槛、次数与顺序、组级判据、预算和停止条件。涉及概率改善或置信区间时，另定比较指标、方法及假设，不能将多命中一次等同于契约修复。
2. **真实输入。** 模型验证使用 [QLT 真实轨迹用例](../../../docs/devSpec/quality-security.md#12-通用核验点与真实轨迹用例)的完整输入；依赖前置模型决策时执行 [EVD 连续验证](../../../docs/devSpec/change-evidence.md#11-模型依赖链必须连续验证)。裁剪、改稿、手工补证或理想反馈只作诊断，不计正式修复验收。
3. **固定比较条件。** 除声明变量外，固定 Prompt、材料、对象、Schema、模型、Provider 参数、预算、恢复策略与评测器，核对实际 SDK 请求，记录温度、seed、版本和缓存的已知或未知条件。对照被误改时先恢复；确需改变条件时按 [EVM 比较身份](../../../evals/AGENTS.md#5-比较身份与归档)建立新比较并取得相应基线与候选证据，原 baseline 和成绩不改写；历史证据仅在其复用边界内使用。
4. **额度与停止。** 按实际输入、历史耗用、推理及正文输出、修订和服务延迟预留足够额度，核对单次输出上限、总 tokens、轮数、工具次数与等待时限的实际值。已证明不足的单次额度须修正，不能仅扩大总预算。先完成既定用例，再按同一结果契约优化成本；截断、预算耗尽或费用不足按责任记录失败或未验证，不靠减最低次数、裁必要材料、放宽判据或无界重试取得通过。执行成本同时遵守 [EVM 效率规则](../../../evals/AGENTS.md#7-e2e-执行效率是评测设计门禁)。
5. **独立运行与留证。** 独立运行之间不消费其他运行的答复、审读或期望答案。保存原始输入、首响应、正式恢复后结果、实际反馈及逐物理调用用量；首响应与恢复结果分别计分。语义或输出契约错误不能按服务故障剔除、补跑替换；无完整响应、服务异常和未知用量另行归因，按预声明恢复或停止。重复解析、评分、服务重试和结构恢复不增加独立次数，不挑成功样本或重跑直到命中。
6. **结果解释。** 报告实际次数、分子／分母、未执行、未到达、未触发、未决和成本；一次轨迹内多次调用或同一输入重复运行不冒充多个独立任务。允许满足同一契约的合法表达和不同执行路径通过，不用当前实现的输出代替成功标准；精确文字、顺序等要求仅在对应契约成立时断言。

### 3.1 自主决策的验收例外

输入规则允许模型自主选择动作、路径或继续／交付时，按选择是否符合规则、必要前提和用户结果契约验收，不设固定 10 次运行或 `10/10 pass` 门槛。按预声明场景与反事实检查错误决策；不同合法选择、不触发可选机制或合规停止不计失败，违反规则或必要结果契约的决策仍计失败。

可选机制未触发时如实记录，不强迫补跑凑次数，也不声称该机制已验证；本次目标要求的机制仍须取得适用证据。修正不合理的既有判据时，先据输入规则更新计划并记录新比较身份，原结果保留。

### 3.2 局部语义判断类修复的重复验证

不适用第 3.1 节，且目标是修复明确漏判、误判或无效反馈等语义契约错误时，每个关键真实输入的基线、候选各至少运行 **10 次独立判定**，不是两组合计十次，也不机械扩大为十轮完整 Product E2E。[同输入重复诊断](../../../docs/ablation/claim-verifier.md#217-固定输入的二十次重复)是该最低次数的工程依据，不构成稳定性或总体统计代表性保证。

- 分别记录准确命中、漏报、已发现但反馈失准、输出契约失败、合法关系误拒与未决。解释、类别、定位、引用和证据须对应同一实际差异；文字提及问题但对象或反馈错误，不能算准确可用结果。
- 同一运行可同时审读多个判断关系，按各自分母报告，不按关系数增加调用或相加冒充更多独立样本。
- 成功声明须完成基线与候选两组最低次数，候选组满足预声明的修复契约与组级条件。失败早停可提前否定候选，但不得声称完成整组；测量固定次数的波动或命中频率时，不因语义结果提前结束，预算、服务和安全停止条件仍适用。
- 十次最低要求自 2026-10-20 起适用于新增或重新准入的修复计划；历史成绩与已关闭项不追溯改写或追加门槛。

## 4. 选择最小推进动作

- **实现偏差或验证问题：** 保留方案及成立部分，修正最早责任边界，再按原用例和判据验证。独立阻塞按 [EVD](../../../docs/devSpec/change-evidence.md#71-独立阻塞优先解决并保持方案一致性)解除后接续原方案。
- **参考前提不适用或机制被否定：** 指明反例否定的具体主张，定向修订或撤回相关部分，其余成立机制和原始证据保留。
- **原因未明或重复受阻：** 先做能区分假设的最小诊断，明确输入、判据、成本和停止条件。同一阻塞一次有界修正后按原判据仍未解除，按 [EVD 复审门禁](../../../docs/devSpec/change-evidence.md#72-重复阻塞先复审方案再继续)重新准入后再继续。
- 达到既定通过条件后按 [EVD 闭环规则](../../../docs/devSpec/change-evidence.md#14-真实用例驱动优化与验收闭环)关闭，不因独立后续失败或新增泛化、稳定性要求否定原有效结论。

## 5. 输出与同步

验证计划给出第 3 节的适用类型、依据和预声明，未执行结果标为计划。结果分析先给保留、修正或撤回结论及已成立／未验证边界，再用第 2 节的相关对照项说明证据，最后给下一步、停止条件、恢复入口与撤回范围；不重复排查流水或无关字段。

在本次授权内当轮更新唯一设计及受影响引用；只读任务仅报告分析和建议，不另建重复方案账本。

## 规范归属与分工

本技能拥有验证计划、比较方法、重复次数、组级验收与推进方法；完整方案审计使用[工程方案审计](../audit-project-proposals/SKILL.md)。准入与闭环由 EVD、验证资格由 QLT、比较身份与归档由 EVM 拥有；模型输入核对按 [CTX](../../../docs/devSpec/context-memory-retrieval.md)，记录与表达按 [DOC](../../../docs/AGENTS.md)和[中文写作规范](../../../docs/chinese-writing-spec.md)。
