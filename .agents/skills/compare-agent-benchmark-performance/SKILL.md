# Agent 测试集性能比对

## 1. 先明确测试条件

从已有报告、评分结果、运行日志和轨迹核实 A 和 B 的身份、比较目标及双方实际生效的条件。仅有计划值时，注明实际值未确认。[评测归档位置](../../../docs/evals/04-running-and-release.md#新运行的归档位置)

| 条件 | 核对内容 |
| --- | --- |
| 测试集与评分 | 数据集版本、分片、用例 ID、每题试次、输入与初始状态、任务完成条件、评分器版本及配置、分数尺度和权重。 |
| Agent 与模型 | Agent 代码版本、正式入口、Prompt 与配置版本、模型及服务方、采样与推理参数、可用的 seed，以及轮次、token、工具和时间预算。 |
| 执行环境与缓存 | 工具、权限、沙箱、初始会话和工作区、并发数、运行顺序、服务负载、缓存冷热与预热方式。说明各方是否可能复用另一方预热的缓存。 |

用数据集版本、用例 ID 和试次配对，核对原始输入、运行身份与已有归档校验和。列出已知差异、未确认条件和受影响的指标。多项关键条件同时变化时，将结论限定为整套配置的观察结果。评分尺度、任务输入或指标口径无法对齐时，呈现各自可用数据，对应差值标为不可比。

## 2. 按同一口径计算六项指标

从评分报告、运行报告及模型请求的用量记录提取逐题数据。按请求标识合并流式更新及重复汇总，独立计入重试。注明每项指标的来源与覆盖。[LongDS 用量与预算](../../../docs/budge/README.md#评测中的独立预算)

| 指标 | 统一口径 |
| --- | --- |
| token 消耗量 | 汇总任务内模型请求的总输入和输出，分别给出输入、输出及总量。总输入包含缓存读写对应的输入，按服务方字段语义对齐，已计入的分项只算一次。评分器调用单列。存在未报告用量的尝试时，标为已知小计并列出缺失数。 |
| 缓存命中率 | `Σ 缓存读取 token / Σ 总输入 token`，只纳入同一请求中两项均有效的记录，报告覆盖请求数。分母为零或字段缺失时，对应全量值标未知，可另报已观测请求的比率。汇总时按 token 加权。 |
| 模型调用次数 | 数实际发出的物理模型请求，包括主决策、辅助调用以及已发出的重试和失败请求。评分器调用单列。若日志只记模型轮次、成功响应或逻辑调用，按实际口径报告。 |
| 总耗时 | 每题从提交到终态的墙钟秒数。双方采用相同的起止语义，排除评测准备与评分，注明多轮外部等待和超时的处理。并发批次的整体墙钟时长可单列。 |
| 任务得分 | 采用同一评分器、版本、评分尺度和预先确定的汇总规则，给出逐题分数与测试集汇总。任务失败按评分规则计分。无有效评分、超时和未执行保留各自的原始状态。 |
| Runtime 耗时 | 默认取同一任务窗口内的 `总耗时 − 模型请求区间并集时长`，表示墙钟上没有模型请求进行的时间，包含对应的编排、工具执行与等待。先将请求区间裁到任务计时窗口，再合并并发重叠区间。只有已证实模型请求全程串行且时长完整时，才可用模型耗时之和。记录时间边界和计算依据，时间信息不足时标未知。若用户指定其他 Runtime 口径，按双方共同可测的定义报告。 |

## 3. 输出可复核的配对报告

1. 先给测试条件、实际差异、双方运行 ID 与证据位置。写明已知的计划配对数、有效评分配对数和覆盖缺口。
2. 用六项指标表给出 A、B、`B − A` 和各项可配对样本数。每项差值基于两边同一组可比样本和一致的统计覆盖。用量与调用次数报合计，逐题耗时默认用中位数汇总，有可比整套墙钟耗时时一并给出。保留失败试次及其已观测的资源用量，完成耗时与超时耗时按不同终态解释。缺值标未知或不适用。缓存命中率差值用百分点，其他差值用原单位。需要相对变化时用 A 作分母，A 为零时省略相对变化。
3. 附逐题、逐试次的数据或证据位置。说明得分与效率是否同向变化，并指出预算耗尽、分数下降、缓存冷热或观测缺口对结论的影响。把结论限定在已覆盖的任务与实际配置。
